## 2. E1：格式、因果和转换前置门

**最小输入**：已有Qwen3短Q/K/V和整数linear切片、合成边界；缺GQA共享query头或连续cache版本时，
才新增一层/一个KV头全部关联query头的小捕获。兄方从已有Qwen2.5、Qwen3.5运行导出代表层prefill/decode，
Gemma仅在授权后取local/global各一层。代表层/outlier层按校准统计预选，不按评价结果挑有利样本。

只保留三条分叉：①直接Q/K/V8与独立校准、全GQA共享、因果冻结的dyadic变换；两者不通过才加
KV/QK16或更细scale，并重记digit/wide/metadata成本。②P7已有512均匀行全零反例，从任意长度默认合同移除，
先用P15并按三次8位乘计PV；不盲扫所有位宽。③R state32/conv16、V norm/GELU、bias33和scale生成分别核验。
Gemma有效gamma范围、norm输出范围和GELU缺实现时保持pending，不能用SiLU或饱和后放大代替。

**观测**：原浮点/已量化输入oracle/整数kernel分层，整数不一致、overflow、饱和和随长度漂移；
未来token不改变既有前缀输出，完整prefix/cached/chunk状态版本一致；scale更新是否重写旧KV及字节。
质量沿用事前冻结协议；若采用旧拟议NLL≤5%/准确率下降≤2pp预算，需评价前明确采用、报告配对95%区间；
它是工程预算，证据不足为inconclusive，不能看结果后改阈值。

**分叉/停止**：数值、因果或版本失败立即否定合同；停止相应性能比较，先改格式/转换再重建图。
Issue39同张量离线平衡仅定位，不是独立质量或连续cache接受证据。E1不新增多模型GPU吞吐矩阵。

## 3. E2：联合判别RQ位置、M/A边界和bank争用

**两个子图**：Linear→bias/RQ→有回压的norm/门控消费者；以及QK→score三遍→P→PV digit→O→消费者。
必须计完整K、scale/bias/M/r访问、score spill、M分时复用、A单TX和有限队列，不只测一条link。
选decode一行N16（物理拍无字节收益）与prefill多行；attention先S128、d128/256，再取解析容量临界点的逻辑S。
逻辑长S可用固定/合成tensor做服务仿真，不在本机跑大模型长上下文。

**最小配对**：RQ近M/共享侧 × M/A分离/同宏，4组织；分别在RQ通道1和8两份固定库存比较，
至多8个组织/库存点，各跑prefill/decode。解析下界已超过事前吞吐目标的点只留拒绝记录。
8通道比1通道增加7个乘法器及控制/寄存器成本，不能算placement收益；每个配对内计算、RAM/FIFO、ROM口、
bank1RW和外存/链路相同。合并不删掉对照FIFO/RF再称只换标签，物理面积/时钟差异另记。

**观测**：子图完成cycle、M/RQ/V/A利用/排队、bank冲突、packet与metadata、FIFO峰值/回压/死锁，
输出逐位相同。宽算术服务由实际微架构/适用RTL校准；未实现的服务用区间敏感性，不设乐观常数定赢家。

**分叉/停止**：在两个阶段和合理服务/突发区间内保持可行，改善须超过测量/模型不确定度；
报告最差退化，面积/时序还需E4。只有字节少而cycle相同/更差，D2不选近端必配；M/A往返或score主导，
D3保留合并或另立在线算法候选，后者先回E1，不能在同函数配对暗换舍入。胜负翻转就给条件策略。
复用Issue33/39反例与Issue29控制器，不把其不同header/资源/合成服务直接当v1校准。

## 4. E3：递推反馈与共享向量池

**最小输入**：K128×V32 tile、共享q/k头约束，独立整数序列先8/32步，加入chunk/history/epoch负例及不同初态。
真实质量须用兄方Qwen3.5状态/输入并核SHA；未收到用户完成通知时只做独立合成/已有本机工作。
两种归属：R局部8lane/32KiB，与同资源移到V域；叠加同一full-attn/FFN请求流和M输出流，避免孤立核掩盖排队。
保持全K投影后才更新state及所有round/sat次序，q/k norm/history推进次数相同。

**只选三个服务情形**：当前tile热驻留、S容量临界/1RW冲突、明确canonical冷backing压力。
后者为地址/服务仿真，实际layout/cache命中未知；只在可能翻转选择的临界区扫描外存率和上下文交错。
若共享侧可通过已有M/S路径加速宽点积，应保留相同矩阵资源的优化基线，不能故意只比低效向量循环。

**观测/分叉**：逐步state/y oracle、版本、饱和/漂移、每token周期、backing等待/字节、V排队和暂存峰值。
局部反馈收益在公平调度及合理服务区间仍存在则保留R；backing主导且归属差异可隐藏则退共享宽池/条件实例化。
算力主导则先调整算术映射/库存，不凭状态标签定独立Block；无法映射/溢出不赠送SRAM或删除hybrid负载。

## 5. E4：必要连接及物理资格，只对剩余候选做一对

从E2/E3列完整端口图：M↔A、M↔V、计算↔S、V↔R、D控制。在相同端点/有源资源下比较满足需求的
最小连接集合与增加一组有明确需求的连接预算，不先跑全交叉网络。新增边要说明消除哪个不可达/争用。
本机先查有向可达/格式、TX最多4目的、1RW、有限credit/阶段依赖、backing及clock/reset/控制遗漏。

后续物理仅选剩余一对：同工艺/计算存储、冻结pin/有源buffer/clock，核允许层接入、DRC/连通、
提取RC、setup/hold/电气、总面积/线/通孔。Issue31是其他成员openTPU H2范围，复用方法不代签A/R宏，
不自动启动新作业。需新增有源buffer/端口、改冻结资产或无合法路径/时序失败，则本H2候选失败；
返回边界/库存，不把改约束当同一次成功。缺物理输入时仅报告逻辑候选/pending。
