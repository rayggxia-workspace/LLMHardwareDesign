## 1. 三层各自负责什么

| 层级 | 拟实施边界 | 归属 |
| --- | --- | --- |
| 岛内：local CTRL—小宏、小宏—小宏 | 选用的宏、原生端点适配、S访问、MUX、holding和本地控制均在共同底座内固定；各功能岛按需要选宏，不要求全七类 | 已有L2/L3/L4及后续L6/L7各岛实施，本轮不重新拆出一条主线 |
| 母控—功能岛local CTRL | 主候选为共同底座内固定任务/事件控制网络。物理采用集中、分段或区域层，依据端口/扇出/位置/时序反馈选择；母控只发粗任务，本地仍调宏op/ACK | L4/W5-IF先定合同与能力需求；L5/W2实现有界母控网络，W6扩展；L8/W11接收物理层分配 |
| 功能岛—功能岛 | 模型相关数据路线及其valid/ready、分片、存储确认和释放返回通路，在已预制端点之间由M11/M12连接/永久选择；不要求全连接交叉网络 | L4/W5-IF先列合法端点与生命周期；L5/W2做双岛闭环、W6做一般拓扑；L8/W11验同底座产品差分 |

时钟、复位、电源及必要测试/host/MEM等基础设施要单独列入共同底座预算与接口，不能只统计张量数据线。公共固定连接可按需要保留；模型数据网络和公共设施不混为一项。原方案只明确岛内固定，母控端口曾纳入顶层候选，并未冻结全局控制网；本计划将“固定母控控制网”明确为待验证主候选，不回写成已有物理事实。

全部运行时MUX、仲裁、缓冲、ROM/译码、寄存器、中继及必要CDC须在共同底座有源逻辑冻结前存在。M11/M12只能连接预留被动线路、已有常量/选择端，不能补造有源逻辑或修复CTS。固定控制网络可以承载有限产品的不同任务顺序，产品入口与参数永久绑定，不依赖启动装入新控制程序。

## 2. 当前L4先做W5-IF：接口合同前置

**安排时点：继续扩大完整A/F岛顶层之前先完成接口合同；岛内已明确的计算核研究可继续。** 本轮只规划此子任务，没有完成下面的接口合同。

产物应包括：

1. 三层端口清单：方向、生产者/消费者、时钟复位域、数据/任务/事件分工；区分逻辑接口、RTL服务和实际M10可达pin。位宽/岛数未定处标待测算，不能编造固定总线规模。
2. 任务准入和事件语义：接单、计算结果就绪、片段末尾、目的stored ACK、源可释放、状态发布、整任务完成、错误/partial分别定义；只有满足任务规定的全部义务才能报成功。
3. 数据合同：有效字节/tail、数值尺度与布局、长度来源、源保活、目的缓冲预约、重复/晚事件隔离，以及共享资源唯一owner。
4. 控制网/数据网边界：母控通过什么方式找到岛；哪些信号必须有独立前进能力；数据路径不要求经过母控；固定控制网的候选拓扑和相应资源预算。
5. 前置物理约束：按有限模型和岛实例预算评估pin数量、方向/可达层、扇出、线长、组合ready路径、区域划分、预留中继/缓冲、clock/reset及MEM/host端点。数值和容量未知项保留gap。
6. 后续R/MoE扩展需求：不可取消提交窗口、old/next/root版本、partial、动态选择/归并事件；先记录需求或缺口，不承诺已实现全局原子性、无reset回滚或通用动态控制器。

**合同退出门**：接口与事件表、资源/lifetime表和至少一个完整producer→consumer时序例子能够相互核对；数据被接受与真实存储确认分开；无未归属端口、资源或关键事件。通过范围明确到已选择的有界接口，R/MoE/MEM扩展仍待接收。逻辑合同可审查，不等于RTL或物理冻结。

## 3. L5/W2：先实现母控与双岛最小闭环

这是该问题的主要RTL实施步骤，依赖已接收的W5-IF有界合同及W1共同岛壳。

- **W2-C控制部分**：实现一个母控、两个岛local CTRL的固定任务/完成/错误网络；任务与完成均保持到接收，收集事件时独立进展，不让母控WAIT阻塞必要的返回排空。本地控制器继续独占小宏原生端口。
- **W2-D数据部分**：实现双岛输入/输出端点、片段传输、目的实际写ACK、源CLOSE/release与复用门；将拟由M11/M12绑定的正向路线和必要反向确认通路在RTL测试连接中明确表达。
- 首次可用已有MST/复制核，或已有匹配合同的内核。当前A8/F8入口包含各自权重和padding帧，不能因为出口同为128bit就把两者裸接为完整hidden张量接口；若使用它们，应先补齐W5-IF规定的适配和供数责任。
- 至少测试两种已声明合法的永久路线/产品绑定fixture，共用相同有源底座定义；路线变化不得通过generate参数偷偷增删有源MUX/缓冲。RTL层只能提供该约束的逻辑证据，实际M1–M10字节一致性留W11物理门。

**RTL退出门**：两端独立背压；task/event/payload保持；目的ACK延迟时源不被覆盖；重复/晚完成不影响新任务；abort/reset时在途事务按合同处理；同岛重入冲突被拒绝或实际物化；部分传输失败不报成功；必要返回可独立前进。新仿真及回归只在服务器Verilator，经Slurm在本人目录执行，保留源码/配置/工具/输入/输出SHA和失败尝试。

## 4. L5/W6与L6/L7：扩展已验证边界

W6在W2基础上扩展同S/同T复用、fork/join、条件分支和有初值feedback，验证资源等待图与有界活性。未选分支不能被等待，多个消费者的源释放需要明确全部确认或分次复制；多push-pull输出不得以“软件互斥”为由短接。静态算法DAG不代替实际资源无死锁证明。

L6/W7/W8复用控制网与接口，补NUM及R状态/history、不可取消commit、版本/partial事件；L7/W9补MoE动态选择、专家任务和归并事件。需要的新事件/缓冲/路由能力必须在共同底座冻结前回馈W5-IF和W2/W6，不等完整产品物理验收时才增加有源器件。MoE不必等待R资格，但仍须满足自身数值和接口依赖。

## 5. L8/W10/W11：真实系统和物理接收

W10实现真实MEM/host平台、容量、延迟、存储ACK和故障处理，并接入同一控制/数据边界。其起步依赖W1/W2及已接收的MEM/host接口合同，可与R/MoE开发并行，不要求先完成L6/L7；只有W11最终产品集成才汇合全部所需服务。外存仍保留灵活性；小双岛测试不代表MEM控制器或PHY已经存在。

W11最终接收实际共同底座、母控完整有限产品程序、ROM/层表、整岛封装/时序及M11/M12连接。至少对两个已接收产品验证共同M1–M10、PG/CTS及所有有源资源一致，定制金属/通孔差异合法，并完成所要求的STA/几何/电气等检查。路线、pin和时序的可行性反馈从L4/L5开始；此处是最终验收，不能作为推迟架构反馈的理由。
