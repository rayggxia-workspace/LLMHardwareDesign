# R局部状态接口适配：实现合同

Issue162 / PR163。新增`control_adapter_r`对应PR167现行`r_stream_local`端口，固定每版本1024个S32状态元素。该生产者的最终资格、真实配对与系统接入仍待完成。当前235实例基线继续运行，不改写其冻结源或授予R资格。

描述符W0沿用`tag16|flags4|endpoint4|op8`，endpoint=7、flags=0。W5～W7必须为零；S地址为16字节对齐的字节地址。

| op | W1 | W2 | W3 | W4 | 完成result32 |
|---|---|---|---|---|---|
| 0：S→R装载 | load_target0～7 | 起始128bit包索引 | 包数1～256 | S源地址 | 已装载包数 |
| 1：R状态→S | rd_bank0/1 | 起始128bit包索引 | 包数1～256 | S目标地址 | 已写S包数 |
| 2：R命令及结果→S | cmd_op0～7 | cmd_rows0～128 | bit0 role、bit1 clear、bit3:2 mode | S结果地址 | 成功固定4包 |

装载目标0/1每目标256包；2/3各16包；4/6各6包；5为1包；7为4包。传输起点与包数必须同时落在目标和16KiB S容量内。全部32位字段先校验再截断，防止溢出和别名。R具体命令语义和数值错误继续由R负责；rsp_error使适配器返回status4，不向S写命令结果。描述符错误status2，无外部请求。成功status0。

适配器仅保持一项R读事务，一项S事务；每次R读响应先保存128bit，再写S并等应答后递增。装载等最后`load_ready`恢复，以确认生产者写流水排空。命令结果完整保存512bit，按低128bit起顺序写入4个S包；四个S确认全部到达后才完成。完成保持至队列消费，不以延迟相等判断正确。

所有新增有状态逻辑归适配器固定M1–M10：状态机、tag/op、剩余数和索引、S请求寄存、128bit装载保持、512bit结果保持及完成保持。R拥有其算法状态、读信用和读回FIFO；适配器不增加算法状态阵列。reset取消控制/未完成事务；实际组合必须同步复位R、S访问控制及队列，状态阵列是否初始化沿用R合同，不保证事务回滚。

当前文件是可审查的接口及RTL定义，不代表实际配对、最终网表功能、布局布线、300MHz或M11/M12接入已经通过。端点7尚未加入当前C/路由/S仲裁基线；需新组合独立验证，旧21类单块或235实例证据不得转授。
