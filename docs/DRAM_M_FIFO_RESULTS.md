# DRAM侧读接口经FIFO直供M：服务器实测结果

本页保留首次RTL交付的完整记录。后续500/300MHz综合、布局布线、独立STA和最终门级验证见[物理续跑结果](DRAM_M_FIFO_PHYSICAL_RESULTS.md)，原始结果与证据保留。

2026-11-03（Asia/Shanghai）；[Issue #173](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/173)；执行账号huangpingyang04-lgtm。

**已在服务器运行通过：18组测试、2340个正确矩阵结果，两个故意损坏数据的负例都被拒绝。实现没有经过S，使用了仓库原版M。**

这里“DRAM侧”指内存控制器之后的读事务接口。仓库main没有完整DDR控制器/PHY，本次外存是数字事务模型，不能称为真实DRAM器件或板级测试。

## 1. 实际实现了什么

```text
片上300MHz：
  LOAD描述符 → 请求生成 → 请求异步FIFO
                                ↓ 500MHz读侧
                    单在途、128bit外存读事务接口
                                ↓ 500MHz写侧
                          返回异步FIFO
                                ↓ 300MHz读侧
              A128保持 / 四个128bit字拼成B512
                                ↓
                原版M的A/B银行 → 矩阵计算 → S64结果
```

新增硬件是两个FIFO和有界读请求/装载状态机，不是完整D宏，也没有S存储。请求/返回都安全交接，地址、A/B位置和错误信息随事务关联；没有只跨数据而把请求留在错误时钟域。

本次没有自动C控制或结果STORE：测试程序只提供LOAD描述符、尺度与M执行/结果读命令，所有操作数必须由内存事务模型经过FIFO进入真实M，不能由程序直接写M操作数端口。结果由M实际运算，独立整数参考逐值核对。

完整接口、布局、错误与复位合同见[实验说明](../project/experiments/dram_m_fifo/README.md)。

## 3. 18组测试的结果

| FIFO深度（请求/返回各自深度） | 外存侧 / M侧时钟 | 初态与相位组合 | 结果 |
| --- | --- | --- | --- |
| 2 | 500 / 300MHz | 3组 | 3/3通过 |
| 16 | 500 / 300MHz | 3组 | 3/3通过 |
| 2 | 300 / 300MHz | 3组 | 3/3通过 |
| 16 | 300 / 300MHz | 3组 | 3/3通过 |
| 2 | 200 / 300MHz | 3组 | 3/3通过 |
| 16 | 200 / 300MHz | 3组 | 3/3通过 |

每组采用零/一/随机初态之一、0/3/7仿真时间单位相位之一。300/300MHz组也包含相位偏移，不默认两个独立时钟同相。仿真时间单位为1/6ns，M半周期10单位、外存半周期6/10/15单位；这些是数字时钟激励，不是目标频率STA签核。

每组实际覆盖：

- 128组矩阵：rows1..8、K8 tile数1..4、尾K/尾N、S8/S16四种组合、两个M银行；每次装入实际数据后计算并读出S64结果。
- 错误恢复与复位恢复各再完成一个矩阵，所以每组130个、总计**2340个正确矩阵**。
- 8个非法描述符拒绝：行/块数越界、未对齐、40bit地址保守溢出；没有发出内存读。
- 一次真实读错误：返回错误沿FIFO到达，LOAD报告失败，继续排空读事务；调用方使M银行失效后，M拒绝不完整数据上的计算，重新装载后计算正确。
- 一次读已接受时的协调复位：同时清理模型在途与两侧控制，重新装载计算正确。每组3525个接受读、3524个返回，差的1个明确属于该复位放弃，**不是运行中丢包**。
- 强制M装载口暂停700个core周期、随机请求/接收停顿；两种FIFO都确实到过满状态并恢复。
- 请求地址/顺序、A/B内容/银行/位置/格式、背压保持、完成保持、不提前完成，及多次指针回卷均受检查。

累计程序检查计数为34,331,545，包含逐仿真步watchdog与等待上限检查；不能把它解释为同等数量的独立矩阵案例。

两个负控制：对每种深度实际翻转外存返回中的一位，两次都以 `FAIL B payload` 非零退出。检查器能识别坏数据，不是只观察“程序运行完了”。

## 4. 这次验证说明什么

**在冻结的只读、单在途协议与协调复位条件下，FIFO能让500MHz侧和300MHz M安全地按各自节奏交接，满了停发请求、空了等数据；暂时堵住M后仍能恢复，矩阵结果正确。**

深度16的返回FIFO有16×16B=256B数据载荷容量，另含元数据；请求FIFO、B拼接64B、A/B保持项另算。不能把FIFO容量重复当作多笔在途的可用位置。当前只允许一个外存读在途，发起前已有返回槽，避免下游停住后无处接收已承诺的数据。

这不是FIFO“消除带宽差”的证明：测试内存响应延迟人为设为1..9个mem_clk，最多单在途，未模拟DRAM行命中、刷新、控制器重排或真实突发效率。随机矩阵/停顿生成还会随运行路径消费随机数，因此不同深度的周期计数只作运行诊断，不能据此宣称严格同工作量的性能收益。
