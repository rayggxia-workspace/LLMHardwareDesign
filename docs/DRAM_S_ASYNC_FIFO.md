# DRAM→S→M：500 MHz / 300 MHz 异步 FIFO 跨时钟方案

日期：2026-11-03（Asia/Shanghai）；任务：[Issue #171](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/171)。

本文总结讨论方案，供后续接口设计与审查使用。本次交付是文档，没有新增 FIFO RTL，也没有取得本项目 500/300 MHz 跨时钟实现的功能或物理验收证据。

## 完整路径补充（2026-11-03）

三个聊天合并后的[完整实现流程](DRAM_SRAM_S_M_FLOW.md)给出：DRAM/PHY/控制器 → 跨时钟桥（若需要）→ D → SRAM S → 供数与适配 → M，以及C调度、结果写回和多S边界。

这里的500MHz应核对为控制器用户接口时钟；若控制器接口与D/S/M共用同一300MHz时钟，则该边界无须异步跨域，不能把FIFO简单移到DRAM引脚前。采用AXI D时需要处理全部请求/响应通道的跨时钟桥，不能只跨返回payload。D内部同步缓冲不等于本篇异步FIFO。下文保留简化接口的原理、容量及验证要求，具体模块位置以完整流程的时钟条件为准。

## 1. 条件和结论

采用用户给定条件：

- 数据路径为 **DRAM→S→M**。
- 简化场景假设DRAM控制器对片上提供的用户接口时钟为 **500 MHz**；必须与DRAM引脚时钟区分。
- 片上 S、M 使用同一个 **300 MHz** 时钟域。
- 下文用这两个时钟说明简化DRAM→S边界；加入D、完整AXI及多个S时，按[完整实现流程](DRAM_SRAM_S_M_FLOW.md)补齐相应模块和通道。

建议在 **DRAM→S 的接口边界**增加异步 FIFO（又称双时钟 FIFO），500 MHz 侧写入，300 MHz 侧读出后按 S 的原生协议写入 S。S→M 继续使用 300 MHz。

```text
DRAM 返回数据
    │ 500 MHz 侧接收并写入
    ▼
异步 FIFO：有限存储 + 指针同步 + 空满判断
    │ 300 MHz 侧读出，再写入 S
    ▼
S（300 MHz）→ M（300 MHz）
```

FIFO 是建议补充的接口电路，不是当前项目已经具备的实现。它用于吸收两个时钟之间的到达时刻差和短时速率差，不要求两边逐拍对齐，也不要求把 S/M 改到 500 MHz。500:300=5:3 这个数值比例本身不能证明相位受控；本方案按异步跨域处理。

## 2. 怎么做

### 2.1 数据交接

1. 500 MHz 一侧接收一笔有效 DRAM 返回数据，在 FIFO 有已预留容量时写入。
2. FIFO 将读写位置通过专用同步电路传到另一时钟域；读侧确认存在可读数据后，才允许取出。
3. 300 MHz 一侧按照 S 的接收能力读取 FIFO，并按 S 原生请求/应答协议写入 S。若取出的数据先进入暂存寄存器，该暂存也必须明确容量和归属；S 暂停时保持数据及元数据，不能丢弃或覆盖。
4. 数据块的全部有效字节写入 S，且所需写确认已经收齐后，再通知该块可以用于计算；不能把“进入 FIFO”或“从 FIFO 读出”当成“S 已写完”。
5. S 按原来的 300 MHz 时钟和供数握手向 M 交付操作数，计算启动遵循原有数据就绪条件。

### 2.2 FIFO 内部的跨域原理

- 使用支持所选实现方式的存储，分别提供写侧、读侧访问。具体采用标准单元还是合适的双时钟存储，要根据 ASIC 工艺与容量决定。
- 常见方案在本域维护二进制读写指针，将寄存后的 Gray 编码指针通过同步器送往另一域，用于判断满/空。典型深度取 2 的幂，使用额外回卷位；最终以所选 FIFO 实现的合同为准。
- 满标志在写侧使用，空标志在读侧使用；对端进展跨域可见会有延迟，要接受保守的满/空判断。
- 同步器用于控制亚稳态传播风险；数据总线依靠 FIFO 存储、位置和读写协议整体交接。不能给多位 payload 各自加两级触发器就认为整包数据一致。
- 写入的数据与对应的地址/偏移、有效字节、结束标志、错误状态等实际所需元数据必须保持对应，可在同一 FIFO 项携带，或由经过验证的协议关联。
- 所有实际跨域的请求、应答、完成或错误信号都要有明确的同步/握手机制；单独处理返回 payload 不代表整个双向接口已经完成 CDC。本文不预设 AXI 或其他总线协议。

### 2.3 背压和在途容量

FIFO 满时不允许继续写入，FIFO 空时不允许继续读取。接近容量上限时，应让控制 DRAM 的一侧提前停止发起新的读取；DRAM 时钟可以继续运行。

已经发出的读取可能仍会返回数据。若该返回接口不能暂停，必须在发命令前预留全部返回容量；不能等 FIFO 已满才要求 DRAM 撤销已接受的读取。若接口允许背压，也必须明确上游缓存和可暂停边界，不能默认 DRAM 引脚数据本身可以随时停住。

可采用以下保守准入检查，单位统一为 FIFO 数据项：

```text
D     ：FIFO 的实际可用容量
Q     ：当前占用量的安全上界，包含尚不能安全重用的项
R     ：已接受读取中，尚未计入 Q、但已经承诺接收的返回项数
K     ：准备新发起的读取所承诺的返回项数
H     ：停止发起/背压生效前，尚未计入 R 和 K 的额外最坏到达量
G     ：实现规定的其他安全保留量

允许新发起读取的必要容量条件：
Q + R + K + H + G <= D
```

已读出但尚未写入 S 的暂存项，必须另有实际容量和独立计数；若纳入总容量预算，需证明不会覆盖且没有重复计算。R/H/G 的定义必须互不重叠。FIFO 深度不能仅根据 500/300 的比例决定，还取决于突发长度、最大在途量、同步/控制延迟和 S 的最长暂停时间。

若 S 可无限期暂停，上游必须最终能停止产生新的数据，并能容纳此前全部承诺的返回；任何有限 FIFO 都不能保证无限期接收不可停止的数据流。

## 3. 有什么困难

| 困难 | 影响 | 处理方向 |
| --- | --- | --- |
| 异步采样和亚稳态 | 指针/控制可能在采样边沿变化 | 使用经过审查的异步 FIFO 结构、同步器及可靠性评估 |
| 多位数据和元数据一致性 | 数据可能写错位置、结束或错误标志错配 | 按事务整体交接，验证顺序和关联关系 |
| 写入快、取出慢 | 有限容量最终被持续流量填满 | 背压、读取准入及在途容量预留 |
| S 暂停接收 | 返回数据仍可能继续到达 | 预算最坏积压，保持输出，提前停止新读 |
| 复位时存在旧响应 | FIFO 清空后旧数据可能被当成新数据 | 协调排空/复位，或实现并验证可区分旧事务的恢复协议 |
| ASIC 存储及 500 MHz 时序 | 通用 FPGA 结构不能直接授予工艺资格 | 明确存储/同步单元、布局布线与两侧约束，分别验收 |

**跨域安全与持续带宽是两件事。**仅作为等宽、每拍一项的算例：128 bit×500 MHz=8 GB/s，128 bit×300 MHz=4.8 GB/s（十进制）。理想情况下持续 1 μs 会多到达 200 项，即 3200 字节。因此异步 FIFO 只能暂存这部分积压，不能让慢端长期无条件吞下快端全部满速流量。这个算例不冻结本项目数据宽度或 FIFO 深度；S 的实际服务速度还需计入请求/应答和原有端口竞争。

## 4. 需要注意什么

### 4.1 时钟、复位与物理实现

- 两个时钟周期分别为 2 ns 和约 3.333 ns；写侧、读侧逻辑均须满足各自时序要求，片上 300 MHz 的已有结果不能证明新增 500 MHz 侧合格。
- Gray 编码不能代替物理约束。同步器级数/单元/放置及跨域指针的延迟、位间偏斜，需要依据所选实现和工艺约束；不能仅把整个跨域路径设为 false path 就宣布 CDC 通过。
- 复位时禁止伪握手，读写指针及有效状态应处于一致的协议状态。可采用两域协调复位及各域同步释放；若独立复位或允许停钟，需要专门的启动/恢复协议。不能只复位一侧指针后继续接收旧返回。
- FIFO 的存储、同步器、计数及控制是有源电路，应明确放在接口电路或宏内的物理归属、面积、供电和时钟；若采用 M1–M10 预制底座，应在对应阶段纳入固定实现和验收，不能仅凭后定制金属生成。
- 不直接给现有单时钟 S 的存储另接一个 500 MHz 写时钟。先在边界完成跨域，进入 S 的访问仍属于 300 MHz 域。

### 4.2 后续实现与验证顺序

1. 明确实际接口协议、payload/元数据位宽、最大突发及在途量、能否暂停返回、S 最长暂停和复位恢复条件。
2. 选择可审查的异步 FIFO 结构，确定容量、阈值和读取准入规则，冻结 S 写确认及块完成条件。
3. 编写 RTL 后，做独立顺序/内容参考检查与断言：无溢出、无空读、无丢失/重复/乱序/元数据错配，块完成不提前。
4. 使用 500/300 MHz 的不同初始相位、满空边界、指针多次回卷、随机及持续背压、S 长暂停、最大在途返回、错误及复位中断进行仿真；检查请求和返回的完整 CDC，必要时进行形式验证。
5. 完成 CDC/复位检查，以及目标工艺下两侧的综合、布局布线、时序、电气和同步器可靠性评估。普通 RTL 仿真不能证明模拟亚稳态行为，文档与 IP 示例也不能代替物理验收。

待确定：FIFO 位宽/深度/存储结构、同步器级数、阈值、安全裕量、实际协议、最大在途量、恢复方式和物理归属。本文不编造这些实现参数。

## 5. 为什么说方案已有实现、工程上可行

**AMD 已提供支持独立读写时钟的 FIFO IP 及官方实现说明，异步 FIFO 作为跨时钟方法已有产品级实现依据，并非本讨论临时提出的设想。**

官方链接：[AMD Embedded FIFO Generator（PG327）— Independent Clocks: Block RAM and Distributed RAM](https://docs.amd.com/r/en-US/pg327-emb-fifo-gen/Independent-Clocks-Block-RAM-and-Distributed-RAM)。

该节说明：FIFO 可以使用独立的读写时钟，两者不要求固定频率或相位关系；实现包含存储、读写指针、Gray 编码同步和状态判断，并区分各信号所属时钟域。这直接支持本文“500 MHz 侧写、300 MHz 侧读”的方法原理。

**可行性边界：**AMD 文档面向 FPGA，其 block RAM/distributed RAM 和产品约束不能直接移植为本项目 ASIC 的验收结果。可据此确认技术路线已有工程实现；本项目在目标容量、工艺和 500/300 MHz 条件下是否通过，仍需第 4 节的实际设计与验证。不能据此给出未经测量的面积、延迟或吞吐承诺。

物理约束补充参考：[Altera Quartus Prime — Dual Clock FIFO Timing Constraints](https://docs.altera.com/r/docs/683082/25.1/quartus-prime-pro-edition-user-guide/dual-clock-fifo-timing-constraints)。该节说明双时钟 FIFO 指针跨域需要适当的偏斜/延迟约束；其中 FPGA 命令仅作参考，本项目采用目标 ASIC 流程对应约束。上述链接于 2026-11-03 在线核对。
