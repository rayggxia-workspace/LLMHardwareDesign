# 七宏外存供数合同与有限 DMA 首版

任务：[Issue #156](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/156)。
范围：M／N／E／G／R／S／T 七宏，S 同时覆盖标准单元版与 #155 SRAM 版。
冻结依赖为 `33d87f6868d98befe0aa01bf9c5725fe7ef47a40`；最终逐文件 SHA 和实测值见
[156 证据入口](../work/YUZE-LU/156/README.md)。

本轮交付是数据合同、真实计算 RTL 路径验证、独立可综合 DMA。既有七宏源代码、
生产选择和 #155 物理任务没有修改。真实 DDR/HBM 控制器、PHY、全模型调度及新增逻辑的
布局布线不属于此次交付；SRAM 仿真模型不能代替 #155 的真实宏物理结果。

## 1. 存储和数据归属

| 对象 | 固定容量／职责 | 本轮外存关系 |
| --- | --- | --- |
| M | 原有双银行 A/B 操作数缓冲、归约／累加／结果 | 外存→DMA→S→原供数器→M；结果→T→DMA→外存 |
| N | 统计上下文与有限流水寄存器；没有完整长向量存储 | S 分窗提供统计、EXP、归一化回放；中间 EXP 可暂存外存 |
| E、G | 原有逐元素／格式、函数与门控通路 | 本轮约定使用 S/T 数据流；没有额外声称已验证两者的外存执行路径 |
| R | 两份 8 KiB 状态银行及原有向量／历史缓冲 | 外存→DMA→S→R；显式提交后 R→S→DMA→外存；读出结果经 T |
| S 标准单元 | 16 KiB；4×256×128bit；普通口 128bit、内部宽读 512bit | DMA 与 N/R 的普通访问共用同一实际普通口，仍与供数器争用银行 |
| S SRAM（#155） | 同样 16 KiB／端口／原供数器，4 个真实 SRAM 位置 | 等待真实响应；保留额外响应阶段及含在途预留的有限响应槽 |
| T | 6 KiB＝384×128bit；一份结果租约 | 完整填入、commit 后才可读；DMA 最后一笔写确认后才 release |
| 新增 DMA | LOAD 四槽×128bit，STORE/STREAM 一个 128bit 保持寄存器 | 不新增隐藏的权重缓存、整向量缓存或无界队列 |

两种 S 是替代实现，本测试没有把它们并列相加成 32 KiB。S/T 也不是整个外存控制器。
片外存储模型是外部地址空间，不能把其容量算入片上容量。

## 2. 描述符与接口

正式 RTL：`project/rtl/external_memory/finite_dma.sv`。

| 字段 | 单位与约束 |
| --- | --- |
| `cmd_mode` | 0：外存→S；1：S→外存；2：T 流→外存；3 非法 |
| `cmd_ext_base`、`cmd_ext_stride` | 32bit 字节地址／相邻行起点差，均须 16B 对齐 |
| `cmd_rows`、`cmd_cols` | 11bit 行数／每行 128bit 字数，各为 1…1024；乘积≤1024 |
| `cmd_s_base`、`cmd_s_stride` | 11bit S 字地址／相邻行起点差，实际请求地址 10bit |
| S 地址边界 | `base+(rows-1)*stride+cols≤1024`，`stride≥cols` |
| 外存地址边界 | `stride≥16*cols`；最后字节不能溢出 32bit 地址空间 |
| T 大小 | `rows*cols≤384`；S 地址字段在此模式不使用，仍需正确的外存行描述 |

连续传输是 `rows=1`；二维搬运逐行跳过间隙。没有子字节写、非对齐访问、硬件打包、
gather/scatter 或内存一致性功能。一个描述符活动，完成未被消费前保持 `done_valid/error`。
非法描述符只产生错误完成，不发 S／外存请求。

外存侧是平台中性 128bit `valid/ready` 请求和响应口：

- 每个被接受的读或写恰好返回一条响应，严格按请求接受顺序返回；没有 tag。
- 读响应返回 128bit 或错误；写响应表示平台已确认该字的写入。
- 不接受同拍组合响应：响应最早在请求接受后的下一拍出现，且必须遵守背压保持。
- 最多四个 LOAD 请求含返回数据占用，共享四个预留槽；没有“请求四条，另藏四条响应”。
- LOAD 等每笔 S 写确认才释放其槽；STORE 每次取一个 S 字，等外存写确认才取下一个。
- STREAM 接收 T 字后保持至写确认；核对 `stream_last` 与描述符总字数。

真实 AXI／DDR/HBM 平台必须实现必要的协议转换和响应排序，不能直接把该接口称为
已有 AXI burst 控制器。平台的“写确认”语义也必须满足调用方复用源缓冲的要求。

## 3. 所有权、完成与异常

软件必须先等待 S 普通口此前的响应排空，再交给 DMA；DMA 活动期间不混入 CPU 请求。
验证夹具使用一个明确的普通口选择器，并未增加 RAM 端口。S 供数器仍可并行活动，
但只读已完成填入且不再被 DMA 改写的区间；补料须使用不重叠区间。供数器完成只表示
A/B 数据交给 M，不代表 M 已完成计算。

T 的次序为 `begin→顺序 write→sealed→commit→读出→外存写确认→release`。
最后一个 T 字被接走时，外存写可能还在途；不能仅依据 T 的 `release_ready` 提前释放。

外存错误不会回滚此前成功的写入。本实现继续排空描述符，正常字仍传输；错误的读字
不写 S，错误写不能算成功结果。调用方看到错误后必须丢弃／重新初始化整个目的结果，
不能把残留旧字当成新数据。测试故障模型让错误写保持外存原值；真实平台仍需定义自己的
失败副作用，软件不得依赖错误写保持原值来获得原子性。

T 长度与描述符不一致会报错，但不能保证自行恢复：短描述符可能留下不可 revoke 的
committed T 租约，长描述符可能等待缺少的输入。正常调用前必须校验 T 字数；异常需要
协调复位／平台恢复。单独复位 DMA 会遗失外存在途事务，禁止如此使用。没有超时器、
跨时钟域、乱序恢复、多消费者／多描述符调度。

## 4. 真正验证了什么

采用 Verilator 对原 M／N／R／S／T RTL 联合运行，外存为有限四项响应队列的 C++ 周期模型。
不是只跑 SystemC，也不是用 C++ 计算替代 DUT 的 M／N／R 输出。数学 oracle 与 DUT 分开：
M 用整数点积，N 用量化 EXP 的独立数学插值及 ties-to-even 归一化，R 用 128bit 中间计算。
这里只验证冻结整数合同，没有声称得到 FP32 全层或全模型精度结论。

| 路径 | 实际经过 | 主要覆盖 |
| --- | --- | --- |
| 矩阵 | 外存→DMA→S→原供数器→真实 M→T→DMA→外存 | 8×29×7 S8，K 尾部、二维输出、另一 S 区间并发补料 |
| N 回放 | 多轮外存→DMA→S→真实 N；EXP 经 S 写外存；最终经 T 写外存 | 257、8193 元素 Softmax；8193 超过单份 S 可容纳的 8192 个 S16，窗口最多 2048 元素 |
| R 状态 | 外存→DMA→S→真实 R；旧状态检查→错误 owner 拒绝→commit→S→DMA→外存 | GDN／SSM 各 17、256 行；8 KiB 最大单银行状态；输出经 T 写回 |
| 搬运单元 | 真实 S 普通口与新 DMA | 25 组随机二维／整份16KiB，行间哨兵、越界拒绝、错误排空、完成背压、协调复位、T 长度错误 |

平台配置：延迟 1／7／31 拍；请求接收间隔 1 或 4 拍；可配置随机拒绝请求。
每 4 拍接受一个 128bit 请求限制请求带宽为至多 4B/拍。延迟 7 时的随机拒绝概率为 1/3，
延迟 31 为 1/2。数据、握手、计算响应背压使用独立随机数流，各配置复用同样的数据种子。
两种 S 各运行三种 Verilator 初态／种子，解析初态参数后才构造 DUT，并在回执中读回核对。

所有路径计数已接受的外存请求字节，包括 128bit 尾字填充。每组还记录总拍数、外存请求等待、
S 请求等待；检查有限外存队列／DMA 预留占用，记录 T 实际字数峰值。总拍数包含软件逐命令
控制和响应背压，不能当作优化后的独立 DMA 吞吐或七宏硬件调度器性能。

### 仍由软件／测试台承担的工作

| 内容 | 当前承担者；不能计为现有硬件能力 |
| --- | --- |
| 权重／激活分块、M 的列优先 B 打包、基址和 stride 选择 | C++ 驱动；片外输入格式已打包 |
| 发描述符、等待完成、S 区间与 T 租约安排 | C++ 驱动，尚无片上全局 sequencer |

## 5. 当前边界决策

保留七宏现有 pin／端口；S 标准单元与 SRAM 版本的选择不改变 DMA 合同。
本轮证据不足以要求增加 M/R 外存直达端口、扩容 S/T，或改动已完成的宏布局布线。
其中 R 参数和命令桥仍由软件承担，因此也不能据当前状态流量推断直接供数永远无必要。

新增 DMA 是真实有状态计算电路，综合映射结果单列。它尚未被纳入七宏的物理验收。
系统装配时必须明确放在平台侧、固定控制区，或作为受控 S/T 接口升级；需要真实面积、
pin 和时序验证。**M11/M12 只改变连线，不能凭连线生成 DMA、仲裁器或调度器。**
自动生成的联合夹具只证明这些既有接口可以按合同协作，不构成一块新物理宏。

## 6. 复现入口

在 Linux／WSL、具备 Verilator 5.042 和 C++ 编译器的环境中：

```bash
python3 project/experiments/external_memory/run.py \
  --verilator /path/to/verilator --out /new/empty/results --jobs 4
```

输出含完整命令、生成夹具、逐初态 JSON、源码 SHA、严格 DMA lint 和联合 lint／编译日志。
遇非 ASCII 工程路径，会复制所需源码原字节到私有 ASCII 临时目录编译，然后保存证据；
不会为适配旧工具修改 N/R 等依赖源码。联合 lint 保留冻结 R/T 的既有警告，新 DMA 单独严格 lint。

综合使用 `map_dma.py --rtl-receipt ... --out ...`，远程入口 `remote_map.sh`：只申请 4 CPU、
在 Slurm 内运行固定 ORFS 镜像，核对上传文件／RTL 通过回执／Liberty，真实映射并 `check -assert`。
综合不等于布局布线、STA、门级仿真或形式等价通过。
