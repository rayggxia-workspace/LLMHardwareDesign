# H1：金属控制存储的逻辑预算与后端输入合同

2026-11-03（Asia/Shanghai），Issue151 / PR152，Melodydt。输入提交 `08451c3a563cdb331a3516d83cbf9647cd0554b1`，承接[混合总方案v0.6](HYBRID_METAL_CONTROL_PLAN.md)和[决策0009](decisions/0009-hybrid-metal-control-product-graphs.md)。本文件是H1候选规格及后端输入清单，不是ROM RTL、可制造位单元、布线或PPA验收。本轮不新增叶宏资格，不运行RTL/服务器/物理流程。

## 1. 共用底座与三产品的核算口径

H1使用同一个候选实例图：一个A、一个F和一个独立edge S16KiB。原生叶合计为 **M2/N2/E2/G1/R0/S3/T2，共12叶**；母顺序器、局控、TX/RX、S仲裁/helper、元数据/事件存储、参数提供者、测试、时钟复位和驱动另计。这里新增的edge S是候选资源，不能把既有AF1024的11叶验证冒充12叶通用底座已经实现。具体候选见[target.json](../project/experiments/hybrid_control/h1/v0_1/target.json)。

独立edge S划为4个4096B槽，共16384B；逻辑对象的分配、有效版本和生存期由机器调度表证明。对象描述符不等于数据槽：一个槽可以在旧对象真实释放后承载另一对象，但不能因描述符不同让两个同时存活的4KiB张量重叠。四槽已使用全部edge S容量，不能再免费存控制表、描述符、事件邮箱或gamma。

| 产品图 | 共同资源下的含义 | 必须独立证明的控制/存储事实 |
|---|---|---|
| G1 AF | A后接F | 输入/参数齐备、源保活、目的真实写ACK、释放与终态 |
| G2 AFAF | 同一个A和F各复用两次 | 不复制宏；重入前旧上下文/输出完成保存与关闭，参数身份不串代 |
| G3 A fork至两个F调用，再选择输出 | 一个A结果供同一物理F以两个不同参数调用，运行时p选择一个结果 | 两分支的真实供数、完成和回收都存在；不是ADD，不默认跳过未选分支，也不新增第二个F |

G3中A的edge对象至少保留到两个实际消费者均确认所需数据已存储。F只能按其真实输入槽和任务生命周期串行复用；p只选择发布对象，不能自动释放尚有义务的源或未选分支。参数p须在声明的任务边界捕获且在该任务内稳定。是否允许特定提前发布、以及发布后其它分支如何排空，必须由完整程序另证，不能由本文件推定。

三图是H1的有界样例域，不是八模型已经准入，也不是任意新图都能装入该底座。L4-QUALITY-AF、新代表性数据/产品阈值、R/NUM、MoE、MEM和系统物理门保持独立。

## 2. 128bit控制记录候选

记录宽度的算术为 `8+8+16+16+16+32+16+16=128bit=16B`。以下固定LSB方向，便于机器文件、hex和后端位映射一致；字段语义仍须以同版本机器ISA表逐opcode定义，不能单靠字段名推断。

| 字段 | 位域 | 候选职责与约束 |
|---|---:|---|
| opcode | 7:0 | 已预制粗动作的枚举；未知/保留值拒绝，不自动拥有256种操作能力 |
| flags | 15:8 | 仅允许该opcode显式声明的位；未定义位必须为0，不能隐藏新入口/新执行语义 |
| a | 31:16 | opcode规定的对象、任务、入口或其它**单一命名空间**索引 |
| b | 47:32 | 同上，具体角色由该opcode的编译期schema确定 |
| c | 63:48 | 同上；不能因字段都是16bit就混用对象/参数/路线编号 |
| imm | 95:64 | opcode规定的有界常量、计数或表引用；有符号性、单位及范围必须明确 |
| next | 111:96 | 声明的后继PC/目标；必须在当前产品有效程序域内 |
| aux | 127:112 | opcode规定的另一目标/引用/补充字段；不能同时隐含多个未定义角色 |

编码后必须做逐条解码读回，验证与机器语义记录相等。字节序、hex显示顺序、物理行/列映射分别声明，不能把软件128bit hex的高低位方向当作金属阵列的物理坐标。

粗动作候选为RESERVE/ARM、TRANSFER、RUN、WAIT事实、CLOSE/RELEASE、CALL/RETURN、有界LOOP、条件BRANCH、JOIN及终态/受控错误。不是逐MAC/逐S字指令，native操作仍由固定岛内程序展开。动作名称不会增加T/R/MEM联合原子性或未实现的数据转换。

每个opcode的机器schema至少必须给出：a/b/c/aux所引用的表及角色、imm的单位和合法域、flags掩码、读写副作用、发出/接受/存储/完成事实、后继和错误分支、可取消阶段及资源释放条件。未使用字段采用明确的规范值；是否有NONE、TRAP或隐式fall-through及其编码必须显式冻结，禁止一处把65535当有效PC、另一处当空值。

## 3. 程序深度和永久元数据预算

对每个产品G分别输出完整程序和表，包含正常路径、分支、循环、调用、故障/取消路径及必要入口。定义：

```text
D_G       = 该产品分配的128bit控制记录数，包含声明的保留/陷阱/入口空间
Nobj_G    = 分配的64B对象描述符数（不是四个数据槽的数量）
Nparam_G  = 分配的32B参数引用数（不含权重/gamma本体）
Nroute_G  = 分配的16B路线描述符数（不等于物理wire数）

Bimage_G(bytes) = 16*D_G + 64*Nobj_G + 32*Nparam_G + 16*Nroute_G + Bextra_G
```

`Bextra_G`必须展开入口/局控绑定、额外常量/地址/尺度/维度表、分支选择表、消费者列表、有效性/校验/对齐填充等实际存在的内容。若它们已经完整包含在上述记录中，给出逐字段覆盖依据，不能再次计数；若超出记录容器，就增加真实表项，不能写“由软件知道”而免掉硬件需要读取的位。

| 候选容器 | 必须由机器schema明确覆盖的内容 | 不含的成本 |
|---|---|---|
| 对象64B / 512bit | shape/有效长度与tail、静态数值/layout引用、区域/槽及版本、消费者/释放引用、角色与访问约束 | 4096B数据、TX/RX holding、运行时有效位/ACK状态 |
| 参数引用32B / 256bit | 参数身份/版本、提供者/区域/范围及尺度/layout引用；访问边界和关联方式 | 权重、gamma、RoPE系数、cache、完整参数提供者与MEM控制器 |
| 路线16B / 128bit | 源/目的端点和选择、返回/ACK路径、搬运及格式profile引用、方向/约束 | MUX、布线、驱动、仲裁、FIFO、CDC及中继 |

32B参数引用不能在没有额外空间的同时装下完整256bit SHA和地址/长度/身份等字段。完整SHA可保留在离线manifest，由紧凑、受控的表引用关联；硬件是否校验数据摘要属于另一个真实实现门，不能凭manifest宣称运行时已经校验权重。

### 共用容量按最大需求，不默认把三个产品相加

每个产品分别制造自己的金属内容时，共同硬件的容量必须容纳每一产品：`Dcap >= max_G D_G`，各元数据表同理，并记录保留项、对齐和明确余量。不能把G1/G2/G3简单相加当成必须的存储；也不能用平均深度掩盖最长产品。若选择在同一产品中同时保留多入口/多图，才按实际共存图、共享子程序及重定位后的完整镜像重新计算。

128bit记录每增加1行，纯记录逻辑量增加16B；256/1024行分别为4096/16384B。这仅是乘法示例，不表示相应深度已经成为可布线ROM容量。实际`D_G/Nobj_G/Nparam_G/Nroute_G/Bextra_G`引用[逐图机器预算报告](../work/Melodydt/151/h1/evidence/report.json)及同目录的`*.tables.json`、`*.program.json`、`*.image.hex`。本文件不沿用旧2MiB/32KiB估计。

| 图 | 128bit记录 | 程序B | 对象数×64B | 参数引用数×32B | 路线B | 头部B | 逻辑镜像总B | 静态峰值edge槽 |

共同逻辑容量候选为256条记录、17对象、16参数引用、6路线及64B头：

```text
Bcandidate = 256*16 + 17*64 + 16*32 + 6*16 + 64
           = 4096 + 1088 + 512 + 96 + 64 = 5856B = 46848bit
```

这是共同上限内的一种**逻辑分配候选**，尚未冻结为物理ROM。它不是三产品镜像相加，也不意味着5856B必须以同一个阵列实现。具体表布局、空项填充及镜像读回以机器成果为准。

5856B不含权重/gamma/系数本体、参数服务缓冲、运行时元数据/事件/栈、native和岛内本地程序、通用故障处理程序、ROM译码/读出/保持/测试及物理面积。当前样本程序的错误拒绝/抽象异常检查也不等于已在镜像中编码通用fault handler；若以后加入对应记录或表，必须重新计数。

当前参数`reference_digest192`只是对符号引用名字等内容形成的身份摘要，不是实际训练权重SHA；真实参数manifest及供给仍为GAP。路线记录中的ACK宽度为`H2_TBD`，镜像暂占位编码0不表示已经决定零宽ACK或可以删除回程。控制表字节数不能证明这些缺口已经解决。

### PC和命名空间边界

- 16bit PC最多表达65536个位置；实际Dcap、入口、保留值和陷阱位置须更小或相等，并与所有后继引用一致。当前镜像头的记录**计数**本身是16bit无符号字段，另受65535上限，不能把可表达的PC位置数当成该计数字段也能装65536；本轮Dcap=256在两者范围内。索引足够宽不代表已经预制65536行存储。
- 顺序PC加一及地址/长度加法必须先扩位检查再缩窄；末行fall-through、越界跳转、未初始化/非法记录均拒绝，不能回绕到第0行继续执行。
- a/b/c/aux的16bit表引用分别检查实际表深度、有效项和类型。NONE若占用一个编码，必须扣除该命名空间可用范围。物理地址译码可按实际表深度实现，但高位非法值必须仍被发现。
- 不同产品永久装入不同内容时，产品图ID/角色/Fin一般可由编译与永久绑定确定；不因此强制每个payload携带通用类型/大handle。运行时任务、片段、版本和已存储关联事实能否省位，需要等价与晚返回排空证明。

当前机器记录的flags均为0，未使用的a/b/c/imm/aux按opcode掩码为0；指令映射和分支字段由[检查器](../scripts/check_h1_graphs.py)定义，不能把本文件的概括性a/b/c用途当成新的ISA。镜像采用little-endian字段打包，当前`*.hex`逐行展示原始字节；后端必须显式处理这种字节展示与整数高低位显示的差别。

## 4. 循环、调用与动态状态必须另计

H1首先限制为有界、可静态检查的控制语法。当前三产品样本按调用展开为线性记录和明确select路径，机器目标`max_calls=16`不是16层硬件调用栈；不据此声称CALL/RETURN、运行时LOOP或有初值反馈已经lower/实现。调用递归不默认支持；增加真实调用/循环后，其最大深度和迭代范围必须由完整程序重新求得并接受。imm32不表示允许无界循环或保证可运行任意32bit次数。动态p、token长度等只在已声明范围内选择既有动作，不修改opcode或控制程序。

后端预算报告至少拆出下列**运行时有源存储**，不能混入永久ROM位数：

| 状态 | 预算表达式 / 核查内容 |
|---|---|
| 取指 | PC位数、指令128bit保持、请求/响应有效位、读取未完成标记、必要地址保持；读周期未定 |
| 调用栈 | `Ccap * Wcall + ceil(log2(Ccap+1))`；frame明确返回PC、参数/上下文绑定、错误返回以及必要循环深度恢复信息 |
| 循环栈 | `Lcap * Wloop + ceil(log2(Lcap+1))`；frame明确剩余次数/边界、body/exit PC及必要归属 |
| 任务上下文 | 当前静态候选限制1个active kernel job，先把输出真实存至edge槽再关闭kernel；对象的有效/消费者/回收状态仍需独立保存。若未来保留未关闭producer同时启动consumer，须另计这些同时存活上下文 |
| G3选择与消费者 | p的捕获/有效状态；源对象两个消费者各自的存储确认、关闭及重复抑制；未选结果的回收状态 |
| 事件/错误 | 事件payload和valid/保持、FIFO指针/计数、关联/去重、first-error、partial及终态保持 |

`Wcall/Wloop/Ccap/Lcap`的具体值由共同实现选择和完整程序确定。若用编译证明省掉frame某字段，应声明禁止何种跨调用循环/动态参数绑定/恢复路径；不能既声称通用CALL/RETURN又不存其返回和恢复事实。栈溢出/下溢、递归、非法循环/跳出和超过上限均有确定拒绝或受控错误行为。

共同顺序器至少必须保持其当前未退休记录及元数据到请求接受/返回匹配完成；不能在WAIT时覆盖同一个holding。若将表项分多拍读取，还须计算多拍暂存与一致性，不能把128bit记录按32bit端口读四拍却计成单拍指令。

## 5. 事件、返回与共享S的进展预算

H1机器模型必须分别记录TASK_ACCEPTED、INPUT_STORED、RESULT_SEALED、REMOTE_STORED、SOURCE_RELEASED及任务终态；其中不存在于当前profile的state发布不得仅靠预留opcode变为已支持。

以每条可发出请求建立其返回义务，统计同时在途任务/片段/消费者和每类返回峰值。事件方案可以是带信用的邮箱、FIFO或不丢失的按身份sticky事实；选择哪一种就计哪一种的真实状态、仲裁与端口。若采用记录式缓冲，其基本量为 `Nevent_slots * Wevent + valid/pointer/count/identity成本`。旧64bit CMD/EVT/ACK和单fragment只是接口候选，不在这里自动冻结。

当前[target](../project/experiments/hybrid_control/h1/v0_1/target.json)采用1个ACK槽、1个事件槽、1个全局在途数据字及1个edge S普通owner的抽象串行资源约束。它只约束本轮静态服务模型；事件位宽、来自不同端点的同拍返回保持、错误优先及实际RTL信用仍待H2证明。`ABSTRACT_FAIR_PROVIDER_NO_CAPACITY_CLAIM`的参数提供者不证明真实MEM容量/带宽、权重/gamma暂存或故障恢复。

- 母控WAIT期间RX、helper、真实S写ACK、事件捕获/返回和必要排空仍须推进。不能要求先退休WAIT才能腾出其所等的ACK空间。
- 正常完成、目的存储确认和错误终态不能因共享一个已满队列而形成环；提前预约返回空间，或给出独立保留信用/保持能力及调度证明。
- 四槽edge S只有真实既有端口能力。普通req从接受到ACK退休的owner不可提前切换；路由、RX/TX或母控不能并发抢用同一事务。helper/仲裁与数据/返回holding另计。
- G3的两个consumer可以串行，但源ACK义务仍有两个；JOIN/选择只等待语法声明的分支，不能把未选数据发布与未完成分支清理混为一件事。成功终态前关闭全部已接受义务。
- 返回重复、错任务/片段/版本、错误先到、输出已消费前缀以及取消必须都有定义；不能只用任务计数总和代替逐关联事件检查。

运行时事件格式不应包含软件已经证明可常量化的每包role字段，但其身份/关联不能在没有证明时一并消失。对“单在途”优化，必须检查等待中的producer、非当前RUN任务的返回及复位迟到消息是否仍然存在。

## 6. reset、晚返回与永久内容的界限

产品控制表是永久内容，reset不改其位值；reset清运行时valid/PC/栈/owner/事件及任务状态，如何恢复到入口由固定共同硬件定义。S RAM旧内容或gamma数据不因reset而自动归零或有效。

初始H1可以采用受限的全参与者协调reset域，但须明示端点、local CTRL、native/helper和参数提供者的停止/排空范围。若reset后立即重用任务编号，必须实际保证旧返回不能重新出现；仅增加软件generation标签或把PC归零不构成隔离证明。

跨独立warm reset、外部MEM晚返回、有限编号回绕和跨时钟域不默认为已经支持。若共同底座需要这些能力，必须在冻结前加入真实epoch/保留表、drain、信用和CDC实现并重新计价；否则对相应运行情景保持GAP并拒绝发布。不支持无依据的任意晚返回容忍或透明恢复。
