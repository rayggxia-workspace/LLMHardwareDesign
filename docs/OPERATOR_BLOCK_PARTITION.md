预连线及同资源替代；[最小决策实验](BLOCK_MINIMAL_EXPERIMENTS_V1.md)对应D1–D6。

## 1. 把五种决策分开，再联合比较

- **语义算子图G**：张量形状、数据类型、归约维、依赖、持久状态、动态专家/缓存访问。一个模型家族名不等于一个图。
- **执行策略S**：tile、循环顺序、在线归约、重算、驻留、双缓冲和精度。software fusion属于这里，不能直接证明物理Block应合并。
- **制造前模板B**：矩阵/向量/归约/路由能力、bank与端口、状态容量、内部网络、端点和时钟供电。固定模板可以被多个语义算子分时使用，不要求一算子一硬宏。
- **产品映射与定制C**：固定模板的实例映射、允许修改的连接和预算。区分运行时专家dispatch与产品确定后的静态连线。
- **真实实现P**：位置/朝向、合法接入、线RC、驱动负载、时序、供电和拥塞。P可否定G/S/B/C中的候选，而不是最后仅用于展示。

候选为(G,S,B,C,P)，比较时说明究竟改变哪个变量、冻结哪些资产。先用语义/资源必要条件淘汰，再用调度模型、RTL和物理实现逐级验证；启发式未找到解不等于不存在解。

## 2. Benchmark的选择依据

用户允许少量代表，不要求兼容全部开源模型。选择轴是结构差异、公开可复查程度、实际可执行性、目标产品相关性及与现有研究主张的关系；“当前常用”需要另有使用证据，不能凭版本新旧断言。

| 结构轴 | 首轮候选/用途 | 不能混淆的边界 |
|---|---|---|
| Dense GQA + SwiGLU | Qwen3小模型为后续权重运行候选；Llama3.2作为跨实现验证候选 | Q宽未必等于hidden；Meta权重/config受限需实际权限，当前只用官方公开SKU |
| MLA + routed/shared MoE | DeepSeek-V3/R1原版结构；缩小数学子图和配置分析先行 | R1-Distill-Qwen采用学生GQA，不代表教师MLA/MoE；本轮不下载671B权重 |
| 混合递归/全注意力 | Qwen3.5作为扩展或适用边界压力案例 | Gated DeltaNet是持久矩阵状态，不等同KV序列；仅验证full-attention核不能称覆盖整模型 |
| 历史/尺寸敏感性 | Qwen2.5等仅作结构对照或尺寸扫描 | 不自动纳入正式论文benchmark，不把大量相近shape当独立模型证据 |

实际已观察的模型/config和四图旧实验均为探索数据，不能事后称盲测。正式比较前固定主集合、参数选择集和另选未参与调参的工作负载；记录纳入/排除理由。若事后排除，保留失败，修订适用范围并另做验证。创新性还需要相关工作和受控基线，不能只以“跑通几个模型”证明。

## 3. 首批候选：先验证契约，不冻结最终划分

| 候选固定内容 | 值得保留的边界/变化能力 | 选择理由及反证条件 |
|---|---|---|
| 参数化矩阵引擎、局部bank、向量/归约单元；短程配对链路 | 宽度/transpose/tile描述、外部权重与状态搬运 | 高频局部通信可被固定；若内部布线、低利用或面积代价抵消收益则拆分 |
| SwiGLU局部流水与部分输出累加 | FFN/expert宽度、token分组、权重加载；专家dispatch独立评估 | 避免全部中间激活常驻，但token分块会增加权重重读；不能只看激活存储 |
| 在线attention的max/sum/output更新能力 | GQA分组、MLA latent/expanded两种路径、KV descriptor | 状态复用与数值稳定性重要；矩阵/向量拆分可能增加tile输出传输 |
| 可描述的KV/latent/递归状态接口 | layout、共享范围、精度、分页/分片与更新语义 | 避免固化每层独占KV；若接口过于通用导致端口/控制开销过高须收窄 |
| 专家局部算术与缓存 | token→expert动态分发、加权聚合、热点与背压 | top-k/共享专家和偏置语义不能丢；只用平均负载不能确定FIFO/带宽裕量 |

目前只提出候选，不把GQA、MLA和递归状态强塞进完全相同的硬件。可通过多个模板/产品特化覆盖代表集合，代价应包括模板数量、面积闲置和验证复杂度。

## 4. 资源、裕量及Pareto筛选

每次比较冻结计算单元及能力、SRAM总量和bank划分、端口与仲裁、外部带宽、预制有源单元/位置/内部连线、连接预算。必须显式记输入、权重、KV/latent/递归状态、中间值、累加器、FIFO和双缓冲的生命周期。多副本、跨域同步、ECC/DFT/备用资源若尚未建模就标未知，不能隐含免费提供。

使用向量指标：外部传输、片内逻辑读写、跨Block传输、各bank同时活跃峰值、接口突发/服务需求、利用率、合法连通、时序和真实面积能量。优先保留Pareto候选，并对工作负载变化做稳健性分析；没有依据的加权和不能包装成唯一最优。

存储余量可记为1−peak_live/capacity。带宽余量必须有已声明的到达曲线/服务窗口及可达到的服务率，不能把总字节除MAC数称真实峰值带宽。copy调用粒度可重新分包，不能直接等同不可避免的突发、物理pin数或引脚裕量。时序/负载裕量需要真实工艺与提取，0/10/20%预留扫描只是敏感性假设。

所有跨Block数据必须有协议、位宽、时钟、时序预算和可连接端点；必要时用FIFO/背压，但有源资源必须在制造前资产清单中。H1可以研究额外buffer的工程代价；H2不能针对每个产品临时新增buffer而仍声称底座未变。

## 5. 本轮微实验回答什么

两固定存储bank、一矩阵引擎和一向量引擎，物化/流式调度分别比较split/joined归属。joined仅将同一传输从跨Block记为块内，不增加bank容量、计算能力或免费搬运。因此跨界归零是定义，不是已经测出融合收益。

- FFN在token/intermediate两维分块；每token tile重读权重，完整记录。取整个intermediate为tile时，流式保留输出累加器可能反而增大峰值。
- Attention同时覆盖prefill和decode；相同GQA分组与Q/K/V读取口径，在线O由向量单元更新，额外tile O跨bank不可省略。
- 全部按FP32逻辑字节计；缩小数值核同时查FP64/FP32，不宣称BF16/FP8实现。未展开PE寄存器/广播/端口冲突；SRAM逻辑读写不能直接换算能量或周期。
- 每个候选输出事件账本、闭式公式交叉核对、容量通过/失败、Pareto候选与来源SHA；失败只否定所选调度/容量点。没有为溢出候选偷偷添加DRAM spill使其变可行。

Issue21当时仅提供输入、反例和候选筛选基础，**不回答完整端到端收益数值**。后续Issue23已执行真实Qwen3权重FP32推理，Issue27已建立未物理校准的端口服务模型；量化质量、该新候选RTL/布局布线及功耗校准仍未完成。

## 6. 接下来按证据门槛推进

1. 模型子图：官方实现/配置固定，缩小正确性、真实shape、精度/状态/路由语义核验。当前正在交付。
2. 代表权重：先执行可获得的小模型，捕获prefill/decode真实算子、KV/专家热点与输出质量，固定产品场景；权限或资源不足明确记录，不能由缩小模型宣称完整验证。
3. 硬件候选：把模板能力、bank/端口和FIFO具体化，建立相同总资源的拆分/融合/混合候选，校准周期与通信；解析上界只是筛选。
4. 物理回馈：复用Issue15有效证据，补充新候选真实尺寸、接口、内部时序/端口和跨界负载，验证冻结资产及允许连接；不能从旧ACT/MXU结果外推新模板。
5. 端到端比较：同工作负载/精度/总资源/带宽下比较固定单任务网络、常规可编程互联与受限定制候选；同时报告无法覆盖的图、闲置/定制代价和不利结果。工作负载集合及基线自由度预先固定。

## 一手方法依据

[FlashAttention](https://arxiv.org/abs/2205.14135)提供精确attention的IO感知tile与在线softmax依据；[DeFiNES](https://arxiv.org/abs/2212.05344)强调同时计权重、激活及片内搬运；[LoopTree](https://arxiv.org/abs/2409.13625)联合探索tile、驻留与重算。本项目没有复现这些完整工具或获得它们的硬件校准精度，也不把已知fusion/online算法作为自身新算法。详细模型来源与独立小实验见work/Liangruizhi/21/research/。

## 后续证据更新：以状态/端口服务约束筛选边界

[Issue23](experiments/issue-23-qwen3-real-trace.md)已用固定真实权重验证prefill/decode和KV增长；[Issue27](experiments/issue-27-state-port-model.md)进一步把算子展开为读/算/写事务，固定逐bank地址/容量、端口、scratch和静态link。相同流量的状态放置，在不同端口合同下可能有模型周期差异，也可能完全无差异；仅改变Block标签始终零效应。调度基线优化可显著缩小表观差距。

因此候选划分的判据是：局部状态归属能否消除公平调度仍无法隐藏的关键路径服务冲突，同时满足容量、输出驱动/外部负载、连接与时序余量；不能只以跨界字节少来划分。当前仅单头attention子图、假设服务参数，尚未确定最终Block，也未证明端到端收益。INT8矩阵与KV/非线性格式需分别冻结，下一阶段进入可执行微架构端口验证与差异架构/全模型耦合。
