# 项目简介

- 项目 ID：`llm-hardware-design`
- 名称：LLMHardwareDesign：预制计算底座研究
- 主要负责人：[@YUZE-LU](https://github.com/YUZE-LU)
- 阶段：首轮 Block 实现与表征；共同底座和任务定制分阶段验证

## 目标与问题

研究一种面向多个计算图的预制计算底座：预制计算 Block、物理排布和部分互联资源，在确定目标任务后，通过有限的金属／通孔层定制跨 Block 连接。希望在同一底座支持多个任务的前提下，评估版本定制成本，以及避免 FPGA 式运行时可编程路由开关可能带来的性能和能耗收益。两类收益均需实验验证。

当前要解决的核心问题是 Block 粒度与接口、底座排布、预埋轨道与受限布线、模型映射与调度，以及存储供给、时钟和按需启用的实际开销。完整定义和证据状态见[项目说明 v1.0](../预制计算底座项目说明_v1.0.md)。

## 范围与边界

- 目标使用场景：以 LLM 及相关计算图为主要研究对象；已有 Qwen2.5、Qwen3、Qwen3.5、Llama3.2、Gemma3、Phi4、Granite MoE、Falcon-H1 的八模型分析，见[模型资料](model-analysis/README.md)。算子/数值分析不等于整模型硬件验证；独立测试集合仍须制定。
- 当前范围：研究定义、参考设计分析、代表性 Block 与小规模物理实例、可校准的映射／布线及性能能耗评估方案。
- 当前不以完整大模型芯片、量产级签核或流片为第一阶段前置条件。
- 第一版工艺方案已选 Nangate45：原生 M1–M10、via1–via9 预制；新增研究层 M11/M12、via10（M10↔M11）、via11（M11↔M12）后定制。新增层的几何、电气和工具资格仍需验证，不代表原生 PDK 或真实制造资格。
- 首轮叶块交付关注功能、真实资源成本、物理实现、同源宏视图及接入/驱动负载边界；同类 Block 可重复，也可形成分别表征的物理版本。实例数量、版本组合、排布、固定预连线和轨道组织在共同底座阶段决定并统一冻结。
- 固定预连线是已经连通的固定资源；预埋轨道是预留供后续接入的资源，两者均须声明层、接点、容量和成本。具体拓扑尚未确定。详见[当前实施边界与分阶段冻结](decisions/0004-block-library-base-freeze.md)。
- “无开关互联”仅针对跨 Block 的 FPGA 式运行时可编程路由；不排除 Block 内控制、存储寻址、门控或必要的缓冲。

## 当前基础宏规划

| 宏方向 | 主要职责 |
| --- | --- |
| M | 分块矩阵乘、归约/累加、局部缓冲与完整数值处理 |
| 归约与归一化（由 V 拆出） | 完整 Softmax、RMSNorm、L2Norm；统计、函数和回放缩放留在块内 |
| 基础向量算术（由 V 拆出） | 加减乘、残差、广播、比较、量化/格式转换与 RoPE |
| 激活与门控（由 V 拆出） | SiLU/GELU/Sigmoid/Softplus 等近似与紧邻门乘 |
| R | GDN/SSM 宽状态递推、读出与提交；现有短卷积模式先保留 |
| S | 有限工作存储及访问控制；既有 16 KiB 为起点 |
| T | 结果保持、背压和完整消费；既有约 6 KiB 为起点 |

当前选择是 **V 三宏方向、首版保留独立 R、每种先一个实现并逐宏完成最终布局布线**。新三宏尚待实现，M/V 收窄和 M 部分和减少仍为候选；具体位宽/通道/缓冲/端口/延迟不得由功能表推断。S/R 当前标准单元存储不能写成已接入 SRAM；R 的大容量存储和四抽头卷积均不是其独立存在的充分理由。

完整依据及既有实现来源见[边界与位宽讨论](COMPUTE_BLOCK_BOUNDARIES_2026-10-30.md)、[决策 0005](decisions/0005-compute-block-v-split-r.md)。原 M/V/A/R/S/D 是逻辑职责；本表是物理功能规划，不能机械一一对应。

## 当前成功标准

首轮成功标准：每个最终选定宏有明确数值/端口合同、实际资源、最终布线/网表/寄生及同源视图，功能、几何、提取后时序/电气和接入负载有检查证据；失败保留且不能称合格。不能仅交规格或 RTL。阵列、多实例、裕量版本和跨块预连不作为本轮新增前置条件。

以下是底座/项目阶段的成功标准。同底座多计算图与系统级对比保留为后续验收，不自动成为首轮叶块交付的前置条件；已单独约定更大范围的实施 Issue 仍按其范围跟踪。

1. 明确一套预制底座和至少一个合法的任务定制实例，写出固定资源、可定制资源与接口边界。
2. 给出可检查的映射、互联、端点、存储及时钟成本口径，保留失败与不适用情况。
3. 用同一底座的多个计算图和受控基线评估性能、能耗与定制成本；具体案例、阈值和验收数值须通过后续 Issue 确定，不能先写成已实现结果。
