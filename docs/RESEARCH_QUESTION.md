# 共同研究问题与验收目标

更新：2026-10-22，UTC+08:00。依据本用户本轮明确指令，任务 [Issue21](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/21)，主要负责人 Liangruizhi。

> 给定几类有差异的 LLM 工作负载，哪些计算、状态和通信应当在制造前固定在一个 Block 内，哪些连接值得留到产品确定后再定制？在真实存储、端口、布线和时序约束下，这种划分能带来多少端到端收益？

这是后续调研、实验和论文主张的共同问题。算子/Block划分是当前首要研究问题；Liangruizhi主要推进划分与块内预连线/接口裕量，利用而不接管其他成员的块间布局布线、物理对照。已有ACT/MXU划分是候选与校准来源，不能预先当成答案。

首轮以**推理prefill/decode**为执行范围；训练方法用于解释架构、权重/状态、路由和精度约束，不宣称支持训练执行。允许选择少量有差异的代表模型，不以全系列兼容为目标。不因一个少见或历史模型强迫所有Block变成最一般的结构；也不把实验后失败静默从统计中删掉。

常规模型版本、规模、候选、实验与验证顺序由Agent自主决定，记录理由、替代方案、来源与失败；重要结果及时汇报。只有研究目标/权限边界等原则性问题或无法独立解除的关键阻塞需要用户决定。遵守AGENTS/协作Skill，完成阶段后重新核对Issue/PR/交接再推进，不覆盖多人工作。

## 需要交付的答案

1. **算子层**：有语义和数值依据的分解、合法重排、融合、tile、驻留/重算选择；不能跨非线性随意交换矩阵乘法。
2. **Block层**：计算能力、存储/持久状态、局部固定网络、端口/协议和允许的参数范围；每种候选有合并/拆分理由和淘汰条件。
3. **定制边界**：制造前不可变资产清单，以及产品确定后可改变的金属/通孔/连接集合；权重加载、运行时路由和制造后定制三者分开。
4. **耦合约束**：真实可用SRAM、bank端口、队列/背压、布线可达性、时序/负载、时钟/供电及裕量；不能靠添加未计价的buffer/SRAM修好后仍称同底座。
5. **端到端收益**：正确性、质量、prefill延迟/吞吐、decode逐token延迟/吞吐、实际资源/功耗或能量；统一模型、上下文、batch、精度和基线自由度，保留失败和不确定性。
