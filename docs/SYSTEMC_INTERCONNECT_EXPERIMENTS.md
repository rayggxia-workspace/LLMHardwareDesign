## 预先约定的验收和证据边界

## 步骤33：软件职责清单（第二项）

| 当前职责 | 实际归属/入口 | 底座必须落实的能力或边界 |
|---|---|---|
| 模型层序、分支、块复用与循环 | Driver::infer，按metadata和family分派 | 可配置执行序列/控制器；连接本身不能替代循环 |
| 大矩阵沿K/N分块、参数寻址 | Runtime::linear、Checkpoint | 地址生成、加载与累加上下文、尾块有效数；全部权重不在S |
| 静态参数变换/位置RoPE表 | 导出器、rope_table；普通RoPE也有host系数准备 | 明确预存参数或系数生成服务，当前非硬件实现 |
| 动态指数/范围/舍入位置选择 | peak/output_shift/compact/Scale调度 | 尺度元数据和数值控制；不能只有S16数据线 |
| KV保存、切头、拼接与转置 | LayerCache与attention | 外存/工作区、动态地址、序列长度、重排及复用 |
| residual、向量复制、concat/repeat | Driver及host Tensor | 活性区间、分发和缓冲；逻辑活性不等同实际主机分配 |
| R完整状态/卷积历史 | RecurrentCache，update/convolution | 外部S32状态存储及分块读改写；有限R容量不变 |
| R S32/S16转换与重缩放 | Recurrent::narrow/widen/prepare_state | 当前由host执行RNE/边界转换，属于明确硬件缺口 |
| MoE ID到专家权重、argmax大词表ID映射 | moe、topk/argmax外层循环 | 动态访问控制；N比较结果不自动完成数据搬运 |
| 精确SiLU/Softplus等复合算子 | Runtime，实际调用M/N/E/G | 指令调度和共享资源开销；不是一个新硬件函数块 |
| 有限S回放/T完整交接 | 原S/T命令，host分批组织 | 确实调用有限引擎，但不是全模型的统一存储/网络 |
| 文本编码/解码与独立FP32参考 | Python工具 | 系统边界外的输入准备/验证；不供给SystemC预测 |

数据流事件有明确host.external来源和控制决策未编码为Tensor的情况（例如alpha/beta、token/专家ID）；报告保留这些缺口，不用不存在的边填图。R状态I/O按真实分块容量显式统计，权重逻辑读取量不包含指令头、填充、缓存命中或假设总线重传，因此不是实际DRAM流量。

## 步骤34：有限桥实验的具体合同（运行前约定）

使用同一f2算术/观测二进制。桥在外层算子程序的Tensor输入/输出之间实际传输编码字节，并核对重构：输入传输恢复后逐字节相等才执行，输出使用重构后的Tensor继续计算；包ID、顺序、尺度和尾包均核查。复合算子内部仍调用原宏FIFO，其内部命令不是逐条经此桥。因此这是软件中转的算子边界桥，**不是已经选定的M11/M12宏级拓扑或完整DDR流量模型**。

预先采用三个对照：narrow=128bit/1包，wide1=512bit/1包，wide=512bit/4包；各方向FIFO分别限定，MTU256B，每包附加2ns、每拍1ns。参数均为实验假设。发送窗口为队列容量+1，接收按ID校验，未一次性把全张量放入有限FIFO；外部序列化副本仍占host内存。共享桥按完整张量加锁，真实模型当前串行调度，不能由此声称存在多块并行收益。独立三发送者测试负责实际争用/等待覆盖。
