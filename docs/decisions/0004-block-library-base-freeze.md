## 背景

共同入口仍将工艺和定制层笼统标为待定，容易混淆首轮叶块交付、共同底座设计和最终系统验证。用户已明确第一版采用 Nangate45 原生全部金属层预制，自建更高两层做定制互联；同类 Block 可能重复或形成不同裕量的物理版本，跨块也可能采用固定预连线，其数量和拓扑不宜在第一轮叶块阶段全部锁定。

## 决策与原因

### 第一版工艺与层集合

| 对象 | 当前方案 |
| --- | --- |
| 原生研究平台 | Nangate45，原生最高布线层 M10，通孔定义到 via9 |
| 预制资源 | 有源单元、M1–M10、via1–via9、固定 M10 landing；采用的固定 PG/CTS、预连线和有源中继均须登记 |
| 后定制图形 | 自建研究 M11/M12、via10（M10↔M11）、via11（M11↔M12） |
| 定制时限制 | 不修改固定 M10 landing，不移动/替换有源单元，不新增 buffer 或改变固定时钟/电源资源 |
| 证据边界 | 新增层的几何、RC、提取、检查和宏接入仍须验证；不是 Nangate45 原生十二层或真实制造资格承诺 |

原生层依据为实施计划核对的 [OpenROAD-flow-scripts 固定版本技术 LEF](https://github.com/The-OpenROAD-Project/OpenROAD-flow-scripts/blob/64939f3717ad7c694199ba04cb98924b98022868/flow/platforms/nangate45/lef/NangateOpenCellLibrary.tech.lef)。本记录沿用既有核对，不代表本次重跑技术验证；服务器实际输入由实施任务另行封存。

### 三个交付层次

| 层次 | 本阶段确定/交付 | 后续事项 |
| --- | --- | --- |
| 首轮叶块库 | 功能与数值/事务合同、真实计算/存储/控制成本、原生物理质量、同源宏视图、合法 pin 接入及驱动/负载适用边界；完成后可冻结该叶块版本 | 不必穷举裕量版本，也不要求确定最终实例数量、阵列排布或跨块预连拓扑 |
| 共同底座 | 选择实例及物理版本、数量、位置/朝向、固定跨块预连线、预埋轨道、公共 PG/CTS 和预制有源中继；形成统一冻结清单 | 冻结前允许在本阶段权衡；修改已冻结叶块须形成新版本并重新表征 |
| 任务定制与评估 | 在同一冻结底座上只改变允许的定制图形，完成多计算图连接/调度、合法性及性能/能耗/版本成本对照 | 不得因任务改变固定资源；未通过的实现与失败范围如实保留 |

**叶块冻结不等于共同底座冻结。** 单个宏合格，不能据此声称公共时钟/电源、父层固定导体、预制中继和多产品底座已经完成冻结。两套产品可以共用同类 Block 的多个实例，也可以共用包含多个物理版本的底座；比较时所选版本、数量和位置必须相同。

同功能的不同裕量版本可能具有不同单元、几何和时序，必须有独立标识、视图和表征，不能在产品定制时替换。首轮仍应参考少量代表性接入场景，防止遗漏端口或负载义务；完整阵列与两个完整产品不是叶块阶段的通用前置条件。

### 固定预连线与预埋轨道

- 固定预连线是已经连通的跨块连接；预埋轨道是供后续接入的预留导体资源。轨道本体及其预制有源部分固定，只有声明的定制接点/图形可以改变。
- 哪些实例相连、使用哪些层、线段/接点/中继数量和具体拓扑留在底座阶段确定，并受本方案预制/定制集合约束。可在该阶段完成合法的原生层父级固定接线，不要求首轮叶块交付时全部确定。
- 已采用的导体、通孔、端点、容量、缓冲/流水和时钟/电源开销须完整计价，并纳入共同底座冻结；不把预连线默认视为可按目标改线的资源。

## 考虑过的其他方案

同时确定所有实例、裕量版本和预连拓扑，会把后续底座问题提前展开，扩大首轮设计空间。完全不考虑接入场景，又会使叶块缺少可组合的驱动/负载边界。因此先交付有适用范围的叶块，再在底座阶段作组合选择；已有的小规模接入和接口检查仍保留。
