# 0005：按实际文件接收已完成的验证计算

- 日期：2026-10-30
- 状态：proposed（Issue130已试行，待PR审查）
- 决策负责人：YUZE-LU
- 关联 Issue / PR：[Issue130](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/130)／[PR132](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/132)
- 替代记录：无

## 背景

S 的一次完整物理网表编译、严格等价证明或完整 GDS DRC 需要较长时间。几何修复可能只改变布线路径，逻辑网表保持完全相同；完整证明计算也可能成功后因尚无功能回执而汇总失败。重复全部计算不能代替明确的输入与证据绑定，失败候选也不能沿用原来的资格。

## 决策与原因

保留原始失败及成功记录，分开记录计算与最终候选接收。所有最终门仍需绑定同一个封存源；只允许下列有明确检查的接收：

1. 功能编译复用要求原完整功能构建及测试实际成功、所有有序编译输入与二进制 SHA 一致；对新封存源重新运行三个初态。只复用编译产物，不复用新源的测试结论。
2. 严格等价接收要求原本实际运行的全部证明命令成功、严格全边界 UNSAT/IDENTICAL 且没有未匹配边界；重新核验原始全部输入、输出和代码，并重新运行实际正反例控制。新源 RTL、综合输入及成功功能测试的完整物理视图须与证明输入完全一致。原 producer 的总体 FAILED 保持原样，接收报告明确记录来源及失败发生在何处。
3. 完整 DRC 可以与原生 finish 并行计算，但只有最终 DEF 与受检几何逐字节相同、GDS 与未修改 deck 的 SHA 一致、所有原始输出复核通过，且对最终 ODB 再做独立全片检查为零，才接收该计算。计算完成本身不授予叶块资格。
4. 任一字节或条件不匹配即拒绝接收，按实际新输入重跑；不依赖“看起来相同”或参数名称相同。

最终交付复制真实六文件、四门回执、必要的原始 producer 记录与单网几何修复证明。下载后逐成员复核 SHA；仓库中的轻量证据检查再次验证源、功能、证明、DRC 与交付文件之间的对应关系。

## 考虑过的其他方案

- 仅按模块名或逻辑功能复用结论：无法证明实际文件相同，拒绝。
- 把已有 producer 的总体失败改为成功：会掩盖历史事实，拒绝。
- 每次无条件重新编译与证明：保留为不匹配时的路径；文件完全一致且具有上述证据时，不作为唯一选择。

## 影响与验证

增加来源检查、原始记录归档及接收步骤，换取可审查的计算复用与并行执行。原失败候选仍拒绝，修改后的几何需要新的物理与最终接收门。实际作业、结果路径和 SHA 以 Issue130 的验收档案为准；本决策文档本身不是候选合格证据。M11/M12 系统、层级 Liberty、abstract coverage 和制造签核仍须另行验收。
