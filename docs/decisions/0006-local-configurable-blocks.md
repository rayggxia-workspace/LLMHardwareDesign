## 背景与选择

仅把很长模型链包成一个六宏大岛，或只画三个组合区，会掩盖可定制互联的价值。另一方面，按每个细原语单独跨区也缺少局部性。采用 3～4 宏、允许重复类型的局部公约数，作为下一阶段的可审查候选。

1. 主要计算数据连接在 **Block 内及 Block 间**都允许由后制 M11/M12 确定；可保留声明并计价的有限预连。全部有源器件与局控/母控/适配端点在共同底座冻结前预制。
2. 后续 S 修改为服务所属局部 Block，由其局部控制器管理；跨块数据写入目的私有 S 并等实际存储确认，不借他块裸 S。F/J 也有明确工作存储。
3. 两级控制的固定硬件/ISA 不预存候选模型的完整程序目录；模型选定后编译母控/局部程序与参数。RAM 装载与真正金属编程存储是载体候选，不能把仿真 ROM 写成物理实现。
4. 候选为 P=M/G/S，U=N/E/S，C=R/G/E/S，F=G/E/S，J=E/S/T；3P/2U/1C/1F/2J、P.S32KiB/其余S16KiB 是三模型对照的示例池，**本决策不冻结这些实例数或容量**。
5. 保留 R，且承认其尚未合格；不通过改图绕过 R 数值/接口/状态和最终物理验收。
6. 互联意义由同资源固定共同网络对照检验；若收益不显著如实报告。局部程序调用顺序不同，不自动意味着物理连线必须不同或定制一定更优。

详图、控制/存储职责、数值差异与证据入口见[局部 Block 设计说明](../LOCAL_BLOCK_DESIGN.md)。本 PR 是文档提案，不替其他进行中 PR 修改架构或接管其实施；相关冲突/实现增量必须后续对照审查。
