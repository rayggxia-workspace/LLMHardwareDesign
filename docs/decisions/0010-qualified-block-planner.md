# 0010：以已登记服务、流式初解与联合约束搜索实现 Block 规划

- 状态：proposed；核心实现有局部验证，五类整网综合未完成。
- 日期：2026-11-07，Asia/Shanghai。
- 任务：[Issue #219](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/219)；[PR #220](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/220)。

旧前沿原型将完整激活对象放进 S，用假设 FP32 服务和未校准路径评估，不能用来判断真实 16 KiB 底座能否运行模型。该实验保留为历史，不作为正式模型或硬件结论，也不再用 0.6B 模型作正式 benchmark。

采用模型产物、合并硬件清单和调用参数作为作者输入。内部 IR 和证据记录由工具生成。真实服务必须明确格式/形状/属性、实际端点、资源、完成确认和测量时间。未登记的转换、分解、时序或协议不能自动补齐。硬件资源变化由清单驱动；相应新硬件的资格需要重新绑定。

局部覆盖 DP 只沿私有线性链提出少量服务覆盖；全局成本由实际资源/存储/传输联合规划决定。先用保守流式调度生成合法初解，再对静态网的全部跨层使用者、长寿命缓冲和资源竞争任务组做 CP-SAT 大邻域改进。S 同时安排时间和地址，外存有实际 STORE/LOAD、稳定区域和可选容量约束；源数据和 TX 保持槽持续到真实目的 ACK。跨层静态网按并集计算，物理驱动冲突不可用分时规避。目标采用完成时间和硬布线预算，而不是随意把周期、根数相加。

覆盖数量截断、串行初解、有限邻域和大任务组绑定耦合都是显式启发式。CP 证明仅针对当前已降低图及固定/耦合选择；UNKNOWN 不能写成硬件不可行。独立回放器从原始服务重建约束，不信任求解器资源汇总。

Block 仍是控制归属，算法不要求硬化为大矩形或经封装边界接线。实际固定本地路径和真实可后接端点分别登记。当前只把 #214 U 的一个真实服务接入本编译器；其他叶宏已经实现的资格不等于整个算子 lowering 已实现。#213/#214 的控制 profile 也不能只凭共同 v2 镜像格式合并。

结果和未完成项见 [实现说明](../../project/experiments/block_synthesis/README.md)及[本轮证据](../../work/YUZE-LU/219/JOINT_RESULTS.md)。事件程序 IR 和原生描述符不等于可部署 MC/LC 镜像；全模型数值 lowering、原生 DMA/局控闭环与物理反馈仍需完成，不作论文级性能或签核主张。
