# CPU迁移以FP32正确性优先，保留BF16线程敏感失败

Issue53，2026-10-23，依据[实际pilot](../experiments/issue-53-cpu-migration.md)。

服务器不是只有默认Python3.6；已找到3.12.7并建立本人独立环境，已有小模型FP32迁移通过。
可把非GPU专属性质的参考/采集/oracle移到CPU，但模型、长度、后端各自需要核验，不一次重跑师兄已有批次。
GPU显存/吞吐/实际GPU量化内核仍保留GPU。4bit后端改变不是无条件等价迁移。

BF168/16线程的cached/chunk部分指标超事前门；32线程暂通过也不允许事后只挑赢家或放宽预算。
失败配置不用于性能收益比较。先用FP32作后续参考；增加同源码独立重复，保留每个条件原结果和计时。
当前小模型CPU吞吐不按参数量/线程线性外推，也不代表W8A8或Block硬件实现。

模型试验和RTL作业在Slurm实际分配内并行；同一线程伸缩测量内各模型进程顺序执行，避免自身抢核掩盖比较。
不为“并行”同时复制未知进度的成员任务；并行来自独立问题与独立输出目录。
