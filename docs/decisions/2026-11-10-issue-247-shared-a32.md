# 共享 A 入口扩为每 P 两个容器，容量保持 32KiB

Issue247 / PR243；负责人 Melodydt。用户已接受 run33 评估后的优先方案。

## 决策依据

原条件评价中，16→32B/拍使 prefill2/W8 由 3.388659→3.894197
token/s（本地 shared 层），或 3.496459→4.398913（idealdual 层）。
32B 以上的最佳增益仅约 0.1450%/0.6972%；64→128B 双组交错完全同速。
因此先实施 32B 入口，不同时增加共享容量、SRAM 读取组或 FIFO 深度。
这些是既有 S32/K256 条件模型数据，不作为本次原生 RTL 的实测速度。

## 实施取舍

- 共享池维持八颗 4KiB 宏、一个全局 64B 服务、每 P 四个 64B FIFO 槽。
- 每 P 原子接收一或两个 128bit A 容器，bank/format 共用，每个容器保留独立 row/tile。
- 两容器只来自同一 FIFO 头；尾包和第 3 号起始容器允许单片。无需跨头拼接或新增信用。
- M 保持原操作数数组、乘法器和计算调度；增加并行写入解码。非法高片单独有效或重复目的标签整体阻塞。
- P 的本地 A 仍走原单片保持寄存器，额外片补零；B 路径保持原实现。
- standalone pool/M 以及 P 参数保持默认单片；新的 pair 包装层默认双片。pair 的旧行为比较显式选单片。
- 接口扩宽不是增加模型数值精度。S8 每容器低 64bit 有效，S16 用完整 128bit。

## 验证与边界

使用真实 SRAM 行为模型、服务器 Slurm 和冻结旧源，验证背压、边界、部分包、
控制竞争、两种 M 配置、默认单片兼容及完全等工作量的 16/32B 周期。
面积比较相同综合工具/库下的 pool 与 M 参数；宏数应保持不变。
模块面积差不能替代完整 P/SoC 面积、STA、布线或功耗。

旧 shared32_native 实验源保持冻结。其 pair bench 观察单片内部信号，
只能在历史源 commit 上原样运行；当前实现通过 shared_a32_native 严格派生
单片兼容 bench 和双片生命周期 bench，保留原检查。

后续优先定位 M 计算服务、输入完成等待以及非 Dot 阶段。输入 ACK 等待
不能直接等同外存带宽饱和，也不能把重叠计数简单相加为可消除时间。
本决策不改变上述后续模块的 RTL；实际结果与执行回执另见本阶段实施报告。
