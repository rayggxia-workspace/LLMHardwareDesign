# Issue247：容量/端口两路线的条件取舍

2026-11-09 Asia/Shanghai；负责人Melodydt；状态：研究建议，待独立审查，未批准生产实现。[报告](../experiments/issue-247-capacity-port-compare.md)；[Issue247](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/247)/[PR243](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/243)。

run04/101665及run05/101672分别以同binary因子对照和单一预取谓词干预比较两P各48/64KiB＋读写并发，以及各16KiB＋相同并发＋8组部分和。两轮87完整trace、6尾块、6非法CLI通过，包含历史/默认回放，未取得新RTL或物理资格。

默认容量联动预取会让大容量decode退化；固定16KiB的预取判定但保持真实48/64KiB驻留后，W8/context512的A48/A64为3.541567/3.543921，B为3.496169 token/s，增量仅1.30%/1.37%。W16和长context也约1%至2%；prefill2则A48/A64相对B增加20.84%/23.01%。不以单一decode配置否定大容量，也不把这些模型数值视为实际生成速度。

取舍：decode且希望保持数据SRAM预算时先推进16KiB路线；prefill吞吐优先时保留48/64KiB路线并配合预取策略。A48/A64活跃私有S总量112/144KiB，B为48KiB另加1344B部分和数据寄存器和控制；这些是数据位预算，真实面积效率待测。W8 decode的64相对48只多约0.066%吞吐，不据此默认选择更大容量；64保留K256、地址组织与prefill等潜在价值另计。

端口合同优先于扩容：若仅A64端口占用从1变1.25拍，吞吐3.490348已低于B的1拍3.496169。若所有路线都增加相同占用，大容量仍有小幅优势；不能混淆这两个比较，也不把占用等同全芯片降频。现有1RW四bank宽读占满全部bank，128bit普通写/粗分相前端尚不能兑现模型64B读＋64B写；真正1R1W、bank冲突、同址语义、响应/写ACK、宏视图和物理时序需独立验收。

下一步最小工程是隔离验证共有的读写并发合同及地址/生命周期，校准模型后再评估数据容量与上下文实现。遵守用户约束，SRAM扩容继续不实装。真实宏面积/功耗、96位多上下文RTL、DDR与实际权重/KV生成均待验证；实施与独立审查负责人待指定。
