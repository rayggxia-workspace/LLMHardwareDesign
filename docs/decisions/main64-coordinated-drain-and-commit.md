# main64原生服务的协调停止与传输保持

Issue179 / PR180，2026-11-08，Melodydt；R8.4候选，实际资格看验证索引。

采用main自身LC、native适配器、数据宏和原有直接通路；在生成副本的native服务边界添加halt门及请求/响应观测，保留原始main225源。理由是直接复用旧通用局控会丢失main U三源和独立TX保持槽等已修复行为。服务门阻止新服务，已经接受的宏指令及存储回执必须排空。

跨块每方向保存一字数据和完整身份ticket。目的请求被提出后不可撤回，只有实际SRAM回执才能记提交。取消未提出的字使用显式abort；已经接受的写即便取消仍计数并排空。源S读取、U TX槽和J提交输出具有独立所有权，不用请求接受信号冒充ACK。

外层主机/终端监督器跨内层复位保留失败信息与epoch水位。超时进入隔离而不复位仍有义务的内层；消费失败结果后重试。用户请求mask作为诊断记录，实际总是完整组协调复位，避免母控/两个局控/PM/存储接口身份不一致。

J桥接已提交输出并校验标签/次序，源终端在整条路由真实提交和ACK前保持；P保持READY后才启动任务。路线配置是op15主机管理记录，不扩展64位执行指令，不伪造J SEND或P RECEIVE原生操作。

该选择增加保持寄存器与组合校验；不借用旧顶层或main独立物理时序资格。R8.5建立覆盖闭环，R8.6重建综合交付与组合时序；完备周期交错、任意路由和模型图编译另行验收。
