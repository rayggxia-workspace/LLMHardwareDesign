# M11/M12 宽线负载与 M 数据位宽：讨论、证据和后续评估

- 日期：2026-10-29（中国标准时间，UTC+08:00）。
- 关联任务：[Issue #121](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/121)；现有实现另见 [PR #122](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/122)。
- 整理：huangpingyang04-lgtm。本文是讨论总结和候选评估，不是已批准的接口变更或新的物理验收。
- 范围：只讨论宽线负载与 M 供数位宽；SRAM 端口组织作为供数依赖。本文不执行 RTL 修改、EDA、服务器任务或整模型性能实验。

## 1. 先用通俗的话说明结论

计算块像加工机器，数据口像送料口，M11/M12 像连接机器的运输通道。

第一件事是运输通道不能无限长、无限分叉。缓冲器像接力站：它把一段驱动任务分成几段，不会让总电容消失，而且自己也占面积、耗电。后定制阶段只能增加允许的金属和通孔，不能临时增加接力站；需要的电路必须在共同底座冻结前准备好。

第二件事是送料口可能太窄。机器内部有64个基础乘法器，不代表现在的128bit输入口每拍都能把它们需要的新数据送齐。应把权重、激活、参数和结果分别计算搬运量，结合数据复用和真实等待时间判断要不要加宽。

**当前建议：先测出端口的负载/距离适用范围，同时保留128bit基线，比较独立256bit、512bit权重通道。具体驱动、最大距离、位宽和银行数量均未冻结。**

## 3. 问题一：宽线电容与冻结后不能加缓冲

### 3.1 问题是什么

当前研究规则中的 M11/M12 线宽为2µm、间距2µm，见[S2]。线宽是单根导线的尺寸，数据位宽是并行信号线数量，两者不能混为一谈。

一条连接的负载不仅是导线电容，还包含接收引脚、通孔/接点、分支和相邻线耦合。发送端要在规定时间内把这些负载充放电，才能让接收端可靠识别数据。

较宽导线通常降低电阻，也会改变对地/耦合电容。不能只看“线更宽”就断言总延迟必定更好或更坏；必须在实际长度、间距、层高和邻线条件下比较 R、C、转换速度与延迟。

### 3.2 为什么不能靠后期补救

项目已有阶段边界[S1]：有源单元、原生M1–M10及采用的固定PG/CTS/中继在各自冻结阶段确定；后定制仅改变研究M11/M12与via10/via11。

因此：

- 普通实现流程可以增加缓冲、调整驱动；本项目不能在任务定制时自由做这些操作。
- 共同底座冻结前可以评估预制中继；若改动已经冻结的叶块，须形成新版本并重新表征。
- 预制中继要有固定位置、供电、接入端和实际连线可达性。仅写“预留缓冲”不构成已经可用的资源。
- 若采用寄存器作流水接力，还会改变延迟和协议；它与组合缓冲不是同一方案。
- 任务定制不能按目标更换驱动规格、增添有源器件或修改冻结M10接点。

### 3.3 已有试验说明了什么

run287 报告[S3]在实际端口加入串联R和两端电容，保留原生寄生，比较 base 和 R/C 同时乘1.5的 high 条件：

| 场景 | setup/hold | 电容检查 | 可得结论 |
| --- | --- | --- | --- |
| M base/high | 报告均通过 | 0违规 | 仅支持该试验声明的边界 |
| T base | 报告通过 | 0违规 | 支持声明的base边界 |
| T high | 报告通过 | 9项违规 | 不能接收该high边界 |

T high 的外部数据驱动采用 BUF_X2；上限为121.154999fF，最差总负载141.876312fF，超限20.721312fF。失败包括8位write_data和read_take。

这证明“时序通过”不能覆盖“电容超限”。降频只能放宽周期要求，不会减小实际电容，也不会自动消除库模型规定的最大电容违规。

high 是未校准敏感性条件，不是正式工艺角；P2出口和虚拟接收边界通过，也不代表任意远距离、任意分叉或整底座通过。全部输出C通过不能代替输入驱动、clock、控制和完整R/C检查。

### 3.4 解决方法与代价

| 候选办法 | 作用与原因 | 条件及代价 |
| --- | --- | --- |
| 靠近放置计算与存储、缩短路径 | 减少线长和相关寄生 | 受宏外框、引脚位置、PG及其他通道约束；须按真实路径计价 |
| 点对点或限制分叉 | 减少一个驱动拖带的支路/接收端 | 复制数据需额外端口、存储或传输，不免费获得广播 |
| 冻结前加强发送端、控制接收端负载 | 提高驱动能力或降低末端负担 | 大驱动本身增加面积/功耗及前级负载；须验证全路径 |
| 共同底座预制组合中继 | 将长线的驱动分段 | 固定位置/数量/接点及面积、PG、线和功耗全部计入；后定制不能新增 |
| 预制流水中继 | 将长路径分为多个周期 | 改变延迟、队列、背压和clock成本；需新的协议和功能验证 |
| 优化线宽/间距/走线拓扑 | 权衡R、对地C和耦合C | 改研究规则须另行记录；不能只按减C忽略增R或面积 |
| 增加周期/降低目标频率 | 对仅时序不够的连接提供余量 | 不能覆盖max-cap/max-slew违规；性能成本明确计入 |

“更强驱动”和“更多预制中继”属于冻结前候选，不是对冻结后禁止增加缓冲的例外。若最终不采用任何中继，则必须接受有限的直接连接距离和扇出，超范围连接应被映射器明确拒绝。

### 3.5 建议的验证过程

1. 固定真实发送端、接收端和共同规则；分别登记数据、valid/ready、地址、控制、clock，不能只测数据位。
2. 在独立候选中比较线长、分叉数、邻线切换与有限几何；先用估算筛选，再用适合本研究层集合的提取/场解验证。未校准模型只能给敏感性结论。
3. 同时检查电容上限、转换速度、setup/hold、全部寄生覆盖、连接、PG和几何规则。
4. 输出每种端口可支持的负载、距离、扇出、频率及适用条件，不提前编造“最大可连多少毫米”。
5. 对需要中继的连接，先登记固定资源和全部成本；共同底座冻结后，所有目标共享同一批资源。
6. 超出范围时，要么调整冻结前方案并重验，要么报告该映射不可行；不放宽规则隐藏失败。

## 4. 问题二：128bit M 数据口是否足够

### 4.1 当前实现

固定修订源码[S4]的输入 `cmd_data[127:0]` 与输出 `rsp_data[127:0]` 各128bit，是两个方向，不应说成“整个M总共只有128根线”。

输入口承载A/B装载与部分参数/命令数据；输出承载应答、部分和和完成结果。M有64个S8基础乘法器、8路归约/累加，以及两个操作数银行；每银行驻留四个K8 tile。实际发射速度、命令速度和输入速度是三个不同量。

在假设每拍接受一次传输、300MHz且没有停顿时，纯数据通道上界为：

| 数据位宽 | 每拍容器字节 | 单方向理论GB/s |
| --- | ---: | ---: |
| 128bit | 16B | 4.8 |
| 256bit | 32B | 9.6 |
| 512bit | 64B | 19.2 |

这些数值不包含ready停顿、应答、参数、尾块、存储冲突和链路等待；不代表整模型或当前M已经持续达到该带宽。

### 4.2 一个可检查的供数例子

限定为驻留装载op7/op8、满K8/N8、S8×S8、每个tile均装一套新A/B：

- A是8个S8，共8B，当前占1个128bit命令容器。
- B是8×8个S8，共64B，op8每次装16B，共4个命令容器。
- 合计72B有效操作数、80B输入容器、至少5次输入接受。
- 这组数据对内部阵列对应一次64乘法的发射；完整命令仍有流水填充/排空和完成响应，不能写成“一个tile一拍算完”。

对四个全新tile的一组descriptor，仅装载就是20次输入接受；核心S8发射为4次。两者不是完整执行时间的直接比值，尤其不能据此宣称固定20%端到端利用率。

若权重或输入可复用，所需新数据会减少；S16又有不同容器和位片周期。双银行允许重叠部分装载/计算，但不会增加共用输入口的总传输能力。是否真正供数受限，要由实际工作负载和等待归因判断。

### 4.3 两个参考项目的实际情况

参考配置见[S5]–[S9]；不采用默认参数替代案例的实际参数。

| 通道/组织 | openTPU small，D=32/MCOLS=2/LANES=4 | llaccel固定参考 |
| --- | --- | --- |
| 权重数据输入 | `b_rdata`，D×8=256bit | `gemm_w_rdata`，2048bit，搬一块256B权重 |
| 激活数据输入 | 从ACT_RAM本地读取MCOLS×D×8=512bit | `gemm_a_rdata`，512bit容器；普通A行请求实际16B |
| 尺度/参数 | 独立256bit尺度行输入；ACT_RAM另返回128bit尺度记录 | 与A侧接口共享rq/bias/aux等参数请求 |
| 结果/工作存储 | TMEM读、写数据各4×32=128bit声明接口 | `gemm_wr_wdata`，512bit容器，常用16B/32B有效输出 |
| 复用/预取 | ACT_RAM驻留激活，权重FIFO/重放和结果FIFO | 权重双缓冲，16×16计算阵列，权重跨A行复用，输出FIFO |
| 访问限制 | TMEM受bank、仲裁和实际有效lane限制 | 16-bank交叉开关；256B权重请求占全16bank，与A读串行争用 |

几点不能误读：

- 2048bit一次权重读不等于每拍持续获得2048bit新权重，更不等于所有读写口同时满带宽。
- llaccel普通A行只请求16B，虽有512bit容器也没有每次用满64B；结果有效字节也要与容器分开。
- openTPU的512bit激活是片上ACT_RAM到MXU的本地通道，不能与外部DRAM权重流相加后当作统一外部带宽。
- openTPU默认MCOLS=8不是small的实际MCOLS=2。两个参考的阵列规模、数据格式和复用方式不同，不能按接口位宽直接排名。
- 参考llaccel_core物理结果没有包含bank存储体；不能据逻辑bank接口推定已经包含实体SRAM及其全部物理成本。
- 值得借鉴的是“按用途分流、就近驻留、配套预取/银行”，不是机械照抄最大位宽。

### 4.4 候选方案与评估

| 方案 | 可能收益 | 需要检查的代价 |
| --- | --- | --- |
| 保留128bit，改进复用和调度 | 改动小，保留基线 | 新数据频繁替换时仍受输入带宽限制；不能无限增加缓存 |
| 单一输入口改256/512bit | 减少某些装载传输次数 | 参数/数据仍共享；装载格式、缓冲、上游口和握手均需适配 |
| 保留命令口，增加独立256bit权重口 | 分离大宗B数据和控制/A流 | 每个S8满B tile至少2次权重传输；实际流水/存储可用率要测 |
| 保留命令口，增加独立512bit权重口 | 64B满B tile有机会一次装入 | 更多pin/线/驱动/接收/缓存；不能只看命令次数减少 |
| 分成多个较窄并行通道 | 便于分银行/分组引出 | 总线数和总位宽仍计价，仲裁和不均衡可能损失吞吐 |
| 不改宏，仅外加宽转窄适配器 | 可连接宽上游 | 宏入口仍128bit，不能突破入口持续带宽；只能改善某些调度/缓存行为 |

当前优先建议是**保留128bit基线，研究独立256/512bit权重通道**，不是批准任何一种。主算术资源可以作为受控比较的不变量，但装载缓冲、有效位、写入粒度、命令/完成顺序及背压都要修改和重新验证。

特别需要同时评估上游：一个128bit、单1RW的S，每拍最多提供16B访问总量。把M入口改成512bit，如果仍由同一个S供给，通常只能攒几个周期再送一拍；不能凭接口变宽获得4倍持续供数。必须明确采用何种更宽存储或多个能同时访问的银行，以及它们的冲突、容量、地址和物理成本。改用SRAM本身也不保证变宽或多端口。

### 4.5 为什么加宽与负载必须一起考虑

位宽扩大增加并行线数、引脚数和总切换电容；单根线的电容仍由其长度、邻线和接收端决定，不能简单说“512bit使每根线负载变成4倍”。

更多粗线还可能迫使引出通道/宏间距扩大，增加线长，或提高耦合和拥塞；因此逻辑带宽收益有可能被物理代价抵消。单根线变细也不是无条件补救，因为电阻会改变，且已批准的几何规则不能悄悄更改。

## 5. 建议的联合评估顺序

| 步骤 | 做什么 | 交付/判断条件 |
| --- | --- | --- |
| A：固定基线 | 绑定128bit现有源、格式、K/N形状、时钟和实际存储 | 各方向有效B/容器B、装载/执行/消费/等待可追溯 |
| B：先定位瓶颈 | 区分供数停顿、内部算术、结果背压、存储冲突 | 若供数不是主要瓶颈，不凭位宽数字扩大接口 |
| C：有限逻辑候选 | 比较128bit、独立256/512bit权重口；先做单M与实际存储 | 数据正确、尾块/复位/背压/银行所有权和数值合同保持 |
| D：真实供数 | 分别测冷装载、驻留复用、连续供数、存储争用和消费停顿 | 完整周期、有效MAC、有效B与容器B；不能只测内部峰值 |
| E：物理与负载 | 选代表连接距离/分叉，评估全部端口与固定中继 | 面积、pin/halo、线/via、R/C、setup/hold、电气及DRC |
| F：选择并冻结 | 根据收益、代价和适用范围选择一个实现 | 先重验叶块，再登记共同底座；后定制只改允许图形 |

至少覆盖既有矩阵形状的投影、QK、PV及S8/S16组合，包含短K/长K、尾K/尾N、冷加载和可复用情形。带宽和物理比较必须使用同一工作量、数值/结果合同和上游供数约束；增加的银行、缓冲、中继与驱动不能免费。

应同时报告：完整操作周期、供数等待占比、有效计算利用率、各方向有效/容器流量、宏外框/单元面积、全部新增pin、引出halo、线长/通孔、最大负载/转换、setup/hold及模型适用范围。没有校准和活动数据时不填写虚构功耗收益。
