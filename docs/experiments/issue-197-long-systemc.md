# 七模型 SystemC 序列长度补测

对应 [Issue #197](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/197) 和 [PR #198](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/198)。此前七模型各处理 9 个位置。本轮输入同一条自然语言提示词，各自 tokenizer 编码为 12 或 13 个 token，各生成 12 个 token，每模型处理 23 或 24 个位置。最后一个提示词位置预测第一个生成 token，最后一个生成 token 作为输出记录。

提示词为 `Explain how a computer stores and retrieves information in simple terms.`。各模型运行全部文本推理层，沿用 #154 的 S16 权重和数值配置。原始模型、量化权重及版本有 SHA-256 绑定。对使用显式 RoPE 表的模型，原工具在新文件里追加覆盖全部位置的官方旋转表。独立 PyTorch FP32 运行先生成贪心序列和逐层参考，SystemC 自己生成 token。若两条序列分叉，数值比较在实际 SystemC 前缀上重跑 FP32，同时保留独立贪心序列是否一致。

## FP32 对照

七个 SystemC 分片均正常结束，合计 **165 个处理位置、84 个生成 token**。与同前缀 FP32 的 Top-1 合计 **163/165**，原数值验收门通过 **5/7**。

| 模型 | 输入 + 生成 | 处理位置 | 同前缀 Top-1 | 独立贪心序列一致 | 最差 logits / 隐藏层相对 L2 | 原门 |
| --- | ---: | ---: | ---: | --- | ---: | --- |
| Phi-4-mini | 12 + 12 | 23 | 23/23 | 是 | 0.93% / 2.42% | 通过 |
| Gemma 3-4B 文本 | 12 + 12 | 23 | 23/23 | 是 | 2.27% / 3.38% | 通过 |
| Qwen3-0.6B | 13 + 12 | 24 | 24/24 | 是 | 1.10% / 0.99% | 通过 |
| Qwen3.5-4B 文本 | 13 + 12 | 24 | 23/24 | 否 | 3.36% / 5.13% | 未通过 |
| Falcon-H1-3B | 13 + 12 | 24 | 24/24 | 是 | 1.56% / 2.26% | 通过 |
| Qwen2.5-3B | 13 + 12 | 24 | 24/24 | 是 | 0.72% / 0.68% | 通过 |
| Granite 3.3B | 12 + 12 | 23 | 22/23 | 否 | 2.40% / 5.13% | 未通过 |

- Qwen3.5-4B 在第 14 个处理位置选出了不同的第 2 个生成 token，独立贪心序列自此分叉。随后按 SystemC 的实际前缀重跑 FP32，余下位置的 Top-1 一致。
- Granite 的差异出现在第 23 个处理位置，对应第 12 个、也是最后一个生成 token。此前喂入模型的前缀一致。
- 两个未过门的模型均保留全部结果。其连续误差阈值通过，门槛差异来自 Top-1 和独立贪心序列。短序列复验确认，新增计数代码下 Qwen3-0.6B 的 9 个位置仍复现原 hidden/logits 和 C/D 计数。

## 序列长度与内存、搬运

七模型的 KV 在本轮测得**随上下文位置线性增加**。从第 9 个位置到末位置，KV 增为 **2.56–2.67 倍**，单步 C/D 搬运增为 **1.40–1.82 倍**，因此累计搬运增为 **3.20–4.07 倍**。

表内箭头依次是位置 **9 → 16 → 末位置**。末位置为该模型的第 23 或第 24 个位置。

| 模型 | KV 常驻 MiB | R 常驻 MiB（末） | 单步 C/D MiB | 累计 C/D GiB | 逻辑活性峰值下界 MiB（末） |
| --- | ---: | ---: | ---: | ---: | ---: |
| Phi-4-mini | 3.38 → 6.00 → 8.63 | 0.00 | 109.50 → 147.47 → 185.53 | 0.77 → 1.67 → 2.82 | 27.04 |
| Gemma 3-4B 文本 | 3.59 → 6.38 → 9.16 | 0.00 | 113.72 → 140.18 → 166.68 | 0.87 → 1.75 → 2.81 | 11.77 |
| Qwen3-0.6B | 2.95 → 5.25 → 7.88 | 0.00 | 57.97 → 80.12 → 105.47 | 0.40 → 0.88 → 1.62 | 9.29 |
| Qwen3.5-4B 文本 | 0.28 → 0.50 → 0.75 | 49.13 | 47.81 → 56.74 → 66.95 | 0.37 → 0.73 → 1.22 | 2.79 |
| Falcon-H1-3B | 0.28 → 0.50 → 0.76 | 128.84 | 55.56 → 66.96 → 79.99 | 0.43 → 0.85 → 1.43 | 1.82 |
| Qwen2.5-3B | 0.95 → 1.69 → 2.53 | 0.00 | 102.33 → 130.81 → 163.40 | 0.76 → 1.57 → 2.73 | 4.16 |
| Granite 3.3B | 1.69 → 3.00 → 4.31 | 0.00 | 88.91 → 108.50 → 128.19 | 0.68 → 1.37 → 2.19 | 4.69 |

- **递推状态占用稳定，搬运仍累积。** Qwen3.5 与 Falcon 从位置 9 到末位置，R 常驻数据分别保持在 49.13 和 128.84 MiB（含卷积历史）。同期累计 host R 状态读写分别由 0.84 → 2.25 GiB 和 2.25 → 6.00 GiB。
- **每 token 的权重读取在本次输入下稳定。** 七个模型的整段逻辑权重读取约 26.64–188.00 GiB，每处理一个位置都会重新统计权重访问，MoE 选中的专家可以变化。该数值按算子访问统计，实际外存流量仍取决于缓存与调度。逐模型 prefill、decode、尺度元数据及完整逐位置统计见[结果 JSON](../../work/huangpingyang04-lgtm/197/long/long-systemc-results.json)。

- **KV 常驻字节**来自每个 token 结束时实际 `LayerCache.keys/values` 的 S16 数值及尺度。统一指数每张量按 4 B 计，逐元素指数每元素按 4 B 计。R 单列 S32 状态和卷积历史数值及尺度。它们是模型的有效载荷和元数据，分配器、容器容量及对象头开销另计。
- **逻辑张量活性峰值下界**由完整运行的算子序号与最后使用位置计算。它和 KV、R 使用不同的记账视角，表内各列应分别阅读。
- **C/D 搬运**是有限 16 KiB S 与 32 KiB 暂存窗之间实际经过 128 位运输字的双向流量，装载和写回均计。逻辑权重读取及 host 侧 R 读写独立统计。后两项保留 host 管理语义，未计入 C/D。报告给同一次运行内的位置 9、16 和末位置，避免把不同提示词的两次运行当成严格同前缀对照。
- **时序口径**沿用 #154 的事务和假设链路时间。该轮的输出是存储、活动和数值对照。系统 RTL 逐周期测量的依赖见[整模型 RTL 缺项](issue-197-full-model-rtl-gaps.md)。
