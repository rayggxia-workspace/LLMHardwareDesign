# 七模型 SystemC 行为外存接入

[Issue #197](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/197) · [PR #198](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/198) · [RTL 接口缺项](issue-197-full-model-rtl-gaps.md#qwen35-4b-外存接口验收表)

## 数据路径和计量口径

这次在 #154 的冻结 SystemC 计算模块旁接入外存控制端和独立的 TLM 行为内存。控制端从模型实际发起请求，按 16 字节总线字、最多 256 字节一突发、4 KiB 边界切分。目标端完成真实数据复制并返回成功后，按地址区间统计方向、突发数、有效字节和包含首尾部分字的总线字节。每个处理位置独立核对控制端请求有效字节与目标端成功完成字节。结果对应 SystemC 行为端口，尚无 DDR/HBM 器件命令、排队延迟、刷新、PHY 或器件能耗校准。

| 区域基址 | 数据路径与当前策略 |
| --- | --- |
| 0 GiB，检查点只读 | M 消耗 K 分片前从目标端读取权重行片段，暂存在最多 **16 KiB** 的缓冲。高低残差分量、嵌入、卷积系数、归一化参数和 RoPE 表都通过该端口取值。检查点预装载及控制端持有的尺度索引/标量元数据不计流量。预取先于消费，当前串行，无重叠或跨 token 复用。 |
| 16 GiB，KV | 逐层追加新 token 的 K/V，K 已做 RoPE；再按注意力查询头，从外存读取有效历史切片供 QK/PV 使用。同组查询头各取一次，Gemma 滑窗到界后复用最旧槽。单槽保存 S16 值、公共尺度及适用时逐 lane 尺度。 |
| 17 GiB，R 递推矩阵 | 每个 R 所有者按 8 lane 分块加载、执行并提交，读回后写到目标端。局部状态块最多 **8 KiB**。首位置以零初始化，下一位置从端点读回 S32 矩阵与尺度；所有块写完后才写回新尺度。 |
| 18 GiB，R 卷积历史 | 保存最近三次卷积输入，下一次读取有效历史并覆盖最旧槽。与递推矩阵分开统计。 |

旧 C/D 往返是用于验证张量交接的暂存镜像。本次运行关闭该镜像，保留同一套计算宏、检查点和量化策略。结果独立于旧 C/D 流量，能耗比较须区分两次执行。实现入口在[基准目录](../../project/experiments/seven_model_system_bench/README.md#systemc-外存端点回放)。

## 验收

先用 Qwen3.5-4B 的前两个输入位置检查权重、KV 读写和 R 写回/重载。用旧整模型输出逐字节比对 hidden、logits，核对预测 token、数学 MAC，并检查各类流量与先前的逻辑权重、KV 容量和 R 状态/历史规模一致。扩展时七模型均使用原输入及生成长度，对整段输出和计算宏事务计数做同样的对账。

## 七模型全序列

试跑通过后提交 Slurm 数组 `98704`。七个分片均完成，共 **165 个处理位置、84 个生成 token**。每个模型运行原定 12 或 13 个输入 token 并生成 12 个 token。七份 hidden 和 logits 与冻结结果逐字节一致，输入/预测 token、数学 MAC、各宏命令及饱和计数也一致。汇总作业 `98729` 再次核验每组输出、输入校验日志和已验证回执的 SHA-256。

- **权重**占这套预取策略总线字节的 **95.7%–99.9%**。每个 token 会重载所需片段，Granite 仅读取当时选中的专家权重。
- **KV** 在生成阶段仍逐位置追加，每个查询头按当时有效历史取数。七模型 decode 阶段的 KV 读为 prefill 的 **2.30–2.54 倍**。这是分阶段累计值，两个阶段的处理位置数略有差异。
- **R** 只在 Qwen3.5 与 Falcon 上有流量。两模型都在首位置写回递推矩阵，之后每个位置先读回再写。其余五模型的对应读写均为零。
