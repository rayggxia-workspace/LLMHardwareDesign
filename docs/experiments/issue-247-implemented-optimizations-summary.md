**生产 RTL 已接入 6 类可选提速功能：P 侧 3 类，U/N 侧 3 类。** 它们已完成相应服务器功能验证，但参数默认仍保持旧路径。独立实验中的弹性链路、U 流水控制器和第三轮矩阵双缓冲，单列为候选；SRAM 48/64KiB 扩容、E→E 融合等不能写成已接入的生产功能。

最新采用 R1＋R2＋R4 组合。R3 矩阵双缓冲虽完成 RTL 和评估，但整图结果退化，未作为最终组合。以下均为 ctx8、每 block 16KiB 的旧体系条件结果，单位 token/s：

## 2. P 侧已经接入的三类优化

### P1：消费者优先、有界公平的 S 仲裁

出发点是 G 读取和 M 写回可能等待外部普通 IO，拖延当前计算链。新增 popt_s_policy_arbiter 将外部 IO 与本地消费者分组；组内轮转，两组同时有需求时默认最多连续服务两个消费者，然后服务外部请求。计数只在实际握手成功时推进，背压时保持 owner、地址和数据，响应退休前不抢占。

启用参数为 S_CONSUMER_PRIORITY=1，默认 0。该实现改善消费者等待，不等于完整 DMA 自适应预取。原生 P 尚缺 tile 依赖、缓冲代次和外存仲裁的完整描述符接入；单 owner 队头阻塞仍可能存在，公平上界以授权次数而非绝对周期衡量。

### P2：16KiB 四 bank 的机会并发

原 LOAD 会阻止全部普通 S 请求。S_BANK_RW=1 允许无冲突普通请求与 feeder 宽读重叠，仍使用四个 256×128 的实际 1RW 宏，总容量 16KiB。竞争时可同拍完成 48B 宽读片段与 16B 普通访问，再优先补齐缺失片段；总访问能力仍最多 64B/拍。

实现包含 bank mask、宽读拼接、独立响应信用、输入区间租约和同一拼接行写保护；只有真实宏写 ACK 后才报告写完成。默认 S_BANK_RW=0。新增控制、响应缓冲、比较器与布线有面积代价，不能将这个实现等同于模型中每拍 64B 读加 64B 写的理想 1R1W。

### P3：八组 S64 部分和、A 复用与 B-only LOAD

将循环改为 K 分段在外、输出列组在内：装入一次 A 分段后，顺序为最多八组 B 累加各自部分和。M_CONTEXTS=1/2/8 选择新上下文模块，默认 0；八组复用原八行×八列 S64 结果槽，不新增八套 M。新 op13 检查 nextK、tag、格式、首段/末段和状态；op14 释放或中止正确代次。最终才执行 RNE/clamp，中间结果不通过 S16 往返。

配套 ENABLE_REUSE_A 允许 rows=0、reuse_b=0 的 B-only LOAD，保留 A，B 仍经过真实 S 读取和握手。新增约 325bit 控制状态，原 4096bit 结果数据复用；活动上下文不能同时占用旧多行 batch 的结果槽。跨命令的 A 生命周期仍需调用程序维护，不能在其他 context 尚需 A 时覆盖。

```systemverilog
pu_p_group #(
  .S_CONSUMER_PRIORITY(1),
  .S_BANK_RW(1),
  .M_CONTEXTS(8)
) p (...);
```

局部验证保留负结果：消费者平均响应延迟 14.9375→10.8125 拍，总事务时间仍 516 拍；bank 并发局部程序 95→71 拍；完整 P 长 K 程序 2112→2032 拍，短 K 程序 672→676 拍反而变慢。不能把这些局部比例乘进整图 token/s。

源码落点：project/rtl/pu_leaf_base/pu_p_group.sv、pu_p_store_control.sv；project/rtl/block_local_s/popt_s_policy_arbiter.sv；project/rtl/s_sram/block_feed_s16k_bank_rw.sv、local_s_p.sv；project/rtl/block_feed_v1/block_feed_loader.sv；project/rtl/block_v2/block_v2_m_context.sv。

## 3. U/N 侧已经接入的三类优化

### N1：共享唯一 N 的批量 EXP 路径

R1 增加默认关闭的 NEXP_BATCH，把 U op15 的 EXP 批处理请求送入同一个原生 N，避免重复调用和单元素包装开销。PACKED16 一包最多八个 S16；NX32 一包最多四个 S32 容器，采用各容器有符号低 16 位，输出 U16 零扩为 S32。高位处理与尾部零填充必须遵守已验证合同，不能解释为任意 S32 指数精度。

同一 N 的所有权在普通归约、原有直接路径和新批处理之间显式仲裁，S 读、S 写和真实 ACK 保留。R1 四命令方案会改写 N 统计会话，普通统计需要重新初始化。新增约 402bit 显式状态，没有复制完整 N 或增加 SRAM。

### N2：保持持久状态的单 op12

R2 新增默认关闭的 NEXP_DIRECT，以一条无状态 relative-exp 命令替代 R1 四条原生命令。count 为 1..8，param/aux 和未用 lane 必须满足零值约束；EXP 数值函数不变，maximum/count、factor、exp 统计、replay 等持久状态保持。DIRECT=0 保留四命令兼容路径。

复用原两条 EXP 通道和结果寄存器，没有新增寄存器声明、LUT 通道或 SRAM。实际计算包装器 n1..8 接受间隔从 R1 的 [15,15,19,19,34,34,38,38]，下降到 [7,7,9,9,16,16,18,18] 拍。

### N3：仅为 op12 扩展到四路 EXP

R4 新增 NEXP_DIRECT_LANES=2/4，默认 2；仅 BATCH=1 且 DIRECT=1 时选择四路。普通 N 指令仍维持原两路循环，响应时序和数值回归通过。NX32 包宽仍为 128bit；n5..8 必须拆成两个真实子包，不能免费塞入八个 S32。

四路 n1..8 实际间隔为 [7,7,7,7,14,14,14,14] 拍。n4 完整 U 事务由 18 拍减为 16 拍，其中 S 输入 5 拍、计算 6 拍、S 输出 5 拍；模型只替换已校准的补充计算费用，不重复收费或删掉 S/DDR 工作。新增 34bit 状态及两条实际 EXP 组合路径；查表端点、插值、舍入和布线仍有面积代价，34bit 不是总面积。

```systemverilog
pu_u_group #(
  .NEXP_BATCH(1),
  .NEXP_DIRECT(1),
  .NEXP_DIRECT_LANES(4)
) u (...);
```

上述参数默认 BATCH=0、DIRECT=0、LANES=2；源码可启用不代表既有母控镜像或默认系统已启用。旧 prefill 的 S16 输入/S32 输出模式不符合 NX32 条件，完整回退，所以四轮 prefill 结果不变。新 RTL 的完整生成图编译和物理实现仍需单独验收。

源码落点：project/rtl/pu_leaf_base/pu_u_group.sv、pu_nexp_shared.sv、nexp_batch_adapter.sv；project/rtl/block_v2/block_v2_n.sv。最新 R4 只增改 N 和 U 两个生产源，router/adapter 保持 R2 源版本。

## 4. 其他已实现路径与候选方案边界

| 项目 | 当前实现与证据 | 是否进入本次生产优化组合 |
|---|---|---|
| 既有 U 的 N→E 直接路径 | 生产 pu_u_direct_pair 已存在；公平局部比较 52→45 拍 | 属继承基础，不重复计作本轮新增 |
| 既有 P 的 M→G 直传与门控 SiLU | M 两个 S16 结果可经已配置路径作为 G 输入，跳过对应 A 读 | 属继承基础，不是任意宏通用互连 |
| P 两槽弹性链路 | 独立 RTL 与局部综合；孤立链路 0.5→1 beat/拍，真实 P 程序仍 288 拍 | 未替换生产 pj_feed_hold |
| U FIFO 流水重叠 | 独立控制 RTL 已验证；32 tile 串行 1440→1071 拍 | 未接入生产 U 顶层，整图收益为条件模型 |
| R3 矩阵有限双缓冲 | 独立 S32/W8/S96 K16 RTL、真实 S、有限队列与生命周期验证通过 | 未替换生产 P；整图退化，独立备份 |
| R LOAD 越界修复 | 完整索引在截断前检查，防止高位越界地址回绕 | 正确性修复，不列为速度收益 |

R3 单/双包槽的局部连续供数确实改善，例如 ctx8、K11008 的首接受至末完成从 33033 降为 16538 拍；但旧整图主场景双缓冲仅 2.758650 / 3.660417 token/s，低于 R2 的 3.378344 / 3.669582。DDR、真实 S 访问、外层 tile 边界与完成成本限制了收益，因此最终回到 R2 基础实施 R4。

R3 候选包含 128 个 32×9 有符号乘法器及八组 S96 部分和，不能用它的资源预算描述生产 S64 M。大面积候选备份 task/247-m-k16-area-initial，前态备份 task/247-pre-m-area-r2-ed9f5ee6；R4 扩通道另备份 task/247-nexp4-area-r4。均保留可恢复源码及证据。

**尚未作为生产 RTL 实装：** 48/64KiB SRAM、真正同容量 1R1W 宏、1KiB A 寄存器缓存、E→E 256B 融合、第三 P 的完整通道感知分工、N16/N32 的生产矩阵扩宽、U8/16 lane 通用向量宽化，以及完整 DMA 自适应预取。部分方向已有 SystemC 结果或局部 RTL，但没有经过生产接入和整图资格确认。不同候选的百分比不可直接相加或相乘。
