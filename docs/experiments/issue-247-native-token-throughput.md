当前原始 Qwen2.5-3B trace **不能由现有原生 RTL 直接执行完整生成**。旧整图模型接受 S32、96 位累加和理想 1R1W；实际 P 接受 S8/S16、段和 S40、合并 S64，S 是四个真实 1RW bank。不能把旧 3.496 token/s 当作新版实测，也不能将局部 RTL 加速比例乘回该数值。

本轮分三层验收：重跑历史条件 SystemC；运行实际 P RTL 小程序校准；在明确候选转换器和控制程序的条件下执行新的完整图时序模型。第三层输出专用字段 `conditional_tokens_per_second`，而 `native_full_model_tokens_per_second` 保持 `null`。真实权重、KV 数值与 token 采样生成、模型质量、完整原生网表、物理面积与时序均未在本轮验证。

### 为什么此前是3～4 token/s，本轮只有约0.08？

这不是同一硬件、同一程序的版本回归，而是两套模型前提不同。旧3.496是16KiB、理想1R1W和八组候选部分和的decode；旧4.467/4.547来自48/64KiB方案的prefill2，本身也不是同一个decode场景。本轮run12重新执行并核对的是下表四个16KiB历史场景；48/64KiB的4.467/4.547保留此前run05证据，本轮未重复运行。

| 关键前提 | 此前候选架构研究 | 本轮原生接口约束的条件程序 |
|---|---|---|
| M数值入口 | 假定直接S32、完整96bit累加 | 原生S8/S16、S40/S64；S32须无损拆成三项并付转换费 |
| 普通S服务 | 模型常用64B/拍，另假定独立读写端口 | 原生128bit握手，无背压连续访问为16B/6拍 |
| K和命令 | K256虚拟流服务、候选流水 | K≤32，每条实际命令、缩放、ACK和释放计费 |
| 调度 | 有限排队、预取和计算重叠的候选模型 | 每P内串行供数/转换/计算；两个P仍可并行 |
| 可用于什么结论 | 比较所声明候选架构的相对收益 | 核对原生接口成本下这一个具体条件程序的收益 |

前三项RTL实现并未同时实现旧模型假定的原生S32算子、96bit路径、理想宽端口和完整异步供数。因此旧数字不能作为这版RTL的现成速度承诺。另一方面，本轮0.08174也不是最终优化速度、严格性能下界或完整原生实测，它仍依赖候选转换器，并采用保守串行程序。**公平的本轮比较是0.06758→0.08174（+20.95%）；不能计算3.496→0.08174的“版本降速百分比”。** 若此前将3～4理解为现有RTL已经达到的速度，该理解需要更正。

## 2. 历史重现与原生校准

run12 / Slurm101767 的四个完整 RESULT 与 run05 全字段相同，包括工作、流量、缓存、周期和速率；只确认旧条件模型可重现。

| 历史场景 | token/s |
|---|---:|
| W8 decode，context512 | 3.49616888299 |
| W16 decode，context512 | 2.11665860003 |
| W8 decode，context2048 | 2.55280435873 |
| W8 prefill2 | 3.69669737899 |

run13 / Slurm101769 使用真实 SRAM 模型和当前生产 P RTL。两种 bank/仲裁参数、三种随机初始化共 6 次运行，每次 1,556 个事件逐字段相同：1,440 条命令、108 次 LOAD、8 次外部普通 IO，含 288 次 op13 和 96 次释放。12 个数值场景覆盖 B8/B16、K1/7/8/9/31/32、N1/5/8、三行 S16 A、shift0/15/30、八组活跃 context、最终 RNE、实际写 ACK 和读回。

| 已实测服务 | 无背压串行费用 |
|---|---|
| scale / raw read / release | 相邻命令接受间隔 4 拍 |
| M | leaf 延迟 + 4 拍，包括 P 包装及接受间隔 |
| final RNE + S 写 ACK | 12 拍 |
| 外部 128bit 普通访问 | 相邻接受间隔 6 拍 |
| LOAD | 随 rows、tiles、宽度变化，逐项核对实测；不是固定一拍宽口 |

M 的多行费用由两组部分和流水与四对输出处理的递推计算，并与实际命令事件比对。新条件模型的 LOAD done 后保留 2 拍统一调度间隔；实际校准程序跨 LOAD/命令入口可以只需 1 拍。这里额外保留的 1 拍是保守控制程序选择，不宣称整个模型程序与小测试逐拍完全相等。多 bank/仲裁的两种后端在该串行程序中相同，因此本轮不计入尚未安排的并发收益。

## 3. 新条件模型如何对应原生 P

两条路线都固定 300MHz 条件频率、2P/1U、17.1GB/s 外存参数、每 P 16KiB S、N8，以及冻结的候选 U 模型。没有扩大 S 容量。每 P 的四个 1RW bank 总访问最多 64B/拍，普通入口按实际 128bit 握手收费；不再使用旧模型的独立 64B 读和 64B 写日历。

S32 无损表示为三个有符号 S16 limb，基数 2^15，位移 0/15/30。读源、转换、padding、写 packed tile、LOAD、每条 K≤32 的 M 命令、输出与释放均计费。

- **旧接口程序**：静态矩阵用 op10 的三行积累未缩放 limb 部分和，最后逐项 raw S64 读出，经候选 S96 合并器缩放、合并并最终 RNE；不借用 op13/14。
- **新版程序**：单行静态矩阵将三个 limb 通过 op4/op13 合入一个数学输出 context，按 8 个 N8 列组复用 A，只为后续列组装 B；最终 op5 写回，等待输出 DMA ACK，再 op14 释放。flattened nextK=3K，要求 K≤21845；实际最大 K11008 对应33024。另测单 context 的相同新接口程序，以分离八组调度收益。
- **动态 S32×S32**：9 个真实 S16 term 逐个完成，使用共同的有限 96B S scratch 和候选 S96 read/modify/write 合并；两路线保持一致，不能把 9 个 term 当作免费的一组原生 context。prefill 多行也使用共同 fallback。

每 P 还明确承担 **2712B 未实装的适配器寄存器预算**：2560B 转换 tile 暂存、128B RX/TX、24B 合并临时数据。它不属于原生既有 512B 结果寄存器，也不从 16KiB S 中免费借用。转换器吞吐、两 lane S96 合并、RNE 和完整图编译/DDR 桥仍是候选假设，面积和频率未知；真实原生准入因此仍拒绝。

原始 DDR 字节不因转换偷偷减半；W8/W16 是独立权重存储配置，不是已验证的真实量化质量。两路线 B/输出工作和标量 MAC、S8 bit pass、U 工作应完全守恒，A 工作只可在实际复用时减少。普通 IO、packed96 共享 word 的 RMW、DMA 最后 S ACK 和结果槽释放均进入独立审计。

本程序每 P 内串行 staging/转换/LOAD/M/输出，两个 P 可并行并竞争外存。没有新的异步预取控制器，所以消费者优先与 bank 读写并发的整图收益明确为 0；不能把该结论解释为硬件并发无用。逐 bank 分量仅是相对 tile 偏移记账，本轮只核验操作总量及 1RW 上限，没有完整 S 地址分配器，也未验证复杂并发 bank 热度。

A复用减少了重复读写和打包，但三次缩放/单行M命令增加了计算流水和控制开销；本轮净收益来自前者超过后者。单个P普通128bit入口每6拍服务16B，300MHz下对应0.8GB/s的无其他等待服务上限，另有源读取、packed写入和M bit pass费用。它与旧理想宽口模型的前提不同，因此旧3.496与新0.08174不能作“硬件版本退化”比率。
