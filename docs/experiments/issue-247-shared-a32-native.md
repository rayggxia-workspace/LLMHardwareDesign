## 1. 出发点：先兑现32B能力

此前真实共享池RTL每P只能送一个128bit容器/拍；旧条件模型中4.398913 token/s的prefill结果使用32B入口。run33具体评估确认，32B以上的最佳整图增益只有0.1450%（shared）或0.6972%（idealdual），64→128B双组交错完全同速。因此优先扩原生入口，不继续增加共享容量、读取组或FIFO深度。

这里的目标是减少实际A握手和搬运周期。旧条件模型的百分比是研究依据，不能直接当作新RTL速度承诺。本轮同时安排同输入、同命令、同数值结果的原生周期对照，避免用不等负载或纯带宽倍数外推token/s。

## 2. 五个模块的具体改动

| 模块 | 具体做法 | 保持的资源/合同 |
| --- | --- | --- |
| shared_a_pool32 | A_WORDS_PER_BEAT支持1/2；同一FIFO头最多取两个连续容器 | 8颗4KiB宏、全局一次64B读、每P四个64B信用 |
| block_v2_m | 独立row/tile的双片原子写入；非法形状整拍阻塞 | 操作数数组、64个S8乘法器及计算调度 |
| block_v2_m_context | 同样的双片写入与bank锁；不改变context算术 | 既有8组结果/部分和语义，无新增算术槽 |
| pu_p_group | SHARED_A_WORDS参数贯穿共享接口；本地A只驱动低片，其余清零 | B保持寄存器、本地SRAM和LOAD完成汇合 |
| pu_p_shared_pair | 默认A_WORDS_PER_BEAT=2，接通两P与池 | 两P独立消费、不广播；RELEASE/复位所有权 |

standalone pool/M和P仍默认单片；P的SHARED_A默认关闭。pair包装层默认双片，因此旧pair逐周期比较显式选择A_WORDS_PER_BEAT=1。不能说所有无参数顶层行为都未变化。旧实验源保持冻结，新suite通过严格文本派生保留旧断言；历史shared32_native runner原样复现须使用历史固定commit。

S8每容器只有低64bit有效，S16使用全部128bit。因此32B是容器带宽；S8模式每P有效数据带宽为16B/拍。这次没有引入S32精度、扩展K上限或改变算术拆分。

## 3. 握手、边界和生命周期

每P两个有效位只接受01或11，共用ready、bank和format；每片有独立row/tile。一次valid[0]与ready握手原子接受整拍。M遇到10或两片目的row/tile重复时，将ready置低且不写任何片；生产者须修正输入，该操作数通道没有新增错误回执。

池按P优先、低片在前打包。两个容器只能来自同一64B FIFO头，不跨头拼接。头游标1可以送第1、2片；游标3或一片尾部只送01。row先递增、到边界后tile递增；rows=1时一次双片能跨两个tile。sent、done与FIFO弹出均使用本拍实际接受片数。

背压时FIFO头、有效mask、数据和标签保持稳定；新返回行不升级已呈现的beat。信用仍统计排队行及在途读，不增加隐藏缓冲。clear-all、clear-bank、START和执行bank锁对双片整体生效；另一bank仍可接受合法双写。

BEGIN、真实fill ACK、SEAL、epoch、对象边界、LOAD的A/B完成汇合、RELEASE等待外层LOAD结果消费以及cold-reset取消保持原合同。失败LOAD仍可能部分更新操作数，必须完整重装后再计算；本次没有增加失败回滚。

## 8. 下一步瓶颈与实施边界

当前证据支持先停止继续扩A端口。原生测试的供数明显变快，但部分LOAD与M/命令阶段未变；后续优先记录A完成、B完成、LOAD join、命令接受/完成、结果读回的真实时间，分别研究M服务和输入ACK流水。应在真实目标形状上比较，避免只优化微程序固定等待。

原完整图条件模型的最佳ideal服务已达到M_work成本，非Dot阶段约占47.47%；因此M计算服务、输入完成流水及非Dot算子是后续方向。输入ACK等待包含重叠与调度，不能直接等同DDR总带宽饱和。本轮只完成A32 RTL及上述瓶颈定位，没有改这些后续模块。
