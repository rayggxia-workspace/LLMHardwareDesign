# 第一轮：NExp批处理接入U

Issue247 / PR243；负责人Melodydt；2026-11-10，Asia/Shanghai。本文属于本次最多四轮提速迭代的第1轮。当前状态：RTL已形成，服务器功能、周期、旧体系吞吐和PDF交付尚待完成；本轮尚未计为完成。

## 1. 出发点：先减少已知的逐元素重复工作

主比较是旧PR241/Issue247体系的W8 decode、context512、八组上下文、16KiB。保持2P/1U、300MHz、17.1GB/s以及原trace。共享口起点3.23081074122 token/s；理想1R1W条件参考起点3.49616888299 token/s。目标5 token/s沿此理想端口参考层判定，两个端口层始终并列，不称当前四1RW硬件已达到该数字。

起点run15的主参考层总耗时286.0273867ms，其中Dot224.1015367ms，其他算子合计61.92585ms。NExp占18.4871833ms，canonical占21.49358ms，reduce占8.6253133ms，vector占13.25398ms。M工作与adapter工作包含重叠，不能再加到墙钟上，也不能把它们当可独立删去的延迟。

本轮36个NExp操作共294,912个元素。旧模型在完整 `vector_region` 后额外收取16拍/元素，合计4,718,592拍，即15.72864ms。因此本轮最多能替换的是这段额外计算费用，不能删除NExp的全部18.487ms，也不能免去原E包、S读写、cache或DDR。

固定Dot流量和现有串行关系，仅优化P/M而不改变其余阶段不能达到5 token/s；即使Dot达到字节/带宽下限，仍约为4.0 token/s。这使有明确逐元素重复开销的NExp成为首轮可验证对象。canonical的SiLU41步和Reciprocal128步缺少完整数值配方，本轮不靠调小这些系数申领收益。

## 2. 方案与复用来源

本轮复用PR241在 `189e43c77a6277955c1be54281b0d6b0b0d55c1f` 的 `nexp_batch_adapter` 候选。原作者已有独立批处理思路；本轮新增的是正式U接入、共享N所有权、明确S32容器适配、S读写/ACK与错误保护，以及和旧评价模型相接的实测校准。

旧标量参考每个值需要五条原N命令：清状态、统计输入x、统计0、结束统计、指数回放。其结果为 `exp(x-max(x,0))`。批处理先把正值变为0，然后以四条N命令处理一帧：清状态、统计n个0、结束统计、对n个截断后输入做指数回放。对每个S16输入，两者调用同一原生指数表和舍入规则，数学表达式相同。这里的exp指原N固定点查表/插值函数，不表示IEEE浮点指数；结果的原始整数编码保持。

保留一个原N核。新控制器在批处理内部四条命令及最终响应被接收前保持所有权，普通N命令不能插入。外层原 `ucf_s_compute_client` 继续持有事务直到实际S写ACK和DONE消费，不提前释放或把结果有效当作已经写入存储。

```text
N命令入口 -> 描述符检查 -> 原S计算客户端
                            | 读S的128bit操作数
                            v
                    pu_nexp_shared
                       | 普通N直通
                       | 批处理四命令
                       v
                    唯一原生N
                       | 结果/错误
                       v
                 原S写回 -> 实际ACK -> DONE
```

## 3. 新接口合同与兼容性

`pu_u_group` 新增参数 `NEXP_BATCH`，默认0。默认模式保留原N路径，不启用新opcode语义；测试比较原源码与参数默认0版本的命令、S活动、结果和周期轨迹。

开启后使用保留opcode15，并要求精确magic、一个S源、禁止direct转E。描述符错误在读取S前返回；数据未用lane不为零等错误在发出原N清状态命令前返回。错误不写目的S，不消耗原N统计状态。

| 模式 | 输入/输出 | count与标识 |
| --- | --- | --- |
| PACKED16 | 一拍128bit中最多8个S16，输出对应U16 | count1..8；0x4E455850 |
| NX32 | 最多4个S32容器，各取有符号低16；输出U16零扩展为S32 | count1..4；0x4E583332 |

NX32不进行免费S32饱和转换，也不是任意S32指数函数。已用容器的高16位按继承的旧packed假设忽略，因此0x00010000与0在该入口产生同一输入值。未用S32容器整项必须为0。报告和测试保留这种有损别名边界，不能把局部等价扩写为完整模型的精度证明。

opcode15明确为clobber操作：它会新建并覆盖原N统计会话。调用者不能在批处理之后继续此前尚未结束的normal统计流程，恢复普通统计必须先发新的op0。这里采用明确新ABI，避免复制第二个N来掩盖共享状态问题。

有效/就绪遵循背压合同。数据、count、模式在接受时锁存，不读取随后变化的输入元数据。结果被阻塞时保持稳定，复位丢弃未完成事务，不产生幽灵响应或写回。新opcode的非法描述符可以比旧保留opcode错误更早返回；默认0的兼容性与启用后的普通命令兼容性分别验证。

## 4. 具体修改及面积账本

| 文件/模块 | 本轮修改 | 作用 |
| --- | --- | --- |
| pu_u_group | 默认关闭参数、新opcode前置拒绝、N路径选择 | 正式U接入并保留实际S事务 |
| pu_nexp_shared | 共享核所有权、容器拆装和结果保持 | 普通N与批处理互斥；明确输入格式 |
| nexp_batch_adapter | 复用固定版本上游四命令控制器 | 合并逐元素重复统计工作 |
| rtl_iterations/round1 | 基线源码、生成校验、RTL测试、Slurm运行器 | 数值、生命周期、完整U和周期证据 |
| iterative_speed/round01 | 独立生成扩展、profile审计与16场景计划 | 保持旧评价体系和可复现基线 |

生产RTL没有修改原N指数表、归约运算器、E算术或16KiB SRAM。按显式状态声明，新增状态约402bit，其中384bit为三份128bit数据保持，约18bit为模式、count和控制；这是结构账本，综合可能共享或删除状态，不能把位数换算成已测面积。

没有新增乘法器、指数查表副本或第二个N。本轮属于增加少量控制/暂存的方案。迭代前完整源已备份到 `task/247-speed-base-a22e199c`，固定 `a22e199c1dce7d1037995a26f71f8b1358d038e0`。综合面积、布局布线、功耗与300MHz时序尚未执行，新候选不继承历史物理资格。

## 5. 验证设计

计算单元测试以未改原N的五命令序列为数值参考，覆盖全部65,536个S16值、PACKED16 count1..8、NX32 count1..4及INT32极值/高位别名/随机值。测试包括非法count、未用lane、响应背压、内部所有权、复位及恢复。

完整U测试使用实际S bank模型。正常结果必须在实际写ACK后完成并读回一致；错误目的地址的哨兵保持，非法描述符不产生S读写。覆盖原统计会话被显式clobber及新op0恢复、普通N/E程序、S响应被另一客户端占用、结果阻塞和中途复位。

每个配置使用既有三组初始化/seed。默认0的完整事件轨迹与冻结原U比较；启用模式的普通合法事务与新opcode时延分别处理，不强求有意提前拒绝的错误事务仍占旧周期。

周期分两类记录：compute-wrapper的接受到下一次可接受间隔用于模型的NExp额外费用；完整U同时记录输入S、计算、输出S/ACK三段，用于实际接入检查。模型不能把完整U的S开销和保留的vector_region重复收取，也不能把单独S16批处理响应延迟当作NX32服务间隔。

## 6. 旧体系评价方法

旧生成器、矩阵调度、cache和DDR实现不变，新扩展关闭时删除唯一新增 `iteration_study` 元数据后，整份RESULT须逐字段等于run15。W8/W16 decode512、W8 decode2048、W8 prefill2各取共享口和理想端口；先8个基线，再8个候选。

S32输入/S32输出的NExp按1..8元素分组。NX32真实帧最多4个S32，故n8收费为两次实测n4的接受间隔之和。费用由完整通过的RTL回执生成并锁定源码commit、日志SHA、命令与实际测量，禁止手填加速倍率。

独立解析发现prefill2的NExp是S16输入/S32输出，共36个操作、792,576元素。它不满足NX32输入合同，本轮保留完整旧路径及16拍/元素费用；不能把packed S16 n8的128bit输出当成原图需要的256bit S32输出。prefill候选整份旧RESULT应保持相同。

审计核对NExp元素/帧数、收费差额、非NExp算术、M工作、逻辑与总线字节、描述符、S服务/预约、cache、容量和端口设置。等待时序允许随真实计算延迟变化。另执行原kernel/validation/smoke，保留错误profile、缺测量、漏wrapper成本及非法CLI拒绝。
