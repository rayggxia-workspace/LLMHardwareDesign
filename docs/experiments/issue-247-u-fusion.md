本轮完成两个建议的隔离研究：相邻算子省去中间S物化，以及有限缓冲下生产/消费真正重叠。**原生RTL局部连续流显示重叠有明显收益；完整架构模型的收益必须另看占比，不能把局部1.34倍乘到全模型token/s。** SRAM扩容仍只保留研究，生产RTL没有新增修改。

## 建议一：把相邻算子的中间值留在局部寄存器

本次最小候选为256B转发寄存器，另列32B标签/控制元数据；只允许同一vector region、相邻E操作、唯一消费且只出现一次的S32中间值。每个算子仍在同一个E执行，保留原逐算子舍入/饱和边界，不把两次乘法变成无中间舍入的乘积。寄存读写16B/周期，吞吐容纳于原E服务时间；另实跑每包0/1/3拍的额外控制成本。原模型没有独立的指令分发费用，**本轮没有虚构省掉指令的收益**。

```mermaid
flowchart LR
    A[E生产算子] --> B[256B转发寄存器]
    B --> C[同一个E的消费算子]
    C --> D[最终结果写S并等待ACK]
```

原来的SiLU/RoPE/Reciprocal canonical vecpipe已保留内部packet，这些收益不重复计算；NExp、整行归约及P路径没有改。重复消费、跨region依赖和不匹配长度不套用此融合。

## 建议二：允许前后stage同时工作，而不只增加直连线

当前原生pair控制只有一个在执行/待响应上下文；一对N/E退休前不会接受下一对。直接传数据能省S事务，但不会自动形成跨tile流水。本次RTL候选增加136位/项（128位数据+8位标签）有限FIFO，N结果交给FIFO且n_done确认后才发下一N；E独立发起，从FIFO接A、从原S读B，最终S写回ACK后才释放E活跃槽。FIFO在A被E接管时出队，其槽可以重用，不能误写成‘FIFO槽一直占到ACK’。

|---|---:|---:|---:|
| 1 | 45拍 | 48拍 | -6.25% |
| 16 | 720拍 | 543拍 | +32.60% |
| 32 | 1440拍 | 1071拍 | +34.45% |

深度1/2/4全部相同，正常流最大在途数2；深度1已够本样例，不能推荐继续加深来追求未观察到的收益。两路线每tile都是3次S读、1次S写，仍竞争原单事务S仲裁器。每个目的槽逐个用不同B值读回，额外检查标签顺序、push/pop守恒、满队列保持恢复和held reset。单tile负收益说明需要短链旁路或按长度选择。

深度1/2/4新增FIFO原始数据+标签预算仅17/34/68B，另有指针、计数、调度状态和布线；这不是宏SRAM扩容，也不是综合后的实际面积。深度2可作为更长背压的候选余量，本次并未证明它比深度1更快。错误路径只定义sticky fault后全组reset恢复，正式流式取消/drain协议尚未验收。

## 重叠对整个trace的条件预测

重放按原始输入/E/输出实际阶段时间安排，单E、单输入输出控制器，FIFO深度1/2/4/8；每个packet输入缓冲768B、输出256B，另一个256B转发寄存器。D2数据预算2304B，加32B转发元数据及尚未定量的FIFO/4输入描述符控制。输入槽从输入开始保持到输出ACK，单E按原顺序，依赖、region边界、尾部和转发拥有权逐项检查。

prefill实际最大输入1024B：36个region/148608个packet不适合768B输入槽，**整段保留原串行时间**。4个小输入可在预算内处理，不能删掉第四输入。源事件仍全量记录，fusion本身仍按原顺序逐个读输入；768B限制仅属于重叠候选。depth1必须完整还原源region和整图时间。

以上D2/D4数值均是**条件预测**。DDR/cache每个阶段费用冻结为原实测值，所有非region时间也冻结；并发可能改变真实请求顺序、bank仲裁和cache行为，因此它不是新的并发全系统实测。联合模式由融合后的事件再独立回放，没有直接相加两项百分比；D8完整数据和所有A路线在[机器可读摘要](../../work/Melodydt/247/fusion/summary.json)中。

原生RTL的delay4样本反而比delay0流水周期更少，表明共享S请求相位很重要。该现象与轮转仲裁和N的连续两次读一致；没有逐grant trace，不把源码推导写成逐请求实测，更不把人工等待下64.88%的相对提升作为主结论。

## 下一步实现顺序与验收

1. 先保留已有直连路径，做固定短链的分离发起/退休与1/2项FIFO候选；短任务可走原pair，避免3拍启动损失。增加流长度/标签/目的槽正式描述符，明确最后tile drain、stall时valid稳定与归属。
2. 实装前补齐异常位置矩阵：N入队前/后、E接管前/后、写回前/后、reset与取消；证明不会把旧结果送给新命令。测试真实外部S响应背压、地址别名、目的冲突和尾块，不把本RMS→ADD一例当任意宏融合支持。
3. 然后实现完整SystemC并发仲裁，重新计算DDR/cache和S排队；用同输入同资源比较真实token/s，验证条件预测是否兑现。优先测prefill与实际热点链，decode仍须与P/权重瓶颈占比比较。
4. 若整体收益值得，才做同宏同库同约束的综合面积、时序与P&R。ready断开组合路径并不代表已通过300MHz；端口/SRAM面积或能耗均未实测。

## 生命周期、计时与公平性核对

生产 `project/rtl/pu_leaf_base/pu_u_group.sv:61–63` 将N结果有效和N完成拆开：直连数据接管前不暴露正常 `n_done_valid`。候选 `overlap_control.sv:66`、`:86`、`:109–111` 先通过真实 valid/ready 把结果交给 FIFO，置 `n_enqueued`，随后才确认 N done；`:78` 和`:106–107` 只在 N 无挂起时发下一条。因此 N 结果不是通过提前 ACK 或猜测运行时间来释放。

FIFO在E的 A 握手时出队（`overlap_control.sv:67`、`:92`、`:122`），**此 FIFO 空位随后可以复用**。数据已归 E 服务及引擎内部寄存器拥有，E的 `e_tag/e_taken/e_state` 活跃槽继续保留；只有真实 `e_done` 确认才退休（`:124–125`）。这不是“FIFO槽一直保留到写ACK”。生产 `project/rtl/pu_leaf_base/pu_compact_e_service.sv:112–120` 在算术结果后执行 WRITE_REQ、WRITE_RSP，再进入DONE，保证成功路径的最终存储响应已付费。

`overlap_control.sv:76–77` 要求全部目标N/E退休、无N挂起、E空闲、FIFO空才完成。FIFO输入ready只依赖寄存count与reset，满时不能同拍pop+push，复苏气泡也真实计入（`:16–18`、`:23–34`）。最大在途数为N已接受命令数减E已确认退休数（`:68`、`:105`），不把FIFO出队当成整个tile已完成。

bench的全局周期计数只在posedge累加，两个task均在negedge设置和读取起止；串行计时包含每对原pair的最终ACK，新流包含最后排空/完成ACK（`prepare_overlap.py:113–117`、`:124–142`）。人工delay=4在两路线都实际阻止四个可接管posedge：串行由`:108–113`保持direct_connect关闭；候选由控制器`:118–121`在真实E ready时递减四次，再允许A有效。没有把人为等待移出计时、使用负周期或隐藏写回。

单tile多出的3拍与新增加的真实边界一致。生产 pair 可以提前同时发N与E，让E先等A（`project/rtl/pu_leaf_base/pu_u_direct_pair.sv:32–36`、`:72–75`）；候选等FIFO非空后才经过E_ISSUE、E命令接受、A接管（`overlap_control.sv:114–122`），比已提前等待的旧E晚。该额外控制成本已经体现在45→48的实测中。

## 人工四拍背压与共享 S 相位敏感性

| tile数 | delay=4原direct串行 | delay=4 FIFO重叠 | 相对对应串行比值 | 同一FIFO的delay=0→4 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 49 | 52 | 0.9423× | 48→52，增加4拍 |
| 16 | 784 | 487 | 1.6099× | 543→487，减少56拍 |
| 32 | 1568 | 951 | 1.6488× | 1071→951，减少120拍 |

这组反直觉结果说明请求相位会影响共享 S 调度，**不能把1.6488倍作为无条件或无背压的优化收益**。主要结论使用前面的delay=0数据。

可核对的生产原因是：`project/rtl/block_local_s/block_local_s_arbiter.sv:34–43` 按next_owner轮转挑选，`:63`在接受时推进轮转指针；`:61–70`每次事务占有整个IDLE→SEND→RETURN流程直到响应被接管。它不能同时处理N和E请求。N读完第一个输入后马上请求第二个（`project/rtl/pu_leaf_base/ucf_s_compute_client.sv:61–69`）；E则须先接受直连A、SEND A，再请求S中的B（`project/rtl/pu_leaf_base/pu_compact_e_service.sv:83–85`、`:100–109`）。四拍门控会改变这两条请求在轮转点的竞争先后。

从状态机推导，下一N与当前E同拍接受命令时，delay=0使E的B请求与N的第二个输入请求竞争；首个N读接受后next_owner朝向E，E B事务可插入N的两次读之间。delay=4则让E的B请求稍后到达，下一N能先完成第二次读；E后移部分被N后续归一化计算覆盖。按当前普通S的采样/返回与仲裁合同，一个插入事务对应四拍（`project/rtl/s_sram/block_feed_s16k_sram.sv:1–4`、`:49–69`；arbiter`:50–54`、`:61–70`）。

此推导与所有实测周期精确一致：在测过的n=1/16/32上，delay=0为`48+33*(n-1)`，delay=4为`52+29*(n-1)`。因此delay=4在首tile增加4拍，但每个追加tile少4拍，总差为`4-4*(n-1)`，分别得到+4、-56、-120拍。**这是源码推导和结果的一致性解释，现有回执没有逐请求grant时间线，不能把推导中的每次授予顺序写成已记录的trace。** 不需要为报告追加实验；若后续优化S调度或评估更多delay，才有必要新增被动的逐请求/响应时间戳和grant trace，分开冻结验证。

## 资源代价与最小生产化范围

新增FIFO每项含128位数据和8位标签，原始数据/标签寄存预算为`136*DEPTH`：深度1/2/4分别136/272/544位，即17/34/68B；另外还有指针、占用计数和调度/归属状态。现有N输出寄存器、E内部数据寄存器仍在原生产宏中，不应重复计为新FIFO。这个预算不是SRAM扩容，不是综合后的精确FF数，也不是面积。run07只执行RTL lint、编译和功能/周期仿真，**没有综合映射、STA或P&R，不能声称面积、功耗或300MHz已通过**。

建议下一步最小实现为固定深度2的标签FIFO及分离发起/退休控制，保持单N/单E和原S不变；深度1作为本样本面积/延迟对照保留。深度2是容错调度余量候选，本次数据尚未证明其比深度1更快。生产接入前至少补齐：

1. **顶层命令与归属**：正式表达流的tile数、算子/参数、源/目的槽、标签或等价目的归属；命令valid在背压下稳定，消费者停顿不得撤销已发命令；最后tile必须drain。不能仅把testbench调度行为视为已接入生产控制层。
2. **错误合同**：当前候选仅成功路径验收；异常置sticky fault并停止新发起，恢复要求U、FIFO、控制器全组reset。需要定义N出错时未消费/已消费FIFO项、E已读B/已启动写/已ACK各阶段的取消或完成政策，以及已完成结果保留规则。不得将原串行pair的取消测试移作新流水的异常资格。
3. **地址和数值合同**：验证真实slot复用、输入/输出别名和destination冲突，覆盖不同数据/尾部尺寸/所支持op；保留S16 RNE/饱和及中间格式。此次RMS→ADD证明不能转移到原生S32路径、任意融合或其他block。
4. **协议回归**：保留本次全槽readback、tag顺序、push/pop守恒、满/空、背压稳定、末尾排空和held复位；增加真实外部S响应停顿、异常阶段切入与正式命令仲裁测试。
5. **实际资源与时序**：在同一宏/库/约束下比较候选与基线的综合面积、关键路径和必要的STA/P&R。ready分离避免了直接sink→source组合路径，但寄存数组mux、队列控制和新增扇出仍需实际收敛。

本次足以支持“原生生产宏可在不扩SRAM、不复制N/E的条件下，用小FIFO和独立控制提高连续RMS→ADD局部流吞吐”的候选方向；尚不支持整体网络速度保证或正式生产接入完成。
