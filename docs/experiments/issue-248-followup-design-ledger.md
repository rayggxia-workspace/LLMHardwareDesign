## 2. 已确定的数值方向与“尽量不用S64”的含义

采用总外存预算51.2 GB/s，不因102.4 GB/s曾出现10量级结果而改变目标。权重仍为INT8；A16是有符号16位激活容器，S32/Q16表示32位有符号整数按2^-16解释；总线128 bit是16 B传输，不能混同于每个数128位。

新生产profile不依赖S128运算/存储；持续部分和与投影上下文目标S32/Q16，Mid优先S32/Q16，另保留两遍重算选择。**已验证的是窄化后的数学合同和本轮质量范围；现有研究S128模块仍保留作旧参考，不算新profile的合格实现。** 精确Python大整数参考也不等于硬件需要同等位宽。

不能直接截断旧整数。旧方案为精确保留不同分组尺度的低位，四个FFN曾观测到68位Down前缀。新方案每128项完成A16×W8组点积，应用FP16权重尺度后RNE到持续状态格式，再累加；检查每个前缀的范围。128×32768×128=2^29，组点积用S32可容纳；它不能推广成任意全K都用同一S32整数尺度无条件精确累加。

G的S32×S32门乘可以有短暂S64乘积，然后立即RNE为S32；不再保存每个元素的S64 Mid。若要连短暂S64乘法也避免，需要分解/近似及新的质量与费用证据，本轮没有证明。系数mantissa乘积、插值、移位、RNE和溢出应分别推导实际暂态位宽，禁止为省事再次把整条路径默认为S128。

六组S32/S40/S48持续状态×Mid32/Mid64，均通过原预设部分语料门槛和16/16步teacher-forced top1检查。最省存储的S32/Mid32：公开参考PPL20.238568916037，候选20.250746496112；比值1.000601701638；top1一致99.512195%，最差序列logits余弦0.999977599273，无S32裁剪。原宽候选PPL20.250750754012，本样本几乎相同。

覆盖：Qwen2.5-3B全部36层、1025输入位置/1016 loss位置、context512的16步teacher-forced decode；MLP为新分组整数规则，其余投影使用冻结FP32筛查，Norm/Attention/KV仍为浮点。不是完整逐位整数LLM、长期生成或新硬件无溢出普适证明。

四个冻结实际FFN每配置8192个最终输出；S32/Mid32相对旧参考最大相对L2为0.000160532，最大绝对误差0.004638671875。两遍Mid的44032个归一化A16结果与原S64存储路径逐位一致。所有108个MLP投影本样本最大前缀需29位（含符号），不能把这一观察替代任意输入界限。

## 4. 舍入与Mid重算的全部时间消融

原9.24067472228 token/s为宽状态/原Mid基线。本轮S32状态+S32 Mid若不额外增加周期为9.25413041454；每组额外1/2/4拍分别为9.21564723269、9.17634436060、9.09170073009，较旧基线分别慢0.27084%、0.69617%、1.61216%。这些附加周期是假设，不是新RNE RTL实测。

只将Mid改为两遍重算，保持其他旧状态，分别为9.19420464273和9.22220597270，约慢0.50%和0.20%。两个变体首遍附加服务分别34/2周期，第二遍均计34周期；尚未RTL校准，不能将较快者直接当作零代价重放。

全部24种状态位宽、额外周期和Mid模式在[完整配置附表](issue-248-followup-all-cases.md)逐行保存，不只保存上述推荐行。S32和S48在该64 B端口模型中同速，不证明它们面积/能耗相同。

## 6. 四银行与流式直供的全部区别和代价

两者都从外存读取逐token权重，本轮都绕过普通S权重写入/读出：

```text
四银行：外存 → 内存控制器/请求前端 → 四个完整record银行 → M
流式：  外存 → 内存控制器/请求前端 → M的有限接收缓冲 → 128 B操作数 → 乘法器
```

这里的银行是权重缓冲，不是局部S内部四颗SRAM bank。四银行先等完整record填满，再读8个128 B M操作数；流式按收到的有效前缀逐包消费，消耗的数据空间立即释放。四个描述符/控制槽仍可存在，不等于有四份完整数据银行。结果写ACK和描述符生命周期仍需保留。

普通record为1024 B W8+16 B scale+48 B pad，共1088 B；head为1024 B W8+128 B scale，共1152 B。本轮流式采用header-first提议，总字节没有减少。原真实record审计的128 B包内是8个输出lane各连续16个K；新增合成布局检查采用提议的K-major顺序。**新布局/重打包与原真实W8、M RTL的逐字节联合兼容还未证明**，后续须固定N/K lane次序，不能只移动header就宣布部署完成。

数据请求发出前占接收预约，容量包含在途返回和已到达未消费数据；没有隐藏无限MC返回缓冲。128 B入口假定两条独立64 B写lane及独立128 B读出，双通道返回用beat tag/有效位管理连续有效前缀。64 B/拍×300MHz×3P=57.6 GB/s入口上限；128 B对应115.2 GB/s，仅为局部端口上限。双通道、每通道每周期2个64 B请求的发起上限另为76.8 GB/s，不能把名义DDR预算当成实际交付带宽。

完整41次trace均为36层、一个decode输出token；所有通过配置的逻辑读3365952512 B、写8191232 B、M命令3028352均与窄格式四银行基线相同。流式不是靠漏读权重提速；它没有减少逐token的W8外存流量。

## 8. 并发、FFN、底座与顶层互联不能遗漏的耦合

原同资源DMA排队/输入释放曾从5.953188到7.171451 token/s，主要是27.983512 ms排队和0.551933 ms输入释放改进；这来自原较早S32模型，不可与新9.216混用成一次同条件收益。请求并发需要地址/长度/事务ID/credit、返回定向、结果槽、源lease、ACK与reset/flush；没有增加PHY带宽的魔法。新流式宽入口还多了有效位重排，这项成本已被失败micro暴露。

FFN每次生成128个Mid，三P管理gate/up和分布式Down状态；同资源取消逐K全局屏障的旧收益3.876%已在原报告保留。有限FIFO只能处理短暂等待，不能替代Down状态。外存Mid、保存Mid、多批输出/重放、重算或分布式S的旧比较继续保留在原[FFN精度/存储报告](issue-248-precision-ffn-exploration.md)。本轮没有完成“完全取消算子屏障”的新联合RTL，也没有完成新S32合同下的所有重算/上下文数/外存容量组合搜索。

P/U/C/F/J继续是控制归属，独立功能宏、局控和必要适配器各自实现；不重新硬化五个大框。时钟/复位/供电、选定预连和模型可变数据路径逐条登记。M原生请求/接收缓冲、scale/RNE、G宽范围/小表、X来源选择器及仲裁都属于M1–M10新有源底座。M11/M12只连接预留真实端点，不能增加这些逻辑。顶层需覆盖同产品Attention/FFN/GDN等所用静态网并集，分时执行本身不消除金属。

当前3P是性能试验资源，不能推出五类九实例、母控/局控、真实SRAM与顶层金属已联合通过。固定FFN配方不等于#220动态映射/路径DP；还须导出完整数据/握手/确认端点、拓扑版本、源保持规则，并把实际布线/负载/时序反馈给综合。没有20%纯DP收益证据。

## 9. 参考项目的实际启发及比较边界

LLAccel冻结快照 `f7db8a22791a1ce9dc13e7c90b0b9b9386169aa5`，`gemm_engine.sv:123,136,519–522`：S32持续累加、临时S64系数乘积后缩窄S16/S8。OpenTPU冻结快照 `f237dab2f196855a59a083b1454786df8f01291f`，`otpu_tech_dsp.sv:61`及`otpu_mxu.sv:1588`：48位累加再转FP32。它们并非所有路径最高S16，不能仅按权重位宽比较中间结果。
