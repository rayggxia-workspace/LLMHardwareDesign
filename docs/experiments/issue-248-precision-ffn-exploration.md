# A8、原生 G 与有限 FFN 存储探索

2026-11-10，YUZE-LU；[Issue248](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/248) / [PR249](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/249)。隔离研究，不修改生产宏、其他成员分支/作业或预制底座结构。结论：**简单整行 A8 不是合格数值方案；G 的固定范围确实会损失重要特征；有限 SRAM 部分和在容量与数值上可行，但需要真实上下文换入换出服务。** 本轮没有新增合格的整机 token/s 或能耗结果。

## 输入与验证范围

只读使用既有 Qwen2.5-3B checkpoint `qwen25-3b-5defd279`，36层，hidden2048、FFN11008。它是浮点工件；本实验自行按输出通道 `amax/127` 生成对称 W8。**尚未确认用户最终采用的 INT8 权重包、尺度、zero point、分组及量化方法**，不能把这里的量化策略称为官方/实际 INT8 模型。checkpoint 各 json/safetensors SHA、输入 token、库版本和作业信息均在回执中。

两条旧校准文本、8条独立中英文短文本，最多64 token；实际100个输入位置，其中92个可计算 next-token loss 的位置，最后最多4个位置合计29个用来比较 logits。整图筛查中 attention、norm、KV 和大部分非线性仍为浮点；A8/A16是量化后再解码至浮点的质量筛查。不是 B1/context512 decode 性能，也不是标准语料困惑度、长期生成或全整数模型验收。

## A8 误差不是乘法器算错

以下均对相同 W8 权重比较。PPL仅是这92个短文本位置的诊断值；不能凭某个方案在此处更低就宣称质量提高。

| 激活方案 | 最低 logit cosine，相对 W8 浮点激活 | 29位置 top1相同数 | 短文本 PPL诊断 |
| --- | ---: | ---: | ---: |
| W8浮点激活参考 | 1 | 29 | 39.2172 |
| 旧两文本静态 A8 | 0.592785 | 17 | 98.1638 |
| 整行动态 A8 | 0.034219 | 28 | 78.4876 |
| 每32个输入一组，动态 A8 | 0.999074 | 29 | 39.0938 |
| 整行动态 A16 | 0.999705 | 29 | 39.4181 |
| 整行 A8，仅 down 改 A16 | 0.370136 | 27 | 89.4932 |
| 整行 A8，仅 down 改分组 A8 | 0.323855 | 26 | 85.9704 |

整行动态 A8 的观测裁剪数为0，但仍有大量非零输入量化成0。原因是一个尺度要覆盖整条向量：大幅值会撑大量化步距，小幅值就分不清。第一层 down 输入相对 L2约13.2%，若干层也在10%左右。逐层隐藏状态显示误差早期出现、后期放大；隐藏状态 cosine 很高仍可能伴随幅值偏差，不能只看 cosine 或 top1。

**只改 down 不足以修复**，其余投影及跨层误差也需要处理。按32输入分组在当前筛查中有效，但尚不是经过验证的整数硬件路径。其计算是

`y[n] = sW[n] × Σg (sA[g] × Σk∈g qA[k]qW[n,k])`。

不同组尺度不能忽略后把所有整数部分和直接相加。下一步需把尺度限制为可实现的乘数/移位或指数合同，明确对齐、累加位宽、元数据存储和费用，再做独立整数参考、RTL及完整语料质量。当前任意实数 group scale 的好结果，不能直接套用已有单尺度 MAC 的速度。

## 原生 G：输入范围和门乘输出范围均需处理

G 的 S16/Q5.10 表示范围约为−32至+32；它既不接受任意 S32 原始整数，也不接受任意尺度。G内 SiLU 的既定数学误差已经独立验证；本次发现的是**接入模型时的数值范围**。

整图独立筛查原生 gated G，约3963万输入值中，gate输入10次、up输入73044次、输出778次饱和。大多数 up 饱和集中在第1层。比例小不能证明影响小：某些重要通道即使只有一个异常值，也会贡献很大输出。

| G 接法 | 最低 logit cosine，相对 W8 | top1相同数/29 |
| --- | ---: | ---: |
| 原生 gated，gate/up/Mid均固定Q5.10 | 0.813144 | 23 |
| 原生 ungated，门乘保持宽位 | 0.937068 | 27 |
| ungated + 大正 gate 旁路 + 宽位门乘 | 0.992174 | 28 |

第三行在 `gate>8` 时使用原 gate 近似 SiLU(gate)，其他范围仍走原生 G 的量化/LUT行为。它只是定位范围问题的**新有源适配候选**，需要比较器、旁路选择与同步，宽位门乘还需独立算术资源。不是现有 G/E 已经具备，也不是可由M11/M12加金属实现。仍有误差，尚未通过充分语料/模型质量验收。

## 共同整数参考已做到哪里

新 `precision_oracle.py` 以 Python 精确整数执行 RNE、饱和和编译后的正S16乘数/0..63右移；650项独立 Fraction 检查通过。对四个实际 W8 FFN 输入建立：

`A16输入 → W8 gate/up整数点积 → 显式尺度转换 → 原生G算术 → Mid转A16 → W8 down整数点积`。

gate/up/down使用S40安全范围；每个K128部分和保持精确，不提前舍入。尺度发现暂由host float64完成，生成整数描述符后逐项执行；不把动态尺度发现当免费硬件。宽位门乘候选保留up整数累加值，用独立宽位乘法，和原生gated路径分开。

| 实际FFN切片 | gate/up/Mid饱和次数，原生gated | gated输出相对L2 | ungated+宽位门乘输出相对L2 |
| --- | --- | ---: | ---: |
| 第0层，Hello | 0/0/0 | 0.2194% | 0.0989% |
| 第2层，Hello | 1/17/2 | 96.9334% | 34.5859% |
| 第17层，英文存储文本 | 0/0/0 | 0.2852% | 0.1525% |
| 第35层，中文存储文本 | 0/1/3 | 13.3422% | 0.0446% |

对比基准是相同W8权重、原浮点激活FFN。第2层在宽位门乘后仍有严重误差，与gate范围问题一致；上表不是分离所有变量的完整因果归因。反之第35层保留宽位up/Mid明显缓解了饱和。

实际整数点积、转换系数生成了RTL向量，覆盖gate、up、两种Mid→down转换，均匀抽样并**强制纳入所有饱和值及最大幅值**。原生G重放含背压与逐包模式，逐位比较输出/饱和；转换RTL逐位比较RNE/输出/饱和。通过只能证明对应单元遵守本数值合同，不能证明整个模型质量或联合M/G/S/局控链路。

## FFN tile：容量可行不等于端口和协议已实现

在同一3P、每P16KiB候选上固定Ktile128、每P八个8列上下文，输出按8列循环分给3P，各负责688/680/680个输出。以下是软件容量/逻辑负载核算，不是布线后的周期模型。

| 方案 | 主要代价 | 当前结论 |
| --- | --- | --- |
| 完整Mid写外存再分批down | S32 Mid写44032B、总读1453056B；A16各减半 | 上下文语义可沿用；完整G/DMA链路仍未实现 |
| Mid只产生一次，部分和存私有S | S96每P峰值约12864B；S40/A16约7552B；每FFN部分和本地读/写各2088960B或870400B | 装得下；需要活跃部分和保存/恢复、真实ACK和端口仲裁 |
| 为输出批次重算Mid | 固定归属并保留1个生成上下文时13轮；gate/up权重额外541065216B/FFN | 可以省Mid驻留，却大幅增加W8权重读取；不是理想默认方案 |
| Mid分散留在3个私有S | A16每P约7360B，加本例scratch约11456B；S32本例约19328B | A16容量可行，需合法的跨P读取/重放路径；固定scratch假设下S32不够，不是所有调度均不可能 |

计算时另保留1536B工作区、双B缓冲与双A tile；实际底座中各存储的物理归属、字宽/填充、lane mapping、其他并发租约仍须按真实合同重建。上述候选不是穷举最优；可以继续探索其他组的S、不同tile/驻留分配。不能根据单个S装不下Mid就断言整底座不可行。

新有限down数值回放每次只保留128个Mid值，直到所有消费者完成才释放；每P最多64个活跃输出，其他部分和显式存入各自S。四切片×两种Mid路径均与全K整数结果逐位一致。每FFN S40部分和读/写各870400B，绝非免费；没有假设无限FIFO或无限寄存器。**验证覆盖down的有限部分和调度；gate/up生成与它的联合调度、M上下文save/reload接口、局控程序尚未实现。**

## SystemC及后续决策

本轮不把新数值路径直接塞入旧计时模型，仍拒绝整图原生准入。必须先固定分组尺度/旁路/门乘选择，再从共同整数任务生成包含以下服务的事件：尺度发现或host描述符到达、系数取数、转换器、G、宽乘、部分和load/store、S端口租约、数据到达与写ACK、上下文释放。

即使按实验四路转换器的理想II=1，64个值的一次转换也需16次发射；gated若gate/up/Mid共享转换器，至少48次发射，不能只计G的37周期/64值。尺度发现、元数据读取、S搬运及背压还需另计。四路80bit内部乘法的300MHz时序未验收，不能由仿真假设转移物理资格。

建议优先：**先验证可实现的分组A8或A16参考，再选择G旁路/宽位门乘或经验证的回退；并行实现一种有限部分和合同。** 数值/存储合同稳定后才联合SystemC计时和RTL校准，最后做新增有源逻辑的独立底座物理PR。能耗需相应服务/存储/外存的校准成本或功耗证据；当前 `token/s`、`J/token` 均不新增数值，不把CPU测试墙钟当芯片速度。
