## 第一轮：有限权重 bank 直供 M

权重仍从 DDR 读取，但不再先写普通 S、再从普通 S 读给 M。DMA 填两个有限 B bank，M 只消费已填满的 bank；同一 bank 的填充和读取共用单端口日历。bank 归属来自原两 token/上下文握手，保留原真实完成与 ACK；不是无限流、无限缓存或免带宽。

在原资源、S32 激活路径上，decode512 从 3.38396291561 到 3.67268820044 token/s，约 +8.53%。脚本逐项断言逻辑读写字节、M 命令与工作、KV 写入工作不变。收益来自绕过 S 的端口争用，**DDR 权重字节没有减少**。context2048、prefill 的结果也单独留存。

模型仍在 16 KiB 预算内为双 B tile 扣账；独立 RTL 当前做的是两个 128 B packet 槽。两者粒度不同，尚不能把局部 RTL 的拍数直接代入全模型。需要后续统一完整 P/DMA 的 tile/packet 组织。

## 第二轮：W8 固定，比较 A8/A16

新增 K16×N8 叶核，即每拍最多处理 16 个 K 方向元素、8 个输出列，共 128 个有符号乘积。权重始终为 8 位；A8 配 S32 累加，A16 配 S40 累加，完整 K 上限 16384，不在 K 片之间舍入。旧 S32 路径作为独立对照保留，不宣称新叶核支持 S32。

第一次尝试在每个 M tile 前重复转换 A，约降至 1.56 token/s，保留 run06 负结果。修订为按不可变的源张量转换一次：U 第一遍扫描求全 K 共同尺度，第二遍转换，写出新 A8/A16 对象并等待写 ACK；Q/K/V 或 gate/up 共用输入时复用该对象。**扫描、转换、S 端口、DDR 写回和之后的读入均收费**。原图张量没有直接改小；动态 Attention Dot、多行 prefill 不走这条新路径。

在 17.1 GB/s、两 P、统一 S 端口下，A8 为 3.48713832791、A16 为 3.59797405116 token/s，均未超过第一轮 S32 直供。K8/K16、64/128 B 每拍 bank 读取分别消融，结果接近，说明乘法数量不是这个配置的主要限制。

`w8_requantize4.sv` 单独实现四路 S64×正 S16 系数、右移、RNE 和饱和到 S8/S16/S32。它没有实现动态尺度发现、倒数/除法或系数逼近，也没有接成完整模型的整数链。

## 第三轮：带宽与新增资源逐项记账

测试 17.1 / 51.2 / 102.4 GB/s、两/三个 P、64/256 B DDR beat、固定通道归属/2 KiB 地址条带化。保留两个通道各自 32 credit、实际 beat 填充、有限队列与 S/bank 服务费用。64 B×300 MHz×2 的入口理论上限为 38.4 GB/s，设置 DDR=102.4 并不会让它自动消失。

原固定归属为 P0/P2 共享一通道、P1 另一通道；条带化按地址选择通道，统计、credit 归还和费用都跟随真实选择。它需要额外的多通道 DMA 路由能力，不能声称旧 DMA 已有。256 B beat 也需要新增宽入口与拆拍逻辑，填入 64 B/拍 bank 的费用仍保留。

增加第三 P 和加宽 beat 有时更慢：多 P 会增加 A 复制、S 争用和通道不均衡；大 beat 会增加小请求的填充和 bank 占用。最终摘要包含匹配的 S32 路径，避免通过换精度/换资源选择对照。

每 token 仅静态 W8 权重就约 3.086 GB；17.1 GB/s 的权重流理想上界约 5.54 token/s，尚未扣其他流量。10 token/s 至少需要约 30.86 GB/s 的**有效权重**带宽。提高 DDR 上限之后，系统实得带宽仍远低于该上限；原命令尾费、S 日历、算子屏障和非矩阵算子依然收费。模型 port wait 指标可定位问题，但不同线程等待会重叠，不能把 wait 相加当执行时间。

## 第四轮：让服务选择实际进入前沿扩展

`planner.py` 将以下选择交给同一个状态转移：K tile=64/128/256、上下文=1/8、缓存丢弃/保留旧 A/保留当前 A。状态记录一个不可变完整 A 对象，P 对称地保留同一对象，容量按每个私有 S 计算。热命中减少本次 A DDR 搬运；保留旧 A 则占用后续可用容量。每个前沿都重算费用，贪心和 DP 共用该函数。

这是带全算子屏障的有限研究：资源日历在边界清空，尚未做跨算子搬运/计算重叠、任意中间结果驻留、重算、非对称多 P 缓存或模型静态线束集合搜索。当前 DP **没有接替 #220 的完整图编译器**，也没有凭空实现五类 Block 的全图搜索。

小图独立枚举 4968 条路径，DP 与穷举最小估计费用一致；完整 decode 有 325 个 Dot 服务，前沿峰值仅 2。精确性只对声明的加性估计器成立。估计器省略详细 bank/credit/队列等待，不能据此声称全系统最优。

生成的 K/context/cache 文本由 SystemC 真正读取，命中跳过 A DMA，缓存容量扣除、保留描述符与 ACK 都收费。低带宽下 DP=3.65733290894、贪心=3.65587400413 token/s，DP 仅约 +0.04%，还低于固定第一轮配方 3.67268820044。prefill 两者相同。**这个负结果说明代价估计还没足够准确，而不是证明 DP 已有有效的大幅加速。**

同份计划还生成带 binding ID 的研究程序 IR 和部分操作数端点需求；明确标 `deployment_qualified=false`、`complete_static_net_set=false`。没有真实 pin、完整结果/控制/ACK 网集合，也没有 #180 母控/局控二进制 lowering。历史 run12 的 coupled bundle 记录了尚未同步的旧 DDR 位宽；最终 `report.py` 按真实 64 B case 重新导出并核对执行文本逐字节不变，旧回执不改写。

## 资源与预制结构

| 资源 | 本轮费用/资格 |
| --- | --- |
| 每个 P/U 的 S | 仍为 16 KiB，SystemC 峰值约束逐 case 检查；未修改已验收 SRAM |
| 新 M | 每 P 128 个 A8×W8 或 A16×W8 乘法器；8×8 累加寄存器分别 256/320 B，另有管线寄存器；面积与 STA 未测 |
| packet buffer | 每 P 两个 128 B B 槽、两份 A（合计 32/64 B）和 metadata，额外寄存器资源；不是现有 S 免费多出的端口 |
| 转换器 | 四路系数乘法/RNE，动态 reduction/系数发生与完整适配控制尚缺联合 RTL；模型已收费 |
| 第三 P | 改为三P可用资源预算；若底座原有则计其常驻资源/端口，若没有则需新增计算、S、局控/适配及DMA。不能作为同活动资源下的纯算法收益 |
| 高 DDR/宽 beat/条带化 | 报告名义带宽与实得 GB/s；控制器、PHY、片外芯片、IO 面积/功耗/成本未测 |
| M11/M12 | 只能连接冻结前已有的真实端点；本轮无新物理 pin/LEF/ODB/Liberty，没有布线验收 |
| 能耗 | 记录搬运量与服务工作计数；缺合格系数，J/token 明确为 null |

P/U/C/F/J 仍是局控归属，独立叶宏摆在共同底座上；没有重新包成五个大硬框。新增 bank、转换、mux、宽 DMA 入口都是需要在 M1–M10 中预制的有源电路。如果选择这些候选，需要新的叶宏/适配底座物理验收，不能在冻结后靠 M11/M12 加出有源功能。C/F/J 与原生母控本轮未改。

## 复跑、失败与后续

Windows 工作树保留 CRLF；旧生成链有精确源码 SHA 锁，应用 LF Git archive 重建。部署器锁定父输入及源 SHA，在本人新目录通过 Slurm 分配 4 CPU；native RTL 和 SystemC 都只在计算节点运行。命令见 [ARCHITECTURE](../ARCHITECTURE.md)。

run01 是工具 PATH 失败；run02 严格 lint；run03 是 C++ VlWide 接口；run04/05 找到有符号三元表达式导致乘法被当无符号的问题；run09 是新增转换测试的严格 lint。修复后复跑，旧失败原样保留；没有关闭检查让它通过。run06 的重复转换性能退化也没有藏掉。源码、工具、Slurm 终态、输入 SHA、原输出及 SHA 在离线包中逐项核验。

下一步优先统一 bank tile/packet 和真实 DMA/局控程序，测完整原生 P 的服务，再回填 SystemC；其次用每算子实测等待修正 DP 估计器，和固定配方同资源比。A8 需要另做数值方案，不能把简单截位当加速。更高带宽下若仍受 S/命令约束，先出有源硬件变更的独立 PR 再取物理资格。与 openTPU/LLAccel 的 FPGA 实测不能直接排名：需统一模型、上下文、精度/质量、总缓存、外存与真实执行范围。
