# Issue #55：可复用方法、输入和验证边界

本文件说明服务器实现的方法与实际适用范围，运行证据以 `results/summary.json`、进展文档和各不可变服务器索引为准。上一版方法在本次索引目录的 `previous_methods.md` 和既有 Git 历史保留；精简不删除实验记录。

## 1. 目标、边界与两个阶段

目标是让 openTPU small 与 llaccel_core 两个**完整硬件案例**使用同一套资源并集底座，仅改变许可层连接。当前主候选1/3，底座**未冻结**。现行 Issue55 主方案是 M1–M8 固定、M9/M10 及真实 via8_0/via9_0 定制；M11/M12 是尚未启用的独立后备。冻结前本人派生副本的必要内部迁线不等于冻结后可修改低层。

生成底座：输入完整资源、Block 尺寸/接口、代表性案例、工艺和预算，输出共同实例、位置/朝向、固定接线、接入点、PG/clock、余量和可追溯版本。使用底座：输入**同一冻结版本**与某目标连接需求，输出分配/调度、定制网络及独立功能/物理/电气检查。增加单元、移动 Block、改变底层预连线都必须形成新候选并重验，不能在两版中各自补资源。

openTPU 使用 otpu_asic_top、33个内部 SRAM；llaccel 保持 EPILOGUE_FUSION=0、DMA_MAX_OUTSTANDING=16。后者外部16个 SRAM bank、DRAM、主机参加功能测试但不计 core 面积。不能用缩小容量、通道、位宽、增加流水或放宽3ns约束换取通过。

## 2. 可替换输入与版本绑定

分开提供五类输入，拒绝把 HTML 图、颜色或端口位宽当完整可执行规格：

| 输入 | 必需内容 | 缺失时的处理 |
| --- | --- | --- |
| Block | 原语、精度/数值行为、吞吐/延迟、状态、存储容量/端口、逻辑协议/时钟/复位；尺寸、允许方向、PIN几何/层、OBS、PG/clock、资源数量及余量 | 显式待补，不自定最终团队规格 |
| 目标需求 | 计算/存储/控制实体、位宽/数值、连接、带宽/时序/执行次序、公共IO/闲置行为 | 硬件案例用 RTL/网表适配；未来 LLM 前端另接入 |
| 工艺 | 原金属栈、真实层/via、轨道/规则、LEF/Liberty、RC、可变层/范围 | 不编造可制造性；假设试验独立标记 |
| 预算与验收 | 资源/面积/层范围、不可重叠、功能参考、连接/DRC、时序及外部负载 | 未约束项目不能算通过 |
| 来源 | 原始版本、配置、输入/工具SHA、生产者提交/作业/receipt、依赖和结果 | 名称相同但身份不同必须重新资格化 |

目前实现仍有案例适配器：完整硬件分区、SRAM/宏接口、具体原始时序边界与工具平台路径。它们不能直接推广为任意 Block/LLM 编译器。配置示例在本目录 `configs/`；每次运行采用固定提交的独立快照，新增配置而非覆盖封存版本。源层名/坐标必须来自当前技术与数据库；未知外部 clock rise/fall、open37个常量输出负载保持 null，不填0。

## 3. 完整清单、分区与功能参考

完整清单从实际网表/数据库枚举实例、master、连接、端口、时钟、存储和几何；分区后建立双向归属映射并核对多重集合，发现遗漏、重复归属、跨边界端点失配即失败。逻辑模块边界不等于可直接移动的物理宏边界，报告中的 core 外 SRAM 不自动算作已放置在 core 内。

功能对照把原设计与相应派生版本绑定到同配置/复位/输入，比较实际输出、状态/操作覆盖；用实际执行的 case 数、任务数、比较字段和错误日志记录。已经完成的有限回归只适用于对应版本，不能沿用到新增 buffer、改变逻辑或不同物理版本。active+idle 组合还必须检查闲置资源的安全输入和无争用输出，编译通过不等于完整运行通过。

历史实测示例：open20例/87160行/2317514字段，llaccel六组180任务/243883行/17769493字段。它们是对应旧版本的有限证据，不是当前最终两案例验收。

## 4. 状态锥资格与逻辑变化

先精确比较状态标识、初态/复位/时钟/使能、端口和组合锥。严格图方法保守失败时保留反例；只有完整骨架/接口匹配且库单元语义明确时，才使用已资格化的库对称性归一化，不能凭同名寄存器宣称等价。未知存储/初态假设必须写出，限定结构证书不是上游RTL全等价、四态或 SDF 证明。

如果最终 .v 字节和全部八类资源/连接表与已验证 CTS 完全相同，可在实际身份破坏负例通过后限定复用其证书。实际92797对65545状态/168074锥采用此方法；后续92810增 buffer/resize 后**不能复用旧字节身份**，需新完整状态锥检查。原严格比较3696图差异仍保留。方法的失败反馈区分身份变化、未知库语义、真实状态/接口变化与单纯图重写，不自动豁免失败。

## 5. 布局、公共IO与固定预连线

从完整资源并集生成实例，按尺寸、通信权重、接口方向和通道约束产生有界布局候选；本案例采用明确候选和可核查的几何/容量检查，没有证明全局最优布局。坐标、数量、边界和允许朝向由输入决定，不应写入通用算法；当前未实现的任意朝向适配必须拒绝或列为待做。

布局验收检查全部矩形不重叠、合法位置、PIN可达、OBS/资源/面积范围和完整归属。公共IO先生成逻辑索引，再检查实体位置/容量/全部端点和实际连接；专属IO、常量别名、闲置输入驱动需要明确归属。增加驱动单元后，其放置、PG、接口、全量连接和共同资源版本都须重验。

固定预连线由完整代表性连接需求和公共端点规划，区分固定连接与各 case 定制需求。M8落脚→M9轨道、边界走廊和出口是候选路径/接入准备；**14059项固定连接目前仍为方案，不是已完成实际导线；每案例841项闲置扇出也未完成。** 不能将连通路径示意或累计线长算布线验收。

## 6. PG、clock和端点接入

真实 PG 接线必须从 master PIN 的实际图形和当前导体出发，检查每个新增单元的供电、合法通孔、异网接触和独立连接。曾遇到 PIN 边界/端点不可达时，反馈应是调整本人未冻结派生接入方案并重新检查，不扩大矩形覆盖其他网络或跳过电源引脚。

clock 使用共同输入、真实状态负载、CTS资源和最终线路，分别检查图传播与物理导体。CTS成功、估计时钟质量、实际详细布线、全量DRC、真实RC/STA是不同结果。真实状态负例用来证明检查器能检出断连，不能把时钟网存在当传播正确。共同有源资源最终必须纳入冻结清单，两 case 不得各自补时钟/控制单元。

## 7. 必要迁线与原拓扑复用

冻结前将原占用保留定制层的少量内部路线迁回许可固定层，输入当前真实原 DEF/native 元数据、完整目标网、真实层/via、端点、跨度和有界轨道候选。候选生成先做全量导体/cut预筛；冲突者明确拒绝，不进入数据库；通过者才实际修改派生 ODB，并由新进程读回核查。

现有原拓扑适配器仅支持指定的局部形状模式，不是任意网全自动布线器。末行via规范化曾导致 NETS 分号丢失、真实 DEF 读入失败；现有格式测试要求终止符保留和完整单网 record，实际失败/修正记录保留。几何文本规范化仍须通过真实native检查和真实RC质量门槛。

本轮新增 `same_plane_upper_projection_v1`：显式允许一个原M9水平段迁到相邻M8的非首选水平走线，保留两端原M8普通导线，只移除两枚原via8_0。要求真实相邻层、有限跨度、原DEF/native58形状精确往返、端点正面积接触、其他原始形状完全保持。候选精确52形状；额外/遗漏低层、改变via、错误接点和缺失结束符均必须拒绝。**该适配不是新增定制层或新逻辑，也不自行证明真实DRC/RC。** 92871预筛通过后，92874实际52形状/完整41网3边界/资源/非目标/原27记录保持及92883独立资格通过。92884/85真实质量显示相对e238 setup恶化0、改善37，但4个cap项恶化，候选拒绝。物理通过不等于质量或功能验收。

## 8. 实际物理资格与完整源检查

每次实际变更后，独立核对全部目标/必要端点、边界PIN、非目标导体、八类资源/连接表、实际修改形状与声明的精确多重集合。局部方案要保持全部41相关网络和3处边界连通，不能只查修改的一个网。原27条 native DRC 若逐条保持且新增0，表述为继承记录未增加，**不是零DRC或制造签核**。M9/M10为空也只是冻结前保留层条件。

大设计整片检查按完整几何extent、master PIN/OBS、所有源导体定义4096区域并保留guard/边界责任；区域化用于可恢复覆盖，不用于隐藏超范围对象。资格检查器须有真实缺陷/身份/报告破坏负例。92538的闭合 BATCH 仅为进度；全部4096区和源/时钟/控制/负例/规范化DEF条件闭合才有完整结论。

恢复仅采用自然终态后的完整、可信、同源检查点。实际封存批次、helper/engine/source/box合同全部匹配才继续未完成区域；原作业未结束不能重复提交同实验。92793是条件恢复链，不等于已取得整片通过。

## 9. 真实寄生、完整质量和有限失败反馈

只有独立物理来源资格通过后才对当前真实 ODB 提取。对比同时绑定真正原始参照、post-M8参照和最近保留父版；使用相同Lib/SDC/RC/提取frame、时钟、状态/端点和单位。输出完整 max/min 负端点及逐PIN cap/slew，而不只看 WNS 或违例计数。无有限 fanout 限值不能记覆盖通过；外部未给定负载/波形限制单列。

判定使用严格数值，不能自行设小差异容忍度或用“新增违例0”掩盖既有端点变差。来源通过、工具成功退出、测量完成、无新增几何问题与功能/质量验收分别标记。发生原始问题、当前新增退化、自建辅助不足分别保留，不把所有问题都归为继承。

实际反例：54形状路线物理通过，但相对e238多10个setup负端点、3个cap项恶化，拒绝。后续有限M7上方9600/11200两候选也实际物理通过，但分别29/83个setup负端点、各1个cap项恶化，仍拒绝；此有限轨道族结束，不作全局不可行结论。保留e238本身仍有相对原始200setup/26cap恶化，**也不是合格最终源**。较短导线/较少via未保证较低电容或较好时序。

本轮四个cap退化引脚先经真实native端点唯一映射，再比较已提取SPEF的命名记录多重集合：别名/记录顺序规范化，单位及内部节点身份保留。92900发现两版目标网对四网都没有直接耦合记录；92902发现四网CONN/RES一致而实际CAP值改变，不能仅归为STA显示/排序噪声。合成改R、缺C、截断及别名/顺序控制通过，仍不作排他因果或容忍度豁免。

最慢端点切换时，从最新实际完整负端点选取路径，同名端点还须匹配起点及有序pin/edge arc；不同路径不可直接相减。原始和pre-M8封存报告可在SHA/解析器/选取身份一致时复用，只实际测量新当前。缓存必须绑定ODB/native/SPEF及helper/parser/所选集合，并用真实破坏负例验证；旧schema/parser失配明确拒绝，不重新命名掩盖。当前缓存适配仅验证有限内部网，不推广到未知输出端口或任意Block。

## 10. 执行入口、依赖门槛与资源

`flow.py` 提供 inventory、integrate、prepare-base、route、verify、replay 入口，但**并非每个阶段已经实现为最终流水线**。先用 `--help` 和实际适配器支持范围选择输入，不虚构命令。

- inventory/integrate：清单、完整分区及现有案例适配。
- prepare-base：共同布局、PG/control/clock/IO/接入及固定预连线等已有子步骤；当前 freeze 明确拒绝，因为先决条件未闭合。
- route：当前只转发 retained_parent、added_cell_local、qualified_current_retained_parent 固定父层连接；**不代表最终两完整case定制布线已实现/运行**。
- verify：依具体检查器进行独立核对，结果范围以receipt为准。
- replay：当前仅原生清单重放，不能描述成全流程一键复现。

现有专用程序/配置是这些入口的下游适配器，避免仅复制名称维护第二套方法。完整迁线、资格、RC、状态与连接用独立程序串联。Slurm afterany仅唤醒；现有 `continue_after.py` 等须再核验精确 submission/提交、实际 COMPLETED0、receipt、输入/配置哈希，前驱失败则不做下一项证明。排队记录不算结果。92832/33实际因容器缺sacct而未启动子检查，不是已验证的上游状态拒绝；修正后宿主采集实际accounting、容器验证同job/source/config/producer/freshness。92904实际拒绝FAILED92810、未启动子程序，5合成状态负例通过；92908实际只读成功分支闭合；92937/38启动子程序后因目录参数错误退出，保留证据并在r02修正。

所有新作业4CPU；native多线程最多4，BLAS1，独立任务并行时总进程/线程不超分配。单线程步骤可仍只用约1核，报告实际CPU时间/墙钟和均值，不声称4倍加速。原活跃任务保留，不无检查点停止/重提；缓存、临时文件、构建和输出均位于本人任务根。
