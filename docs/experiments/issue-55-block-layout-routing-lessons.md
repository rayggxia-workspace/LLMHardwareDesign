# Issue #55：Block 划分后的布局布线问题与处理经验

关联 [Issue #55](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/55) / [持续草稿 PR #58](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/58)。负责人：huangpingyang04-lgtm。

本总结依据 **2026-10-29 18:00（UTC+8）** 只读核查到的主任务记录；是经验归纳，不是新增物理实验或阶段验收。后续状态以主任务最新不可变索引和实际 execution.json 为准。本文引用的脚本部分仍仅在服务器工程版本中，不能据此宣称 GitHub 已包含完整可复现输入或全部后阶段源码。

**最重要的经验：Block 的矩形放得下，只是第一关。还必须让真实引脚接得出来、电源和时钟接得上、导线不短路，并且不使时序或负载变差。当前并没有随意搬动原有计算单元来解决这些问题。**

## 1. 先说清楚哪些东西可以调整

当前完整范围是 openTPU 的 otpu_asic_top（含原 33 个内部 SRAM）和锁定配置的 llaccel_core（EPILOGUE_FUSION=0、DMA_MAX_OUTSTANDING=16）。ACT、MXU、GEMM、VECTOR 之外的控制、状态和其余资源归入两个辅助区；llaccel 外部 16 个 SRAM bank、DRAM 和主机参加功能测试，但不算已放在 core 内的存储体。

当前主方案为**冻结后 M1–M8 固定，M9/M10 与真实 via8_0/via9_0 定制**；M11/M12 是尚未启用的独立后备。候选仍为 1/3，尚未冻结。不能把早期讨论的 M11/M12 方案与当前验收范围混用。

| 对象 | 处理原则 | 本任务已经做了什么 |
| --- | --- | --- |
| 原有功能、状态、存储和 TAP 单元 | 本轮受保护，不能为了布线随意移位、删除、换逻辑或改流水 | VECTOR 替换试验独立读回确认 733520 个受保护原实例的 master、位置、朝向和状态保持 |
| 新增 buffer、tie 等基础设施 | 冻结前，可在授权的派生版本中选模型、找合法位置；必须检查供电、连接和行为 | 做过模型容量筛选、实际 ROW/site 搜索和新增单元放置，不等于最终电气通过 |
| 物理填充单元 CORE_SPACER | 也是已有实例，不能自动当空白或任意删掉；保留 PG 几何要求 | 用户单独批准具名 26 个填充实例的有限替换；无其他填充单元豁免 |
| 整个 Block 的位置、朝向和间距 | 冻结前形成共同候选；变换必须同时作用于实际 PIN、OBS 和相关几何 | 既有共同布局检查覆盖六块及全部端口，并核查不重叠；不是只看示意矩形 |
| 冻结后的内部单元、低层线和预连线 | 两案例必须完全相同；若确需改变，形成新底座版本并重新验证 | 当前尚无最终冻结版本，不能声称已完成两完整案例最终适配 |

**通俗地说：可以在装修定稿前安排新增插座和接线盒；已经要求保留的机器不能随意挪走。定稿后，两套用途只能改约定的上层接线。**

## 2. 问题—办法—真实结果

### 2.1 逻辑上分好模块，不等于物理上就能直接拼接

模块端口可能穿过原来的共享逻辑、存储或控制边界；漏掉辅助逻辑，会出现“核心块都在，完整机器却不能工作”。报告中的模块颜色和端口位宽，也不能替代完整网表、实际几何或吞吐说明。

处理办法是建立完整资源清单和唯一归属，保留跨块网络、位宽、驱动方向、时钟、复位及存储边界；从原生数据库核对每个端点。已存在的有限完整功能回归只对对应版本有效；后续增加 buffer 或改变实际连接后仍须复核，不能直接沿用旧结果。

### 2.2 Block 没重叠，但引脚仍可能被挡住

线和通孔有宽度、包围、间距和阻挡；一个引脚上看起来能放一个点，并不代表完整通孔能放进去。通孔还可能碰到邻网导线、另一只引脚、电源手指或单元 OBS。

处理办法是用**真实 PIN 多边形＋完整技术通孔形状**检查，先做完整固定几何预筛，再写入新的数据库做原生检查。要分开判断：

- 本 PIN 是否有真实金属接触；
- 完整通孔的金属落脚和 cut 是否满足技术定义；
- 是否侵入其他 PIN、PG、OBS 或固定线路；
- 接出后能否沿许可层连接到最终目的地。

只要求新增落脚金属与本 PIN 正面积接触，和要求落脚金属完全藏在单个 PIN 矩形内，是不同的候选生成方式。前者仍必须遵守真实通孔包围和所有外来间距，并经实际 DRC 资格化；不能把放宽候选形式写成放宽工艺规则。

### 2.3 想加缓冲器，却找不到真正空闲的位置

VECTOR 在保留全部原实例（含 411821 个物理填充单元）时，原有 ROW 内没有可放该研究缓冲器的空位。只看布局图片上的颜色空隙会误判。

实际办法是先查完整合法行、site 间距、master 尺寸和占用区，再给出具体回收清单，获得用户许可后执行。此次仅将**具名 26 个 CORE_SPACER 替换成 26 个 BUF_X4 和 53 个补齐填充单元**，最近放置点距对应驱动最多约 2.8 μm。93277 实际放置、拓扑和独立保持性读回通过，完整实例数 733599；数据库明确标为 UNROUTED。

填充单元也带电源金属。逐项比较发现 3 处共 6 个原 M1 电源矩形必须显式保留，不能因为新单元有 VDD/VSS 端口，就假定原供电几何自动保留。后续 93287 的 placement 和 VDD/VSS 拓扑检查通过，但不是 IR/EM 或完整信号布线证明。

### 2.4 位置离驱动很近，输入引脚却接不出来

这是最具体的一条局部修复经验。各次试验使用同一批获批位置，不是搬动原有计算单元，也没有增加主要底座轮次。

| 接入候选方法 | 实际结果 | 能说明什么 |
| --- | --- | --- |
| 严格引脚落脚要求；改试全部 9 种真实单 cut via | 18/26 个缓冲器通过预筛，8 个失败 | 仅换通孔型号还不够 |
| 允许本 PIN 正面积接触的新增 M1 落脚 | 20/26，通过之外仍有 6 个输入受阻 | 部分失败来自候选接触形式过严；仍非原生 DRC 通过 |
| Y 坐标按真实制造网格搜索，X 保持实际 M2 轨道 | 仍是相同 6 个输入失败 | 更密地试位置并不能消除固定障碍 |
| 有界短水平 M1 引出，再落 via | 22/26，仍有 4 个输入受阻 | 短引线能绕开部分占用 |
| 最多一个拐弯的有界 M1 引出 | 26/26 找到候选，所选引出最长 660 DBU＝0.33 μm；缓冲器位置变化 0 | 找到了下一步值得实际验证的接入方案 |

93342 又独立读取**全部 733599 个实例及 8896902 条源几何记录**，检查全部 52 个 A/Z 接入候选与保留导线、cut、实际邻近 PIN/OBS 及候选彼此，没有发现接触或保守最小间距冲突。此检查没有实际创建通孔，不是完整布线或全规则 DRC。

核查时 93344 正在新副本中执行实际 first-via/M1 引出写入、26 个区域的原生 DRC、独立 52 路径读回、真实异网短接负例及完整非目标保持性检查；尚无闭合验收结果。它即使通过，也只覆盖局部第一段接入，后续完整数据网络、RC、时序和功能仍要验证。

**经验：先改变新增引出线的走法，可能比移动单元代价更小。当前这 26 个缓冲器保持原获批位置；没有证据支持“已经移动原有零部件并解决全部布线”。**

### 2.5 工具说有接入点，仍不能当作已避开固定导线

全设计 native pin_access 完成、引脚没有缺 AP，并不自动证明在“全部旧线路固定”的约束下可放入所需通孔。

此次独立读回 52 个 preferred AP，核对实际引脚、网络、坐标帧和 UP 标志。在每个首选点试放 9 种真实技术 via 的几何预筛中，34 个点有候选，18 个点没有。它们是**假想通孔形状的冲突**，不是实际制造了 18 处短路，也不是证明 18 个引脚永远不可布。

坐标也不能重复翻转：本次原生 AP 点已经含特定朝向的局部坐标效应，须按实测帧转换到全局，再对照真实 PIN；R0/MX 的处理不能只凭名称猜测。当前 Tcl 接口有嵌套对象返回不透明指针的限制；接口读出失败须单列，不能把它当作没有 via 或设计物理失败。

### 2.6 满足单点间距的布线网格，也可能根本不连通

此前公共控制网络的一个保守交错点集虽然避开了 cut 间距，却把 M7/M8 搜索图分成两组，A* 找不到跨组路径。这反映的是候选图构造问题，不能立刻下结论说资源不够或必须改用后备金属层。

主任务已有的修正是增加满足同样间距约束的桥接行，检查图的连通性，再进行实际连接、独立读回和断线、短接、缺 via、错网负例。该经验来自既有 92071/92078 失败及 92085/92087 记录；本次只读归纳，没有重跑这些实验。

### 2.7 路由器报零错误，fresh 检查仍可能失败

AUX 的 124 个目标网已连通，61 个公共物理岛及 579 个原引出形状保持，目标对完整电气节点的异网接触检查为零，但 fresh 整片原生 DRC 仍报 **45 项 M3 间距问题**，整体仍是 FAIL。

处理办法不是删除报错或挑一个有利网格：保留同一完整源，控制 GCell 网格、guide 和路径状态，独立对比真实资源与导体几何，并查看报错位置。当前观察包括：

- 同样源几何在不同检查网格下出现不同报错集合，说明检查上下文会影响报告；
- 45 个报错框被实际同网 M3 金属并集覆盖；有限桥/断桥/短接夹具能正确区分相应缺陷，但不能替代整片资格；
- 完整 DEF 文本保持检查失败的历史结果仍保留；93315 的独立完整 native 比较另外证明验证副本的资源、PIN、导线、通孔和 virtual 图相同；
- 基于这项独立证据运行的 93336 完整源路径状态对照，仍得到与原结果完全相同的 45 条报错记录。**只改 FIXED/ROUTED 状态没有解决问题。**

上述结果不构成“已证明是假报”、继承豁免或物理验收。当前新 AUX 源的下游 RC、回装和完整回归仍未获放行。

### 2.8 线更短、通孔更少，也可能使电容或时序变差

主任务记录中，若干 M8/邻层迁线路径在物理保持和局部连接检查后，仍出现相对参照的电容或 setup 退化，因此被拒绝。保留来源本身也有尚未消除的新增/恶化问题，不能把它当作已合格底座。

处理办法是使用**相同 Liberty、原 SDC、真实提取 RC 和逐端点身份**比较，保留每个 pin 的 cap/slew 与 setup/hold 变化，而不是只看总错误数或线路长度。缺失的外部 clock 上升/下降时间和 openTPU 37 个常量输出负载保留为未确定，不能填 0。更强的 buffer 也有更大输入电容和面积，必须重新测量。

### 2.9 预连线清单和 guide 仍然不是导线

14059 项固定连接的清单、轨道方案和 guides 是输入；只有实际数据库里的导体、完整端点连通、短路/规则、资源保持和质量检查闭合，才算完成对应布线。核查时完整父层 DRT 作业 93130 仍在运行，不能用中间日志或局部成功替代最终结果。本次总结不停止、重启或重复提交它。

## 3. 如果以后确实需要调整 Block 内部零部件位置

下面是后续工程操作的判断顺序，**不是本次已经执行的全部动作**。

1. **先锁定可调整清单。** 区分受保护原单元、新增 buffer、填充单元和固定连线；不允许工具默认把整个 Block 重新布局。
2. **先看能否只改接入。** 保持单元位置，尝试真实 via 变体、合法接触点和有界短线/折线；这正是本次 VECTOR 的实际经验。
3. **需要移动新增单元时，搜索真实 ROW/site。** 从对应驱动或目标端点附近选点，检查 master 尺寸、朝向、site 对齐、占用、PG、PIN/OBS 和接入走廊，不能只按欧氏距离选最近点。示意约束为 `x = row_start + k × site_step`，实际还须满足该行的朝向和高度。
4. **没有空位时先形成具体回收方案。** 列出具名填充实例、拟新增单元、补齐碎片和需要保留的 PG 金属；超出已有许可须取得授权，不回写原始源。
5. **每个位置候选都检查完整引脚及邻域。** 同时检查输入、输出、VDD/VSS、所有 via 的上下层落脚/cut、其他固定导线及邻单元 PIN/OBS。放得下不代表接得出。
6. **实际写入后独立读回。** 校验 master、位置、朝向、端点/网络和原实例/非目标导体多重集合，使用真实错位、断线、短接等负例验证检查器。
7. **重新提取并验证。** 复核供电、完整数据/控制/时钟、DRC、RC、setup/hold、cap/slew 和对应版本的功能；不通过则拒绝候选。
8. **到冻结阶段才统一定稿。** 底层或有源资源改变后，两个案例使用同一份新底座重验；不能各自移动一套位置后再声称底座相同。

如果要移动受保护的原功能单元，或重做整个 Block 内部布局，那是超出当前这项有限替换的另一种变更：必须先明确授权和资源/行为保持合同，形成新派生版本，重新检查内部连接与时序。本文没有证明这种重布局已经完成。

## 4. 给后续 Block 设计者的输入建议

这些是根据失败整理的需求建议，尚非团队最终规格：

| 应交付或预留的内容 | 原因 |
| --- | --- |
| 真实 PIN 多边形、允许接入层、via 规则、OBS 和合法朝向 | 端口名和一个中心坐标不足以判断能否接线 |
| PG/clock 锚点及完整内部电源/时钟边界 | 逻辑接上 VDD/clock，不代表物理接通或电气合格 |
| 合法行、site 与可用的 ECO/缓冲位置和资源余量 | 避免全部位置被固定填充后无法做必要驱动修复；余量数值仍需实验确定 |
| 输入电容、输出驱动上限、延迟、slew、时钟/负载合同 | 接入路线改变后必须能判断是否电气退化 |
| 区分不可变内部几何和允许调整区域 | 防止工具偷偷移动原单元或重写低层，破坏共同底座 |
| 边界走廊与可达的固定层接入点 | 降低“块不重叠，但 pin 被围住”的风险 |
| 外部存储、复位、握手和闲置输入要求 | 避免只验证计算核心，遗漏完整机器的控制与状态行为 |

可复用流程应是：**完整清单 → 固定/可调整合同 → 容量与连通性预检 → 候选布局/接入 → 实际数据库实现 → 独立保持/连接/规则检查 → RC/时序/功能 → 冻结 → 两案例定制复核**。其中未知项显式报错或标为未验证；本总结没有新增一个已经验证的通用算法实现。
