整块 `store82` wrapper 暂作显式黑盒边界：16 KiB、128 bit、1RW。`store_reset` 保留实际 `reset || soft_abort`，没有用顶层 reset 替换它；只在证明相同后省去独立 store clock 端口。缺少目标 SRAM 宏、真实目标 PVT、上游驱动阻抗和 LVS 条件。平台自身说明为不可制造研究库。因此即使后续研究库布线通过，也不能写成完整 Block 制造验收。

## 引脚容量与控制树：已经能指导后续电路设计的发现

当前整合核带完整观测信号，共有 551 个输入位、1,818 个输出位：

| 接口类别 | 输入位 | 输出位 |
|---|---:|---:|
| 命令与执行控制 | 116 | 12 |
| cfg 读写接口 | 141 | 130 |
| 外部数据/epoch 接口 | 162 | 66 |
| SRAM wrapper 切分接口 | 130 | 142 |
| 纯观测、计数器、debug | 0 | 1,468 |
| 测试背压控制 | 2 | 0 |

纯观测占输出位约 80.75%。单侧 pin 容量失败反映当前完整仪器化接口的成本，不能据此断言算术 Block 本身无法布局。四边候选保留所有 2,369 个端口位，仅改变明确登记的 pin 分配策略；工具生成的实际 pinmap 已被冻结，且修复及 CTS 的每一位几何均独立比对相同。若之后设计 CSR 或串行观测接口，必须作为另一个硬件候选，重新记录逻辑、周期与覆盖，不能在本轮静默删端口。

原始最差路径从 reset 经 NOR2_X1 和 INV_X1 到 DFF，前两级分别扇出 2,118/947、负载约 3,441.22/1,416.65 fF。裸控制树的负载和 slew 严重超限，最差 setup 约 −224.91 ns 不代表算术固有延迟。优先在原资源预算内修复控制树，再评价真实计算路径。理想时钟另有 4,019 个接收引脚、约 3,816.66 fF 的引脚负载；这还不是 CTS 或真实时钟输入驱动通过。

## 全局布线首次结果与待闭包项

93 的一次固定 GRT 配方完成 41,303 个网络，实际各层 congestion overflow 均为 0，
单元与连接不变，`final.v` 与 C3 逐字节一致。原配方允许 M2–M10，实际此批
M8–M10 demand 为 0；不能据此声称已满足成员的固定底座、M8 pin 引出或真实宏条件。

接收仍独立等待，不因无拥塞而跳过时序。
