## 1. 目的与本轮范围

从已有 openTPU small 和 llaccel core 的 RTL、接口及物理结果出发，回答两个连续的问题：先确定哪些计算、状态、局部存储与控制应封闭在预制 Block 内；再检验这些固定 Block 能否在明确端点、轨道、时钟和存储供给约束下支持不同计算图。

普通“Block 内实现＋顶层布线”是工程准备。它允许顶层重新布局、插入有源单元和自由选线时，只能证明常规分层实现可行，不能直接证明少量金属／通孔定制的预制底座可行。后续必须另行冻结底座，限制可变化资源，再做多计算图对照。

本轮先选规模较小的 llaccel `vec_engine`（实例 `u_vec`）验证硬化、抽象视图生成及顶层集成流程。该 pilot 不代表 L0/L1 比较已经完成，也不代表已经实施所有 openTPU 候选。pilot 的运行、排队、成功或失败状态，以 Issue #7 关联的实际日志、结果索引和交付回执为准；本文不把计划写成测量结果。

用户已授权使用原集群。实验在独立任务目录进行，复用经核对的源码和既有工具；不覆盖历史结果、不修改参考包。本轮不重新生成完整分析报告，也不例行审查或重算 `ref-project/`。

## 3. openTPU 候选边界

### 3.1 各方案共同保留的资源

- `u_mxu` 保留取数控制、输入／结果 FIFO、计算阵列、FP32 后处理和任务状态，不能只把乘加器称为 MXU Block。
- `u_vpu` 保留双操作数、写缓冲、复合函数与归约、地址和流水控制；首轮不拆 lane。
- 共享存储 Block 包含 `u_tmem` 及其必需的端口汇聚、bank 冲突判断、请求保持和访问授权。现有 `otpu_slice.sv` 的读写端口汇聚位于约 580–595 行，bank 仲裁从约 601 行开始；这些顶层逻辑必须按本次源码逐项定界，不能只包住 `u_tmem` 而把长组合授权环留在顶层。
- `u_seq`、`u_dma`、collective 接口及其余 slice 管理／外存接入先保留系统级职责；不把原来的 `SLICE_TOP_LOGIC` 统计类别误认成单个现成 RTL 模块。
- 每个 Block 明确时钟、复位、使能和授权分发边界。报告记载 VPU 的 1 bit `gnt` 经 803 条物理 net 分发，说明少量控制 bit 仍可能有显著物理开销。

### 3.2 三种粒度

| 候选 | 预制 Block 划分与应合并的状态／控制 | 跨边界端口与风险 | 要回答的问题 |
| --- | --- | --- | --- |
| O0：ACT 与 MXU 分离 | `u_act` 独立；`u_mxu` 配套已有 `otpu_act_link` 接收缓存、串拆控制、块范围与版本失效状态；`u_quant` 独立 | 已有原型为 128 bit 载荷，另有 valid/ready、块范围、失效及读推进控制；不能把 128 当作全部接点。必须保证 MXU 一行内部的连续消费 | 缩窄接口和本地副本的代价，能否优于绑定计算与 ACT？ |
| O1：ACT＋MXU | 合并 `u_act + u_mxu`，将 ACT 读地址／选择控制和 512 bit 激活＋128 bit 尺度读出内化；`u_quant` 留外部 | 量化写入、权重／尺度读取、MXU 结果、任务命令和共享存储授权仍跨界；不得只计算被藏入内部的接口收益 | 局部复用边界内化后，真实端点、布线、时序、面积和能耗如何变化？ |
| O2：量化＋ACT＋MXU | 合并 `u_quant + u_act + u_mxu`，连同量化 row buffer、ACT 写入／复制控制和 MXU 局部流水；全局调度仍在外部 | TMEM→量化器多路读、权重／尺度外存访问仍需供给；粗 Block 可能降低共享机会、增加任务闲置 | 再封闭一段数据复用链，是否值得额外资源绑定？ |

优先把 O0/O1 做成同资源物理对照，再考虑 O2。报告显示 MXU 输出逻辑与 TMEM 输入选择器可以交错放置，同模块的 SRAM 宏又可能很远；新硬宏必须从 RTL／层次边界重新实现，显式确定引脚、阻挡、通道、时序和宏朝向，不能从原扁平图直接裁块。

### 3.3 已有 ACT—MXU 实验及未完成项

以下均为 2026-10-20 历史报告记载，未在本轮复核：

- 固定配置下，MXU 有效推进时消费 512 bit 激活和 128 bit 尺度；含读地址／选择控制共 684 个逻辑信号位。逻辑位数不是后加工接点数。
- 已做 171 次 RTL 仿真：13 次原始 RTL、143 次时序注入、13 次真实 128 bit 串行通路、2 次不同激活输入的缓存失效对照；报告记载完整 TMEM、DRAM 状态与 ISA 逐位一致。
- 真实 128 bit 通路配本地激活缓存，单次 MM 吞吐为原配置的 87.7%～96.0%。64～640 bit 宽度扫描主要是等待注入；软件拆包重放也不是多种宽度的真实 RTL 串行器验证。
- 原型固定预留 2,560 B 接收载荷缓存，并有发送／接收暂存、宽读输出寄存器和控制；缓存按寄存数组描述，尚未确定 SRAM 映射。原始合并方案没有同等闲置适配资源，物理等资源比较尚未完成。
- 任意 ACT 写入使接收缓存失效；只验证同一时钟、无接收端额外背压、不含 PAIR/replay 等有限范围。仿真 RAM／DRAM 和测试架参数也不等于完整 ASIC 网表及其 RC。
- 缓存允许跨输出复用后，首次装入可被较大 N 摊薄，因此不能以 640 bit 瞬时读宽直接证明必须绑定 ACT 与 MXU。
- 历史 13 个任务通过软件改变形状、尺度模式和重写行为，均沿同一固定 ACT—MXU 连接运行；尚无后期改变这条连接的额外收益证据。

下一步补适配器综合、存储映射、Block 与顶层物理实现、端点／RC／活动功耗、同资源对照和多配对共享成本。已有 Nangate45 接口线长只是实现背景，不能充当后加工可达性证明。

## 4. llaccel 候选边界

### 4.1 L0：完整引擎与共享存储连接分离（首选）

以 `gemm_engine/u_gemm`、`vec_engine/u_vec`、`attn_engine/u_attn` 为计算 Block，以 `sram_xbar/u_xbar` 为存储连接 Block；命令、DMA、DRAM 仲裁及性能观测保留明确的系统边界。

| Block | 保留在内部的局部资源 | 主要外部接口和风险 |
| --- | --- | --- |
| GEMM | 权重双缓冲、prod/psum/acc、矩阵循环、bias/rq、尾处理流水、输出 FIFO、写回地址 | 权重读声明 2048 bit、A／参数读 512 bit，写数据 512 bit 容器及 64 bit 字节掩码；A 口也读参数与偏置。声明宽度不等于全部有效载荷或最终物理引脚数 |
| VECTOR | 双读响应 FIFO、跨行拆分／拼接、共享通道计算、归约／开方／除法、结果保持、地址遍历和流水状态 | 双读口各声明 512 bit，当前拆分器使用低 256 bit；写数据为 512 bit 容器。需保留 grant/rvalid、请求保持与输出反压 |
| ATTENTION | Q 保持、K/V 请求标签与响应拼接、sbuf、归一化、V 加权累加、再量化与输出队列 | K/V 完整数据在外部 DRAM，本地一行保持不是完整 KV cache；输出队列同时服务 ATTENTION 与 KV_WRITE，不能仅按算子名称切开 |
| SRAM 连接 | `sram_xbar` 的 bank mask、固定优先级仲裁、读返回拼接、写选择和相关状态 | 当前 core 仅到 16 个 bank 引脚，不含 SRAM 存储体。无实际宏时不能报告完整存储面积、宏到引擎距离或存储能耗 |

`sram_xbar` 协调 10 个请求口：同周期按完整 bank mask 授权，拒绝请求须保持；读数据下一周期返回。初轮保持原协议，不为顶层长线任意插入额外一拍。若必须改延迟，需要同时修改请求／返回／标签／反压并验证功能。16-bank 切成四块还涉及全局原子授权和宽读取拼接，不是简单层次切割，暂不作为首轮候选。

L0 回答天然引擎粒度能封闭多少内部实现，以及共享存储端口／授权网络是否成为主要约束。可以先只取 GEMM＋VECTOR＋共享存储连接组成受控子系统，但须明示未覆盖完整 ATTENTION／DRAM 行为。

### 4.2 L1：GEMM 计算核心与尾处理分离

在 L0 上，仅将 GEMM 分成两个候选 Block：

1. 矩阵核心：权重双缓冲、prod、psum、acc，以及计算所需循环／取数状态。
2. 尾处理：bias/rq 参数、`d1…d4` 流水、`u_out` FIFO、写回数据与地址控制。

RTL 的 drain 涉及 16×32 bit 累加结果、偏置／量化参数、地址及 valid；输出 FIFO 空间又反向约束 drain。边界应按确切流水状态和控制依赖设计，不能只抽象成一条无反压结果总线。此方案用于检验“通用矩阵计算＋可选择尾处理”的复用价值是否抵消端口和调度开销，首轮不同时细拆 VECTOR 或 ATTENTION。

总报告按接收组追踪出的内部细组只能帮助定位候选，实际拆分必须依据 RTL 状态与连接，不能从 R 分类直接生成硬宏接口。

## 5. 同资源与公平比较口径

每轮先冻结功能、数值格式、张量形状、允许误差、输入／权重、输出及统计边界；固定源码、工艺、PVT、工具版本和合理一致的时序约束。不同自由度的方案分别报告，不用一项归一化指标掩盖差异。

| 维度 | 必须对齐或披露 |
| --- | --- |
| 算力与存储 | 相同计算资源、原始 ACT／TMEM 容量；另列接收副本、FIFO、暂存、标签、失效、串拆和控制资源。严格同资源的 O1 也预留 O0 适配资源，允许闲置；若另做各自优化设计，应标为不同资源对照 |
| 接口与时序 | 数据、地址、握手、授权、时钟／复位分别列出；保持请求／响应延迟或明示改造。宏输入驱动、输出负载、IO 延迟及跨宏时钟传播均需约束，不能让未约束路径制造好结果 |
| 物理预算 | Block 内部面积＋顶层连接／控制＋宏空白／halo，包含全部已制造资源。拆分导致的额外缓冲、时钟、PDN 和通道占用单列；关掉或闲置资源不从制造面积扣除 |
| 存储供给 | 明确实际 SRAM 宏、通用 RAM、寄存数组或仅 bank 边界；外存延迟与带宽相同，数据搬入／搬出是否计入任务时间须一致 |
| 活动与能耗 | 相同任务和完成条件下比较任务时间与总能量，披露活动来源和覆盖率；无活动仿真或可用功耗模型则记未测，不能按开启比例线性缩放 |
| 布线统计 | 新实现单独统计 Block 内／顶层资源，按唯一物理网络或明确几何拆分去重；共享干线不重复摊为每个模块对的专属成本，不把旧报告整网线长当成边界外长度 |

同一矩阵形状的 O0/O1 比较主要隔离 Block 边界；F0/H1 比较主要隔离物理实现方式。不能把两种变化同时发生后的全部差异归因于预制互联。

## 6. 分阶段实验矩阵

以下是执行顺序及验收口径，不是已获得的结果；本次 VECTOR pilot 只负责先检验工程入口。

| 阶段 | 允许的变化 | 最小产物／检查 | 能支持的结论与限制 |
| --- | --- | --- | --- |
| P0：VECTOR 工程 pilot | 选定 `vec_engine` 和清楚标注的顶层负载／接口包装；必要的包装寄存器在对照中保持一致 | 固定源码／配置；Block 硬化尝试；LEF、时序模型、网表、数据库及日志来源；顶层引用该 Block；记录失败点 | 检验工程流程、宏接口和抽象视图。单个 VECTOR 加包装不等于完整 llaccel、实际 SRAM 系统、多 Block 架构或性能比较 |
| F0：扁平基线 | 同一功能子系统全部作为软逻辑实现，允许常规全局优化 | 功能检查、综合／实现记录、完整约束和实际指标；对照顶层包装相同 | 给出常规实现参考；不能当作理论最优 ASIC |
| H1：常规分层实现 | Block 独立实现后以硬宏集成；顶层仍可常规布线、缓冲和 CTS | 宏接口、LEF／Liberty／网表／ODB 版本固定；顶层没有重新综合内部；连通性、时序、拥塞／DRC 等实际状态 | 测量层次边界与引脚约束代价；即使成功也尚非冻结底座的受限定制 |
| H2：冻结底座与受限连接 | 冻结 Block 数量／类型／位置／朝向、全部有源单元、引脚、预埋几何、驱动／流水、时钟／电源及门控资源；只在预先声明的金属／通孔与接点集合中变化 | 冻结清单和新实验校验值；允许集合；前后固定资源对比；受限路由与端点／容量合法性；失败路径保留 | 才能评价一个明确规则模型下的预制底座可行性。禁止靠新增 buffer、寄存器、换宏或移动 Block 修好某个任务后仍称同一底座 |
| 多计算图检验 | 在同一 H2 底座上分别映射任务；固定互联＋软件配置与制造时定制采用相同资源预算 | 至少两个计算／存储块及两个由真实计算图产生、确实不同的通信需求；映射、调度、路由和功能证据；保留无法适配情况 | 检验后期改线相对固定互联有无额外价值。若相同固定连接已同样好，应保留否定结果；仅改变 M/N/K 不自动形成不同拓扑 |

多图可从串行“矩阵→向量→矩阵”与真实分支／汇合的门控前馈路径选取，或选择产生不同存储配对／竞争的任务；具体张量、精度、资源占用、可运行软件参考及控制先在任务中冻结。不能为了得到正收益人为设置明显不适合任务的固定网络。后续保留独立测试图，避免仅为已知两个图定制底座。

H2 首先可采用明确的研究规则模型；实际工艺分界、可后加工接点、线宽／间距、RC 与制造顺序尚未核实时标为待核实。只限制 `MIN_ROUTING_LAYER`／`MAX_ROUTING_LAYER` 并不足以证明固定底座或合法制造定制。

## 7. 工具入口与工程核验

ORFS 官方 [FlowVariables 文档](https://openroad-flow-scripts.readthedocs.io/en/latest/user/FlowVariables.html)列出 `BLOCKS`、`ADDITIONAL_LEFS`、`ADDITIONAL_LIBS`、`ADDITIONAL_GDS` 等分层集成入口，以及 `MACRO_PLACEMENT_TCL` 等配置。它们可作为实现 H1 的候选入口；本计划未证明既有镜像支持这些入口或当前版本的相同行为。

执行时先核对已有镜像中的 ORFS commit、Makefile、变量定义、宏抽象／时序生成脚本及平台支持，再选择其实际可用的流程。宏 LEF 几何、时序模型和真实实现必须对应；顶层网表需证明 Block 保持为硬宏实例。时序抽象不足或缺少时钟传播模型时，如实说明只能完成几何／布线试验，不能称完整时序闭合。顶层使用常规修复插入的新有源单元应逐项记录，这些操作只属于 H1，除非它们已预先纳入 H2 冻结资源。

官方在线文档是使用入口，不替代镜像实测，也不提供本项目的性能、能耗或制造可行性证据。

## 8. 关键指标、记录与失败边界

| 类别 | 要记录的实际值／证据 |
| --- | --- |
| 正确性 | 源码／配置一致性，软件参考或适用的 RTL／形式检查；请求保持、grant/rvalid、缓存失效、反压与复位边界；未执行项目说明原因 |
| 工程产物 | Block 与顶层分阶段状态；LEF、时序模型、网表、SDC、ODB／DEF、需要时 GDS／SPEF 的位置与新实验 SHA-256；缺项标待核实或未产生 |
| 物理质量 | 实际标准单元和宏面积、缓冲／时钟单元、拥塞、未布通网、DRC、过孔、逐层线长；区分资源图可布通、局部检查和完整签核 |
| 时序 | 完整约束覆盖、setup/hold WNS/TNS、关键路径、输入／输出预算、宏内／宏外时钟和 RC 来源；无独立 STA 时不推断闭合 |
| 任务性能与能耗 | 完整任务周期、实际时钟、延迟／吞吐、访存／仲裁／接口等待、利用率、任务能量与时钟占比；时序注入估计与真实 RTL／物理模型分列 |
| 定制与复用 | 固定资源标识、改变的层／几何／接点、端点可达性与容量、预埋轨道利用、失败原因、不同任务是否复用相同底座 |
| 成本 | 分开记录改变的掩模集合和仍需执行的后续固定工序；报价或制造参数不足时只做披露假设的敏感性分析 |
| 可复现性 | 代码 commit、输入数据版本、工具／镜像与配置、平台／PVT、随机种子、命令、任务 ID、资源限制、输出位置和新实验校验值；大原始数据留获授权存储并保留索引 |

若宏接口过密、授权路径不能满足原延迟、存储映射不合法、受限层／端点下不通，或主要收益在计入存储和时钟后消失，应保留失败并调整候选范围。不得以移动 Block、增加有源资源、忽略供给或放宽数值正确性掩盖 H2 失败。

本计划及首轮 pilot 不能宣称：已完成预制底座／制造签核；本仓库可复现全部历史物理结果；历史 LEC 通过意味着独立 STA 通过；宽接口等于相同数量后加工接点；高层金属天然是跨 Block、低层天然是块内；常规分层成功等于少量定制层成功；后期改线必然优于固定互联；所有候选已实现或已有确定的面积、频率、能耗收益。
