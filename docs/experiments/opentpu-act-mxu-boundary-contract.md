## 1. 发现：历史 128 bit 通路尚不是跨 ACT／MXU 宏的边界

本次只定向阅读外部历史实验中的两份源文件，没有重放其仿真、重算统计或校验包内哈希：

- 本地根目录：`D:\Data\电路实验\若干项目布线结果\llm_routing_analysis\outputs\act-mxu-boundary-experiment-20261020`
- 文件：`otpu_act_link.sv`、`run_real_link.py`
- 远程来源索引：`/public/home/yuzelu/project-circuit/llm_routing_analysis/outputs/act-mxu-boundary-experiment-20261020`

源码所示的边界如下：

| 已读证据 | 对物理划分的含义 |
| --- | --- |
| `otpu_act_link` 内同时实例化 `otpu_actram u_source`，并声明 `tx_record`、`rx_record`、`cache`、`saved_base/kb/cols` 和共享 `state` | 发送端 ACT、接收缓存和两端控制仍在同一 RTL module，尚不是独立可硬化的 TX 与 RX |
| `link_data`、`link_valid`、`link_ready` 是 module 内部 wire，未出现在端口表 | 按原 module 硬化不会自动把这条载荷变成顶层连接 |
| `link_ready=1'b1`；同一个时序过程根据共享 `state` 同时推进发送、拼接、缓存写入和完成状态 | 历史测试验证的是始终可接收的同钟原型，未建立两端独立状态、真实背压及完成／取消协议 |
| `run_real_link.py` 把原 `otpu_actram` 替换为 `otpu_act_link`，实例仍名 `u_act`；另给 `u_mxu` 增加需求描述与 `act_ready` 门控 | 若仍以 `u_act`／`u_mxu` 为硬宏，串行器和接收缓存全部落在 ACT 侧，缓存宽读输出仍然跨宏 |
| `otpu_act_link` 的输出仍为 `r_data[MCOLS*D*8-1:0]`、`r_scale[MCOLS*64-1:0]` | 在历史 D=32、MCOLS=2 配置下，仍有 512＋128 bit 数据／尺度跨到 MXU；不能称为 128 bit 物理边界 |

关键的历史内部连线为：

```systemverilog
wire [W-1:0] link_data=tx_record[W-1:0];
wire link_valid=state==3;
wire link_ready=1'b1;
```

这不否定历史原型确实通过 128 bit 内部载荷逐拍搬运数据的行为证据。它限定的是**物理结论**：不能直接把该 module 替换方案用于 128 bit 跨宏布线对照，也不能从其吞吐推导已实现的接点减少。历史 171 次仿真、吞吐和缓存失效结果仍应标为原报告记载，未在本轮复核。

## 2. 三种对照及各自回答的问题

| 标识 | 物理边界与功能 | 允许归因的比较 |
| --- | --- | --- |
| O0-W：原宽接口分离 | 原 `otpu_actram` 为 ACT Block，原 `otpu_mxu` 为 MXU Block；保持原读控制、512＋128 bit 读出及寄存延迟，不引入串行链路或新接收缓存 | 与 O1-W 比较时，主要隔离宏边界、引脚、阻挡和顶层布线带来的代价 |
| O1-W：原宽接口合并 | 把同一原始 ACT 与 MXU 放入一个硬化 Block，原宽读接口成为内部连接；外部量化写入、权重／尺度读取、结果写回及调度仍按同一功能口径处理 | 与 O0-W 保持算力、原 ACT 容量、数值、任务、接口语义和约束一致，不把“合并”额外变成算法／缓存／协议改造 |
| O0-S：窄载荷＋MXU 本地缓存 | **需先重构。** ACT＋TX 为发送宏；RX＋接收缓存＋宽本地读口＋MXU 为接收宏；显式窄载荷与完整控制协议跨宏 | 与 O0-W 比较通信适配与存储副本的代价；与 O1-W 比较时同时包含资源绑定、缓存、协议及实现自由度的变化，不能统称纯边界收益 |

O0-W/O1-W 的第一轮不需要新缓存，适合先验证层次切分与物理抽象是否正确。O0-S 是额外的体系结构／协议对照。若另做严格同资源的 O0-S/O1-W 比较，两方案都须列出并预留适配所需的缓存、暂存、控制与驱动资源；闲置仍计入制造面积和漏电。若比较各自优化后的设计，则标为不同资源设计点。

三个方案外部负载、量化写入、权重与尺度、输出、全局控制、时钟和电源统计保持相同范围。不能只比较 ACT 读出这一条载荷，也不能用相同 M/N/K 冒称已经隔离全部边界因素。

## 3. O0-S 两端的资源归属

以下是拟实施所有权，不是已经存在的新模块名或完成的端口定义。

| 所属物理 Block | 预制资源 |
| --- | --- |
| ACT／TX 侧 | 原 ACT 数据及尺度存储、量化写接口、源 RAM 读地址／延迟状态、需求描述锁存、发送记录暂存、拆拍计数、发送有效／保持控制；写入版本或失效发起状态 |
| RX／MXU 侧 | 需求生成／缓存命中检查、接收记录拼接、接收缓存与有效标签、接收计数和本地完成状态、原一周期宽读口、MXU 原读推进及计算状态 |
| 显式跨宏接口 | 载荷、载荷有效与接收就绪、需求描述及接受、完成／取消／异常语义、写失效及必要确认；时钟、复位另列 |

TX 与 RX 必须拥有独立状态机和各自锁存的描述。禁止通过共享 `state`、层次引用对方的寄存器／数组，或把整个历史 `otpu_act_link` 仍放在一侧来维持“同步”。MXU 看到的 640 bit 宽数据／尺度只允许来自 RX 侧本地缓存，不得在 O0-S 中从 ACT 宏直接跨出。

源 ACT 写入控制不能在 RX 侧被“凭空看见”。若顶层直接广播写使能以失效缓存，这些广播必须成为显式、计入端点和时序预算的跨宏连线；若采用版本消息，则需实现消息保持和在途传输处理，不能只复用历史同一过程中的 `|we || swe` 清状态。

## 4. 跨宏控制与载荷的语义合同

下表用功能语义描述接口，**不是已实现信号名**。精确位宽、编码、哪些字段同拍传送、完成是否单独确认，均须在 RTL 重构前冻结。

| 语义／方向 | 拟要求 | 仍待设计 |
| --- | --- | --- |
| 需求描述：RX→TX | 描述待填充的 ACT 范围、块数、有效列及必要版本；TX 只在明确接受后锁存，不能继续读取 RX 会变化的寄存器 | 历史 `base/kb` 各 16 bit、`cols` 为 MCOLS bit，是历史端口宽度；新接口是否原样保留、压缩或带版本，待定 |
| 需求接受／完成 | 两端都能判断一次请求何时被接受、何时全部数据被 RX 安全提交、何时取消或失败。单次只允许一个未完成需求可作为首版简化，但需落实状态约束 | 接受和完成的握手／确认方式、是否需要事务标识、重复请求规则，待定；不能把 cache hit 的 `ready` 与载荷接收就绪混为一谈 |
| 载荷：TX→RX | 128 bit 可作为首版候选，以已有原型为功能参考。仅在有效且接收就绪时推进；被阻塞时载荷及其描述保持；末拍填充不得写入有效数据 | 精确载荷宽度在配置中冻结；分包次序、块／列顺序、末拍有效长度、边界标识采用字段或确定计数，待定 |
| 接收就绪：RX→TX | 显式导出到 TX，用独立 RX 缓冲／写入状态产生；首版验证包括就绪拉低后恢复，双方不得丢拍或重复提交 | 缓冲深度、组合或寄存反馈、是否引入 skid buffer 及其预制成本，待定。历史常量 `ready=1` 不能冒称已经完成背压协议 |
| 写失效／版本：ACT→RX | 任意会改变所缓存内容的 ACT 数据或尺度写入，使旧缓存不可再被消费；在途填充必须被取消、标为旧版本或按明确规则重新执行 | 首版可选择保守的任意写全失效；版本宽度、防回绕规则、确认、写／填充互斥或并发策略，待定 |
| 取消／异常 | 对超范围、非法列、未支持模式、长度错误或在途失效给出确定处理；失败不产生“缓存可用”完成状态 | 错误编码、上报方向、取消确认及恢复流程，待定；仿真 `$fatal` 不能替代已承诺的运行时硬件处理 |
| 时钟／复位 | 首版为同一时钟域；规定两端复位一致性、在途清空、缓存无效及复位释放后的重新请求 | 若不支持独立复位／CDC，明确列为不支持，不推断存在跨域能力；复位和时钟引脚、树及负载另行预算 |

一个可验收的首版时序应满足：RX 命中缓存时使用本地数据；未命中时发出并完成需求接受；TX 按源 RAM 延迟读取，随后独立发送各拍；RX 仅接收已握手的数据，完整提交当前请求后才允许 MXU 消费。若发生写入、取消、异常或复位，旧事务不能稍后重新置有效。完成确认、在途写冲突和描述变化优先级必须先做决定，不能由共享状态过程隐式代替。

历史支持范围为同钟、低连续有效列、非 PAIR、单个持久 tile。首轮可继续限定这些能力，但每项限制必须能在输入合同和验证中检查；不得悄悄把任意列掩码、额外背压、PAIR/replay 或多事务并发当成已支持。

## 5. 存储映射与公平口径

历史 D=32、MCOLS=2、BLOCKS=32 的声明给出每列每块 320 bit，接收载荷缓存为 2,560 B；`tx_record`、`rx_record` 各为 640 bit（80 B），此外有宽读输出寄存器及控制。这里是 RTL 位容量与原报告背景，不是已测宏面积、功耗或物理 pin 数。

物理试验前须冻结并记录：

1. 原 ACT 数据／尺度采用的实际宏、端口和读写时序；O0-W/O1-W 使用相同映射。
2. O0-S RX 缓存是寄存器、SRAM 宏或其他组织，以及其宽读要求能否由该映射提供；不能把 640 bit 宽读和失效控制视为免费。
3. TX／RX 暂存、缓存标签、版本、握手、错误、复位、skid buffer 等实现和面积；来源数组映射成寄存器与接收缓存映射成宏时分别披露。
4. 相同功能任务、输入、精度、允许误差、时钟／PVT、存储／外存供给和完成条件；源 RAM 延迟或流水变化如需修改 MXU 接口，另做验证。
5. Block 内＋顶层面积、留白、通道、驱动、CTS、PDN 与活动能耗。适配资源位数不能直接换算为芯片面积倍率；缓存闲置也不能从物理资源扣除。

不能在只有行为 RAM 的情况下报告 SRAM 宏面积与 RC，也不能把只测 TX↔RX 载荷的结果当作整个 ACT＋MXU 集合的全部外部通信成本。

## 6. 功能验证准入

O0-W/O1-W 先确认相同原始功能、原宽接口及一周期读延迟；O0-S 在以下检查形成证据后，才进入有结论意义的跨宏物理对照：

- 新 TX／RX RTL 可独立解析，接口方向和状态所有权明确，无共享数组或层次访问；记录相对历史快照的真实修改。
- 复用历史任务作为回归输入，但重构后的 RTL 必须重新验证 TMEM／DRAM 与 ISA 结果、任务完成和数值规则，不能继承历史“171 次通过”。
- 检查需求保持／接受、描述变化、缓存命中、范围／列变化、跨 MM 复用，以及不同激活和尺度写入后的失效。
- 在各发送／接收阶段施加背压，覆盖最后一拍、非整拍有效载荷、计数推进和缓存写入；验证无丢拍、重复、乱序或提前消费。
- 覆盖请求前、源读取、传输中、提交前后发生写入、取消或复位；确认旧完成不能越过失效事件重新激活缓存。
- 对声明不支持的模式给出可检查的输入限制或明确错误处理；记录已执行用例、检查方式和未覆盖情况。
- 比较新实现的源 RAM／本地缓存读延迟、MXU 行内连续消费、请求返回与任务周期。协议延迟变化与物理边界变化分开报告。

elaboration、综合结构检查、行为仿真、形式等价和路由后功能检查分别记录；其中一个通过不替代其他项目。首版限制性合同可用，但不能据此宣称通用双向传输协议、CDC 或任意背压条件均已验证。

## 7. 真实跨宏网络检查

O0-S 的物理验收必须证明窄载荷确实跨越两个独立硬宏，而不只是 RTL 内出现了一个 128 bit wire：

1. **层次与物理对象**：发送宏包含源 ACT 与 TX，接收宏包含 RX 缓存与 MXU；两者分别生成并固定网表、LEF、时序模型及数据库。顶层保留两个真实宏实例，没有把源 ACT 搬入接收宏，也未把宏内部重新展开综合。
2. **端口与网络对应**：从顶层网表、宏端口／LEF pin、实际数据库的 instance terminal 与 net 读回载荷及全部控制连接。核对方向、位序、握手和实际端点；只看端口名或原始声明不算物理证据。
3. **宽数据归属**：在 O0-S 中，RX 缓存到 MXU 的 512＋128 bit 读出为接收宏内部网；不存在绕过串行链路的 ACT→MXU 宽数据跨宏旁路。O0-W 则应如实保留原宽数据边界，O1-W 应将其内化。
4. **全部连接成本**：除载荷外，列出需求、完成、就绪、失效／版本、异常、写入、时钟及复位等实际跨宏 net；常量折叠、别名、扇出和缓冲单列。不把载荷宽度或逻辑 bit 数填写为总物理 pin／后加工接点数。
5. **时序与布线**：用真实宏输入／输出预算、负载、顶层 RC 和时钟传播检查路径，记录授权／就绪反馈是否为组合环、未约束路径、setup/hold、拥塞、未布通和 DRC。若加流水或缓冲改变协议或有源资源，记录其归属和新增成本。
6. **可追溯性**：保存新实验源码 commit、修改快照、工具／镜像、配置、输入／输出索引和新产物 SHA-256；只读历史参考包不因此进入维护或哈希重算范围。

这些检查描述验收方法，目前没有新的通过结果。若时序模型或存储映射不足，只能报告对应阶段的工程尝试，不能称完整时序闭合。

## 8. 与最终预制底座的关系

O0-W/O1-W/O0-S 首先属于 F0／H1 的功能和物理对照。H1 可做常规顶层 CTS、缓冲和修复；即使宏位置固定、128 bit 真实跨宏，也不能单凭这些条件称为 H2。

进入 H2 前，需把 TX／RX、缓存、标签／失效、控制、驱动、必要流水、时钟和电源都预先纳入冻结底座，声明允许变化的金属／通孔／接点集合，并校验固定几何和有源资源没有随任务变化。单 ACT—MXU 对和同一固定配对仍不能证明后期定制拓扑收益；后续还需至少两个计算／存储块及真实不同通信需求，公平比较固定互联＋软件配置与制造时改线，保留固定互联同样有效或受限路由失败的结果。
