先把“通过”的层次分清

这些测试确实在服务器运行过；每种结果回答的问题不同。

① 功能：结果是否算对？

检查给定输入的输出、协议、内存及适用的性能计数器是否与参考一致。

比喻：按菜谱做出了正确的菜。还需检查能否按时出餐。

② 物理：线路是否合法？

核对实际导线、引脚接入、连通、短路、间距，以及固定资源是否保持。

比喻：厨房已经施工，还要检查水管、电路和空间是否符合要求。

③ 时序与电气：能否按要求工作？

使用实际寄生与约束检查及时到达、保持时间和输出负载。

比喻：菜能做对、厨房也接通了，还要按规定速度出餐，设备不能超载。

术语小词典

概念解释帮助阅读报告，不是额外实验结论。

Block（块）一组计算、存储或控制资源的物理单元。端口、内部实现和布局需要明确；画矩形本身不代表映射完成。

网 / 引脚 / 端点引脚是元件连接口，网把相关引脚连接起来，端点是某项检查的到达位置。一个端点失败不等于全设计计算错误。

DRC（几何规则）检查导线间距、通孔等几何规则。B04的上下文和故意短路负例，不能替代B05的时序检查。

RC / SPEF（寄生）导线具有电阻与电容，SPEF记录提取结果。B02中，时钟线未动，周围数据线改变也可能改变延迟。

Setup（建立时间）数据需要在采样前及时稳定。像赶班车，晚到会失败；B05是结果来晚的例子。

Hold（保持时间）采样后，数据还需要维持一段时间。过早被新数据替换也会失败，见B06。

WNS / slack（时间裕量）裕量为负代表该时序要求未满足。B05的−1.572 ns是最差裕量，不能直接当作路径总延迟。

Cap（负载电容）输出端需驱动的电气负担。超限会影响电气验收，不是直接证明数值计算错误，见B03。

AP（引脚接入点）布线器可以进入引脚的位置。有接入点与完成布线是两件事；B10只排除了部分疑点。

Guide / DEF / ODBGuide是规划走廊；DEF/ODB可保存布局和导线。仍须检查文件实际包含什么、是否连通与合法。

冻结底座两案例使用同版实例、位置、内部实现和固定连接。当前数字联合版与旧父层视图尚未统一。

ns / ps / fF1 ns＝1000 ps；1 fF＝10⁻¹⁵ F。比较前必须核对单位、参考版本和约束。
