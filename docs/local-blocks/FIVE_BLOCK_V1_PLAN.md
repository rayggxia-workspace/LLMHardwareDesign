## 1. 交付对象和固定边界

P/U/C/F/J 是五类局控负责的逻辑资源组，每类只选择一个 `implementation_id`、叶宏组成和服务合同。联合底座实例数固定为 P×3、U×2、C×1、F×1、J×2。同类共享叶宏选择、局控/适配 RTL 和 ABI，实例身份是参数；各实例在全局布局中的位置与方向可以不同。每组拥有私有 16 KiB S、局控和明确登记的适配/传输资源。

| 对象 | 本版要求 |
| --- | --- |
| 功能叶宏 | M/N/R256/G/E/S/T 各自保持独立物理实例及匹配的网表、原生端口、LEF/GDS、寄生与时序视图。复用实际合格包 |
| 局控及辅助电路 | 以父层标准单元实现，包含真实局控、必要的仲裁、格式适配、选择器、RX/TX 保持、驱动及取指服务。逐项记面积、端口、容量和时序。程序存储须有有限且实际的物理实现，可共享但须建模仲裁 |
| 逻辑分组和布局 | 分组限定控制归属、私有 S 及服务能力。全局布局直接摆叶宏和局控单元，聚拢和形状规整作为软偏好，服从通信、pin 接入、PG/CTS 与时序 |
| 共同底座 | 固定九组的全部实际有源资源、叶宏 master、位置/方向、M1–M10/via1–via9 图形、有限预连、供电时钟和真实 M10 接点 |
| 产品部署 | 同一映射产生母控/局控程序与逐位连接需求，在共同底座上用研究 M11/M12、via10/via11 联合接通块内和块间数据路径 |

联合顶层不得将 P/U/C/F/J 的组合硬宏或其组合 LEF 当作拼装单元。独立分组的矩形验证夹具可以用于回归，其外框、边界端口和空白不构成顶层摆放边界。服务端点须追溯到叶宏或实际适配单元的驱动/接收 pin。

同一 Qwen 产品的 Attention、GDN、FFN，以及声明的 prefill/decode 程序共用一版静态金属。执行分时只减少同时使用资源的需求；连线复用要求真实端点和预制选择资源确实可共用。新增有源逻辑、改变位置或原生层图形须更新 `base_id` 并重验受影响集成证据。

### 接口必须兑现的语义

- S 普通口是一个 128 位请求/响应口，支持最多两个有序在途请求。外部仲裁必须保存响应归属；实现若只允许一个在途请求，须把该限制写入 `arch.json` 和仿真。16 B 对齐、字节范围检查在缩为 10 位字地址之前完成。
- S_P 普通访问与 feeder 阶段互斥：切入 feeder 前排空普通响应，切回前等待真实 feeder 完成事件握手退休（`done_valid && done_take`）；仅看到 `done_valid` 不足以释放普通口。记录行数、分片、bank 和保持要求；不能把接受命令当作运算完成或 S 写确认。
- 紧凑 S 的写响应数据为零。`stored ACK` 必须来自实际写完成；算术结果由实际结果通道或 S 读回验收。源对象直到匹配身份的写确认才可释放。
- 紧凑 E 按 op 串行送 A/B/C，首拍携带 op/shift，最后一个所需操作数接受后才启动原内核。描述符中的有效源数量、缺省零操作数、实际 S 读次数和背压须一致；复位清除部分操作数。修改 ABI 时必须更新版本并拒绝不兼容旧镜像。

## 3. 端点、面积与并行实现合同

### 预连和后制边

控制归属固定，控制、复位、供电、时钟和程序装载网络按共同底座实现并计价。大部分主要数据路径，包括同一逻辑组内部的路径，默认由顶层后制布线定制。少数高复用数据预连须逐条列明用途、端点、位宽、格式、握手、资源限制和成本；例如 `S_P.feeder→M` 可以论证后固定。不得因属于同一局控，就默认固定全部 S 回放、写回或 J 的 `E→S→T`。

五类各自登记完整服务与路径矩阵：`fixed`（有证据的预连）、`candidate`（有合法接点及必需有源资源，尚待接线）、`unsupported`（缺少兼容资源或接点）。产品连接实际接通、完成几何/电气/功能验收后才标 `realized`。覆盖 P 的 M→G、U 的 N→E、C/F 的 G→E 等已有候选，并逐条评估 R→E、E→G、E→T 等需求的格式与握手；图上存在关系不能代替注册路径。

每条 `edge_id` 必须逐位绑定实际叶宏/适配器实例、驱动和接收 pin、位序、数据及 valid/ready/ACK、真实原生 M10 导体、允许上层接入窗口、驱动上限和时序/RC 模型。几何仍以 LEF/DEF/ODB 为准，JSON 只索引。固定路径记录下层实际网；候选路径保留真实电气断点，综合/展平不得暗中将其接死。多源选择、隔离、保持和必要中继须在冻结前预制，金属不能代替这些有源电路。验证夹具边界端口不能替代真实驱动/接收节点。

每类至少选一条合法局部后制服务，用断路拒绝、实际接通、数值和真实完成确认验收；有 S 回放路径时与其对照。候选估计可供探索，部署器不得把未接通的候选当作合格产品路径。

### 面积和布局

联合 floorplan 从最新真实叶宏外框与局控/辅助标准单元清单出发。联合 ODB 核对上述 28 个独立叶实例、九个正确的局控身份及全部新增有源资源，不得导入五类组合硬宏。各组只施加合理的软聚拢约束，不继承旧验证夹具的正方形外框、固定 halo 或整片空白。

从父层 DEF/ODB 分别报告硬宏、功能/控制/适配/取指标准单元、CTS/中继、填充、不可摆放通道/保留区和剩余合法空闲行。平面分类避免重复计面积；PG/信号金属占用按层另报。每个大块空白、halo 和保留区记录位置、尺寸、用途及 pin 接入/拥塞/PG/时序依据。至少比较两份相同资源和规则的紧凑布局候选，保留较小候选的成功或失败证据，选择实际通过接入、布线和 300 MHz 电气门的紧凑方案。原生层冻结前允许正常全局布局优化；冻结后的改变建立新底座版本。

### 控制和并行工作

P/U 实现以 [Issue #212](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/212) 跟踪，C/F/J 以 [Issue #211](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/211) 跟踪；本合同和联合综合仍由 #184 跟踪。独立夹具里的局控 ID、时钟和 PM 代理不直接充当九实例实现。九个局控拥有正确身份和独立状态，实际父层重新绑定/综合。统一选定指令、描述符和 PM ABI，显式列出支持的 ISA 子集；不同取指位宽的合格包不得混成“已支持最新全部 ISA”。程序容量、实际存储、装载、取指时延、端口和共享仲裁落实到物理资源及模型，单独暴露 PM 接口不代表程序 RAM 已实现。

`READY` 表示目的窗口和信用已预约。目的 S 实际写完成后才发带 `epoch/task/object/fragment` 的 `stored ACK`，源按匹配确认释放。区分 S 读响应占用与源对象生存期：数据进入独立 TX 保持槽后应能退休共享 S 读响应，保持载荷/对象直到目的确认。若采用串行替代方案，须在资源表与生成调度中约束并证明可前进。验证已预约的双向同时发送，允许完成或在发起前明确拒绝非法组合，禁止接受后相互等 S。

## 4. 一个产品级 DP

交接签名必须充分描述后续可行性与成本：仍存活对象的位置/S 窗口、有效时间和未完成消费/ACK，以及上下文、端口、队列和占用。只有这些未来相关量等价，状态才可合并。首版用明确的层间排空和规范交接压缩状态；有跨层重叠时补足在途状态，不能只保留“已做几层、用了几拍”。

1. 仅在已锁定的五类实现上，从已注册的算子实现列出少量局部方案，包含实例绑定、分片、S 窗口、真实服务顺序及所需连接。先用枚举和确定性的资源检查。给不同线束的可行方案保留席位。代价使用实际 pin 接入、轨道占用、负载、时序和执行拍数，不能以虚拟 Block 外框替代。拍数来自已标记的 RTL 校准或估计。对于同一 Qwen 产品，先把层间残差规范到固定交接位置/格式，排空临时 S 与 ACK，KV 和 GDN 状态留在约定的 MEM。若实际选择允许跨层重叠，把重叠段作为一个候选，或把在途对象与资源摘要加入状态。
2. 扫描层或层模板，维护 `(进度, 交接签名, 线束集合 B)`。每次选择一个合法方案，加入执行时间与新的线束。预制的连接仍参与物理和运行约束。后制线束以真实驱动、接收 pin、位序、预制选通及返回协议去重，按整版并集收费。同一进度、同一签名、同一物理需求下保留代价更低的状态。以单一拍数目标时可写为 `D[i+1, sig_out, B ∪ Bv] = min(D[i, sig_in, B] + count[i] × cycles(v))`，可在终点追加线束代价或施加资源预算。多个执行 profile 同时约束时保留相应延迟维度或明确权重。
3. 手算回归使用 #176 的逻辑路线。假设 Attention 用 `a=P2→F0` 花 10 拍，GDN 复用 `a` 花 22 拍，走另一组预制宽口 `b` 花 20 拍。FFN 串行 44 拍，并行 36 拍但需 `c=P1→P0`。其余连线计入固定需求，假设 `b,c` 共争一个只能容一束的通道。GDN 后保留 `{a}:32`、`{a,b}:30`，最终选 `{a,c}:68`，而先选最快 GDN 只得 74。数字、宽口和冲突都是测试 fixture，真实冲突由后端证明。#176 示例每 3 个 GDN 层和 1 个 Attention 层组成一组，每层有 FFN。只有候选、执行范围和交接相同的层可合并为模板，按真实次数计时。prefill/decode 程序的布线需求都进入同一产品并集。
4. 用穷举核对小实例的最优值和非法候选。记录实际最大状态数与编译时间。先以固定需求位集、模板归并和相同状态合并控制规模；状态仍太多时用固定宽度束搜索，记录剪枝、预算与小例最优差距。整套线束同时交给后端。证明端点互斥或单驱动冲突后可添加硬约束；一般拥塞、时序裕量和搜索超时记录实际位置及候选，以代价更新或重试处理。重选后同时再生成程序与线束并重验部署。绝对最优的范围限定为登记候选和当前模型。

## 5. 验收与可重复实验

### 联合验收门

- [ ] 叶宏来源和集成准入。锁定每类唯一实现及独立叶宏 master/ABI、网表、LEF/GDS/SPEF/时序视图和 SHA。五类逻辑服务具备 RTL/数值/协议证据。局控、PM 和支持标准单元随实际九实例全局布局验收；组合物理资格来自完整底座与产品接线，不要求交付五颗组合硬宏。
- [ ] 合同可交叉检查。五类逻辑实现和九实例均有 RTL 路径、真实 pin 绑定、私有 SRAM profile 与 MEM 预算。每项服务给出命令、格式、对象生存期和完成条件。对 S 超量、未接端点、坏 ABI、陈旧/丢失 ACK、交换 pin 位序和非法下层几何分别留拒绝证据。另验 E 源数量/缺省零/部分操作数复位、S 地址与 feeder 切换、双向发送前进、九个 LC 身份和实际 PM 容量。
- [ ] 功能和运行闭环。同一映射生成的镜像在 SystemC 和九实例 RTL 上执行；五类 Block 都由编译生成的路径实际触发。每个代表切片有独立整数参考、真实目的写确认及源释放证据。Qwen 同一部署运行 Attention、GDN、FFN 及至少一次跨层交接，并含两个连续 token 的非零状态路径。单宏和子路径通过情况单列。
- [ ] 候选底座与正式冻结。先在同一个 tentative native fingerprint 上预跑至少两个目标拓扑及局部后制边。归档本合同要求的面积分类、空白依据、两份紧凑布局对比、引脚接入与拥塞证据，然后冻结器件、master/位置/方向、M1–M10/via1–via9 几何、固定 PG/CTS、M10 接点与上层规则。冻结后新增驱动或搬实例要重做版本和对照。
- [ ] 产品物理验收。对同一冻结底座的两版不同需求做块内和块间联合 M11/M12，至少包含 Qwen 及 Falcon/Granite 之一，至少一版通过实际局部后制边执行相应程序并与 S 回放对照。输出实际 ODB/DEF、网表、寄生、DRC/PG、连通与时序。实际连通对逐位清单，零意外开短路、零研究规则违例、原生层 XOR 为空、PG/CTS 连通。按约定低/基准/高 RC，在 300 MHz 检查 setup/hold、转换时间、电容和覆盖率，同时核对 SRAM 脉宽及视图适用范围。使用匹配叶网表及寄生或已验证的父层模型，避免在 M10 边界重复计 RC。公开研究 PDK 和 SRAM bank 内部 PEX 等证据边界。
- [ ] 每条证据带代码 commit、工具/配置、输入权重摘要、复跑命令、输出索引及 SHA-256。覆盖表逐模型分别填图导入、合法映射、SystemC、RTL、物理，注明实际层、tile、上下文和状态范围。完成项必须可从源输入重放。
