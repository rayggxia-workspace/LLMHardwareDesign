## 1. 研究对象和固定边界

采用“固定控制归属、两级可编程调度、端点握手驱动执行”。全部控制核、程序/描述符存储电路、宏适配器、队列、选择器、时钟复位及驱动在M1–M10预制。M11/M12、via10/via11仍是研究中的后制层，只编码/连接预制资源；块内主要数据连接和块间数据连接均可后定制。

| Block | 基础宏组成 | 基础宏数量 | 局控主要管理对象 |
|---|---|---:|---|
| P | M1/G1/S1 | 3 | M操作数和累加上下文、gate/up/Mid、G及S供数 |
| U | N1/E1/S1 | 3 | 单统计上下文、原始/EXP回放、格式/配对变换 |
| C | R1/G1/E1/S1 | 4 | 状态分片、卷积/递推顺序、格式转换及old/next |
| F | G1/E1/S1 | 3 | 多输入片段、激活/门乘、原地覆盖和返回 |
| J | E1/S1/T1 | 3 | 分支/残差、T封存/排空/释放、消费者义务 |

C Block不是其他研究中名为C的母控宏；本方案使用global_ctrl、local_ctrl、blk_c等无歧义名称。表内每个基础宏都是一个独立物理实例；局控及辅助逻辑另计。九块示例池P3/U2/C1/F1/J2共28基础宏、9局控和1母控；不是已冻结或最优实例数。

建议固定“哪个宏由哪个局控管理、S归哪个Block所有”。后制金属改变数据连接，不改变控制所有权。若将来要改变控制归属、共享某个宏或仲裁远端S，须另定义接口、并发和物理成本，不由连线自动获得这些能力。

## 2. 母控结构

| 模块 | 建议职责与边界 |
|---|---|
| 程序顺序器 | 解释全局粗指令；图级顺序、有限循环、条件选择。首版顺序发射，任务异步执行 |
| 任务与依赖表 | 分配完成令牌，记录目标Block/任务序号，建立全局输入输出依赖；不逐拍发原生算术命令 |
| Block准入/命令发送 | 接单前预约完成接收能力；发64B任务消息，锁存R0..R7参数快照 |
| 返回与事件处理 | 独立接收TASK_DONE/ERROR及标量事件，保持到程序消费；源、job、epoch、task_sequence匹配 |
| 全局状态/参数接口 | 保存小规模标量、程序版本及全局状态根；参数、权重、KV和模型系数的真实MEM服务单列 |
| 错误与结束控制 | 停止新任务、通知相关局控停止/排空、汇总已确认前缀，最后保持成功或错误完成 |

全局指令见ISA的G_CALL/G_WAIT/G_EVENT/G_MOVI/G_LOOP/G_BRANCH/G_PARAM/G_FAIL/G_END。G_CALL发出任务后继续取指；G_WAIT等待指定完成令牌。母控程序等待时，命令返回、数据搬运和局控必须继续前进。

图级S所有权不由母控直接操纵裸RAM端口。母控通过任务、对象引用和事件表达预约/依赖；局控对本块具体S窗口执行OPEN/DROP并核验。首轮采用编译期静态地址分配，避免同时由母控与局控维护两个相互矛盾的动态分配器。

建议首轮支持最多32个全局完成令牌、32个标量事件槽及8个32bit标量寄存器。它们是可调整的容量profile；Block实际数、资源mask及存储深度在部署时进一步收紧，超界拒绝。每个活动任务仍由其目标局控单独管理。

## 3. 局控结构

| 模块 | 输入/输出和需要保存的状态 |
|---|---|
| 任务入口 | 解包母控消息；验证程序/拓扑/原生ABI版本及任务描述符；保存job、epoch、task_sequence、8个参数字 |
| 微程序顺序器 | 128bit取指/holding，PC、8个32bit标量寄存器、有界循环和步骤预算；只处理描述符与控制状态 |
| 对象表 | 最多16项：静态基址、预约长度、格式/版本、有效片段、读写/传输义务和是否允许释放 |
| 资源记分牌 | 命令busy与上下文owner分开；8个局部完成令牌及服务序号；不得以busy=0推断M/N上下文已释放 |
| 宏适配器 | 对本块实际拥有的M/N/E/G/R/S/T解释有界服务，驱动原生命令/数据端口，记录真实完成/饱和/错误 |
| S访问服务 | 复用私有S仲裁/feeder；检查bank/端口/地址/尾包；不暗加存储端口 |
| RX/TX服务 | 每方向首轮一笔片段传输，有限holding、tag检查、目的真实S写确认、源保活及独立返回 |
| 完成与故障单元 | 完成tuple一次锁存，背压时保持；统一处理服务错误、取消和协调复位，记录实际已确认前缀 |

首个原型每块一个活动任务，各执行器可在无冲突时重叠。该限制是建议起点，不是用户要求或最终架构定论。后续增加多任务/乱序前必须证明对象、上下文、令牌和返回隔离，计入新增硬件。

对象地址、count、offset、参数索引等动态字段在OPEN或服务接受时解析并快照；顺序器随后修改寄存器不能改变已接收操作。宏适配器按资源类型配置，其内部小型协议状态机是固定硬件。五类Block复用相同控制核，资源mask及适配器不同；MEM资源仅在实际实例化/可达时启用，不自动赠送给每块。

## 4. 程序如何适应块内/块间不同连接

编译器同时读取：资源/能力清单、真实数据端点连接清单、模型/任务IR，输出母控程序、局部程序、对象布局、描述符和金属连接需求。局控始终可控制自己拥有的宏；数据通道按产品端点绑定使用。固定控制逻辑拓扑与可变数据路线分开规划，控制线若走M11/M12也计入共同路线和RC。

| 数据拓扑候选 | 相同局控硬件执行的局部顺序 | 准入条件 |
|---|---|---|
| S→M→S | OPEN窗口；准备结果接收；M供数/计算/读出；WAIT本地存储；TX及WAIT远端存储；DROP/END | 对应端点接通、格式/位宽/窗口/上下文合法 |
| S→M→G→S | OPEN窗口；先准备S接收和G；再M供数/计算/读出；WAIT全部排空/结果存储；TX/确认/释放 | M/G之间已有匹配宽度、格式、背压适配和连接 |
| 同一版金属提供多条合法路径 | 程序选择既有端点或预制选择器 | 选择/复制/独立驱动必须早已存在；不能将多个有源输出短接 |

这是两种拟研究的产品连接，不宣称当前P已经实现这些直通链。宏原生输出不能凭图直接裸接。G只有两路，M读出格式/舍入与G输入Q5.10需适配；分流、接收holding、重定时和ACK所有权均须预制并计价。

程序不能创建未接通通道。拓扑ID及能力profile用于核对部署绑定，完整产物由SHA-256清单追溯；短ID不是密码学完整性证明。若同一颗芯片要执行多种层型，其静态金属必须同时覆盖这些层型需要的合法通路，运行时只换程序/参数。不会在Attention层和GDN层之间重布金属。

## 5. 数据、确认与资源生命周期

对象建议状态为“已预约→写入中→可读→外送/消费中→可释放”；原地覆盖必须确保所有旧读已经结束。不同活对象首版不允许重叠预约；同一对象的原址操作由声明的适配器合同与锁控制。

| 事件 | 必须观察的实际事实 |
|---|---|
| COMMAND_ACCEPTED | 适配器已锁存完整请求；不是数据有效 |
| RESULT_READY | 原生结果可读并被保持；不自动表示写入S |
| LOCAL_STORED | 目标S全部声明字的真实写返回已消费，尾包与有效长度检查通过 |
| REMOTE_STORED | 匹配job/epoch/edge/invocation/fragment/端点/对象版本的远端存储确认 |
| SOURCE_RELEASED | 所有声明消费者义务结束，源游标/窗口或T按原生规则释放 |
| TASK_DONE | 服务令牌已消费、相关资源关闭或按声明转交、输出义务结束，最终状态已锁存 |

v0.1不将上述六种事实塞进同一个done位。L_EXEC描述符只能请求适配器实际支持的完成条件；数值编码存在不代表该条件已由RTL实现。G/N内部有限上下文和T单读游标不能当额外通用S。fork需要每个消费者独立确认；局部T释放与edge/private S对象回收分别管理。

私有S普通口首版每块一笔在途，宽feeder与普通口共享bank。L_WAIT不能暂停RX/TX、S helper和完成接收。母控应先启动接收任务，等待其接收窗口准备事件，再启动生产者。对C→U→C等回路，分片双向接收空间、返回信用和释放顺序必须显式安排；有限测试只证明所测场景，不能冒称一般死锁自由。

## 6. 程序载体、控制网络与存储账

建议首个可执行版本采用空闲装载程序RAM：停止接单、排空任务/数据/返回、写程序和描述符、完成完整性及能力检查，再切换程序版本。复位不假设RAM自动含有效程序。真实金属ROM保留为后续对照，需位单元、译码、读出、接点及物理证据；仿真hex不代替这些硬件。

建议容量profile用于原型预算，尚未证明足够支持所有模型：

| 局控存储 | 候选容量 | 字节 |
|---|---:|---:|
| 指令 | 256×16B | 4096 |
| 对象描述符 | 16×64B | 1024 |
| 执行描述符 | 16×128B | 2048 |
| 传输描述符 | 8×64B | 512 |
| 任务描述符 | 8×64B | 512 |
| 每局控以上合计 | — | 8192 |

九局控合计72KiB；母控若指令256×16B、事件绑定32×16B，另4.5KiB，合计**76.5KiB静态控制内容预算**。这还不含镜像头、全局标量参数、运行时状态/队列/holding、错误逻辑、MEM参数/权重及PG/CTS。先前“4KiB每局控”仅计指令区，不能当完整控制存储。寄存器/SRAM/金属ROM的相同字节数不等于相同面积。

首轮控制传输候选为独立命令/返回方向的32bit有序消息链路：64B任务或事件包至少16个有效flit；包内不交织，背压保持。任务发送前预约最终返回空间，错误完成也占该预算。数据路径采用自身预制端点；跨块对象帧头/ACK在ISA中给出64B研究格式，128bit链路各需4个有效字，开销和反向路线必须计价。块内已绑定的原生流可以用更小的专用握手profile，但须明确固定格式/适配，不凭此省略硬件。

## 7. 错误、复位与状态发布

停止新发射与“所有硬件静止”分开。发生错误时继续办理可安全排空的在途返回；锁存错误源、确认前缀和饱和状态；不能安全排空时poison该cohort并协调原生宏、S helper、收发及参数provider复位。数据RAM已写内容不回滚；新epoch/对象有效状态决定其是否可读。

原生接口没有完整返回tag时，适配器必须单在途并协调排空；不能只给外层加epoch就宣称可隔离无限迟到返回。job/epoch/task/event/service计数不允许带在途事务回绕；编号耗尽要先完成受控排空/重新准入。

局部R提交只更新其本地状态。整层递推的MEM old/next仍由显式服务维护，全部分片及消费者成功后才由母控发布next根；失败保留old根。最终输出前缀和外存写无全局回滚保证，partial=0不等于没有可见副作用。成功DONE、错误DONE和硬复位取消分别记录，不伪造完成。

## 8. 编译和部署路线

1. 模型图导入，显式标注shape、定点格式/尺度、舍入/饱和、状态和依赖。
2. 降到注册的基础宏/适配服务；不支持的EXP系数、宽归并或数值合同明确报错。
3. 根据同一资源池安排宏上下文、Block、私有S对象和MEM分片，生成峰值资源及带宽账。
4. 根据真实端点图做路线绑定，输出生产者/消费者先后关系和所需确认。
5. 生成G_*粗程序、各Block的L_*程序及描述符；执行指令、寄存器、PC、资源、地址/对齐、格式、令牌、对象及步骤预算检查。
6. 编码为小端镜像，绑定program_image_id/topology_id/native_abi_id/capacity_profile_id及完整SHA；程序、金属和参数版本一起交付。
7. 软件解释器、RTL、真实数据/非零状态和最终物理逐级接收；仅编解码成功不能作为完整模型编译成功。

该版本给出24种操作码、128bit指令字段、9类记录布局和参考codec。完整镜像装配器、原生服务参数注册表、资源/生存期编译器、执行解释器和RTL尚待研究步骤落实。编译器遇到未注册的原生ABI/service必须拒绝，不能透传未知参数后声称可执行。
