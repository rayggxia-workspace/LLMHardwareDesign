## 1. 阶段性判断

运行这些模型的目的，是用真实工作负载约束预制底座的能力、数据格式、状态和接口，再比较物理划分的候选方案。模型数量本身不是研究进度指标。

已有证据主要推进了五件事：

1. 建立整段、使用缓存和分块执行的一致性参考，识别执行顺序、精度及后端造成的差异。
2. 用真实激活和状态排除过于简单的统一量化假设；没有饱和不等于误差小，增加位宽也不等于扩大范围。
3. 明确完整归约、scale 单位对齐、宽算术、状态版本和发布规则，形成可验证的接口义务。
4. 将 KV 共享、窗口、动态专家分发和持续状态纳入容量、带宽、端口与控制预算。
5. 为近 M 重定标、共享 V、独立 R 等选择建立受约束比较；所汇总的服务结果仍不足以冻结物理宏边界。

**建议保留 P1–P15 作为能力清单，以 M/V/A/R/S/D 组织逻辑功能，并把物理宏的拆分、合并与数量保留为实现及评估变量。** 六类逻辑组织可作为研究框架；八个模型的软件实验不能独立证明同一预制几何和受限定制层已经适配全部目标。

## 2. 为什么选择并运行这些模型

对本项目而言，模型应覆盖不同的数据流和状态关系。权重大小影响部署成本，但不能替代结构覆盖。

| 具体模型 | 选取目的 | 实际覆盖范围 | 已获得的主要认识 |
| --- | --- | --- | --- |
| Qwen3-0.6B | 以较小模型建立真实参考、缓存与分块流程；作为已有算子实验的起点 | CPU FP32/BF16、线程配置、28 层 KV/logits 一致性；本报告以 CPU 迁移批次为定量来源 | FP32 可作本批次参考；BF16 的部分线程条件有可重复失败，需固定后端和数值合同。[S01] |
| Qwen2.5-3B base | 常规 GQA、共享 KV、投影与 QKV bias 的对照 | CPU layer0、完整一组 8Q/1KV；128/1024 prefill 后 32 步 decode；另有既有 GPU 批次 | 激活分组、KV 精度和归约单位都会影响设计；bias 也须进入整数对齐合同。[S04][S08][S09] |
| Qwen3.5-4B，文本路径 | 检查全局注意力与连续卷积、递推共存的需求 | CPU 全局 layer3、一组 4Q/1KV；连续状态及旧长窗后续整数探针 | 状态范围、单位、历史和失败恢复必须明确；部分早期状态实验仍保留浮点计算。[S04][S05][S09] |
| Gemma-3-4B-it，文本路径 | 检查局部/全局注意力、窗口边界与不同 GQA 比例 | layers0/5、一组 2Q/1KV；长度 128、1023、1024、1025、4096 后 32 步 decode | 概率/KV 格式与窗口存储生命周期不能省略；未执行多模态路径。[S04] |
| Phi-4-mini-instruct | 为冻结方案保留独立验证对象 | layer0、一组 3Q/1KV；128/1024 后 32 步；参考和张量采集后封存 | 只证明所测参考与采集完成，未用于量化/划分调优，尚无冻结后保留集验收。[S04] |
| Llama-3.2-1B-Instruct | 检查 Qwen 的整数语义和量化策略是否可迁移 | 本机 layer0、一组 4Q/1KV；prefill32+decode8；完整 K 的投影切片及扩大校准 | GQA 合同有可复用部分，统一静态激活 scale 却出现严重信息损失；不能按品牌共用未经验证的量化配置。[S02][S03] |
| Granite-3.1-3B-A800M-Instruct | 补上 MoE 动态路由、专家选择、分发与合并 | 参考路由；后续 layers0/13、cal/eval 各 72 行的完整整数 MoE 切口 | router 精度和全部所选专家/合并路径需共同考虑；活跃参数少不等于全部专家权重可常驻。[S06][S07] |
| Falcon-H1-3B-Instruct | 补上 Attention/Mamba-2 混合结构与另一种连续状态 | layer0 完整整数 R 分支、32 heads、72 步及完整消费者；Attention 和 MLP 在切口外 | 因果重定标、连续卷积历史、状态提交和完整消费者得到更强软件证据；仍需区分局部整数闭环与整模型。[S06][S07] |

“完整一组 GQA”指一个共享 KV head 对应的全部 Q heads，不等于所有层和所有头。“完整 K 的投影”也不等于完整输出维度：服务器批次的 q/o/down 探针只取前 16 输出。校准与评价文本分离，但该批校准仅捕获 16 个代表行，不能把输入文本长度当作独立校准行数。[S04]

### 2.1 权重大小应怎样进入 benchmark

应同时记录两条轴：

- **结构覆盖轴**：GQA 比例、Q/K norm、RoPE、窗口、递推、专家路由及状态生命周期，用于检验能力与接口。
- **部署规模轴**：实际格式下的权重、scale、LUT、激活、KV、持续状态、临时空间和外部供给，用于检验容量与服务成本。

例如 Granite 被测单层 40 个专家的 W8 权重为 94,371,840 B（90 MiB），静态 scale 另需 614,400 B；两个所测层不能同时驻留在该服务假设的 EXT128MiB 中。Falcon 单层完整 S32/S16 状态分别为 4/2 MiB，还需卷积历史、旧新代、单位与中间值。这些成本不能由参数名称或“全部字节除四”推算。[S06][S07]

因此，小模型适合快速发现合同错误；部署可行性仍需实际形状、精度、上下文和资源预算。现有八模型不能代表任意架构，Gemma/Qwen3.5 的文本路径也不能替代多模态验证。

## 3. 主要实验结果及其含义

### 3.1 先建立可靠参考：一致性通过不等于模型质量通过

Qwen3 CPU 迁移中，FP32 的 8/16/32 线程条件均通过整段、缓存和分块检查；BF16 的 8/16 线程条件各有 17 项超过事前 2% 迁移探索门，32 线程条件相等，第二轮重现。报告尚不能定位具体内核或归约路径。[S01]

服务器四模型的新参考来自原 BF16 权重加载为 CPU FP32。所选 GQA 和最后 33 个位置 logits 的一致性检查全部通过，但这是固定 token 输入下的执行一致性，不是数学、代码或语言任务质量评测。[S04]

GPU 批次也必须读取修订链：早期 Qwen3.5 的长状态、显存和低精度失败保留；后续固定 INT8 矩阵加规范 FP32 辅助计算，在所测至 8192 的整段/分块与 decode 对照中得到逐位一致。该结果绑定特定运算顺序和浮点辅助，不能改写为完整整数推理。原 GPU 包还包含有限语言敏感性诊断，不能笼统说“完全没有做质量检查”；它们同样不构成八模型统一应用质量验收。[S08][S09]

**设计含义：** 参考精度、运算顺序、缓存语义和误差门应先冻结；不能将参考后端的差异归因于 Block 划分。

### 3.2 投影量化：scale 粒度改变误差，也改变边界成本

下表来自服务器批次。指标为各模型/层所测 prefill/decode 切片的最坏最终输出 relative RMSE；完整 K、前 16 输出、相同输出合同。5% 是事前局部探索门，不是应用质量预算。[S04]

| down_proj | 静态全 K A / 每输出 W | 动态整行 A / 每输出 W | 动态 K128 A / 每输出 W | 动态 K128 A / 每输出 K128 W |
| --- | ---: | ---: | ---: | ---: |
| Gemma layer0 | 28.40% | 14.03% | 4.08% | 3.81% |
| Gemma layer5 | 21.22% | 18.23% | 4.21% | 4.00% |
| Qwen2.5 layer0 | 27.45% | 18.27% | 3.48% | 3.37% |
| Qwen3.5 global layer3 | 8.58% | 5.32% | 4.93% | 4.83% |

Llama 首批静态 down 输入约 99.84%–99.89% 变为零，输出局部误差 70.34%–82.87%；动态整行降至 6.17%–16.86%。后续扩大独立校准并比较粒度，最佳动态 A/W K128 的最坏误差仍为 5.39%，24 个候选均未过冻结的 5% 探索门。零最终饱和和零累加溢出没有阻止信息损失。[S02][S03]

不能由上表得出“所有线性都已通过”：Gemma 的部分 q/o 投影即使局部 RMSE 小于 5%，仍有输出饱和。Qwen3.5 down 的一项最坏误差在最终 RQ 前约 0.84%、RQ 后约 4.83%，说明输出格式也值得检查。[S04]

**设计含义：**

- 动态 K 组 scale 是有依据的候选，但不能给所有算子强制同一粒度。
- 同一单位内的 INT32 部分和可直接归约；跨组单位不同时，需显式对齐和范围证明。
- 对齐、scale 生成、元数据、重读、端口和宽归约都要计成本。
- “完整归约后一次最终 RQ”应作为所选数值合同，而不是由 placement 偷换舍入顺序。

真实输入已经给出反例：Llama 首批每 K128 提前 RQ/饱和再相加，改变了 28,950/43,520 个输出。这属于另一数值函数，不能当作同精度划分的公平基线。[S02]

### 3.3 注意力：KV、概率和投影需要分别定格式

服务器批次的注意力探针保留全部有效 keys，但只选择部分 queries；exp/div 使用明确的 FP64 辅助。P8/P16 表示非负概率的 P7/P15 有效码、分别以 I8/I16 存储，不能与 P1–P15 能力编号混淆。[S04]

| 被测 GQA 组 | KV8 / 概率 P8 | KV8 / 概率 P16 | KV16 / 概率 P16 |
| --- | ---: | ---: | ---: |
| Gemma local layer0 | 34.47% | 3.52% | 0.50% |
| Gemma global layer5 | 6.89% | 4.49% | 1.74% |
| Qwen2.5 layer0 | 13.98% | 12.50% | 0.58% |
| Qwen3.5 global layer3 | 23.37% | 2.88% | 0.95% |

指标是该组所选查询的最坏局部输出 RMSE，不是整模型排名。Qwen2.5 在该合同下更受 KV8 影响；Gemma/Qwen3.5 所选组对低概率精度敏感。概率中的零还包含因果/窗口 mask，不能全部解释为量化丢失。

若仅有 S8 乘法单元，某些 16×8、16×16 运算分别需要 3、9 次 radix128 基础乘积，以及移位、合并和搬运；这不是免费的 INT16 能力。PV 的 INT32 可行性还依赖归一化概率总和上界、固定 head scale 和长度条件，不能把所有概率码当任意独立整数，或将该证明推广到另一种 online attention 反馈函数。[S04]

**设计含义：** A↔M/V/S 的接口要保留单位、有效长度、mask、KV scale/版本和适用的概率预算；“支持 W8A8 投影”不足以自动覆盖 QK/PV。

### 3.4 窗口与 GQA：数学共享不等于免费物理共享

Gemma 的 1023/1024/1025 边界用于检查窗口语义。其原生 FP32 4096+32 条件下，KV 逻辑容量约 393.02 MiB，而 full prefill 保留的底层 storage 约 1096.5 MiB；view 可以保留更大的 base。不能将框架分配当成硬件必需 SRAM，也不能只用数学活跃窗口估算所有工作区。[S04]

同一 KV head 服务多个 Q heads，可以采用重复读取、复制缓冲或广播。Llama 被测组 40 token 的 K/V8 逻辑数据为 5120 B；若逐 Q head 复制则为 20,480 B。这说明共享值得保留，但实际端口、分发和生存期仍须验证。[S02]

**设计含义：** P9 搬运、P11 重排、P12 分发/重复读与 S/D 的合同需分别定义，不能被“有 DMA”或“有缓存”替代。

### 3.5 持续状态：位宽、范围、代际与恢复是不同问题

Qwen3.5 后续范围实验明确比较静态饱和诊断、越界拒绝和因果重定标。固定旧 layer0/end8192 的 S32 256 步窗中：

- 静态合同出现 193 次 state 饱和。
- guard 在第 4 个 token 拒绝，零发布饱和不代表完成全部输入。
- 因果重定标两波后完成 256 步，零发布饱和；仅重编码读写为 262,144 B，完整重试、备份与端口成本另计。
- adaptive 改变了数值合同；它与静态合同的误差差异不能作为纯 placement 收益。
- 这一阶段的 R 内部仍保留明确的非线性和归一化浮点计算。[S05]

Falcon 后续完整整数 R 分支覆盖输入 RMSNorm、投影、持续卷积、全 32 heads、4096 维共同消费者等，在当前 72 步因果重定标合同下零发布状态饱和。full S32 的 nextnorm 局部 relative L2 约 3.0289%，S16 约 3.0297%；增加状态位宽没有明显改善这项下游误差。Attention 和 MLP 仍处于外部切口。[S06]

**设计含义：** R 的接口不能只有 state 指针。需要 owner、位置、单位、scale/epoch、版本、相关卷积历史及提交/中止语义。范围守卫应在不可逆裁剪前生效；失败后重试必须能恢复合法旧状态。共同提交是逻辑可见性要求，不自动强制同一周期或整份双缓冲。

### 3.6 MoE：路由正确性与专家计算误差应分开

Granite 较早 router 探针冻结同一上游 hidden，动态 W8A8 的 top8 集合改变为 720/6912，动态 W16A16 为 6/6912。这里的 6912 含 32 层、3 个执行 profile、72 token，profile 有相关性，不能视为独立统计样本。保守选择性证书使全部行先 W8 再 W16，不能按“偶尔回退”预算。[S06]

后续两层整数切口串起实际路由、全部所选专家、gate、加权合并、真实残差和后继归一化。R16 评价的 nextnorm 局部 L2 在 layer0/13 分别约 8.6287%/1.0196%。两层最终专家集合与 native 相同，也不能证明 router 自身稳健：layer13 对同一当前 norm 的 FP64 router 仍有一处差异，上游与路由误差发生抵消。[S07]

完整切口数学接收通过，只证明执行了冻结整数函数；没有 Granite 有限专家分页/merge 的完整服务验收，也没有整模型质量结论。全 8 路 S32 输出为 49,152 B，S64 merge 为 12,288 B，另需 6144 B 输出，不能免费放进 V16KiB。[S07]

**设计含义：** 动态 ID、gate、专家权重供给、宽合并、tile、背压及高精度/回退都要有真实资源，不能按观察到的专家集合固化连接。

### 3.7 服务比较：先守恒数值函数和资源，再解释差异

| 来源与任务 | 已记录的条件结果 | 正确解释 |
| --- | --- | --- |
| Llama 首批近端/共享 RQ | 48 个包络对照中近端 47 快、1 略慢，最大下降 0.4049% | 有条件的服务差异；还不是完整 attention/FFN 或目标电路。[S02] |
| Llama K128/W128，limb2 | 所列 1/4 行 tile 的近端模型周期分别减少 1.385%/2.334% | 同时要披露该批候选未过局部精度探索门；不能称可接受应用的加速。[S03] |
| Falcon R/V 部署 | 所列同精度部署差小于 0.02%；纯标签对照为零差 | 不能由名称判断独立 R 或合宏必胜；宽算术成本假设可能更重要。[S06] |
| Falcon 输出投影，whole/K512/K256 | 每个固定函数内 near M 相对 shared V 的完整链时隙下降约 0.001007%/0.008010%/0.016005% | 三种粒度是不同函数；驻留比较也不是已实现物理邻近性，不能据此冻结 M/V 融合。[S07] |

不同报告的分母、数据格式、打包及算术模型不同，不能把百分比排列成逐轮加速曲线。减少逻辑字节也不必然缩短时隙：包头、对齐、银行冲突、有限队列和其他瓶颈可能抵消收益。

## 4. 从实验回到 P1–P15 能力清单

以下是需求映射，不是已经全部通过资格验证的资源库存；一个能力可由多个逻辑域共同实现，表中的归属不意味着复制硬件。

| 能力 | 需明确的子合同 | 主要逻辑域与实验联系 |
| --- | --- | --- |
| P1 乘加、点积、分块累加 | 操作数符号/位宽、组内累加、部分/完整结果、溢出和反馈 | M；A/R 调用。不能用 W8A8 资格代替所有宽点积 |
| P2 基本逐元素运算、广播 | operand 单位、广播轴、残差系数、舍入点 | V，A/R 调用；算术广播与 P12 的物理分发分开 |
| P3 分段归约、平方和、行点积 | 完整归约域、跨组对齐、partial context、全 hidden barrier | M/V/A/R；K 分组和 RMSNorm 的直接约束 |
| P4 EXP/EXP2 | 有效域、输入输出单位、误差、表版本及吞吐 | V/SFU，A 与门控调用；可由 P8 实现 |
| P5 倒数、倒平方根 | 近似或精确合同、除法/开方/平方和宽度、异常域 | V/SFU；不能只凭名称认为整数 RMSNorm 已被覆盖 |
| P6 比较、选择、带索引极值 | topk/tie、阈值、范围守卫、动态 ID 输出 | V/D，A/R；MoE 路由与状态 guard |
| P7 转换、量化/反量化、缩放/饱和/打包 | scale 粒度/版本、RNE、饱和、完整归约后的最终 RQ | M/V/D；动态量化及 metadata 一起发布 |
| P8 查表、可选插值 | 表容量、格式、寻址、端口及离线编译边界 | V/S/D；不能给 EXP、SiLU 和 gate 重复或免费分配表 |
| P9 stride load/store、二维 DMA | tile/stride、地址边界、带宽、对齐、端口冲突 | S/D 与计算端点；不自动包含 P10 |
| P10 Gather/scatter、间接寻址 | 动态 ID 到合法对象、分页、完成和访问范围 | S/D；MoE dispatch 不能由普通 stride DMA 推定具备 |
| P11 转置、重排、切分、合并 | view 与实体搬运、bank 布局、暂存、重排吞吐 | S/D/计算端点；不能视为零成本连线 |
| P12 一对多分发、数据保留与重复读取 | 固定扇出、复制缓冲或重复读的选择及生命周期 | S/D/A；GQA 共享 KV 的物理实现 |
| P13 状态/累加上下文读改写 | owner、单位、位置、epoch/version、提交/中止与恢复 | M 部分和、A 上下文、R 状态、S 后备，生命周期不同 |
| P14 循环、地址步进、动态索引 | 有界循环、窗口/位置、索引合法性、动态工作集 | D 与各端点；不能以万能控制器掩盖缺失能力 |
| P15 命令队列、事件/信号量、完成/同步 | 有限深度、背压、迟到响应、数据可见性和等待关系 | D 与各端点；数据和 metadata 的发布顺序需要可验证 |

P1 与 P3 的点积/归约存在交集，P4/P5 可借助 P8；因此这是一份覆盖清单，不是互斥的十五个物理宏。当前优先补齐格式、单位、生命周期、端口和服务合同，不必为增加数量而另列类别。

## 5. 六类逻辑组织与物理 Block 应如何衔接

| 逻辑域 | 目前应保留的职责 | 仍需比较的物理选择 |
| --- | --- | --- |
| M：矩阵/部分归约 | 同单位 MAC 反馈、带类型的 partial/complete、合法宽路径及端点 | 近 M 对齐/RQ 或共享 V；专用宽单元与分解复用 |
| V：向量/归约/函数 | 全 hidden 统计、残差、转换与非线性、参数/表版本 | 流式或两遍读取、共享 SFU/ROM、子单元端口 |
| A：注意力逻辑域 | mask、KV 版本、score/概率归约、有效长度与共享 KV | 调用 M/V，局部闭包或独立单元；不能从逻辑域推定单独硬宏 |
| R：递推逻辑域 | 持续历史、状态单位/代际、局部反馈、guard/提交与恢复 | 独立 R、共享 V、M 复用、shadow/spill 与 tile |
| S：存储 | bank、容量/端口、对象生存期、布局与后备状态 | 分布式或集中式；不将语义窗口等同实体缓存 |
| D：搬运/控制 | 地址、命令、队列、动态分发、credit、完成与错误 | 控制分布、固定连接与端点协议；所有能力需有限资源 |

M/V/S/D 更接近资源模板，A/R 更接近复合数据流与状态域；这六类尚不是完全互斥的物理分区。局部数值闭包要求保留相关数据与不变量，但允许通过合法接口拆分。选择物理宏需要比较：

1. 独立并行执行、吞吐或专用结构带来的收益。
2. 位宽、存储与端口不兼容造成的共享代价。
3. 拆分新增的中间流量、缓冲、队列、端点及电气时序代价。
4. 合并后的闲置资源、复用效率和对其他模型的影响。

任何比较都应保持同一数值函数、总算术资源、存储与端口边界，再将候选落实到实际实现。最终跨模型验证还应固定 Block 类型/数量/位置、预制线、端点、缓冲/寄存器及电源/时钟资源，只允许声明集合内的金属/通孔变化。[项目定义](../../预制计算底座项目说明_v1.0.md)

## 6. 现有证据能支持什么，尚不能支持什么

| 可以据来源提出的判断 | 需要继续限制的表述 |

## 7. 后续研究应优先解决什么

以下为分析建议，不是本次启动的新实验。

| 顺序 | 待解决问题 | 必要证据 |
