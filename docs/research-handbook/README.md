# 从真实模型到 Block 电路：项目研究总报告与入门教程

整理日期：2026-10-26，中国标准时间。任务：[Issue117](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/117)；整理者：Liangruizhi。本文档组汇总已有工作，不启动新模型、RTL 或服务器实验。**原实验做过什么，与本次重新核对过什么，是两件事。** 原运行事实引用固定提交的报告；本次核对来源文档原字节、任务状态、关键数字及解释，不把阅读报告写成独立重跑。

我们共同回答的问题是：

> 给定几类有差异的 LLM 工作负载，哪些计算、状态和通信应当在制造前固定在一个 Block 内，哪些连接值得留到产品确定后再定制？在真实存储、端口、布线和时序约束下，这种划分能带来多少端到端收益？

这份报告从输入、运算和输出讲起。它既说明已经得到哪些依据，也保留失败、假设变化和仍缺的证据。读完后，应能解释为什么“矩阵用 INT8”“把相邻算子融合”“少传四分之三字节”都还不足以回答这个问题。

## 先说明“完成”的实际含义

本项目已经形成有证据的算子组织和可继续实现的 Block 电路候选。它包含完整归约、显式单位、共享 KV、连续状态恢复、动态专家分发、有限存储、响应所有权及原子发布等合同。部分合同已落实为实际 RTL，部分核已完成有限研究条件下的物理验证。

**最终制造前的 Block 物理边界、真实存储宏、全系统映射与端到端收益仍未全部验收。** 这不否定已经完成的工作，而是说明每一项成果适用到哪里。例如，一条真实 V→M 消费者链布线通过，不等于新增 GDN 后的四类共享顶层自动拥有相同的时序和面积资格。

| 层级 | 输入与实际工作 | 当前可用证据 | 不能替代的下一层 |
| --- | --- | --- | --- |
| 原模型参考 | 原始权重、固定 tokens，比较整段/缓存/分块 | 八模型中各自声明范围的参考与采集；Granite 保留参考失败和后续修订 | 整数质量、硬件执行 |

## 八个实际模型的总体位置

| 模型 | 用来检验什么 | 最重要的已知发现 | 下一步仍受什么限制 |
| --- | --- | --- | --- |
| Qwen3-0.6B | 小模型真实参考、GQA、量化及端口方法 | 临时数据和持久 KV 必须分开；固定校准须覆盖整个 GQA 组 | 短切片和 FP32/整数条件各自有效，不是全模型整数验收 |
| Qwen2.5-3B base | 普通 GQA、QKV bias、不同激活分布 | K 分组与 KV16 显著影响局部误差；bias 需整数对齐 | GPU 真矩阵仍有浮点辅助；局部格式不能代表整模型质量 |
| Llama-3.2-1B-Instruct | Qwen 方案的跨模型反例 | 静态 down 输入近全零；K128及输出合同改变误差，也增加单位和端口成本 | 原 5% 探索门失败保留；新合同改善不是新保留集通过 |
| Gemma-3-4b-it 文本 | 局部/全局注意力、窗口、归一化 | P/KV精度分别重要；view 保留对象不等于数学活跃窗口；gamma=1+weight | 未测多模态，部分投影仍有饱和 |
| Phi-4-mini-instruct | 冻结方案后的保留验证 | 原参考、GQA捕获与来源检查已完成 | 数据封存，未用来选精度/划分，冻结后验收未执行 |
| Qwen3.5-4B 文本 | GQA 与 GDN/卷积连续状态 | 位宽不能代替范围；必须全 head 重标，双 head 一致发布 | 完整整数模型与整个状态生产/消费链未全部硬化 |
| Granite-3.1-3B-A800M-Instruct | 稀疏路由、专家、加权 merge | 路由对微扰敏感；全部所选专家与宽 merge 必须收费；生命周期能修正容量排除 | 局部完整链不代表全模型质量；物理宏归属未定 |
| Falcon-H1-3B-Instruct | Attention/Mamba-2 并行、另一种 R | 完整 R 分支整数化与因果重标可执行；跨 head norm 不能各头独算 | RTL 只覆盖声明 head；整分支、Attention/MLP 及长程仍分层 |

这张表是证据分工，不是模型性能排名。不同模型的误差来自不同层、长度和切口，不能把百分比排序就宣布哪一家更容易做硬件。
