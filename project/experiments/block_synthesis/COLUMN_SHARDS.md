# 完整 K 的输出列分片与前沿成本

此功能为可选共同动作池：`full_plan.py --prepare-reuse --primitive-stages --read-cache --state-cost --column-shards`。
同一硬件、数值、外存和静态线束预算下，贪心、启发式和有界 DP 均可使用全部新旧候选。
不能把从旧动作池到新动作池的整体变化算成 DP 独有收益。

## 执行合同

`column_shards.variants_for()` 从输入清单枚举 M 实例。仅覆盖已有 prepared-A、S16 B、M-only 的 Dot 执行阶段。
将输出列 `[0,N)` 分成正宽、不重叠、完整覆盖的区间；每个子服务拥有独立 M、私有 S、局控服务 token 和累加上下文。
每个输出保持完整 K 累加和一次最终舍入；准备阶段仍只有一次，外存地址/容量和所有最终写确认保留。
共享内存通道的子服务按实际资源日历串行，不以宏数除总时间。

静态候选包括均分及按通道共享数分配列宽、子服务发出顺序，以及流式/最大合法前缀缓存。
旧的单实例及其缓存方案完整保留。默认最多四个分片、每任务512个静态组合；达到上限会报告截断，
不以有界候选或窄 beam 的失败证明硬件无解。实际九组实验未触发静态候选截断。

`parallel_shards.children` 保存每个区间与完整叶服务合同；`transition.evaluate_transition()` 在当前前沿上逐个求值。
每个孩子分别使用自己的资源就绪时间、S 内容和 preserve/shrink/discard 策略，父节点完成时间取实际子节点完成的最大值。
全产品静态网取并集，仍受互斥/预算/未来覆盖检查约束。历史中每个服务的真实 start/end、缓存命中及描述符读写数均保留。

## 在每个前沿决定列宽

`dynamic_columns.py` 只为资源集合完全互斥的孩子添加动态列宽族。对于孩子 i：

```
a_i = max(数据就绪, 孩子的各资源最早空闲)
d_i(w,S) = alpha_i * w + beta_i - load_ticks_i * 已复用前缀字数(S)
F_i(w,S) = a_i + d_i(w,S)
```

在当前前沿二分最小整数 T，要求每个选中孩子至少一列，并且
`sum_i floor((T-a_i-beta_i+hit_saving_i)/alpha_i) >= N`。
据此生成完整区间、重算原生命令及缓存冷/热读数，写入 `resolved_columns`；成本没有提前冻结。
这只是一次状态转移内部的精确整数分配，外层仍是同一个有界前沿搜索。
共享通道、任意通信等待和非仿射代价不符合本公式，不使用该动态族；保留静态候选或单实例执行。

`verify_primitive_cost.py` 独立重推每段命令、缓存读数、资源、S 和精确端点集合。
`verify_loop_dp.py` 独立重建被选择的列宽和成本，再检查所有子服务的依赖、时间、缓存、资源与静态网；
它不调用规划器的分片/转移函数。数值回放使用真实 B 列区间和每实例有限 S。
小例另以穷举整数列宽及独立完整调度对照。

## 当前局限与下一轮

当前资源日历仍将内存通道锁到整个服务结束。`phase_accounting.py` 只诊断此保守预约，未改变规划语义。
`phase_trace.py` / `systemc_phase.cpp` 用原生命令与描述符时序做独立小型事件对照，尚未建立整模型阶段调度资格。
这些共同后端扩展和 SystemC 小实验均不计为算法约20%收益。

下一轮需要事件驱动的前沿：状态包括当前时间、完成/就绪任务、正在执行服务的阶段/剩余循环、
有限 S/上下文、通道队列及静态网；动作决定启动哪个合法服务或推进至真实完成事件。
M/局控/累加器从获得到释放持续占用，内存通道仅在已声明 LOAD/STORE 至确认区间占用。
不能把命令总量分成“先全部读、再全部算”来假设 S 装得下，也不能简单把通道从资源表删掉。

长循环必须以经逐事件对照的周期压缩/快进表示，避免展开数十亿命令。
任何快进状态必须保留阶段位置、未确认请求、队列、S/缓存/累加上下文和剩余循环数，
不能只按平均带宽或 MAC 数推吞吐。新动作、成本和日历必须同样提供给强贪心/启发式，
与独立检查器、有限 S 数值和原生 RTL/SystemC 子集对照后，才能形成新算法收益结论。
