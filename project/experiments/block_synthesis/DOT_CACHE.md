# 只读矩阵乘分片如何进入前沿 DP

范围是综合：同一整数程序、宏实例和数值规则，搜索实例绑定、有限 S 分片和执行安排，输出逻辑连接需求。局控整网编码和物理布线在后续阶段。这里不新增作者维护的 JSON。

## 一次转移具体做什么

1. 从 ONNX 降低得到已验收的 `Dot(A,B)`，读取输出行数 R、列数 N、规约长度 K，以及每个操作数实际需要的 S16 分量数 a、b（1 或 3）。
2. 从硬件清单读取每个 M 的归属、独立私有 S 容量、IO、上下文和原生命令时间；仅为串行 S IO 生成本次候选。
3. 枚举 A 前缀长度 t：0、能装下的 2 的幂、最大合法长度；同时保留原来全部写回的候选。上限为 `min(K, floor((S_words-9)/(R*a)))`。不会要求整行或整个权重进入 S。
4. 保留原有算术和 STORE，改变 partial 读操作的地址：A 前缀来自 `S[9:]`；一项 K 的 B 分量复用 staging；零包来自 `S[8]`。其他部分继续使用外存。
5. 搜索状态多记一个表：每个 M.S 当前保留的 SSA 输入 ID、完整输出行索引形状、K、分量数、前缀长度。相同输入、索引和格式才能命中；不同 SRAM 的内容不能互用。
6. 根据实际命中与否，计算本次外存读字数和时间。保留后的 S 地址范围持续占用，直到同一 M.S 的另一个缓存候选覆盖它；其他任务只使用原来的 `S[0:8]`。相同任务位置、时间和连接而缓存内容不同，必须保留为不同状态。

调度仍逐个完成 M 的全部 K 累加，再读最终结果、写外存并等 ACK。前缀缓存不代表同时有多个累加上下文。没有新增 S64 累加器导出、打包硬件、选择器或理想 DMA。原生 `split32`、每次 partial 的运算、最终舍入及所有 STORE 均保留，因此这个版本仍有明显可优化空间。

## 代价是怎样算出来的

只看 Dot 的 partial 所需外存读；其他原生命令、读写和数值计算不变。

| 实现 | 128 位外存读字数 |
| --- | ---: |
| 原来每次都读 A、B、零包 | `3*R*N*K*a*b` |
| 冷缓存 | `R*a*t + R*N*a*b*(K-t) + R*N*K*b + 1` |
| 已保留相同输入且长度至少为 t | 冷缓存减 `R*a*t` |

独立检查器从实际 Dot 指令、硬件清单和原生模板重新推导以上量；测试还逐条枚举小矩阵的 A/B/零包访问，与公式比较。每个真正消除的读，只扣除一次原 #182 单字 LOAD 的模型时间；所有原来的宏命令和本地读时间保持。没有把存储容量直接当作时延，也没有把模型时间称为实测周期。

例如 R=2、N=3、K=5、a=3、b=1、t=2：原来 270 次 partial 外存读，冷缓存降至97次，热缓存85次；本地占21字，即336B。其他准备命令和写回没有因此消失。这是解释访问的例子，不是测得的硬件性能。

## 为什么还需要搜索

同一输入可能由 P0.M 或 P1.M 执行。P0 的 S 中可能已经有它，而 P1 可以更早开始；选择 P1 还可能新增连接或与已有静态网互斥。候选的时间与前一个状态中的 S 内容有关，不能事先给每个算子一个固定代价。

状态为 `(已安排任务, 完成前沿, 资源日历, 静态连接并集, 各 M.S 缓存内容)`。只合并这些未来可见量相同的状态，使用允许全部缓存命中的关键路径作为乐观下界排序，截取有限 beam。宽度1和宽度8使用完全相同的候选；结果保留合法的宽度1回退。**有界搜索不保证全局最优。** 当前候选中较长缓存常常占优，所以必须用实验区分缓存设计收益和 DP 搜索收益。

## 验证和边界

- `verify_primitive_cost.py`：独立推导原生工作量、冷/热搬运及时间、缓存身份和地址；不导入 `dot_cache.py`。
- `verify_loop_dp.py`：独立重建缓存命中、跨任务 S 驻留区间、容量、时间、资源和所有静态连接互斥；错峰不能豁免静态互斥。
- `dot_cache_replay.py`：按选中的内核顺序解析指令依赖，实际写入/读取有限 S 分量数组；缓存内容参与整数 Dot，检查陈旧值和边界。数值回放仍使用完整整数原语模拟器，并非整个 RTL 或 DMA 协议仿真。
- 全模型对照同时保留：原全部写回、有复用贪心、有复用 DP、等逻辑连接预算。完整模型数值与旧整数程序逐位比较，并继续检查原 HF 门槛。

本版仅有只读 Dot 缓存，跨任务命中要求相同 SSA 输入；不搜索任意跨层脏结果、重算、通信与计算重叠，也未减少已预留的外存容量。更大的上下文可自动选择更短前缀，装不下时保留全部写回；不支持的算子仍显式拒绝，不能据此保证任意 3B 模型都已支持。

借鉴：[Timeloop，ISPASS 2019](https://people.csail.mit.edu/anurag_m/papers/2019.timeloop.ispass.pdf) 的循环/存储复用表达。这里只借鉴表达与分片思想；没有移植其搜索器、代价或最优性结论。跨层一般缓存和脏数据生命周期可以进一步参考 Stream，但本版尚未实现，不能算作已移植成果。
