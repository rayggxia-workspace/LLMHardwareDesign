# 外存重复访问与有限 S 的下一轮优化合同

2026-11-09；Issue219/PR220。**当前尚未实现一般 tile 驻留或跨算子中间结果驻留。**
现有只读 Dot 前缀缓存能省部分读，完整后端仍保留大量外存往返。不能将排程改善等同于消除搬运。

## 当前实际选中计划

对已资格化 Qwen2.5-3B 全36层、B1/S2 prefill、无KV的九组18束静态计划，
`traffic_accounting.py` 先调用两个独立检查器，再逐个展开选中的子服务，重推其读取并守恒到总数：

| 逻辑128位标量记录 | 字数 |
| --- | ---: |
| A未驻留部分的重复读取 | 17,315,923,200 |
| 静态B权重读取 | 6,171,394,048 |
| A前缀填充 | 335,532 |
| 动态B读取 | 1,769,472 |
| 零包 | 578 |
| 缓存Dot中的其他原生读 | 4,718,592 |
| 缓存Dot写回 | 4,287,488 |
| 其他服务读 / 写 | 2,362,858,936 / 457,094,572 |
| 总计 | 26,318,382,418 |

A重复读约65.8%，静态权重约23.4%。按每记录16B计为421,094,118,688B，
**这是保守执行器的逻辑记录/描述符账，不是已测DRAM总线流量、工作集容量或能耗。**
一个记录常只承载一个S16分量；不能用张量的有效字节替换传输字节，也不能凭空假设打包适配器。
完整原件和输入SHA见[本地审计](../../../work/YUZE-LU/219/throughput-opt/results/column-memory-local/traffic-accounting.json)。

设输出R行N列、归约K，A/B分别有a/b个分量，缓存前缀t、已有命中h：

`A读取 = R*a*(t-h) + R*N*a*b*(K-t)`；`B读取 = R*N*b*K`。

当前S布局要求 `9+R*a*t <= S_words`，且每次完整K归约和最终STORE/ACK保留。
同一M只有当前命令允许的累加上下文，不能把逐输出的循环交换为K在外层、任意多列在内层，
同时假设所有未完成的S64结果都仍在宏里。

例如R=2、K=2048、A用三个分量，完整A按当前记录需196,608B；16KiB S只能留最多169项K前缀。
这个限制由实际布局/格式得出，不是“16KiB足够装下一层”的判断。

## 能合法引入的选择

1. **算子内部tile。** 从已注册M命令的行数、列数、K段、格式和累加合同导出候选。
   当前M原生最多8行/8列、每段K最多32，不能解释成64个独立完整程序上下文；双输入bank也不复制计算阵列。
   一个多列tile可以在宏允许的范围内共享A，多个输出行可以共享静态B；必须完成相同完整K与同一最终舍入。
2. **有限S布局与供数。** 为A/B/输出/系数/描述符分配真实窗口。静态权重可明确离线重排；动态A的分量打包、
   gather/散布必须有真实原生命令或已验收适配通路。缺服务的候选直接拒绝，不能只减少JSON中的读取数。
   #234/#235正在做原生tile与功耗校准；其未发布工作文件不作为本PR已验收的完整数据通路。
3. **跨算子驻留。** 决定哪段SSA中间结果留在何处、消费者是否真的能从该S取到、最后消费/发送ACK何时发生。
   在S冲突时比较写回、换位置或别的已注册配方；脏数据不能按只读缓存随意丢弃。重算须单独注册等价配方。
4. **分阶段日历。** 通道在描述符提交/ACK后才能释放；M、S端口和LC的持有区间按真实命令分别确定。
   省掉访问与重叠访问分开记录。现有阶段实验仍是常量描述符成本模型，不提供真实银行、行缓冲或RTL仲裁资格。

一般DP/贪心转移必须根据当前状态重新计算：

`(当前驻留、空闲窗口、活动上下文/端口、未完成ACK、静态网并集) + (实例、tile形状、循环、驻留动作)`

得到实际新增读写、释放事件和完成时间。只合并未来可见状态等价的历史；不能只凭已做节点数和总时间合并。
已证明不再使用的值才从前沿删除。候选/能力和成本模型对同池贪心、旧DP和适用强启发式完全共用。

## 不可绕过的边界

- 首先验证完整tile的实际供数、整数数值、尾块、S地址、背压与ACK；不能仅用离线numpy打包证明动态通路存在。
- 3–4B全部权重无法装进这些16KiB局部S。B1 decode的一颗权重通常每token只用一次，权重流式读取仍有必要；
  prefill可在多个token/行之间复用。不能承诺tile会消除所有外存访问。
- 较强tile执行器提供给所有基线，从旧标量后端到tile的改善单列。只有同动作池的调度/驻留选择收益计入算法约20%。
- SystemC仍须用实际地址/端口/队列/信用及RTL校准，随后覆盖带KV decode。当前S2账不能冒充token/s或J/token。
- 如果合法供数确实需要新增适配/端口，在独立硬件PR处理并重验；当前M规模必要条件由[Issue236/PR237](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/237)独立跟踪。

运行：`python traffic_accounting.py <已冻结IR> <选中计划> <输出.json>`。
工具默认查表并验证完整原生成本和计划；与`phase_accounting.py`的时间成分分解互补。
