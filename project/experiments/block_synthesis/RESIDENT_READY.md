# 就绪原生DAG、分组和有限S的同一前沿

这是显式原型；输入仍是已绑定来源的原生M/E图、实测行服务、实际有限S和复制合同。
不根据模型名改规则，不增加MAC、SRAM、复制器或金属连接。

状态是在原多行分配器状态上增加 `completed`：已经完成且收到输出S写ACK的原生节点集合。
同一物理排列但不同 `completed` 不能合并。其余仍包含S中的具体记录/保护字、外部备份、真实B银行和累计成本。
`ReadyGraph` 只生成依赖都在 `completed` 中的节点；M节点只有命令/输出格式、B身份、系数与分项一致才能组成多行。
`windows`枚举同合同就绪列表中的连续窗口，`all`枚举固定规范行序下的所有兼容子集。
前者是受限动作族，不宣称覆盖所有分组；后者也不枚举任意行置换或算术融合。

每个动作都调用原有限S分配/搬运/原生命令转移；命中、付费重排、保护字、B银行和所有输出ACK重新计费。
完成r个节点的多行动作让 `completed` 增加r个元素。执行时间是全部实际事件的累计成本，仍为串行服务模型。
排序估计另加未来首次消费的乐观搬运界和剩余原生服务的乐观每节点份额；最终报告不使用估计代替实际事件成本。

DP按已完成节点数分层，在一份前沿里同时比较不同就绪集合、分组、实例/存储选择。
宽度N是每层的有界束搜索；无界只对声明的有限动作/分配族穷举，不是一般编译最优。
严格贪心每次只从当前一个状态选择下一步，使用相同动作与成本。
不能将“每个完成数层保留一个状态”称为贪心，因为多行跳层仍会留下多条历史。
首个冻结试验301具有这个标签问题，保留为窄束控制；302修复为严格贪心，不以重命名制造收益。

当前测试包括真实依赖、不同B身份、同原生输出、三类S32边界、付费跨S、提前执行故障及小动作族穷举排序一致。
