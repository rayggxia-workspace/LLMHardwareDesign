# 有限 S 驻留与显式候选传输

Issue219/PR220，迭代17。默认原图覆盖注册不启用本合同；当前没有把候选 P↔U 传输记成合格硬件服务。

## 状态与转移

在原生算子前沿保存 `slots / backed / padding / banks / transport_nets`。
`slots` 是每个私有 S 的实际有限地址，允许多个 S 各保存同一对象的真实副本；
`backed` 仅在外部 STORE ACK 后置位，片上传递不产生外部备份。
`transport_nets` 是此前选择的静态信号组并集，不能在数据消费后删除；连续循环也继承它。
只有上述状态一致的历史才合并。有限束宽仍是启发式；小例 `width=None` 枚举全部有限状态。

当前状态 s 中，消费者 a 请求对象 x 时，列出：

1. 已在 a.S：实际地址命中，不额外复制。
2. 已在另一个真实 S，且有显式候选路径 p：分配目的地址，必要时保存被替换的最后一份脏副本，
   准备实际 M 保护字，然后执行整字传输，保持源至目的写 ACK。
3. 外部搬入：如果 x 尚无外部备份，先找到实际脏拥有者 STORE 并等 ACK，再 LOAD 并等 ACK。

每次转移按当前状态生成真实事件，成本是原生服务槽、实际 LOAD/STORE 和候选传输槽之和：

`g(s') = g(s) + Σ LOAD_ticks + Σ STORE_ticks + Σ transport_ticks + Σ native_service_ticks`。

约束为 `|E(s) ∪ nets(p)| ≤ transport_net_budget`；这里 E 是静态信号组集合，
不是同一时刻的活跃线数。传十万次同一路径只登记一次静态连接，但十万次动态搬运都计费。
线束 ID 是显式资源单位，不能把两条不同端点的总线因为名称相似而视为同一条。

`FutureCopies` 的乐观后续界根据当前 E 排除剩余预算永远装不下的路径；
估算某种宏的首次数据到达时，比较外部 LOAD 与候选路径的最后一跳，不把跨 S 使用必然计为外部 STORE。
它忽略容量和部分约束以保持乐观；实际扩展不忽略这些约束。零路径预算须保持原来的前瞻及程序。

## 候选路径清单

`resident_records.plan(..., transports=..., transport_net_budget=...)` 显式启用。
每条 `resident-transport-candidate-v1` 提供唯一 ID、source/destination、128 bit 整字、正整数 ticks、
静态 nets、服务 resources、来源及 `reserved-sink/source-held-through-write-ack` 协议。
目前只支持候选资格，不从坐标、同组关系或宏字母推断可用路径，也不做隐式格式转换或自动多跳。
昂贵路径和预算不足时仍有原外存回退。有限束搜索可能退化，结果必须与保留的强基线比较。

`resident_replay` 从实际源 SRAM 读取整字并写目的 SRAM；观察结果字典不能供数。
独立校验路径、地址、对象身份、预约、源保持、写 ACK、静态并集及逐项搬运成本。
循环核验覆盖冷启动、过渡、周期和尾部；静态并集不能在每个循环元素重新归零。

## 当前硬件对应及缺口

#214 固定 `46389f671761a5f5f7ca15d7cc98fd052c57d87e` 的 `controlled.py`：
P_ENDPOINT 把 `pu_p_group` 的 `io_req/io_rsp` 暴露在外，没有接入 U_ENDPOINT 那套
`send_start / stored_link / receive_reserved`。U 的传输复用 #195 原 `stored_link`。
因此 P 的实际 SRAM 接口可复用，但不能把 P↔U 的可编程 SEND/RECV、独立目的预约和资源仲裁当作已实现。
需要核对顶层已有控制/DMA能否提供这些义务；确需新增有源电路时走单独硬件 PR，并在 M1–M10 冻结前实现。

原版 #195 `stored_link.sv` SHA256 为
`7a852eebeb6988b2dc448bec9f4dfd48cdad56728c7ad07633008ed614c15571`。
新边界夹具只把它连到两块真实16KiB `local_s_base` 原始端口，检查预约、背压、实际写确认与提前ACK故障。
它没有 P/U 组仲裁器、`pj_mem_port`、局控或母控，也不覆盖同时双向 SEND。
原链接保持源响应到目的 ACK，不能从串行通过推断并发无死锁；#213 的独立 TX 槽修复不能自动转移给该旧链接。
边界测得的 6 个包容服务槽不等于完整 P/U 路径延迟，也不是长线、DRAM或系统周期校准。

## 进入完整综合器前的验收

- 为每个实际实例/方向登记真实接口、独立预约来源、源保持槽、ACK 返回、静态端点与资源，禁止任意重绑定模板。
- 将所选传输资源和静态并集交给外层图覆盖前沿，并与其他层/服务共同限制；当前默认注册尚未做此步。
- 从同一选中计划生成实际局控/母控程序与拓扑，验证反压、复位、错误和并发；最终顶层另做物理验收。
- 逐项区分候选路径敏感性、真实边界数值、原生RTL边界、完整控制、物理与SystemC性能。
- 同候选池的强贪心和 DP 分别报告；对小路径目录增加静态子集枚举的贪心参考，避免用过弱贪心夸大DP收益。

这些动作优化的是现有原生记录数据流，仍不是一般矩阵 tile/跨算子流水综合。
原生重复分解、有效地址窗口及完整算子分片继续独立分析；不得以候选低延迟或增加硬件容量兑现算法20%。
