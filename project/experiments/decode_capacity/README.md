# 3–4B decode 的容量必要条件

Issue236，Refs Issue219/PR220 与 Issue234/PR235。本目录只做源绑定和可复算容量分析，
不提供系统 token/s 仿真，不修改原M、S、局控或任何已验收物理视图。

## 已有证据

`inventory.json`的P0/P1/P2.M来自PR220已提交的九组完整审计，原回执字节复制到work236并绑定SHA。
三颗使用当前相同M RTL；源SHA与Issue219冻结原生命令回放输入一致。
当前M的物理乘积数组是64路S8，每个ISSUE拍最多64个动态乘积。八个row顺序复用该阵列；
两个输入bank和两个partial bank允许保存/流水，不会增加乘法器数量。S16宽输入是3×3 digit串行。

工具给硬件一个非常有利的上界：所有输入免费变成合法S8，三M每拍64路全满、没有流水空拍、
没有外存/S/局控/确认开销，也不算注意力和其他向量操作。于是300MHz下最多57.6G乘积/秒。
它约束**当前注册的密集M/GEMM执行**；不是对稀疏、低秩、未注册快速线性算法或任意电路的普适复杂度证明。
也没有声称现有Qwen量化已达到免费S8假设的质量。

对标准稠密gated decoder，每token的线性投影/完整词表head工作量为：

```
Q = num_attention_heads * head_dim
KV = num_key_value_heads * head_dim
MAC/token = layers * (2*hidden*Q + 2*hidden*KV + 3*hidden*intermediate)
            + hidden*vocab
```

Qwen3的Q维度4096，不能误用hidden=2560。embedding与head即使权重绑定，decode的完整head仍要计算。
每个MAC按一个标量乘积计，不把一次乘加再乘2。

| 工作负载 | 密集投影MAC/token | 三M理想计算上界 |
| --- | ---: | ---: |
| Qwen2.5-3B | 3,085,697,024 | 18.6668 token/s |
| Qwen3-4B | 4,022,272,000 | 14.3203 token/s |

Qwen2.5形状式与完整导出B1/S2图中253个静态权重Dot的6,171,394,048乘积除2完全一致。
这只是从既有导出图核对线性投影，**没有把S2无KV回放称为decode**。
Qwen3只有官方配置分析，没有本任务新增导图、权重数值、映射或仿真资格。

作者报告的[U280原生Qwen3-4B Q4_K_M](https://zedongpeng.com/blog/2026/llama-cpp-on-an-fpga/)
为tg128 72.5token/s：空缓存生成128、五次均值，带“同版本后续构建”脚注。
代码当时私有，频率/能量和完整复现条件仍缺，不能声称我们已复现或证明这是全球最优。
我们保留它的原生量化，不要求对手使用本项目S16/S32标量程序。

若将72.5作为工程目标，Qwen3上述必要工作需要291.615G乘积/秒，理想情况下至少**16颗当前M等价规模**。
四比特权重每token至少约2.011GB，仅权重最理想流量也要求145.807GB/s；块尺度、实际Q4_K_M混合精度、KV及协议还未计入。
**16只是必要下界，不是推荐规格，也不是已实现/已布通/已达标的配置。**
不能从PR182虚拟外存的周期或通道数直接宣称真实HBM带宽；当前物理外存带宽未资格化。

## 为什么要独立硬件PR

这项条件在理想打包和理想调度下仍存在，区别于PR220的标量软件配方低效。
DP仍应继续改进实际占用和同资源性能，但不能用20%的调度收益补足当前密集执行规模与目标之间数倍的容量差。
三M的原算法基线保持不变，新增硬件不能算进算法收益。
本PR先交付可核查的容量缺口、候选方向和下一阶段门；未完成任何硬件修复验收。

## 硬件选项及必须同时处理的部分

| 选项 | 能保留什么 | 必须验证的耦合 |
| --- | --- | --- |
| 增加已验收M的实例和相应控制/S归属 | 单颗M功能/版图作为原版本复用 | 局控是否能并发发出独立服务、每颗S/feeder、母控目标数、权重分发、面积/CTS/PG、真实M10接入与上层负载；不能只复制资源JSON |
| 扩大单M阵列或增加原生独立issue资源 | 五类控制分组概念、数值/端点版本管理 | 执行/累加上下文、并行归并、S银行及B供数、引脚/驱动、时序/功耗；输入喂不饱时扩大阵列无效 |
| 低比特原生执行及解包/尺度服务 | 原S16路径可作为质量回归参考 | Q4_K_M并非全网统一4bit；激活/权重量化、块尺度和最终舍入、解包吞吐、累加精度、质量及真实并行lane。不能把降精度或免费软件打包当算法收益 |

暂不选择上述任一架构。先用实际原生命令和资源日历比较候选，在同质量、面积/外存/频率口径下筛选。
例如扩大M到6倍理论lane数，还必须提供近6倍有效B供数；现有512位B口或S feeder若成为瓶颈，必须一起解决。
规模变化可能使母控/局控的目标/上下文字段不够，必须读当前ISA和真实实现，不能假定“多M共用一个局控token”自动并行。

物理仍遵守独立功能宏+局控/适配逻辑、控制归属固定、数据路径逐条声明预连/后制；
不重新封成五个大硬框。不混用不兼容端点/ISA或把旧叶宏资格直接转给新RTL。
若做新M，形成明确新底座版本且每种只选一个实现；旧验收包留作原版本证据。
