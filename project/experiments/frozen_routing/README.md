# 冻结互联资源实验（Issue #11）

这是未校准的抽象连接模型与基线工具，不是物理 H2、RTL/周期仿真、实际 LLM 运行或 PPA 模型。依赖现有 Python 3.13 和 NumPy；绘图另用 Matplotlib。项目内 `.venv` 由现有 D 盘 Python 以 `--system-site-packages` 创建，复用已安装包，不安装解释器或修改全局依赖。

```powershell
.\.venv\Scripts\python.exe project/experiments/frozen_routing/run.py --out project/experiments/frozen_routing/local_runs/<新的尝试名>
```

正式运行前提交源码和配置；运行器默认拒绝 dirty source 和已经存在的输出目录。`--allow-dirty` 仅用于开发调试，其事实会写入 manifest，不能用后续 commit 倒填为运行输入。

## 模型合同

- 每条预制导线束及其全部支线先收缩为一个不可拆的电气 component。16-bit 束的每位具有相同连接关系，不允许不同 net 分占同一线段的两端。
- 只有白名单 connector 能在显式暴露的 tap 之间形成后期连接；几何交叉、中途位置不自动可接。tap 坐标只是抽象站点，真实工艺、引出层、线宽间距、via 和驱动能力待校准。
- 输出各有永久潜在 driver 的隔离 stub；闲置输出不会默认三态。后期连接若接入另一个输出，验证器拒绝多驱动。
- 输入／输出端点容量有限。多个 sink 可共享同一 driver 的被动网络。未被当前任务使用的输入允许仍接在固定网络上，但不能改变所需 sink 的驱动归属。
- 时钟、供电、控制分发、权重供给、数值编码、缓冲时序与信号完整性尚未建模，因此这里只证明声明模型内的连接合法性。数值检查使用 float64 软件值；不声称16-bit算术等价或硬件周期正确。

## 实验与公平性

4种不同拓扑：设计集 FFN／门控 FFN，保留集 residual FFN／双投影汇合；所有图在首次配置中固定。每种底座先冻结，随后运行全部图和固定种子。算法对照使用同一个映射；seed改变合法物理映射，不将仅换张量尺寸称为新拓扑。

对照顺序最短连接路由与多顺序搜索（透明基线，不主张算法新颖性）。失败记录为 `heuristic_no_solution`；大例没有不可布通证明。两种 span 在相同 track 数下保留相同预制导线总长度，但暴露端点数量不同；track数和access预算不同的变体属于设计空间，不能称严格同资源收益。

固定互联基线从设计集所有成功路由及其电气合法两两并集组成的有限候选中，按设计集覆盖最多、再按连接成本最小选择一份连接；允许所有同类型单射映射，评估后不为保留图改线。此候选搜索不是所有可能固定网络的全局最优，不能将未覆盖图说成固定互联的固有限制。逐任务路由只试三个固定映射，搜索自由度与固定基线的映射穷举不同；两者覆盖率分别呈现，不计算不公平的性能倍数。

小例通过独立 BFS 穷举全部白名单连接子集，比较精确可行性／最小抽象连接成本。业务验证器另外用全局并查集重建电气网络，不相信路由器的路径或资源归属声明。软件功能通过已选连接读取实际 driver，再用手写循环执行，与独立 NumPy 表达式比较。
