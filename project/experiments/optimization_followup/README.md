# 由run35瓶颈结果触发的补充研究

Issue247 / PR243，Melodydt。生产RTL不改。原四场景×shared/idealdual，共56例。
run35显示单独提高M的K并行度未加速，且prefill的36个NExp、792576值全部走S16输入回退。

| case | 条件改动 |
|---|---|
| base | 精确复现原共享32KiB/A32B八个控制 |
| s16_n4 | 将S16→S32 NExp接到4路目标服务；每8值额外支付1拍格式桥接 |
| s16_n8 | 同一桥接，NExp每8值7拍目标服务 |
| vector16_s16_n4 | U向量16路＋S16桥接＋原4路NExp服务 |
| read128 | 仅M从本地S取数64→128B/拍；不增加外存或共享池带宽 |
| m16_feed2_read128 | M的K并行16＋A64/B128适配＋M本地取数128B |
| balanced | 上项＋U向量16＋S16桥接＋4路NExp |

S16桥接的1拍/8值、128B读服务均是待实现的条件目标，未新增RTL校准或精度验收。
保持现有有符号S16与S32低16位的NExp数值合同，桥接须按该合同显式打包；
完整模型的缩放/饱和和精度仍待验证。不得把此研究写成现有S16格式已支持快路径。
原输入输出S访问、vector_region、缓存/DDR费用全部保留，未免费删除中间张量。
本地128B读取需要新bank组织/端口/仲裁和面积时序验证；现有1R1W后端只有64B读能力。
本模型仅更改M取数服务，DMA输出读和其他客户端仍按原64B，不能作为整条总线已扩宽证明。

复用optimization_sweep的基线、守恒、负控和实际生成头的数值/FIFO验证；补充检查桥接值数与原回退账本一致。
一次Slurm构建，最多4个模型进程并行。源码、输入、输出SHA独立保存；run35原件不覆盖。
