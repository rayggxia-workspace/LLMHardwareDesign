# 当前共享32KiB配置上的优化敏感性研究

Issue247 / PR243；负责人Melodydt。原四场景×本地shared/idealdual，每项8例。
固定300MHz、2P/1U、原S32/K256/S96及R1/R2/R4调度合同。生产RTL不修改。

| case | 唯一改变或明确组合 | 边界 |
|---|---|---|
| base | 共享32KiB、A32B、原17.1GB/s | 全RESULT去新增计数后必须等于run25；与run30的32B控制相同 |
| vector8 / vector16 | 两处既有U向量流水由4路变8/16路 | 保留每包5拍固定成本、S访问、缓存、归约与NExp补充服务 |
| nexp8 | 合格S32容器的NExp补充服务由每4值7拍变每8值7拍 | 条件目标，未获8路RTL校准；保留原数值合同、所有输入输出和向量费用 |
| m16 | M内部K并行度8→16 | 只改变MAC主体rows×ceil(K/lanes)，固定尾部/启动/读回费用不变；未实装 |
| feed2 | 共享与本地A32→64B，B适配64→128B | 本地S总读服务仍64B；池全局服务仍64B、四槽、无广播；不是无限供数 |
| ddr25p6 / ddr34p2 | 总外存带宽17.1→25.6/34.2GB/s | 保留两通道、32信用、行命中/切换/延迟与S服务；非DDR已饱和的先验断言 |
| pool48 / pool96 | 共享池32→48/96KiB | 保留A32B、全局64B服务；必须全RESULT回归对应历史容量值 |
| write16 | 仅M结果写S由模型64降至16B/拍 | 这是对现实窄写通路的敏感性修正；base是补到64B后的模型对照，不算超越base的新收益 |
| m16_feed2 | M16＋feed2 | 实际联合仿真，不相乘单项收益 |
| vector16_nexp8 | 向量16路＋NExp8路 | 实际联合仿真 |
| compute_bundle | M16＋feed2＋向量16路＋NExp8路 | 较大面积候选，仅研究；未授权或声称实现、布局或频率验收 |

共112例；先8例base精确回归，再104例敏感性。生成器只派生五个文件，不改冻结依赖。
8路NExp的实际费用在optimization_sweep中独立记录；旧iteration*_study仍是参考校准账本，不能作为新8路已校准证明。
各例检查外存字节/描述符、M命令/tiles守恒，逐类计算工作差额、token算术、有限信用与生命周期；故意篡改五类结果必须拒绝。
实际生成的共享池头文件在A32和A64两种设置下运行原725输出Fraction数值参考、10个生命周期负控和独立事件审计。

当前P本地后端已逻辑1R1W，不代表整条P访问链都64B/拍：M写回/普通IO仍128bit，独立wide_write为512bit。
write16只校正M结果写的服务宽度，不含真实命令握手、打包、租约或读回延迟，仍不是原生全系统模型。
S32转换、K32命令展开、实际DDR/DMA/LOAD汇合和完整生成质量仍未闭合。所有token/s是条件模型值。
面积只给资源方向；没有新RTL综合，不给未经测量的mm²或假设300MHz已闭合。

服务器Slurm内：`python3 -B source/project/experiments/optimization_sweep/run.py --root "$PWD"`。
依赖与输入按run25/原校准SHA冻结；新代码commit、工具版本、部署及输出SHA由运行回执保存。
