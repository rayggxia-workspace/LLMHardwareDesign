# 共享32KiB的A消费宽度与双组读取评估

Issue247 / PR243；负责人Melodydt。该目录是独立条件模型实验，生产RTL不改动，旧shared_pool_study与legacy_port_probe代码保持冻结。

目标是用真实服务器SystemC执行替代先前两点Amdahl外推，分离A入口扩宽与共享池供数带宽提升。固定prefill2/W8、32KiB共享容量、每P四个64B FIFO槽、读返回延迟2拍，以及原300MHz、2P/1U、17.1GB/s、S32/K256/S96、R1/R2/R4工作与本地A尾部32B/拍。此前的本地shared/idealdual两层分别报告；idealdual不等于新RTL本地1R1W已获得整系统资格。

计划：单全局64B服务配16/32/64/128B消费者；双组各64B服务分别使用连续16KiB组映射和64B行交错映射，配32/64/128B消费者。每种配置跑两种本地端口条件，共20个pool32场景；单组16/32另跑两种本地端口pool0，合计24场景。

双组每组每拍最多一条64B服务；同组冲突需要排队，两个P读同址仍独立计费，不广播。128B消费者必须真正支持两条已返回64B行同拍消费，不得仅扩大步长而继续逐行消耗一拍。FIFO信用包含在途与返回未消费的行。存储组并行不会自动使填充DMA、计算或本地B加倍。

验收包括：

- 16/32控制的完整RESULT精确等run30；所有算术、外存流量及本地旁路账目保持原独立核验。
- 每配置独立Fraction数值比对、原生命周期负例、逐地址消费完整性、每组服务不重叠、有限FIFO和消费带宽核验。
- 无阻塞定向测试覆盖真实双组并发、同组冲突及128B双行消费；背压测试不得提前释放信用。
- 全部编译及SystemC执行只在授权个人服务器目录的Slurm分配内；输入、源码、工具及结果SHA均记录。

入口：从新个人run目录执行`sbatch --parsable job.sh`。`run.py --root <run目录>`只能在1至4核Slurm环境内运行。部署用显式源/输入清单及实际已上传源码commit，禁止覆盖旧run。

结果边界：没有原生S32拆分、K32命令映射、真实DMA桥、完整模型权重/token生成及物理时序资格。本实验token/s只代表原条件评价体系；面积暂记录存储宏数量和需要的结构，不虚构综合面积。
