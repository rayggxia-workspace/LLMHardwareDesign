# Issue247：连续算子融合与生产/消费重叠的原生合同

2026-11-09，Asia/Shanghai。仅为父任务准备隔离研究材料和testbench；没有修改生产RTL，没有启动服务器、综合、物理或在线资源操作。研究使用既有`rayggxia-project-collab1.0.0`规则，阶段数据最终由父任务记录Issue/PR、源码commit和SHA。

## 必须分开的两个问题

1. **省掉中间S物化**：生产者结果经有限保持槽直接给唯一消费者，避免一次S写及对应S读；算术与舍入边界保持。
2. **让下一tile生产与当前tile消费重叠**：需要控制器允许多项工作在途，并真实约束同一个N、E、M、G、S端口和FIFO的占用。增加旁路线并不自动获得此能力，也不能把所有`T生产+T消费`都替换成`max(T生产,T消费)`。

本次提供的原生RTL测量首先验证第1项及现有控制对第2项的限制；条件SystemC的原生S32/96位M、E32服务由父任务另行研究，不能由本S16 bench授予资格。

## P：M到G

- `pu_p_group.sv:74–76`限制直连生产者为M格式化读`cmd_op=5`且`cmd_data[9:8]=1`，同一命令不能`cmd_route`与`cmd_store`同时启用。它不是M任意128bit/原始累加结果都能直入G。
- `pu_p_group.sv:166`把M读出的前两个S16值包装为32bit结果槽，并保持valid直到take；`:82`在该槽未释放时阻止新的M命令。`:176`的G_ROUTE直接捕获这32bit作为G的X，`:178`仍从S读另一输入，`:185`最终仍等G写S的实际ACK。
- `block_v2_m.sv:18`、`:26–27`已有输入双bank、S40部分和和S64合并寄存器。不能把M每次乘加都算作一次S中转，或把已经存在的输入银行当新资源收益。
- `block_v2_g.sv:1–12`给出两S16 lane、四级流水、II1的宏合同，全部阶段在输出背压时冻结。但P的gate服务还有G_A/G_B/G_RUN/G_WAIT/G_STORE，单次G任务直到最后S写ACK才完成，**整个服务接口并非因此II1**。
- source/sink接点从P组导出，真实连接要由拓扑绑定。旧`tb_pu_p_group.sv:48–49`显式接回，测试普通S路径与direct数值等价；旧程序包含4拍故意hold和stale槽写入，不能原样以总周期充当两路径公平性能比较。

下一轮P最小性能bench应固定同一已计算M累加状态，分别测“格式化读并写S→G普通读”和“同一格式化读→G direct”，均等最终G写ACK；设置相同G另一输入、相同输出槽、相同中间S16格式。去掉旧测试的故意等待后，再另列0/4/16拍背压测量；数值/非法路由/复位检查保留。没有资格把32bit S16桥接描述成原生S32 M到G流水。

## U：N到E

- `pu_u_group.sv:61–63`从N服务的128bit结果保持槽导出N→E；直连时N完成要等结果被消费，N错误不发布数据。
- `pu_u_direct_pair.sv:35`令N不store、E store；`:39–47`按E操作码计算A/B/C总数、需要从S读的B/C和最后16B写回；`:30–31`在N失败时取消仍等待A的E。
- `pu_compact_e_service.sv:76–84`在DIRECT_A状态接收128bit A，再按普通流程获取B/C、执行和写回；`:119`必须等实际S写响应才完成。不能把A直连误算为所有E操作数均不读S。
- `ucf_s_compute_client.sv:59–63`已有N输入捕获寄存器，结果也在done_data保持；这些不是新的无限缓存。
- `pu_u_direct_pair`只有一个EXEC/RESPONSE上下文。仅当N、E都退休，才回IDLE接受下一配对描述符。因此现有配对服务即使能同时发出N和等待A的E，也没有多pair流水。重复tile须实际执行，不得免费实例化第二个N/E。

### 原生宏的启动与延迟边界

以下为代码结构，不是本轮已测时延：

| 单元 | 代码合同 | 不能据此推导的结论 |
|---|---|---|
| G | 两S16 lane、四级流水、out_ready控制所有阶段，注释II1 | P gate服务每拍接受一任务 |
| E core | `block_v2_e.sv:25`仅IDLE接新完整命令；普通路径IDLE→MUL→TOTAL→WRITE→IDLE，RoPE多ROT_MUL | 单E可以每拍执行任意完整ADD/MUL/FMA，或两个相邻E算子并行 |
| E compact | `block_v2_e_compact.sv:18–38`分拍暂存A/B，可在非last拍缓存数据；最终操作数仍等exec_ready | 物理层已有一个原生三输入、II1、S32宽E |
| N | `block_v2_n.sv:43`直接连接本地除法/根资源；统计通常CALC/ACCUM，归一化回放每对值经过CALC/NORM_MUL/NORM_GATE/EMIT | 归约/Softmax在组统计未完成前即可无条件输出最终结果 |
| N group | `block_v2_n_group.sv:27`、`:29`的迭代除法/根为64/32次迭代，另有发起/取回握手 | 数据直连可删除该计算延迟 |

同一个E做连续两个E算子时必须串行占用此资源；融合主要消除存储/派发，不凭空创造并行算术。N归约/统计与后续依赖需要相应barrier；改变为在线Softmax等属于算法变化，需另证数值与精度。

## 数值和所有权

生产N/E/G为S16相关合同；条件S32模型是另一层证据。普通S路径中已经执行的RNE、饱和、格式化和异常状态必须在旁路上保持。不能以“融合”为理由删除原先的中间量化、把M S64累加器直接接成S16、或将S16桥接当成S32服务。

只有唯一消费者、没有后续重读、格式兼容、地址别名与异常语义明确的中间值可完全不store。多消费者或重复使用的结果需要S、有限多播寄存器或显式引用计数；不能提前释放生产槽。结果被FIFO接管后，可以让生产者退休，但FIFO必须承担数据保持、标签、异常与复位所有权；最终E写ACK仍决定消费者退休。

## 最小新增流水候选与预算（尚未实装）

优先U的“同一归一化上下文、多tile replay→单E消费者”：

1. 新建深度2、128bit N结果FIFO：保守计256bit＝32B payload；full时阻止生产者释放，empty时禁止E取值。不能把ready/not-full当empty。若复用既有128bit结果槽抵扣资源，需另证所有权和覆盖时序，不在研究中自动扣除。
2. E侧可选预取B/C两个128bit操作数：最多32B payload，避免把S等待都串在A到达以后。ADD只需一个16B B槽。所有预取仍占真实S读端口，并处理别名与生产依赖。
3. 可选独立E输出/写回保持槽：每entry128bit＝16B，持有到写ACK，不能当作免费写完成。
4. 上述从零独立分配时，ADD数据槽示例为32＋16＋16＝64B/U，FMA为32＋32＋16＝80B/U；这些是可核对的payload容量，不是综合面积、也不含额外控制。不应与既有保持寄存器重复计算为既有资源或免费资源。
5. 配对控制器需要至少两个描述符上下文、独立N发起/E发起/结果退休游标、目的槽/操作码/移位/异常标签，以及有限输出信用。E仍是单一执行资源，N也仍是单实例，新的上下文不是额外算力。

必须显式保持最终完成语义：单tile完成要包含末端S写ACK，整个流完成要等所有FIFO/写回槽排空。N失败取消尚未开始的对应E，已开始的其他tile按自身标签退休；复位清所有valid并使旧响应不能写入下一代数据。还需验证满/空、同拍进出、consumer停顿及慢S不能造成溢出/循环等待。

这些新增状态的RTL、选择器、时序和功耗未知；原128bit接口还需考察跨宏物理线长/扇出，不能以纸面小容量推断固定面积或300MHz通过。

## 当前公平原生U实验

本目录`prepare_native.py`复用锁定原U testbench的生产接线和helper，替换为同输入同算子的测量程序：RMS replay输入及gamma均八个S16 1024，E做ADD(B=25)，两路径都应得到八个1049。

- 普通路径：N读两个S输入、写中间S；E读该A和B、写最终S。每pair实际4次S读＋2次S写。
- direct：同一N读两个S输入但不写中间S；配对0x104让E A直入、只读B并写最终S。每pair实际3次S读＋1次S写。
- 两路径均在最终E写ACK及服务响应退休后结束计时；RMS上下文准备、初始化和最终readback明确放在计时区间之外。故这不是完整RMS/完整LLM端到端性能测量。
- 测1/16 tile、交接等待0/4拍。0拍是公平正常对照，4拍是受控交接背压；普通路径在N写S完成后同样加4拍。16tile仍受现有单pair控制，不报告虚构的多在途流水或`max(N,E)`收益。
- 分别统计实际S端握手、N/E命令接受数和direct接受数。中间S槽预填毒值，direct后必须保持毒值，排除仍暗中store；最终S数据必须一致。
- 额外检查N非法op触发E取消、禁用direct、结果held期间复位，最终输出guard不得变化。

此bench只覆盖RMS replay→ADD及上述协议边界；不宣称已经验证所有N/E操作、舍入边界或整条多算子图。普通/直接的同操作MUL/FMA/RoPE及RNE ties、饱和、溢出和异常传播，应在后续扩大数值覆盖时另列。旧`tb_pu_u_group`中普通RoPE与direct ADD不相同，旧整程序总周期不能代替本比较。
