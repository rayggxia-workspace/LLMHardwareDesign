标记含义
S已核对 cell 属于哪个模块：名称、层次和网表映射能对应到该模块。这里确认的是归属，不代表整个电路已通过功能验证。
R原来属于哪个模块还不清楚，但能沿实际连线查到输出接入哪个模块。Gemmini / llaccel 等追踪到接收数据的寄存器；openTPU 沿已核对的缓冲/反相链确定连接模块。
C只查清了部分输出连接，另外仍有未查清的分支；图中给出候选模块，不能当作确定归属。
B只知道这个 cell 的基础功能，例如缓冲、反相、加法或存储状态，还没有确定它属于哪个完整计算模块。
UNKNOWN / PHYSICAL_ONLYUNKNOWN：所属模块尚未查清。PHYSICAL_ONLY：库类型已表明它是填充、阱接触等物理辅助单元。

例子：匿名 cell A → 几个逻辑门 → ATTENTION 的寄存器。如果逐一检查全部输出分支，它们都只接到这一组寄存器，且没有查不清的分支，就标为 R: ATTENTION，意思是“输出接到 ATTENTION，原归属还不清楚”。能用名称和层次映射直接查清它属于 ATTENTION 的，则标为 S: ATTENTION。

这里的“连线”指门级网表记录的输入/输出连接，不是看 cell 在版图上靠近哪个模块；“接收”是寄存器接收计算结果；“原来所属模块”指布局布线前 RTL 中的模块或对应逻辑组。

颜色按各图的说明理解：Gemmini 逐 PE 图采用蓝色 R、紫色 S 的证据色系，PE 单独着色；其他精修图让同名功能组的 S/R/C 使用同色相、不同明度。基础逻辑类型沿用相近色系，llaccel 采用较柔和的版本以突出主要计算模块。颜色深浅不编码数量、重要性或置信度。跨图不能只凭相同颜色认定功能或模块相同。

涵盖与计数：原始图与解析图覆盖同一批物理 cell；汇总 PE_ARRAY 与逐 PE 图、整体模块与 lane/基础类型图均为不同粒度，不可相加。S/R/C 说明这次是怎样确定分类的；PE、存储、控制等说明逻辑做什么。看颜色时要同时读图例前缀。

numeric e1、numeric e4 的主表均按整个 ot_numeric_dot 模块归类，vadd8 主表按整个 ot_vector_add_unit 归类，因此三例主表 UNKNOWN 线长及布局图中的非物理 UNKNOWN 单元均为零。原始 numeric RTL 没有可直接映射成 expert/lane 子模块的细层次；不能从 UNKNOWN=0 推断每个 expert 的算术、状态、控制和连接均已分别识别。

定性解释：整模块内部线路包含该点积或向量加法实现的计算、局部状态及控制连接，不能全部称为算术线。时钟、复位、明确控制/握手与顶层 IO 已按优先级独立统计。vadd8 的结构还包含 BF16 加法流水线和 credit/FIFO 控制。

更细的 vadd8 lane 来源视图只认证了 3,524 个保留原名、可核对归属的寄存器；匿名组合逻辑及未通过身份核验的其他单元不能强行分配给某条 lane。该细分视图的排他 UNKNOWN 线长为 70,292.713 μm。它可能涉及 lane 数据运算、非 lane 状态更新、握手/队列和辅助驱动等功能，但这些作用尚未逐门归属，不能用位置推断。

独立接收端视图覆盖 vadd8 全部普通网，可识别 parent 非 lane 状态和八个 lane 接收组，仍有顶层/不明边界。该视图与本报告“仅拆分原 UNKNOWN”的 Gemmini 数字分母不同，不混用覆盖率。填充与阱接触单元已从模块布局中分为 PHYSICAL_ONLY，不视为 lane 功能未知。

fable5 完整 matvec：整体归属已知，内部职责尚未细分

主表以整个原始 matvec_engine 为边界：406,089 个 CORE 单元具有整体模块归属，普通布线 UNKNOWN 为零。另有 641,682 个 filler 和 10,187 个 well tap，合计 651,869 个 PHYSICAL_ONLY 单元；早期原始映射中的 UNKNOWN 数量不能直接拿来当作当前图中未知功能逻辑的数量。

定性解释：matvec_engine 的整体范围涵盖矩阵向量运算及实现它所需的状态、控制和局部数据搬运等电路；时钟、复位、明确控制/握手和 IO 已另行统计。属于 matvec_engine 并不意味着每个标准单元都是乘加器，也不意味着每条内部线都是乘加数据线。

当前没有需要从主表 UNKNOWN 中重新归类的线。若后续要区分具体算术单元、寄存器/缓冲、选择/控制或数据搬运路径，需要建立更细的 RTL/网表映射；不能把现有的整体已知误写为这些细功能都已解析完成。

证据：逐项目单元类型清单 · 连接分析汇总。本节解释功能与证据边界，不更改原始模块映射或统计总量。

统计口径与边界

  • 范围：原有 4 个项目、6 个案例，新增 llaccel 详细布线快照，共 5 个项目、7 个案例。llaccel 形式等价检查待完成；其统计文件在对应章节单独下载，原六案例汇总表未合并该快照。
  • 线长：普通 dbWire 的物理中心线长度，单位 μm；同网络、同层、共线部分取并集。
  • 平均与范围：样本为每条网络在该层的合并后总线长；平均=该层总线长/有线长记录的网络数；范围=这些网络长度的最小值至最大值。不是单个线段长度，也不是两端点距离。
  • 空层：该层没有普通线长记录时，平均/最小/最大留空，页面显示“—”；不把不存在的样本记为零。
  • 纵轴：主图采用 log10 对数纵轴的分组柱状图，显示层×功能总线长；不堆叠，零值不绘制。原线性堆叠图保留供对照。
  • 线段数：共线合并后的连续中心线段数，不是网络数，也不是矩形数。
  • 网络数：单层、单功能内去重；同一个网络可经过多层，跨层网络数不能相加作为全局网络数。
  • 过孔：统计实际 via 实例；cut_boxes 为切孔矩形数，两者不等价。
  • 互斥功能分类：时钟、复位、控制/握手优先；每条普通网络仅属于一个主分类。顶层接口辅助视图与主表重叠，本交付未叠加。
  • UNKNOWN：真实线长已计入总量，但端点模块无法可靠识别；综合打平、改名、工具插入单元等会使原始层次映射不完整。不代表布线失败或线长缺失，不能按位置猜测归属。
  • 模块粒度：openTPU 为已验证子系统；Gemmini 为部分细层次；OpenTallas / fable5 主表为原始模块整体；llaccel 的解析图采用接收端/输出去向口径。UNKNOWN=0 不代表内部子模块已识别。
  • 模块图：每个案例保留按原已知模块归属着色的图并新增功能推断图；显示最终数据库单元矩形，按已有模块映射着色；物理填充/阱接触等独立显示。
  • 电源/地：special-wire 几何可见，但未纳入普通线长与过孔统计；其指标不可用，不能理解为零。
  • 零与缺失：逐层表中的 0 表示该已显示金属层未导出普通线段；不表示该层没有引脚、过孔金属或电源/地。
  • 不可见部分：标准单元及 SRAM 宏内部金属不在本统计范围；模块间整条网络长度不能解释为几何边界跨越长度。
  • 工艺差异：Gemmini / OpenTallas 使用 ASAP7，openTPU / fable5 / llaccel 使用 Nangate45；不能直接按线长比较设计效率。
  • 来源：本目录 raw_tables/ 内的 CSV 和 manifest 为直接输入，source_manifest.json 记录哈希。
  • 完成含义：本交付统计已完成详细布线的数据库；不等同于时序、电气及全部功能验证均通过。
