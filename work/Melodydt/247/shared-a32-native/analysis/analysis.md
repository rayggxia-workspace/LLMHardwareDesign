## 与旧条件模型的差别及证据边界

旧 run33 prefill2/W8、shared32KiB、single 全局64B、ideal 本地端口条件结果为 3.49645863547→4.39891251536 token/s，加速 25.8105%。来源 SHA-256 `e2887d8b137c7c4ca69d442586b26ac711427abf9ff26e5072a1a7115093de9b`。

这是不同工作负载与调度合同：本次 64 场景为短 K（1..4 个 K8 tile）、小批量原生格式 S8/S16 和两 P 的真实 LOAD/响应/结果读回；每场景先 LOAD 后计算，并显式等待 ACK。旧体系是完整图固定工作量的条件 SystemC 调度，其大矩阵 A 重读、供数占比、计算/适配和重叠方式不同。两种百分比不能互相替代。

本快照证明接口扩宽确实减少 A 握手拍数和供数区间，但部分场景 LOAD 或处理周期没有缩短，说明 A 入口不是这些场景唯一的关键路径；B 装载、两路 join、控制响应和原 M 算术均未被这次改动加速。尤其同一场景在 contexts=0/8 下节省相同周期、contexts=8 基数更大，说明额外 context 命令/计算调度摊薄了比例。

下一瓶颈需进一步事件证据拆分 LOAD 的 A/B 完成先后、命令往返和计算/读回。不能由这些区间和单独断言 DDR 或 M 就是完整模型最大瓶颈，也不能据此把旧 token/s 乘 1.02 或 1.26。原生完整图 token/s 与目标频率仍无此次证据。
