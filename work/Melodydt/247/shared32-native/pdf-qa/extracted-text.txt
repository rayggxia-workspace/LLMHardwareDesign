1. 出发点与实施范围
此前私有 S 扩容研究试图减少 A 的重复搬运，但给两个 P 分别扩容会复制相同的 A 存储。共享池的目标是让两个 P 使用
同一份已填好的 A，并直接送入 M 的 A 装载入口，减少 DDR→本地 S→A feeder 中的本地 A 写入和读出。先选择
32KiB，以控制共享容量和外围成本。
本地读写并发解决另一类限制：原四颗 1RW 宏只能在 bank 资源允许时机会性重叠读写，不能保证每拍一读一写。本轮
用额外物理存储和活跃位置表提供一个逻辑读端口及一个逻辑写端口，同时保留每 P 16KiB 的逻辑地址空间。
两项能力通过新增双 P 包装层组合。原有 pu_p_group 的 SHARED_A、S_TRUE_RW 默认均为 0；新包装层显式选择参数，不
要求旧调用方立即切换。此阶段交付的是可综合模块、原生 P 集成和验证程序，尚未把完整母控、DDR DMA 和大模型编
译运行链一起完成。

2. 共享池的实际数据通路
共享池由 8×4KiB 的 256×128bit 1RW SRAM 宏组成，组织为两组、每组四个 lane。一次读同时访问所选组的四个
lane，返回 64B；全局每拍最多批准一次读取，两个 P 用轮询仲裁。同址请求仍分别读取，没有免费广播。

每 P 有独立的 4×512bit FIFO，即 256B，随后以 128bit 容器送入原生 M。单 P 出口上限是 16B/拍，两 P 合计最多
32B/拍；内部 64B/拍用于补充有限 FIFO，不能理解为每 P 都有 64B/拍的算术入口。FIFO 信用包括在途读取，直到对应
返回行的最后一个有效容器真正握手才释放。背压期间，数据及 bank/row/tile/width 标签保持稳定。
对象最多包含 2048 个 128bit A 容器。每容器对应一行的一个 K8 tile，S16 使用全部 128bit，S8 使用低 64bit，但两者
都占 16B。布局为紧凑 tile-major：word = base128 + tile × rows + row。
每个 P 同时只处理一条描述符，字段包括 operand bank、rows=1～8、tiles=1～4、A 宽度、11bit 容器基址和 epoch。
完整扩展位宽核验 base + rows×tiles <= object_words，避免地址加法溢出。错误范围、形状或 epoch 返回错误完成
，不产生 A 数据。

FILL 512bit 顺序行写入；mask 按完整 128bit lane 生效；末行
只能是连续低位 mask
SEAL 所有有效容器写入完成，且全部写 ACK 已取走，才使对象
可读
服务 对象保持只读；每 P 的 done 在最后一个 A 容器真正被接
收后产生，并保持到 take
RELEASE 两 P 已接受的 LOAD、描述符完成、FIFO 和在途读取全部
排空后，使对象失效
填充侧有两个写响应信用，包含在途写；非法地址或 mask 不写宏、不推进位置。服务期间不能填充。A 已复制到 M 的
operand bank 后，池不再参与其算术，因此 RELEASE 无需额外等待后续 M 计算结束。
一次共享 LOAD 同时发出共享 A 描述符和本地 B 装载。本地装载器跳过 A；若同时复用 B，允许本地侧无数据事务。P
等两侧完成并排空后报告 LOAD done，错误取两侧的 OR。失败 LOAD 可能已经更新 A 或 B 的一部分，不提供原子回滚
；计算前必须重新完整装载该 operand bank。
包装层先阻止 RELEASE 期间的新 LOAD，再等待内部 P 的装载状态清空，最后把 RELEASE 交给池。这覆盖外部 LOAD
已接受、内部池描述符尚未转发的窗口。pair_reset = reset || cold_reset 同时清除池和两 P，防止单边复位留下无法
排空的描述符。池复位不清零 SRAM；重新使用须重新 BEGIN、填充并 SEAL。
3. 本地逻辑 1R1W 的做法与代价
每个 P 的四个 lane 各使用两颗真实 1RW 宏，1024bit 活跃位置表记录每个逻辑 128bit word 的最新数据位置。这两份
物理空间是可迁移位置，不是始终一致的镜像。
同拍读写时读取活跃位置，将写入送到另一个物理位置并更新映射。同地址采用 read-before-write；读接受时保存位置
选择，后续迁移不会改变已接受读的返回数据。普通 128bit 读与 512bit 宽读共享逻辑读端口；普通写与带 lane mask
的宽写共享逻辑写端口。响应队列有限，不能把该能力解释成每个外部客户端都独占带宽。
warm reset 取消请求和响应但保留位置映射及 SRAM；真实宏已经接受的写不回滚。cold reset 清映射并使内容失效，
之后必须重写。活跃 LOAD 的本地范围受保护，数据需等待实际写 ACK 才能交付。逻辑容量仍为 16KiB，但物理 SRAM
为 32KiB/P。

4. 容量与 S32 格式边界
此前“单行 A 约 43KiB”指 K=11008、每元素 32bit 的原始数据。旧条件模型直接接受 S32 和 S96；实际 M 的入口是
S8/S16，新增池没有实现 S32 自动转换。
单行 K=11008 的表示 存储量 32KiB 池能否完整存放
旧模型 S32 原值 44032B＝43KiB 否
一个原生 S16 limb 22016B＝21.5KiB 能，但只是三项中的一项
无损 S32 的三个 S16 limb 66048B＝64.5KiB 否
既有条件原生程序用基数 2^15、位移 0/15/30 的三个 S16 limb 表示 S32。当 B 已为原生 S8/S16 时，A 的三个 limb
对应三项乘积，另支付转换、缩放和合并费用；若 B 也为 S32 并拆成三个 limb，通常要处理九项交叉乘积。三个 A
limb 同时驻留时，每 K8 组需要 48B；32KiB 最多容纳 682 个完整组，即 5456 个原 S32 位置。若前缀策略要求完整
K32 命令，还要继续向下对齐。
一次只存一个 limb 可以装下全行，但需要分三轮转换、填充、计算和回收，并重新核对 B 重用及 context 寿命；该调度
尚未实现。S8 同样占 16B/K8 容器，不能仅按有效数据位宽将池容量翻倍。多行及尾 tile 也必须按真实容器计费。
