1. 出发点与可检验假设
第二轮主W8 decode512条件耗时272.510572667ms，吞吐3.66958239533 token/s；Dot占224.101536667ms，即
82.2359%。单独继续优化NExp只能影响较小部分。PR241已有较宽K16矩阵叶核，但叶核的流水接受率不等于整个P的
服务速度：输入必须从真实S读取，部分和有依赖，最终结果必须写回并确认。
本轮假设是：增加有限输入寄存器，把下一包的S读取与当前包计算重叠，有机会缩短矩阵服务。先实现真正的有限资源和
握手，再测量；不使用理想的无限FIFO或把叶核II直接换成整块费用。单缓冲作为同一实现的对照，双缓冲只增加一个输
入包槽。
固定比较条件为旧PR241/Issue247的S32/S96模型、300MHz、2P/1U、17.1GB/s、每block 16KiB、8组上下文、原输
入trace和预取策略。共享口和理想1R1W两层分别报告。实际四1RW宏不具有模型理想端口资格；本轮没有扩容SRAM。
停止条件仅看W8 decode512主项，不能改用prefill或W4。
2. RTL数据路径和资源
独立目录project/experiments/rtl_iterations/round3包含r3_m_finite供数包装、复用的K16/N8/ROWS8算术叶核、真
实S包装、数值测试、控制重放和运行器。原生产P16、R1及R2生产实现保持原有版本。候选是可执行RTL实验，还没有
完成原生P/DMA的全部接口集成。
命令检查 -> 8项完成预约与context租约
-> 1或2个有限包槽 -> A/B真实S读 -> 原K16叶核
-> 每次提交更新S96 -> 最后包产生S32结果
-> 2次128bit S写及ACK -> 完成退休 -> 释放context
每包最多16个K、8个N。A为64B对齐，读取一条64B；B保持原K-major按N排列的字节顺序，可跨1到3条64B线，192B
gather暂存，不要求免费的外部转置。每个包槽有64B A和192B B，共256B数据。主资格N8/K16时B实际读取128B，每
包真实读取192B。
S仍是四个256×128的1RW bank，共16KiB。包装接受512bit宽读和128bit窄写；同一拍读写至多接受一个。读响应
metadata只有2条，最终写状态机只有一个，完成预约固定8条。单、双缓冲使用同一FSM和同一算术资源；槽在叶核真
实接受输入时释放，允许同边复用，不人为延迟单缓冲。
输出占用16B对齐的32B独占区。即便N尾部较短，也执行两次128bit写入；DONE与context释放必须等两次真实ACK，
不能在结果valid时提前宣布完成。输入和输出的别名、越界、对齐与重复使用均在准入检查。

3. 上下文和错误合同
描述符包含ctx、tag、K偏移、总K、当前K/N、shift、FIRST/LAST及A/B/output地址。reserved_nextK在合法命令接受
时前移，使同一context能够有限预取；committed_nextK只在叶核真实第三个推进边沿提交时前移。提交与下一输入同
拍时使用明确旁路，不将尚未计算的数据标为已提交。
FIRST不得覆盖仍存活的context。后续包须匹配tag、K连续性、N、shift和output；LAST关闭新的输入租约，直到两次
写ACK且对应完成被消费后才释放。即使新FIRST的形状和tag本身合法，旧final尚未退休时仍必须拒绝。错误命令占用一
个有序完成预约，但不读S、不送叶核、不改变累计结果。
输出背压保留数据和标签，控制不得因ready拉低而重复接受或丢失完成。全组复位清除在途包、读metadata、context
及完成队列；复位后不得出现上一次事务的写入或响应。本轮在20个复位时点和不同背压阶段验证这些合同。外部DMA
覆写输入的完整联合租约合同仍待接入，不能把局部保护称为全系统一致性。

6. 旧评价体系的具体接入
独立生成器位于project/experiments/iterative_speed/round03。仅static layout0、rows1、A32、W8、shift16、N为
8的倍数、总K2048或11008、旧K256 tile使用新服务；每个旧tile对应16个K16包。W16、动态attention、多行prefill和
未覆盖尾块保留原路径。资格按格式和形状判断，不按workload名字特判。
保留原DDR请求/64B beat、预取、A驻留/前缀、两A bank引用和两B token、8context调度、每旧tile一次切换、结果
DMA、写合并与flush。仅替换完整的本地窗口：删除旧tile输入S聚合预约、adapter/compute/tail服务，改成实测校准
的有限控制器。最后tile已内部执行两次S写与ACK，所以删除它的旧p_result_store，避免双重收费。
每次真实读或写真正握手才预约一次S日历；未接受请求不占费用。等待S时，已接受ACK和计算流水仍推进。响应延迟来
自实测2拍，响应及完成数量受有限信用约束。每个旧tile排空16个完成并推进到下一接受边沿后才返回，跨旧tile不免费
预取；S96 context跨tile保留。入口对齐到核心时钟的不足一拍也计费。
每旧tile输入仍3072B、48次64B服务，但预约从旧聚合变成逐次48个。末输出从旧一次抽象64B服务改为两次16B服务，
增加一次预约和一拍S服务；这些差异显式审计。M_tiles仍记旧tile，M_commands改记真实K16命令，M_work计实际
core推进、adapter_work计读取；新旧这些累计工作量定义不同，不能拿它们直接算整网加速。
完整S布局在producer生成时检查：A驻留或前缀、两A/两B及旧psum必须位于顶部工作区之前。主配置output为14848
到15103，旧512B写合并区为15872到16383，全部落在16KiB中。不能依靠描述符失败或减少覆盖来隐藏容量问题。
Calendar删除已过期区间，但保留所有未来预约和当前竞争，不使区间表按历史总请求无限增长。
shared层使用旧统一S日历；idealdual层使用旧分离读写日历，wrapper自身仍不在同拍接受读写。旧DMA仍以原
Calendar模型收费，尚未与本包装共享真实响应FIFO。因此整图结果属于条件调度估计，不是完整P/DMA/DDR联合RTL
实测，也不验证完整trace的张量数值或真实权重生成。

9. 本轮取舍与下一轮

snoop和防过期回填控制的成本。这个上限是受限诊断，不是已实现性能。

期、状态兼容和旧体系整图验证。1KiB A缓存暂留研究方案，没有实施。四轮上限仍按用户要求执行，不用扩大缓存范围
