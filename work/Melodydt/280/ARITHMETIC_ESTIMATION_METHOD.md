# v3 算术估算口径

Issue #280 / PR #281；Melodydt；2026-11-18 Asia/Shanghai。

用户本轮明确选择：完成能耗估算，允许特殊算子采用明确标注的运算级近似和范围，不宣称 RTL 数值验收。因此本版补齐算术服务的成本模型，不将未实现算子伪装成已通过的 RTL，也不要求等待布局布线。共同控制外壳、时钟/互连、真实实例部署、PHY 等既有物理缺项仍单列。

## 实测、假设分离

1. 继续保留 v2 的全部已覆盖分项、冻结 TLM 三窗时间、token 数和 DDR 器件能耗。系统 SRAM 512 bit、名义 300 MHz、三路 FFN 不变。
2. 公共算术按真实调用签名（窗口/site/形状）乘以对应真实输入样本的活动增量：RMS=N+scan+apply；apply 和 RoPE 已含 E32，绝不再加 standalone E32。每个完整 RMS 服务的分块能量先相加，再乘调用数。已有 G32 SiLU 和原 SRAM 访问不重复计入。
3. 各原始样本的 RMS 因子是完整向量求得的因子。超过 512 个字时只分块 apply，不能对每块重新求 RMS；块偏移连续、长度守恒及期望输出逐项匹配必须通过。
4. 特殊算子的运行级调用数来自冻结回放，标量操作数来自同一服务的表达式。将其转换为实测 S32 E32 乘法、U ADD2 的标量成本代理。浮点精度、格式转换、比较器、非线性实现均未得到匹配 RTL 能耗保证。

## 敏感性场景

这些区间是人为成本场景加采样端点，**不是概率置信区间、已校准误差界或严格上下界**。真实值可能落在区间外。

- E32 乘法标量参考：独立真实 RMS E32 动态增量除以乘法包数和每包四个元素，取全部样本端点。
- ADD2 标量参考：既有无寄生 U 每 128-bit 字增量除以四个 S32 元素。比较/选择只以它作为代理。
- 特殊算子迁移系数：低场景 0.5 倍，高场景 2 倍；这是用于展示依赖程度的假设，不是浮点与整数硬件能耗的事实比例。
- 非线性成本：EXP/tanh/LOG 服务低/高分别假设 4/12 个乘加阶段；倒数/rsqrt 4/16 个阶段。Softplus 拆为 EXP 和 LOG 两个服务；Sigmoid 另计倒数。没有宣称这些阶段数已构成满足误差要求的具体函数算法。
- 新算术驻留：低场景理想门控为零；高场景按共同底座假设 4 E32、4 RMS N、4 scan、4 apply 包装、1 RoPE 包装和 1 softmax 各计一次开钟驻留。此配置不是物理部署已经冻结的证明；E32 provider 不重复加 idle。
- 大向量分块 staging：零额外复制至每字两次 128-bit 读和两次写。使用已有 512-bit 系统 SRAM 的窄访问标定。原 TLM 的访存已含在 v2，不在此再次计入。
- 读 DMA 保留既有 0.5/1/2 倍写侧每拍成本场景；新增算术增量同步叠加到各场景，默认小计不悄悄混入读侧代理。

## 操作数定义

脚本 `operations` 返回每次服务的标量乘法 M、加/比较 A、非线性 T、倒数/平方根 R 次数，之后再乘真实服务调用数。若服务含 c 路、深度 d：Mamba 为 M=3cd+2c、A=2cd；GDN 为 M=4cd+c、A=3cd-c；Conv4 每路四乘三加。GELU 每元素七乘两加一 tanh。Router 以 e×k 比较/选择工作量及 k 个 EXP/归一化服务估计。转换、精确时序、流水寄存器等未单独验收的成本包含在迁移敏感性讨论中，不能称其误差已被严格包住。

## 验证与报告

输入校验包括已完成回放的 SHA、冻结数值/时间对账、算子复算和调用数完整性。公共算术另有 RTL 输出、错误位、活动覆盖、配对功耗验收；代理没有这种验收，报告明确区分。

`verify_arithmetic_estimate.py` 独立检查签名覆盖、冻结时间/DDR 不变、分项守恒、单位及范围顺序。结果 JSON 保留逐签名操作数和全部来源 SHA，PDF 同时列片上和片上＋DDR，以及每模型仍未覆盖项目。

当前 E32 的 9/18 周期差、Falcon 的 S16 Q14 系数越界、GELU/循环浮点服务未绑定，都仍然存在。本版没有修改原数值或把算术资源周期差直接加到 token 延迟。要得到新的 RTL 一致吞吐与精度，需要另行完成格式/指令实现和整模型回归。
