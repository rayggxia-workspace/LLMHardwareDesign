# 阶段E：由实际端口测量重算资源预算

Issue #121 / PR #122。此处完成的是审阅建议允许的块级资源估算，结论为**尚无已证明达到10 token/s的整模型配置**；表中给出已计价部分和具体剩余瓶颈，不把缺失阶段计为零。无需为了这张表实现完整阵列或改动已收敛五宏。

可复核数据：[RESOURCE-BUDGET.json](RESOURCE-BUDGET.json)。生成命令：

```powershell
python project/experiments/block_v1/revision300_resource_budget.py work/YUZE-LU/121/review-20261028/RESOURCE-BUDGET.json
```

输入是run283的20形状/四格式实际冷端口计数、run340当前函数入口流水/新源真实S16KiB工作区及模型长度、309操作数流水递推预算和冷卷积；来源文件/SHA、每个矩阵的K/N/尾块/调度波次和各方向容器流量均在JSON。不是用64乘法器峰值乘频率推测有效吞吐。

条件为batch1；投影S16激活×S8权重，QK/PV分别S16×S16，R保持已验证S32状态/S16因子。格式可被宏执行，不代表模型整数质量已通过。300MHz和预留主机10ms为规划假设；设备窗口90ms。512输入/64次decode与1920输入/128次decode，容量均2048；采用各档最大上下文576/2048保守计价，Gemma局部层裁剪到1024。未测prefill延迟、tokenizer/提示/greedy完整性能循环，不能把表中时间称为实测decode时间或生成速度。

M按每个矩阵的完整8列tile做ceil(tile数/M数)波，再单独付实际词表尾块1/3列成本；每次冷装载、部分和校验、合并、舍入和结果消费均保留，矩阵/层间串行屏障，不假设免费权重复用或跨宏重叠。QK/PV逐query head计价，不把GQA数据扩展当成免费带宽。Phi融合投影拆成对应独立输出片，串行控制不比融合免费；Granite只计算8个活动专家，40专家全部占存储。

四组V/S配对：每组V2KiB回放/S16KiB单1RW；全隐藏norm屏障按顺序，独立head最多四组并行。全组统计、S初始化/读写/回放/最终消费按实际bench收取；learned gamma及未覆盖的外层计算另列。R用6个的候选预算，仅Qwen3.5/Falcon需要；每层512块屏障和完整冷状态/因子换入换出保留。冷conv每8channel46拍，Qwen每层1024组、Falcon576组，与状态更新串行使用R。

## 明确的剩余瓶颈与本轮结论

1. V/M输出为S32槽，下一M的S16/S8紧凑输入必须有有限转换、打包和地址/命令控制。已有格式原语不等于这一整条数据通路已完成，不能免费删掉该成本。
2. 激活、门乘、残差、norm gamma、RoPE、mask/scale、动态量化、T交接和链路等待尚未全部排程。已有实测图谱可用于后续估算，表中没有用其峰值替代真实端口成本。
3. Granite TopK ID到专家权重寻址/搬运、回并，以及大词表主机argmax仍需明确控制。V的有限ID不能直接代表完整大词表/通用MoE系统。
4. 多M供数、KV/state外存、路由延迟及主机真实耗时没有集成执行证据；输入/clock/串联R接口时序也不能由输出C试验自动授予。R/V物理仍在验收中。

因此阶段E提供“所选宏能力、有限资源条件及剩余瓶颈”的证据，**不宣称10token/s达标**，不冻结M/V/R/S/T实例数，也不扩大本轮到完整产品。512+64档每步按576上界、1920+128档按2048上界的已计价总时间可分别用64/128乘JSON对应单步值；prefill单独待后续系统实验，不冒充已测。

验证：所有来源SHA核验；8模型/两上下文/五M数量共80个候选；每个矩阵tile精确覆盖N与尾块，调度波次整除向上取整；增加M数量时已计价周期不增、有效/容器总字节不变；总周期逐阶段相加与ms换算一致；Granite全存储大于三倍活动权重；生成器SHA绑定。纯本地预算计算，不提交EDA、不重复通过的物理/bench任务。
