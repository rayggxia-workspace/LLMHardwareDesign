用途：供主线审查的本地修改建议；与[Block性能与300MHz修改建议](D:/Data/电路实验/block-v1-review-20261028/Block性能与300MHz修改建议.md)配套。

读取基线：Issue #121／PR #122；提交 ad3c2b34511d58792ec5b550252590912f03252e，分支 task/121-block-v1-twelve-layer。
状态：M11/M12 的演示几何基准已经用户认可；接点组织、层资源分配和具体修改步骤是本文建议，尚未实施。本次仅形成此本地文件，未修改项目源代码、原始物理数据库或发布 GitHub。

## 1. 建议结论与本轮范围

保留 M、V、R、S、T 五种宏的功能边界，每种最终保留一个基础实现。以现有五宏为对照基线，把接口修改并入下一版 300 MHz 宏的物理实现，避免先硬化一版接口、随后因吞吐修改端口而再次全部重做。

优先解决“问题2”：粗金属只有两层时，宽总线能否从内部接点完整引出。建议采用“按目的方向组织的小型接点条带＋有明确容量的引出通道”，替代每组128位集中成一个密集方阵。数据位仍然是独立电气网络；接点分组不等于串行化，也不改变128位的逻辑位宽。

“问题3”按有限范围提前消除风险：默认允许宏内部继续使用 M1–M10，但对明确需要的固定预连试行局部 M9/M10 通道预留。只有局部方案缺少足够通路，或已有证据表明需要大规模跨宏固定互联时，才把内部普通信号主要限制到 M8，系统性预留 M9/M10。不能仅因接点向上，就直接认定必须牺牲两层内部布线。

本轮新增的上层工作是小型完整接口引出样例，不是完整阵列和所有模型互联。它用于证明接口可接，并帮助确定宏边界；不展开通用十二层工艺校准、全系统布局或额外产品系列。

建议顺序：

1. 记录并版本化本文件的粗金属规则。
2. 与300 MHz性能方案共同确定端口数量、位宽和方向。
3. 用小型几何样例筛选接点条带和通道，再验证完整宏的全部接口。
4. 根据已通过的接口方案，对选定五宏完成最终原生布局布线及300 MHz验证。
5. 后续实例组合和模型连接复用这个明确的接口合同。

## 2. 本次确定的 M11/M12 演示规则

### 2.1 几何基准

所有长度单位均为 µm。规则标识建议为 nangate45-custom12-demo-2um-v1，避免与已有0.8 µm上层试验混用。

| 项目 | 基准值 | 设置依据与适用范围 |
| --- | ---: | --- |
| M11最小线宽 | 2 | 微米级后加工尺度；高于所参考直写设备模式Ⅱ的1.2 µm线/间距能力 |
| M12最小线宽 | 2 | 同上，首版两层统一 |
| 同层不同网金属最小边缘间距 | 2 | 与线宽统一的演示规则；线端、拐角也检查实际几何间隙 |
| 普通布线轨道节距 | 4 | 2宽＋2间距；不是过孔允许的最小中心距 |
| M11主要方向 | 水平 | 沿用已声明的研究分工；允许明确记录的局部非优选方向接入 |
| M12主要方向 | 垂直 | 同上 |
| via10、via11单孔尺寸 | 2×2 | 后加工孔采用与上层线宽相同的研究尺度 |
| 同一cut层孔边缘最小间距 | 2.2 | 原生via8的0.44/0.4与via9的0.88/0.8均为1.1，按该比例外推 |
| 单排相邻孔中心最小距离 | 4.2 | 2孔宽＋2.2孔间距；仅表示单排规则 |
| via10下方M10承接金属 | 至少完整容纳2×2孔 | 接点处局部扩大；普通M10导线保持原生规则 |
| via10上方M11承接金属 | 至少完整容纳2×2孔 | 零额外包围的演示基准 |
| via11两侧M11/M12承接金属 | 至少完整容纳2×2孔 | 同上 |
| 显式套刻误差及额外工艺余量 | 不建模 | 采用理想对准的几何demo，不把3×3或4×4作为默认要求 |

每个连接同时遵守相关层的规则。M10接点即使承接新增via10，仍须通过原生M10规则；新增M11/M12的2 µm间距不替换下层工艺规则。同一cut层的孔间距与不同cut层的叠放是不同问题，不能建立贯穿所有层的统一“禁布圆”。

对于矩形图形，检查实际形状间的最短边缘距离；不只检查pin中心距或包围盒中心。允许上下相邻过孔同网叠放作为演示起点，但必须保证中间金属连续、异网无短路；不据此声称实际制造的堆叠通孔可靠性已经验证。

### 2.2 为什么不保留3×3或4×4的默认落点

之前讨论的3×3来自2 µm孔加每侧0.5 µm套刻预算；4×4又增加每侧0.5 µm额外余量。它们是另外引入的后加工误差假设，不是原生Nangate45规则的直接外推。

已核对的原生默认单孔模板如下：

| 项目 | via8：M8↔M9 | via9：M9↔M10 |
| --- | ---: | ---: |
| 孔尺寸 | 0.4×0.4 | 0.8×0.8 |
| 下层金属模板 | M8：0.4×0.4 | M9：0.8×0.8 |
| 上层金属模板 | M9：0.8×0.8 | M10：0.8×0.8 |
| 下层/上层普通线宽 | 0.4 / 0.8 | 0.8 / 0.8 |
| 孔边缘最小间距 | 0.44 | 0.88 |

特别是via9模板，上下均为零额外包围。首版按相同抽象方式采用2×2孔与2×2落点，避免只对新增层引入未经校准的额外惩罚。[S3]

这不意味着真实加工没有套刻误差。准确的论文表述是：“微米级尺寸参考公开激光直写能力，连接几何沿用研究PDK风格的理想对准模型。”设备曝光能力也不等于已经获得完整铜互联、介质开孔和可靠性工艺。

### 2.3 依据及其边界

Heidelberg MLA150公开模式Ⅱ的最小线/间距为1.2 µm，全局二层对准为0.5 µm，局部为0.25 µm。因此选择2 µm作为演示尺度有公开设备能力参照；零额外包围则是本项目的简化假设，并非设备能保证零误差。[S4]

原生技术LEF读取的SHA-256为：

834a79295054cd4209178d1bade67c353863c47bb4b3c22ee38b862b7cec37f2

与项目technology.json记录一致。本文件中的via8/via9数据来自对应模板及cut-layer规则，而不是根据图形目测。

金属厚度、介质厚度和RC不是上述几何规则的自动推论。接口几何筛选可先不依赖完整RC；要比较延迟时，使用单独声明且所有候选一致的简化模型。可把旧试验的2 µm金属厚度作为后续讨论起点，但不能因此沿用旧0.6 µm孔的电阻或宣称已有十二层提取通过。首版不以额外套刻/良率/完整场解工程作为开展接口试验的前置条件。

### 2.4 4 µm走线轨道与8 µm接点起始节距

4 µm走线节距不容许同排每个轨道交点都放一个2 µm孔：相邻孔的边缘距离只有2 µm，小于2.2 µm。

对于规则排列、保持上层4 µm格点的单排via，建议先每隔一轨布一个，即8 µm中心间距。8 µm是方便实现的候选排列，不是工艺规定的最小间距；错位排列、非规则位置可以另按二维实际形状验证。

应显式选择上层x/y轨道原点，并检查它与原生M10接点格点、DBU和制造网格的关系。原生顶层轨道节距1.6 µm与新增4 µm的共同周期为8 µm，但这只有在相位兼容时才成立；不能沿用旧上层offset=0.8并假定所有现有接点自动对齐。宏实例的平移和旋转也需在后续组合时检查。

## 3. 当前五宏的事实基线与直接影响

### 3.1 已有实现

现有五宏已完成100 MHz条件下的原生M1–M10单块实现和独立验收，仍是本次修改的可靠对照。它们并未取得本文件2 µm规则下的上层引出资格。[S1]

从当前实际pins.json读到：

| 宏 | 外框 µm | 内部宽数据接点 | 其余信号接点 |
| --- | --- | --- | ---: |
| M | 560×560 | cmd_data 128＋rsp_data 128 | 19 |
| V | 1210×1210 | cmd_data 128＋rsp_data 128 | 21 |
| R | 1870×1870 | cmd_data 128＋rsp_data 128 | 22 |
| S | 1610×1610 | din 128＋dout 128 | 17 |
| T | 1120×1120 | write_data 128＋read_data 128 | 130 |

每组128位为约12列×11行的紧凑簇，中心间距约3.2 µm，落点为0.8×0.8 µm，外包尺寸约36×32.8 µm。R输出簇因实际执行坐标的历史序列化差异，宽度为36.01 µm；应始终采用最终ODB导出的数值。其余信号当前主要靠左边。这里不包含PG端子。

### 3.2 新规则造成的确定性问题

1. 原0.8×0.8落点不能容纳2×2 via10，必须找到现有同网足够宽的金属，或者在本版冻结前扩大、迁移接点并重接。
2. 原3.2 µm同排中心间距小于新via所需4.2 µm；同时2 µm的上层金属形状在该间距下只剩1.2 µm空隙，小于2 µm。旧密集坐标不能原样全部向上连接。
3. 即使接点扩大、间距增到8 µm，也只解决局部落点规则，不能自动证明128根线都能从方阵内部走出去。
4. M/V/R/S的少量控制端子和T的130个其他端子也需要接入安排；不能只优化两组数据口后宣称完整宏可接。

### 3.3 为什么仅扩大方阵仍然不足

以一块包住旧接点簇的40×40 µm区域为例，在M11主要横走、M12主要竖走的简化模型下，4 µm节距的理想四边出口数约为：

N ≈ 2H/p + 2W/p = 40。

它远小于128。该式是方向受限的早期筛选，不是工具不可布通的正式证明；局部非优选方向会改变容量。但它已经说明问题集中在接点簇边界，不能用整个宏上方总面积较大来回避。过孔、转弯与其他线还会消耗资源。

甚至把同样12×11点阵按8 µm重新排，外包约90×82 µm，上述估算仍只有约86个出口；“pin间距合法”和“总线可完整引出”是两层不同条件。

## 4. 首选方案：小型条带、方向分组、专用引出通道

### 4.1 接点组织

先把一个128位端口按8组×16位组织；每组内部优先使用单列或单行细长条带。组大小是候选起点，允许根据真实连线和宏尺寸改成16组×8位，但每个宏最终只保留一个实现。

- 主要向左/右引出的组：pin沿y方向排开，使各位可以进入不同的M11水平轨道。
- 主要向上/下引出的组：pin沿x方向排开，提供从M10经M11到M12的合法过孔与接入形状，再进入不同的M12垂直轨道。
- 同组的逻辑bit编号与物理顺序显式记录，可调整物理排列来减少交叉，但不修改信号身份。
- 条带可位于宏内部、靠近预留通道，不要求全部贴到宏边界。
- 输入与输出各有明确引出区域；控制/地址/时钟单独安排，并计入完整接点容量。

避免把多个组放在相同y范围后，都向同一侧挤出。它们要么拥有不同的轨道范围，要么在转入公共通道时为各组分配互不重叠的位置。多个小组最终汇合处必须再次做容量检查。

### 4.2 有尺寸依据的起始布局

采用2 µm落点、8 µm规则接点节距时：

| 一条单排接点条带的位数 | 条带长度：(n−1)×8＋2 |
| ---: | ---: |
| 8 | 58 µm |
| 16 | 122 µm |
| 32 | 250 µm |
| 64 | 506 µm |
| 128 | 1018 µm |

这些是落点条带尺寸，不是完整引出区域尺寸。16位条带可以作为局部几何样例的最小实用起点。

单层直线通道若需要并排通过n根2 µm宽、2 µm间距导线，纯金属所需宽度为：

B = n×2 + (n−1)×2 = 4n−2。

因此8位、16位、32位的纯直线束分别至少30、62、126 µm；加上通道两侧各2 µm对异网的边缘间隙，分别为34、66、130 µm。以上不包含转弯、过孔阵列、PG和额外控制线，实施时按实际图形补齐，而不是把这些数当作已经够用的最终通道。

不能把128根线全部汇入一个窄口。128根单方向直线本身就需510 µm宽；若还要在规则网格上逐根换层，换层区的尺寸可能由8 µm接点节距主导，更大。

### 4.3 对不同宏的安排

| 宏 | 建议起点 | 需要避免的误判 |
| --- | --- | --- |
| M | 优先按两侧或多个方向分组，适当靠近宏边缘；完整端口先做紧凑尺寸压力试验 | 560 µm外框较小。64位条带已长506 µm，控制口和拐角空间不能忽略 |
| V | 将输入/输出组分开，靠近相应缓冲和接口寄存器；函数与统计不另造独立外部宽口 | 较大外框不代表所有接点可挤成两个小簇 |
| R | 沿状态缓冲与接口数据通路分组，减少内部长引线；为控制和历史传输保留位置 | 宏很大，长距离连接的负载可能比局部落点更早影响300 MHz |
| S | 按读写接口和实际bank组织布置；128位保持并行 | 若性能方案改变bank/端口数量，应重新生成接口，不能沿用旧273点清单 |
| T | 同时布局读写数据和130个其他信号，按功能拆成若干控制/地址条带 | 不能将其他信号当作几根握手线忽略 |

M的小外框和T较多的非数据端子，是两个有针对性的先行完整宏样例；无需一开始对五块做大量布局搜索。具体条带坐标应由引出方向、真实端点位置和布线结果确定，本文件不虚构一组已通过的XY。

### 4.4 保持逻辑接口，与吞吐修改协调

接点分组只改变物理布局，不自动增加带宽。128位每拍一笔在300 MHz下为4.8 GB/s；两个128位输入也不能被误算成四个独立通道。

配套性能建议已经指出：64个S8乘法器在batch=1且无权重复用时，峰值需要64 B/拍的权重供给，而128位数据口只有16 B/拍。因而在确定M的最终pin前，先决定采用更宽端口、多个bank供数、实际复用，还是接受较低利用率。不能先固定“两组128位”后再承诺19.2 GMAC/s持续吞吐。[S2]

首轮局部试验可继续使用现有128位口，作为接口形状试验；最终物理接收必须使用300 MHz新版的真实端口数量。不能用串行化总线、隐藏窄接口或未计价的额外FIFO消除拥塞而保持原吞吐声明。

## 5. 局部金属修改与现有硬件复用

优先保留功能与标准单元布局，修改接点周围的M10形状和必要连接；能否连同所有原布线保持不变，必须由实际可接区域决定。

| 修改等级 | 操作 | 适用条件与验证 |
| --- | --- | --- |
| A：现有金属上选择接入点 | 在已连通的同网M10金属上选择足够大的合法落点 | 需原有金属容纳2×2孔；普通0.8 µm细线本身不足。原M1–M10可不变，但接口抽象和接入负载仍更新 |
| B：局部接点/连线ECO | 扩大或迁移M10接点，调整必要的M9/M10连接与邻近避让 | 首选工程路径；发生在新版预制冻结前。重做受影响连通、原生DRC、寄生和时序 |
| C：固定放置重新布线 | 标准单元位置不变，按新pin和通道约束重新布线 | B无法解决局部拥塞时采用；可能涉及更低层重布线，需完整原生验收 |
| D：重新布局布线 | 与300 MHz流水、buffer及接口寄存器修改一起实施 | 前述固定放置方案无法闭合，或RTL/网表已改变；计入真实面积和全部资源 |

原有金属上滑动via10的自由度仍可利用，但本次不要求先开发全芯片合法接入区域提取器。先选实际相关接口区域做轻量检查；完整自动提取留作确有收益时的工具增强。

M9/M10普通线宽维持原生规则，不整体加粗至2 µm。只有与新via相接的局部M10金属至少扩大到2×2，并让附近异网满足原生间距。也不能把一个新2×2 BPin标签叠在旧ODB上就认为已经接好：最终实际金属和网身份必须一致。

修改最终固定层以后，旧DRC/SPEF/STA接收资格不能自动沿用到新版本。旧100 MHz产物完整保留作对照。几何变化但逻辑未变时，仍可复用参考测试输入；结果须绑定新最终网表。

## 6. 问题3：预连线应如何留位置

### 6.1 先区分预连形式

| 预连形式 | 对宏内部层资源的影响 |
| --- | --- |
| 主要走块间通道，连接靠近边缘的端口 | 可以保留宏内部使用到M10，重点保证块间通道宽度和接入 |
| 少量固定线路需要经过宏上方 | 适合在M9/M10预留指定的贯穿走线区域 |
| 大量固定网络需要横跨宏阵列 | 才有充分理由评估M1–M8内部、M9/M10固定互联的整层分工 |

M10 pin本身不占用整个M11/M12平面，也不天然阻止M9/M10上存在其他固定线。问题是已有宏内部布线是否提前占用了需要的路径，以及通孔/PG等是否把连续通道切断。

### 6.2 推荐主线：有限的局部预留

建议先声明一种可审查的预连需求，例如“一组16位固定横向通道，必要时再加一组16位纵向通道”，用于检验是否存在连续资源。16位是局部演示工作量，不代表足够覆盖未来整套模型。

- 预连线仍按原生M9/M10规则布，不使用新增层的2 µm线宽强加给原生金属。
- M9默认水平、M10默认垂直；先按实际轨道、via9间距和PG占用计算通道，不按一条线1.6 µm机械乘以位数后就宣称可用。
- 通道可以经过标准单元上方；预留某些高层金属不等于下方标准单元必须整条清空。
- 对宏内部网络设置选择性的路由限制，给父层或固定适配层留下通道。PG与clock也要纳入约束；只限制普通信号不代表通道真的空闲。
- 宏向上接入必需的过孔和局部金属作为明确例外，记录其位置；不能用一个大OBS把预留通道重新封死。
- 从实际最终ODB/DEF导出占用；验证至少一条代表性固定预连确实可以穿过预留区域。

不建议为兼顾所有未知未来布局预留大量“万能通道”。先证明声明的有限预连需求，后续拓扑变化超出合同则另行处理。

### 6.3 触发整层限制到M8的条件

只有出现以下证据，才升级到“内部普通信号主要M1–M8，M9/M10固定展开和预连”：

1. 明确的固定预连需求无法在局部预留通道中完整布通，失败原因确实是原生高层连续资源不足。
2. 局部通道已经多到大部分M9/M10必须限制，分散例外反而更难维护。
3. 保持面积、功能和300 MHz口径后，整层分工的实际代价可以接受。

该方案仍需接入过孔、局部M10落点和真实PG/clock分配。不能仅将MAX_ROUTING_LAYER改成metal8，同时继续保留M10 pin，然后假定工具会自动完成合法跨层接入。

对比至少记录：宏外框、有源/物理专用单元面积、路由失败和拥塞位置、setup/hold、电气负载，以及预连是否完整通过。没有这些证据，不把M8作为五宏统一硬要求。

### 6.4 固定互联的逻辑边界

若固定预连把两个端点接成同一网，后续M11/M12不能再将其断开。为支持选择不同连接，可预制独立线段并保留端点，再由定制金属选择连接；不能把多个互斥输出预先短接后期待上层“选择”。

固定预连依赖宏实例位置和朝向。在当前单宏阶段只能验证局部通道合同，不能据此声称任意阵列放置都已具有相同固定互联。

## 7. 有限范围的试验与收敛顺序

### 7.1 阶段和停止条件

| 阶段 | 实际工作 | 完成依据 |
| --- | --- | --- |
| P0：规则/接口冻结 | 记录2 µm规则、源依据、层映射；与性能方案确定真实位宽、方向和流量 | 文字与机器配置一致，旧0.8 µm试验保持原版本 |
| P1：小型接点条带 | 一组16位水平引出、一组16位垂直引出，检查via10/11与轨道 | 完整16位全部连通，新增几何规则无违例；不是只测单根线 |
| P2：完整端口引出 | 先选M和T，分别把所有输入/输出/控制端子同时接到外部测试端点 | 全部信号完成、零短路/开路、几何通过，记录总线长度与通道占用 |
| P3：预连风险试验 | 对声明的一组固定预连做M9/M10局部预留与穿越；失败才讨论整层方案 | 真实路径通过或给出可定位的资源不足证据 |
| P4：五宏最终版本 | 将选定接口与300 MHz吞吐/流水修改一起实现 | 五块各一个最终实现，原生物理与功能验收齐全，全部端口上层引出通过 |

P1/P2先使用薄条带方案。只有出现需要对照解释的失败，才引入一个“靠边条带”对照；再失败时才评估局部M9/M10展开。不要把三四类布局全参数扫完再做决定。

### 7.2 外部测试端点不能放在pin旁边敷衍引出

P2建立一个包围宏的明确接收边界，把测试端点布在宏外，要求完整总线穿出宏边界。测试空间、周边留白和端点坐标固定并计入比较；不得把终点放在接点簇边上几微米处就宣称可以跨宏连接。

首档按声明的方向把输入、输出送向对应边界。再增加一个有限的转向/位序交叉样例，观察换层区是否出现瓶颈。它证明指定连接模式的可行性，不证明任意排列全连接。

同时连接全部相关端口，不能逐位或逐组单独布通后拼成“全口通过”。不可用信号复用、隐藏串行化或放宽线宽/间距来消除失败。

如果宏外展开需要较宽halo，应将其列为接口引出占地。只报告宏本体面积而把大片外部扇出区排除，会错误评价方案。

### 7.3 记录少而关键的指标

- 实际pin位置、尺寸、分组、引出方向和可用接入层。
- 完整接口的成功位数/总位数，全部开路、短路和新增规则违例数。
- M11/M12总线长、最长线、via10/via11数、转弯和换层热点。
- 宏外展开占地、最拥塞通道的需求/容量；预留M9/M10通道的实际占用。
- 修改前后原生宏面积、内部布线变化及300 MHz时序/电气结果。

早期几何阶段可以使用统一简化RC排序；最终单宏300 MHz验收使用重新提取的原生寄生和明确的接口驱动/负载预算。上层互联的RC采用何种简化模型单独说明，不把几何通过直接描述成端到端300 MHz通过。

### 7.4 计算资源组织

实际实施时仍按本任务6–8节点上限；c96默认6个独立任务×16核，动态队列补位。小型规则/条带检查只需要少量CPU，不为占满节点重复启动。

M/T接口几何、其他宏的RTL性能修改、独立功能验证可以按依赖并行；依赖最新端口清单的最终P&R必须等待接口冻结。因内存或依赖降低并发时记录具体依据。几何失败优先本地诊断，避免反复启动全套大宏P&R。

本文件编写过程中未提交服务器任务。

## 8. 与300 MHz建议的衔接

配套文件的核心是持续吞吐、有限缓冲和真实300 MHz实现，本文件负责物理端口能否承接这些吞吐。

共同的冻结点应包含：数据/控制端口数量和位宽、每拍有效字节、队列容量、时钟/复位、数值和事务语义、pin分组与方向、各层可用区域、外部驱动和负载。

特别注意：

1. 300 MHz周期约3.333 ns；旧10 ns实验的I/O max2 ns、BUF_X2和2 fF不能自动成为新端口的适当预算。
2. 新增接点展开和长上层线会改变负载。若必须增加驱动、寄存器或中继，应在预制前加入并计入宏面积与延迟，不能期待后期金属生成有源器件。
3. 保留同样外框是初始尝试，不是凌驾于物理可行性的硬限制。确需扩大时说明是接口展开、拥塞还是流水资源造成。
4. 修改流水后的功能按新事务合同验证；新最终网表对新RTL进行同源等价检查。不能用旧100 MHz结果替代300 MHz验证。
5. 接点位置改变不自动等于内部计算功能改变；应优先复用已验证算术，而不是为了布线重新设计五类职责。

## 10. 本轮建议的交付清单

2. 每个宏一个确定的物理接口方案，包含全部信号端子，实际pin表和带组号/方向的图。
