# 原生驱动分量去嵌入：保留真实输入 RC 的实测

对应 #127 / PR128，2026-10-27 CST。延续 min/max 分离和输入 start-path 归一化负结果，本轮取得进一步改善，**仍不签发完整宏资格**。

## 原型做了什么

固定 OpenSTA 源中，`GraphDelayCalc::findInputArcDelay` 实际计算 `gate_delay - intrinsic_delay`，再将该 load-dependent 驱动部分与 wire delay 一起注入输入到负载的边。新私有原型直接在此处缓存实际分量，在生成输入 setup/hold 与 input-to-output 模型时只减去此分量。保留实际驱动产生的 slew、Ceff 计算、全部 wire RC 和源 SPEF；未改 clock-launched 输出的处理。max/min 模型仍分别导出和加载，测量仍用原始 STA。

没有重写 delay calculator 的计算方法，也没有把输入端口后的整条 wire delay 删掉。输入端口/边沿/scene/min-max 单独索引；要求一个上下文只有一个 native driver arc，否则拒绝。该研究原型只承诺一个 source design、一次模型导出/进程；不是适合任意多设计、多次导出或签核的通用实现。

`build_arc_probe.py` 只接受已核对的两份固定源 SHA，复制静态库并重编两个对象，生成新的私有工具。原始源码、STA、静态库及构建参数 SHA 均保持不变。原型源码明确标为修改版，保留许可证；没有修改主线 exporter、服务器工具或活动版图。两份构建收据、argv、实际模型、源请求、测量和原生分量 SHA 见 `arc-driver-probe-summary.json`，源补丁见 `native-driver-component.patch`。

## 小控制：同驱动低 R 改善，高 R 仍保留偏差

四个 DFF 对照与两个 exact-flat reread 实际运行，收据/TSV/SPEF 独立复算完成。使用同一原始 SDC 导出场景，测量分别用两个驱动。

| 输入电阻 | 测量驱动 | 原单模型最大 slack 差 | 去嵌入原型 | 整个 pair 的 1 ps 诊断 |
| --- | --- | ---: | ---: | --- |
| 1 Ω | BUF_X2 | 4.322064 ps | 0.088818 ps | 通过 |
| 1 Ω | BUF_X1 | 5.321070 ps | 1.001067 ps | 未通过 |
| 20 kΩ | BUF_X2 | 4.323431 ps | 2.620126 ps | 未通过 |
| 20 kΩ | BUF_X1 | 6.019171 ps | 4.309178 ps | 未通过 |

原生实际 rise 驱动分量从低 R 的约 4.32284 ps 变为高 R 的约 1.70689 ps，说明不能仅用相同总电容就假设驱动上下文一致。这里没有用反例失败推翻已经改善的场景，也没有将一个场景通过外推到所有阻抗/驱动。

## 同源真实 T6K A/C

仍先核验原 run168 请求与完整来源，每路从同一 full timing V/SDC/SPEF 重导 max/min；模型只作为独立 control probe。两路各有 max/min 两套、每套 756 个原生驱动分量记录；全部 1,540 项边界聚合测量和原始证据复算通过，native context accepted=true，SPEF 名称缺失告警为零。

| 最大绝对 slack 差 | A 仅分离 min/max | A 本轮 | C 仅分离 min/max | C 本轮 |
| --- | ---: | ---: | ---: | ---: |
| 输入 max | 51.866067 ps | 9.885426 ps | 17.722712 ps | 1.008971 ps |
| 输入 min | 51.768298 ps | 9.833717 ps | 17.622355 ps | 0.954320 ps |
| 输出 max | 6.045831 ps | 1.247891 ps | 4.736656 ps | 1.029843 ps |
| 输出 min | 5.669021 ps | 1.156075 ps | 4.885758 ps | 1.489364 ps |

A/C 总超差项（slack 与端口 slew）从原候选 958/900、前轮 955/897，降至 **192/110**。本轮 slack 超差分别 29/4 项，其余分别 163/106 项为端口 slew。C 的四项 slack 超差均为悲观：全部聚合观测中超过 1 ps 的乐观项为 0，最大乐观差为 0.954320 ps；不能据此宣称全部弧、corner 或 slew 已安全。A 仍有 13 项乐观 slack 超差，最大 9.833717 ps，另有 16 项悲观超差。

该证据支持：原生输出 min/max 路径选择、外部驱动与内部 RC 的归属，是两个需要分别处理的问题。它尚未证明剩余差异的唯一原因。高 R 控制与实际原生分量提示驱动 Ceff/等效输入电容近似值得继续核验；不能将目前的全部剩余差直接归因于它，也不能只按 slack 接近就忽略 port slew。

## 可交给主线审查的结论

1. min/max 分离加外部 driver load-dependent 分量去嵌入有实际改善证据，值得审查可维护实现；本轮不是主线已集成的功能。
2. 需要固定有效驱动、输入阻抗/slew、输出负载、corner 和误差预算。1 ps 仍仅为预先声明的诊断阈值，未被放宽或转成正式项目门槛。
3. 原始工具、完整 V/SPEF/ODB 继续作为参考。当前紧凑模型仍未取得完整资格，叶块物理硬化、功能接收与模型资格分别记账；不让“导出能读回”替代边界验收。
4. 继续接收主线合格 C8；其完整功能/物理来源尚不能由本支线模型实验替代。主线仍负责候选、资源、完整物理功能门及冻结，支线不接管活动作业。

前一轮无效果的 start-path 方案保留为负结果，没有撤掉或改写为通过。#127 保持开放，恢复入口和协作接入缺项见 README/Issue 最新回执。
