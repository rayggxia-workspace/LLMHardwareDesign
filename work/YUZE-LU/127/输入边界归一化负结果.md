# 输入边界归一化：保留的负结果

对应 #127 / PR128，2026-10-27 CST。前一轮 min/max 分离已降低输出 hold 的主要误差；本轮继续验证剩余输入偏差，**没有得到新的修复**。

私有 min/max 工具在生成输入 setup/hold、输入到输出的模型时，尝试从 filtered path 的 arrival 中减去 `PathExpanded.startPath()->arrival()`，只允许真实顶层输入端口，保留输入网的实际 RC 与驱动 slew。clock-launched 输出的 arrival 代码不变。两个私有工具均实际构建成功，原 STA/source/archive 的 SHA 不变；全部检查仍用原始 STA。

实际运行 1 Ω / 20 kΩ、BUF_X2 / BUF_X1 四个 DFF 模型对照及两个 exact flat reread。四个模型对照的最大 slack 差仍为 4.322064、5.321070、4.323431、6.019171 ps，与历史原始 SDC 导出一致。T6K A/C 也实际重导和复验：相对前一轮 split probe 的 1,540 项聚合 slack，最大变化均为 **0**；诊断超差仍为 955/897 项。原生上下文和收据复算通过，模型仍未取得资格。构建与测量的实际 SHA 在 `driver-boundary-negative-probe.json`。

该结果否定了“减去输入 start-path arrival 就能改善此误差”的具体方案，不能直接否定外部驱动影响。固定源码解释了两种数值身份的区别：`GraphDelayCalc::findInputArcDelay` 将 gate delay 与 intrinsic delay 的差附加在输入到负载的 wire arcs；`ReportPath` 又将下一条 wire path 的增量显示在输入端口行。因此，人读到端口行上的 delay，并不等于该 input `Path` 对象自身的 arrival。依据：[GraphDelayCalc.cc](https://github.com/The-OpenROAD-Project/OpenSTA/blob/bc7af6f02679074eaf43657488ca117c05f98eed/dcalc/GraphDelayCalc.cc)、[ReportPath.cc](https://github.com/The-OpenROAD-Project/OpenSTA/blob/bc7af6f02679074eaf43657488ca117c05f98eed/search/ReportPath.cc)。

这也说明不能改为直接减去第一条完整 wire arc：其中包含输入线的真实寄生延迟。后续应独立计算/验证外部驱动的 load-dependent 部分，区分驱动 Ceff 与内部 RC，再评估是否能用于模型归属；否则保留 full timing V/SPEF 作参考。不能用删除驱动、删除电阻、放宽门槛或将该负结果标成成功来推进资格。
