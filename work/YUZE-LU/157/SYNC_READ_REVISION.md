# R1024 同步状态读出：功能与周期实证

Issue #157 / PR #160 的有界实现迭代。原 `r_stream.sv` 保留，新增 `r_stream_sync.sv` 包装，不修改生产 R。**本页不授予物理资格**；实际布局布线见 `SMALL_CAPACITY_ACTIVE_RUNS.json` 和 `PHYSICAL_RESULTS.md`。

## 改动与合同

外部状态读口增加地址／bank 寄存和 128bit 数据寄存，固定两拍延迟；连续输入地址可每拍采样。读写冲突取数据捕获边沿之前的状态，复位及暖机输出不作为有效读取。加载、算术、命令、响应和全局状态事务合同保持原样。

当前 SystemC 控制策略串行等待每个 128bit 包的两拍结果，每包相比原串行策略多一拍。没有实现流水读取队列，不能把接口潜在的一包／拍吞吐计入当前结果。验证用直接状态探针只核对结果，不参与计算和搬运数据通路。

这项修改增加可用时序分段，不会自动减少译码网络的总扇出。地址寄存器 Q 仍可能驱动很大的选择网络；物理核验必须查看新 Q 网络、缓冲后的负载和全块线长，不能只比较外部读地址 pin 的直接负载。

## 已执行验证

- attempt071：63 个原有整数算例、28,174,656 次检查通过，包含 GDN、SSM、四抽头卷积、溢出与回滚；通过后才完成综合。原计算核心 SHA 为 `6ac4cfaf6bc9e6b58a0b01ffaf314b53358ea8f50c54bbccfa14d88e0c93a5d5`。
- attempt074：真实 RTL＋原 S／DMA／DDR 模型，48 组两拍读取运行全部 PASS。
- attempt081：使用当前相同驱动、输入、端口和搬运策略，48 组异步读取对照全部 PASS。早期 attempt015 的部分背压驱动不同，不能用于把背压版本差计成读流水开销。
- 48 对逐项核对输入 SHA、算术事件、流量、S 峰值及事务结果一致；所有额外周期恰好为串行读包数，每包多一拍。复核：`python project/experiments/r_architecture/verify_sync_cost.py`。

综合面积从原 B1024 的 775,882µm² 到 776,918.702µm²，约增加 0.13%。这是完整映射差值，包含新增寄存和映射优化差异，不是最终布局面积。

|cache 策略任务|匹配异步对照 cycle|两拍读版本 cycle|增加|
|---|---:|---:|---:|
|GDN，2048 状态，128 token|1,289,024|1,552,192|20.42%|
|24 层、1024 条带，128 token|10,380,288|11,166,720|7.58%|
|8192 状态，16 token|724,816|790,352|9.04%|
|SSM，2048 状态，128 token|1,532,864|1,796,032|17.17%|
|四抽头卷积，16 token|3,608|3,608|0%|
|Qwen 真实维度 128×8 条带，16 token|18,064|18,320|1.42%|

因此 1024 仍适合作为完整 Qwen 条带的架构候选，但不能把其收益推广到 2048 连续驻留任务；后者读出和交换增多，现有串行策略的代价明显。完整模型仍只做状态尺寸推导，以上算例使用合成整数输入，不是完整 LLM 性能或模型精度测量。

物理候选 B1024S 在异步 B1024 已测得时钟树后违规、上述完整功能与成本验证通过后，限定启动一次代表迭代，与原版并行。原版继续收集终态，不把中间违规描述为最终结果。通过后才执行 GDS、完整原版 DRC deck 和真实几何核验。不同 pin 跨度及具体布局变化应据实记录，不能把全部 PPA 差异都归因于读口寄存。

证据：`smallcap-runs/sync071-*`、`sync074-*`、`async081-*`；48 对 CSV 为 `SYNC_READ_COST.csv`，输入摘要和核验结果为 `SYNC_READ_VALIDATION.json`。大映射图、二进制、原始追踪保存在对应远程 attempt，源归档 SHA 与 commit 见运行索引。
