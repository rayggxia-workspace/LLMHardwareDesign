# Issue #192 迭代记录

## 001 · 固定 P16 合同并建立数值基线

- 基线为 PR #190 的 `0485ed84dd13d8711c88609668cf0a903a006773`。D: 剩余不足以完整检出，独立工作树改放 C: 的任务临时目录。
- DP 对两种合法实例绑定和跨块路径成本求值，使用独立双候选公式核对。成本当前使用估计周期。
- P16 的 M 原生 tile 是 K8。每个 K32 段用 4 个 tile，S8 模式 A/B 分别各占 16 个 128 位字。结果以整字计，只有低两个 S16 lane 有效。第 80 段完成后才做最终 RNE。
- 检查点取已归档的 Qwen3.5-4B BF16 两行权重。post-RMS activation 当前使用显式声明的种子向量。
- 用独立原生 RTL fixture 先核对 M/G/S 数值。可执行母控、局控、SystemC 与对应真实布线反馈属于后续门槛。
- 远端按实际核需求拆分。c96 可用 8×12，c64 可用 6×10。单线程运行用更小配额。每个子任务单独保存日志和回执。

## 002 · 共用程序、原生 SRAM 握手与 checkpoint 数值

- 从同一映射生成实验 MC/LC 镜像和逐位需求。两种镜像均由可综合试验控制器取指，SystemC 独立解码相同镜像，P16 原生投影及门乘由测试驱动的服务适配器启动。镜像版本独立于 PR #180。该轮未验证 #180 装载器、父层时序或完整 FFN。
- 跨块采用 P1/P0 各自 SRAM 端口 1。可综合传输器在目的真实 SRAM 写响应被接收后才释放源读响应。覆盖 0、2、4、6、8、10 个周期的响应背压。错误测试用原生 M 非法命令和 SRAM 哨兵检查控制器停止发布。
- 固定 Qwen/Qwen3.5-4B revision `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`，第 0 层 gate/up BF16 权重，经 HTTP 206 验证每个权重字节区间。选通道 0–11，六组每组两个通道，种子 192–197 的合成 post-RMS 输入。每个投影跑满 H2560。两种映射共 12 个 SystemC 2.3.3 / Verilator 本地对照全部通过。
- 本地调试保留失败归因。首次测试台在成功后落到未结束分支，修复后退出码为 0。Windows WSL 临时目录重启时清理，故在一个进程内准备工具、构建并复制回执。Hugging Face 索引含同名 MTP 权重，提取器明确只选择主模型前缀。
- DP 使用估计周期，4,096 组随机代价与独立枚举结果一致。合成罚项下重新生成的镜像与线表都选择 P0。真实详细布线结果仍待采集。
- 首次远端打包发现 #190 分支没有 #186 的 SRAM 后端源，已改为单独绑定 `27eaaace1` 的后端。后续 SSH 在 banner 阶段连续超时，尚无可核验 Slurm 作业 ID。未将本地用例记为远端验收。

## 003 · 路由反馈入口

- 从分布式映射读取 payload 逐位表生成真实试布输入。128 根数据线绑定 P1 `io_rsp_data[128:255]` 到 P0 `io_req_data[128:255]`，传输控制信号另列固定壳层需求。

另预登记一组金属节约偏好，每 16 µm 已布上层路径加 1 个周期当量。两组策略共用相同 DRT 产物，罚项均为映射偏好，不作时序实测。

## 006 · 真实 M10 端点反馈闭环验收
