# Issue 193 执行记录

复用 PR #180 的 MC/LC、程序装载和镜像编码。C/U/F 与 P/J 的原生 RTL 分别固定到 PR #189 和 PR #190 的快照。P4/N4 封装从 #186 合格来源生成，并与 U/C/F 使用的公共叶 RTL 逐文件核对。银行模型的固定 SHA-256 由运行脚本验证。

C/U 按一个 128 位字和一份在途接收预约运行。接收写确认由目的 S 提供，送端在回执被接收之前保留读响应。返回通路可在 C 局控等待期间独立写入。复位用例覆盖目的 S 已写、回执仍被阻塞时的协同重置，再装载程序完成新的事务。

本地复现使用 Verilator 5.006。为兼容旧工具，只在本地临时副本展开 N 原生 RTL 中一个固定两次的循环，并省略该版本不认识的两项 lint 规则。仓库源码和远程包保留原版 N。远程验收要使用项目 Verilator 5.042 重新验证原版源输入。

远程 Slurm 97923 的 8 个 RTL 场景全部通过，详见[远程验收回执](remote-verilator.md)。[PR #195](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/195) 待独立审查。
