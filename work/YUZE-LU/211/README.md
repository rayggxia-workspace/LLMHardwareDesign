# C/F/J 紧凑叶宏底座验证

任务为 [Issue #211](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/211)，交付见 [Draft PR #213](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/213)。

| 逻辑组 | 叶宏 |
| --- | --- |
| C | R256、紧凑 G、紧凑 E、S_base |
| F | 紧凑 G、紧凑 E、S_base |
| J | 紧凑 E、S_base、T |

S 的单请求口通过宏外轮询接入。首版每次只保留一笔在途，真实 S 响应退休时才释放所有者。紧凑 E 操作数分拍接收。C/F 的 G→E 旁路保留一个 32 位结果直到 E 接受首拍；其余 lane 补零。J 的二路加法由紧凑 E 实现，结果可跨独立端点到写回逻辑；三路加法在组侧按 18 位中间值求和，最后一次饱和，作为额外算术资源计价。

## 已执行的检查

- 98504–98506，C 往返及 F、J 原生服务 7/7。98554–98557 重放 7/7 并通过 C/F 直送与 S 回放对照。98563 的 J 镜像测试使用独立端点和仿真接线。
- 98596–98600 以 `b04c3176a` 再次通过 C/F 直送和回放、R256 地址越界拒绝、J 二路／三路饱和及混合租约拒绝，以及七个控制程序场景。母控／局控、镜像和 U 对端复用 #195，SRAM 使用源 SHA-256 固定的真实 OpenRAM 数字模型。
- 98509/98521 暴露宏名转义和全层阻挡抽象导致的供电接入问题。98532 从原 ODB 重导出精确阻挡，保持 pin 声明；较宽 C/F 及两种 J 摆位完成放置，紧凑 C/F 仍存在 G 供电断连。
- 98560 是带真实分离端点的原生实现试验。默认 CTS 在修复 hold 时触到缓冲上限。98582 用均衡 CTS 复跑。覆盖 F/C 的 34 根线和 J 的 130 根线，独立几何审计随通过的原生候选运行。
