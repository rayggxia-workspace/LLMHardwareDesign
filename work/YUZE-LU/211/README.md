# C/F/J 紧凑叶宏底座验证

任务为 [Issue #211](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/211)，交付见 [Draft PR #213](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/213)。

| 逻辑组 | 叶宏 |
| --- | --- |
| C | R256、紧凑 G、紧凑 E、S_base |
| F | 紧凑 G、紧凑 E、S_base |
| J | 紧凑 E、S_base、T |

S 的单请求口通过宏外轮询接入。首版每次只保留一笔在途，真实 S 响应退休时才释放所有者。紧凑 E 操作数分拍接收。C/F 的 G→E 旁路保留一个 32 位结果直到 E 接受首拍；其余 lane 补零。J 的二路加法由紧凑 E 实现，结果可跨独立端点到写回逻辑；三路加法在组侧按 18 位中间值求和，最后一次饱和，作为额外算术资源计价。

## 局控与物理接入

- 组入口实例化 #195 的可编程局控、任务与事件接口、真实服务分发和 ACK 跟踪。PM 走独立请求响应口，供九组顶层集成，私有 16 KiB S 留给数据。综合候选独立摆放 C 的 R256/G/E/S、F 的 G/E/S 和 J 的 E/S/T，不生成 C/F/J 封装 LEF。
- C/F 的固定服务包括 S 的客户端轮询和原生宏操作数适配。C↔U 需要运行时地址保留和真实写确认。C/F 的 G→E 路径通过保持槽、实际接收选择和独立 data/valid/take M10 端点选择。J 的 E→S 结果从两端各自接入，J→T 当前使用已写入 S 的数据与独立租约握手。
- 98659–98661 对含局控的连接执行七个 #195 程序，C 五种、F/J 各一种，全部通过。98695 的 F 程序选择 SRAM 回放和 G→E 直送，两个结果一致。
- 98630 的 C/F 具有含局控的综合网表，旧摆位在 M10 逃逸区仍拥塞。98663/98670/98678 对比紧凑摆位、宏旁 16 µm 后制通道、路由容量和 G 供电相位。98692 是使用明确 fF 约束、恢复 G 供电相位后的三种紧凑候选，每项 10 核。当前的合格判定要求各自详细布线完成、最终 GDS 原生完整 DRC、VDD/VSS、电气及提取后 TT 300 MHz setup/hold。候选中的物理边界端点是给独立夹具的观测口，顶层集成需交付实际通道和端点清单。
