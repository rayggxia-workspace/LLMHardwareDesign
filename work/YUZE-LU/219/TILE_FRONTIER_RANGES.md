# Algo1 范围动作与归约续接评估

[Issue #219](https://github.com/rayggxia-workspace/LLMHardwareDesign/issues/219) · [PR #273](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/273) · 2026-11-15 CST

## 搜索模型

`project/experiments/block_synthesis/tile_frontier.py` 接受有拓扑序的算子图、访问映射和独立的硬件服务表。读取映射声明按输出范围、按归约范围或读取完整张量。搜索内核没有算子名分支。状态记录每个算子的已提交输出前缀、当前输出 tile 的归约前缀，以及每个仍有读者的片段在 SRAM 和 DDR 的副本。状态沿已执行的原子计算量做拓扑推进。开放深度按依赖链上同时未完成的算子数计算。每次动作可以选择新的对齐宽度、推进归约或提交输出，并决定是否驻留。归约部分和以 S64 占用 SRAM，续接时计入部分和读写。若容量不足，原型用确定性顺序溢出旧片段。beam 剪枝保留整算子和禁止分段归约的计划作为可行方案。

本轮覆盖每个算子的一个连续输出轴和一个可选的顺序归约轴。动作宽度取对齐单元的二次幂及合法边界。代价使用单 SRAM 池、共享 DDR 和串行服务，计算及搬运速率为可配输入。为瞬时工作空间预留 2 KiB。可用实验命令行入口为 `tile_frontier.py CONTRACT.json --depth 2 --width 32 --objective time`。常规 `run.py` 和原生指令生成继续使用现有硬件合同。S64 续接与跨算子 SRAM 同址访问在这次对照中是抽象服务。

## 同图对照

从归档 `blockv2-mod/evidence/full-algo1-113543/hardware.json` 的 Qwen2.5-3B 首层整数图读取 `v288 Product → v289 Dot`，保留一个 token 行、完整 K=11,008 和选定的真实输出列宽。权重按每项 2 B、激活按每项 16 B 计价。归档的 P SRAM 容量为 16 KiB。时延按配置的速率建模。算术检查使用同形状的确定性随机整数输入，比较分块回放与整段 RNE 和饱和运算。所有对照输出一致。

| 输出列 | 目标与 SRAM/DDR 模型速率 | 整算子工期 | 开放深度 2 工期 | 整算子交接 DDR | 开放深度 2 交接 DDR |

| 128 | 工期，64/16 B/拍 | 243,712 | 228,480 | 352,256 B | 0 B |
| 128 | 工期，16/16 B/拍 | 243,712 | 243,712 | 352,256 B | 352,256 B |
| 128 | DDR，16/16 B/拍 | 243,712 | 246,912 | 352,256 B | 0 B |
| 512 | 工期，64/16 B/拍 | 838,528 | 825,376 | 352,256 B | 0 B |
| 1,024 | 工期，64/16 B/拍 | 1,631,616 | 1,626,752 | 352,256 B | 8,192 B |
| 2,048 | 工期，64/16 B/拍 | 3,217,792 | 3,216,672 | 352,256 B | 327,680 B |

128 列在较快 SRAM 模型下关闭续接或使用深度 1，交接仍需 327,680 B。深度 2 选了 42 次 dispatch，计 40,960 B 部分和片上服务和 15 KiB SRAM 峰值。总 DDR 由 3,524,608 B 降到 3,172,352 B。SRAM 降到 8 KiB 时，DDR 优先仍能消除该交接，片上部分和读写增至 86,016 B。深度 3 在这张两节点图上与深度 2 一致。

全部 2,048 列的 S64 部分和占 16 KiB。按输出列再切会让多个输出 tile 都需要读取相同 K 范围。beam 64 下，工期优先和 DDR 优先均选了整段 K 路径。较快 SRAM 模型下，该搜索扩展 41,093 个主前沿状态、生成 269,526 次转移，连同普通计划对照约 8.4 秒。128 列的对应主前沿扩展 2,539 个状态、生成 25,080 次转移，约 1 秒。

## 复现

远端独立工作目录 `issue-219-block-search/generic-tile-Bz7Dod`，原始报告位于 `evidence/release-*.json`。Slurm 作业 114341–114349 均完成。其中 114341 通过 4 项单元测试，覆盖归约深度、分叉汇合、整张量依赖和可导出中间值。114342–114349 是同图评估。

在算子目录中运行：

```sh
python -B -m unittest -v test_tile_frontier
python -B benchmark_tile_frontier.py ARCHIVED_HARDWARE.json --columns 128 --width 32 --capacity 16384 --workspace 2048 --ddr-rate 16 --sram-rate 64 --objective time --output result.json
```

后续需要把普通图的整数访问关系接入正式 lowering，并在硬件合同中提供分段发布、续接、局部端口和可执行控制编码。全宽收益仍取决于可驻留部分和数目和同时复用激活的输出 tile 数量。Issue #219 仍在开发，PR #273 保持草稿。
