# 算法迭代2：恢复真实依赖和资源释放边界

2026-11-09 CST；Issue219 / PR220；目标持续进行。本轮不是约20%算法收益的完成回执。

## 本轮决策

上一轮的下界说明，固定原子内核候选后几乎没有可搜索空间。本轮先把大内核改为实际执行的整数原语阶段，
让后续分片和数据流搜索有可执行的边界。`--primitive-stages`是共享的能力开关，贪心和DP使用同一组阶段和成本。

例如一个已有准备复用的Dot原来在整个任务期间占住M、E及相关S/局控/内存通道。
现在它变成：

```
A的真实生产者 → prepare-A：R*K次split32，写显式外存并等ACK
                    ↓
B的真实生产者 ────→ execute：全部输出的完整K累加及最终舍入，STORE ACK
```

当B本身是S16时，execute只需M，不再占着做完准备的E。NFactor也只占N及其实际S/局控/通道。
View/Mask继续传递真实生产者依赖，不能借零成本元数据提前执行尚未产生的数据。
仍然没有允许同一个局控同时接两项服务，或把内存通道在一个阶段中途免费释放。

全图由1,083个旧内核变为8,404项服务：8,079项非零原语以及325项独立A准备。
没有增加原生命令或删掉算术/搬运。不同阶段可能并行，旧内核共享的外存scratch便不能继续互相覆盖；
本轮保留原区域并显式新增63,768,064B（60.814MiB）阶段scratch，外存总预留50,666,574,784B。
实际外存容量仍未资格化。私有S保持16KiB，原语内所有完成/写确认和M上下文生命周期保持。

## 搜索实现与诊断

8,404阶段暴露旧实现的编译开销：每个状态扫描全任务列表，每次扩展复制整个历史元组。
已分别改为只更新所选任务的子节点、共享不可变历史前缀，最后才物化选中计划。
可就绪集合完全由done决定，不扩大状态等价键；历史仍不参与未来成本计算。
这些是编译时间/内存改进，不计入执行性能约20%目标。

下界诊断另增加资源池：某任务虽不强制使用某个M，却可能必需占用一个M。
对每个池累加`min_binding(warm_duration * 所占池资源数)`，除以池容量后向上取整。
它和依赖链、强制实例下界共同限制当前动作族的潜在收益；仍不是物理芯片性能上限。

## 同10束实验暴露并修复的算法问题

九组包含五组硬件，后者已有合法10束计划。但仅看当前已选线束时，有界搜索可能先选：

| 选择 | 逐步累计线束 |
| --- | ---: |
| P0.M（两条宏接口、两条S接口） | 4 |
| C0.E（同样四条） | 8 |
| 后来才要U0.N及其S接口 | 12，超过10 |

若先选U0.E，则它和U0.N共用U0的两条S接口，最终是`P0.M 4 + U0的E/N/S 6 = 10`。
原有宽度1/8会在早期丢掉这种未来可行路径；增加硬件实例反而可能使窄beam更难找到计划。
失败源与回执保留在algorithm-fix-238，不把`no_plan_in_bounded_search`解释成硬件不可布。

新增`static_wiring.py`预计算全图的最小静态线束覆盖。它只描述未来至少要具备哪些接口，不预先决定任务的执行实例、时间或缓存。
对当前前沿已选的线束集合E，计算是否存在完整覆盖C，使`cost(E ∪ C ∪ fixed) ≤ budget`且没有静态互斥。
没有则提前丢弃当前转移。贪心和DP都使用该条件，S命中、搬运与实际时间仍在每次扩展中重算。

覆盖只按集合包含关系去掉被支配的超集；全图条件去重后保持完整。若超过4096项预处理上限，返回None并停用前瞻，
绝不以被截断的覆盖族证明不可行。100种六线束配置的每个前沿与独立穷举全部最终连线并集逐项比较，含固定线、零成本、互斥和预算。
`wire_lookahead=False`保留旧行为，用于对照。

`optimize(..., incumbents=...)`另接受已有可行方案，先由独立检查器验证，再与新贪心/DP取较好者。
它不允许改变成本或接受失效的旧计划；当前资源数量实验把五组10束计划作为九组的一个已知可行上界。
这避免“搜索没有找到”变成“系统无合法方案”。修复带来可行性改善，是否有执行时间收益仍按同候选强基线衡量，不据此声称达到20%。

九组10束的贪心和DP自己都找到计划，没有依靠incumbent兜底；6项完整覆盖，DP拒绝12,125次未来静态布线无法满足预算的扩展。

## 下一轮的实际搜索选择

仅释放原语边界仍没有把一颗M上的大矩阵分开。优先补足一个状态相关的复合动作：

1. 把Dot的输出列分成互不重叠的区间，每段仍完整累加K、仅作一次最终舍入；共享已完成的A准备外存记录。
2. 同一个前沿尝试单M或多个M、各自的列区间、S前缀和实例绑定。不是先选一个固定分片再只搜索开始时间。
3. 从当前每个S的内容及资源日历逐段求冷/热搬运与服务结束时间，计入所有分段的真实额外读和静态线束并集。
4. 子服务共享同一内存通道或局控时必须串行；不能把多M简单当成`原时间/M数量`。
5. 数值解释器分别写对应列，独立检查覆盖完整且无重叠、保持K及舍入；贪心、原DP和新算法共享这些动作，再比较搜索收益。

在引入任何同块预取/计算并行之前，要核实适配器和局控的真实能力。原生M有输入双bank不等价于现有局控已有两个未完成服务token。
原生多列/K段已有测量；行数变化、封包和有限S搬运仍需对应测量和地址合同，不使用免费运行时打包。
若证明有无法由软件解决的硬件瓶颈，再新建关联Issue及独立硬件PR。
