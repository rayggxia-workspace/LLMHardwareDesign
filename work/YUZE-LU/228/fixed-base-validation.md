# #228 冻结底座上层布线的实现与对抗验证

本实现基于 #229 的通用路由与 #258 的方案。Algorithm 1 交接程序和静态逐位网，Algorithm 2 读取端点、工艺和可选中继，导出上层互联并提供可定位的失败。路由搜索以同一入口处理块内、跨块和控制网。布线期间保持 M1–M10、器件、摆位、时钟与供电拓扑冻结。

| 验收面 | 已执行的对抗验证 |
| --- | --- |
| 交接和通用性 | 新版 Algorithm 1 的 U0 和故障重绑 U1 交接各 130 网。独立检查拒绝漏位、重封摘要的错网、错误端点及原生金属冲突。用任意实例名的合成用例布通 512 条数据线及一条返回线。 |
| 接点与路径 | 偏离粗轨道的 M10 接点在两层内接上；禁止越出局部窗口及切孔间距不足。拥堵用例记录占用网，重布保留无关路线。真实交接包完成 DEF → OpenDB → GDS，删去 OpenDB 回读的一颗 via10 后被拒绝。 |
| 中继与修复 | 同一逻辑网对比直连、分支、单级、多级。中继争用不得共享静态驱动，虚拟中继不能进入实体 DEF 导出。历史 P 的实体中继用例完成直连及分段版图回读，并把实际 OpenSTA 的 setup 失败送回路由器。 |
| 原生不变性 | 成品候选合并前后核对原生单元层级、变换、标签及每个 cell/layer 图形差集。四类源工件均保留 SHA-256。 |

## 实际工件和对照

远程目录为 `/public/home/yuzelu/project-circuit/LLMHardwareDesign/issue228-route-9HivK7`。原始 GDS/ODB 和 STA 日志保留在那里。机器可读索引见 [fixed-base-validation.json](fixed-base-validation.json)。

- U0 与 U1 的 Algorithm 1 生产源为本地 #257 交接试验 102856/102860，交接工件在 `U0-width-8-baseline`、`U1-width-8-missing-pin`。作业 102907 重跑两份交接，固定真实的旧 U_64 原生视图。两个结果在同一底座上分别布通 130 根静态网，均通过几何回读和原生不变性。该 fixture 的覆盖为 N→E 以及该服务的关联信号。实际使用的是源交接包的物理视图版本。
- P 的对照以同一历史 #194 P16 物理基准及已存在的 `BUF_X32` 为输入。作业 102902 分别回读直连的一条物理网与经中继的两段。作业 102903 用这两份新几何生成高／低研究 RC 的 SPEF，以原生提取寄生、真实库及 300 MHz 边界跑 OpenSTA。102906 重新回读并复验反馈选出的具体新几何。下表只报告 VALID 到内部寄存器的路径。

| RC 假设 | 直连 setup / hold | 反馈选择的实体中继 setup / hold |
| --- | ---: | ---: |
| 高 | −238.876 / +2510.056 ps | +33.879 / +2172.944 ps |
| 低 | +181.368 / +2090.093 ps | +285.453 / +1955.693 ps |

高 RC 下，OpenSTA 报告原驱动端总电容上界由 1141.55 fF 降到 604.81 fF，后段由中继驱动，总电容上界 568.56 fF。直连 M11/M12 线长为 4800 μm，反馈后两段为 2416 μm 和 2400 μm。SPEF 由实际走线长度和切孔数套用 #194 同一研究模型。它与搜索时清单中的估算电容各有用途。具体脚本见 [relay_sta_fixture.py](relay_sta_fixture.py)。

## 迭代与复跑

1. 102900 发现 DEF 已导入 130 网，但缺少原生 GDS 散列。实现新增 `--native-gds` 和后端核对，102901 重跑。102907 使用更新后的检查器再跑两份交接及删孔反例。
2. 102904 的真实测量反馈选中了同一实体中继，但几何与独立初次搜索不同。原测试错误地把这两种几何要求为逐段一致。保留原失败，将反馈实际生成的路线重新导出并校验。102905 发现容器清理了三项物理回读环境变量，102906 显式透传后重跑。
3. 本机从仓库根目录执行 `python -B -m unittest discover -s project/experiments/upper_router -v` 和 `python -B scripts/check_project.py`。后端复跑用同一目录的 `readback3.sh`、`readback-relay.sh`、`relay-sta.sh` 和 `repair-readback-v2.sh`，通过独立 Slurm 作业读取已冻结工件。
