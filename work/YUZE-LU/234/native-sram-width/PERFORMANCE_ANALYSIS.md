# Qwen2.5-3B 短程回放与瓶颈分析

实验使用 Algo1 封存的母控指令和局控描述符。母控 CALL/WAIT、局控服务、有限 SRAM 端口和双通道 DRAMsim3 回调推进同一条模拟时间线。DDR 写入在完成回调后可读。Decode 从 512 个代表性 KV 位置起步，每步执行 36 层和完整词表投影，第二步读取第一步实际追加的 KV 与选出的 token。Prefill 从空 KV 开始。控制和算术服务采用事件模型，DMA 仲裁采用 FIFO 模型。所有短程结果的硬件时序校准和正式 P512/D128 验收仍待完成。[执行入口](../../../../project/experiments/systemc_benchmark/README.md) · [输入和证据索引](README.md)

## KV 为什么堵

| Attention 对照 | 首层页面 | 第二步 36 层合计 |
| --- | ---: | ---: |
| 1 个 DDR credit，KV 窗口 1 | 19.629 ms | 708.604 ms |
| 32 个 DDR credit，KV 窗口 1 | 19.629 ms | 708.546 ms |
| 32 个 DDR credit，KV 窗口 8 | 13.652 ms | 492.482 ms |

扩大外部 DMA 在途额度后，Attention 变化很小。局控主动把同一分片的预取窗口扩到八笔，首层快了 **30.5%**，仍等整片写入确认后再计算。107947 中分片之间依然串行。模型统计的零端口争用只表示请求到达时没有因抢口排队，逐笔等待 ACK 仍消耗关键路径时间。[KV 预取模型](../../../../project/experiments/systemc_benchmark/native_tlm_attention.py)

作业中途对齐前 22 层时，Attention 已从约 432 ms 降到 300 ms。当时 Attention 和 FFN 分别约占已执行时间的 68% 和 20%，该阶段尚未执行词表头。上表给出后来回收的完整第二步结果。

| 路径 | 513 个可见位置时，每次 Attention 调用的单位置读取 | 每层 16 次调用的历史 DDR 读请求 |
| --- | --- | ---: |
| K → QK 点积 | 每位置一整行 512 B，8 笔 | 65,664 |
| V → 加权求和 | 16 个输出组各读两笔 64 B，共 128 B，只保留 32 B | 262,656 |

V 占历史 KV 请求的 80%。相邻四个输出小组读同一段 128 B，只各取其中 32 B。八笔预取改变请求发出的时间，重复读取次数保持相同。首层整个 Attention 页还有描述符等读请求，实际为 328,388 读、128 写。

## 接口上限与最小改动

| 数据路径 | 300 MHz 下的上限 |
| --- | ---: |
| 双通道 DDR | 50.8 GB/s，单通道约 25.4 GB/s |
| 母控 DMA 读发射 | 51.2 GB/s，两路各每三拍最多四笔 64 B 请求 |
| 单 P 的 M 权重入口 | 19.2 GB/s，64 B/拍。三个入口合计 57.6 GB/s，共享外存 |
| 每组私有 S 普通 128-bit 口 | 4.8 GB/s，读写及客户端共享 |
| M 内部计算口，每 P | 权重 38.4 GB/s，激活 9.6 GB/s，38.4 GMAC/s。三 P 合计 115.2 GMAC/s |
| Attention KV 与 N Softmax | 共用普通 S，接口上限 4.8 GB/s |
| G32 门控 | 输入合计 4.8 GB/s，输出 2.4 GB/s |
| E32 AP64 | 每方向 2.4 GB/s |

上表是峰值。外部 DDR 按每通道每 4 个 630 ps 时钟传 64 B 计算。M 满拍按 128 MAC/拍计算。G/E 完整服务还含握手和访问次数。[本轮接口合同与 RTL 查证点](README.md#源代码查证点)

| Attention 单层，513 个可见位置 | 量级 |
| --- | ---: |
| KV 写入 S、再读给点积，约 16.8 MB | 128-bit 口满拍的独立下限 3.50 ms |
| QK 和 AV 点积，约 210 万 MAC | 四路 S32 点积满拍的独立下限 1.75 ms |
| 8 笔 KV 预取的首层页面 | 模拟 13.65 ms |

两个下限适用于不同资源，且 SRAM 下限还未计 Q、分数和 Softmax。当前没有点积阵列满载的证据。Attention 的四路 S32 点积和 FFN 的 W8A16 M 阵列分别计账。

128-bit KV RTL 加载器依次经历 READ、READ_WAIT、STORE、STORE_WAIT。一笔 64 B 返回拆成四个 16 B 写，逐笔等 ACK。即便下一拍就确认，写阶段最多两拍发一笔，即 2.4 GB/s。现有 SRAM 响应侧有两个槽，最小 RTL 候选是允许两笔写在途、按标签和地址收确认，并在全部写入提交后才释放点积。验证要覆盖回压、连续写接受间隔和整片交接。

| KV 写口 | K 每笔有效 64 B | V 每笔保留 32 B |
| --- | ---: | ---: |
| 128 bit | 4 笔 | 2 笔 |
| 256 bit | 2 笔 | 1 笔 |
| 512 bit | 1 笔 | 1 笔，仅开启两路 128-bit bank |

| 局部宽写候选 | 当前路径 | 候选路径 |
| --- | --- | --- |
| K 搬入 | 四笔 128-bit 写，逐笔确认 | 对齐后四 bank 同写，一笔确认 |
| V 搬入 | 两笔 128-bit 写 | 两 bank 同写，保留其他 bank 内容 |
| Dot 读 SRAM | 普通 128-bit 口 | 维持 128-bit 读口与现有乘法器 |

现有四银行 SRAM 的 512-bit feeder 只读。局部宽写需补 bank 数据和使能、仲裁、地址对齐和 ACK。假设下一拍确认，512-bit 逐笔等待时的 K 写阶段上限为 9.6 GB/s，做到每拍接受一笔后为 19.2 GB/s。两者都需要在 300 MHz 下验证外围和数据通路。

## 全部在用数据 SRAM 加宽的对照

用户要求先看部署中全部普通 128-bit SRAM 改宽的收益。108284 覆盖 U、P0/P1/P2 的数据 SRAM，以及程序存储的装载写入。每笔合并同一 bank 行最多四个 16 B 字，部分写有 bank 使能，跨行拆开，仍等待响应。容量、时钟、计算单元、母控指令、DDR 配置与八笔 KV 窗口固定。模型假设 512-bit 路径维持原响应周期，单字消费者仍按原服务节拍执行。

| 首层阶段 | 128 bit | 512 bit | 耗时减少 |
| --- | ---: | ---: | ---: |
| Attention 和输出写回 | 13.652 ms | 5.801 ms | 57.5% |
| QKV、RoPE 和 KV 写入 | 1.201 ms | 0.856 ms | 28.7% |
| O 输出投影 | 0.838 ms | 0.544 ms | 35.1% |
| FFN | 4.096 ms | 3.434 ms | 16.2% |
| 首四个完整层合计 | 80.203 ms | 43.540 ms | 45.7% |

首四层逐页 DDR 读写笔数及母控指令周期相同。宽口收益包含数据端口和程序装载写入的合计变化。

| 短程实验 | 工作负载 | 审计结果 |
| --- | --- | --- |
| 107947，128-bit decode 对照 | 512 个代表性 KV 位置，连续生成两 token，582 页 | 1.207 tok/s |

Decode 用两次实际退休时间差的倒数。Prefill 用两个输入位置除以第二个末层残差的模拟完成时间。当前部署的词表投影位于完整 512-token prompt 之后，短 prefill 范围到第二个输入位置的末残差。[Prefill 审计](evidence/108359/timing-audit.json)

## 方案状态与验证顺序

| 改动 | 当前证据 | 下一项验证 |
| --- | --- | --- |
| KV 八笔读窗口 | 完整两步事件回放 | RTL 有限缓冲、返回乱序、ACK 和仲裁 |
| 全在用 SRAM 512-bit | 事务级对照 | 先分离数据口与程序装载的收益，再验宽口 RTL、负载、300 MHz 时序 |
| 128-bit 写请求与 ACK 解耦 | RTL 接口与两槽分析 | 双在途写、回压、最后 ACK 门控及同程序 A/B |
| 256-bit 或仅 KV 512-bit 写口 | 对齐和写入次数分析 | K/V 部分 bank 写、仲裁，单独量化宽写贡献 |
| V 数据跨四个小组复用 | 同地址重复请求已定位 | 用现有 S 窗口与真实 ACK 核对流量和耗时 |
| 搬下一片与计算当前片重叠 | 当前模型分片串行 | 在现有容量下验证双缓冲、端口争用和写后读 |
| 投影权重记录内并发 | 词表头、QKV、O 页面带宽与代码证据 | 保持绑定与指令，独立增加有限请求并发 |
| Algo1 跨头排程或母控屏障调整 | WAIT 归因已厘清 | 在局控访存对照之后，用同算子和字节量检验 |
| 扩 S32 点积阵列 | 四路吞吐下限 | 先测点积等数据周期、阵列利用率和 SRAM 服务间隔 |
