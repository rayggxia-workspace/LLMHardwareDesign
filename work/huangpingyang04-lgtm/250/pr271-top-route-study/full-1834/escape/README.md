# 交换器底层逃逸与顶层引脚接入预留

2026-11-15（中国标准时间） · [PR #276](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/276) · Refs #250、#228

沿用 PR #271 方案 A 的 112878 摆位和 114252 交接，保留完整 1,834 根逻辑网。作业 116202 从原交换器 OpenDB 导出 M9/M10 信号铜与 PG、固定端口以及 V9 切孔。局部逃逸区与其余宏的固定外框不相交。原端口通过矩形精确匹配归属到原生网，网 ID、驱动和接收关系沿用交接。

## 布线

- 对 909 根交换器外框跨越网优先处理原先未布通者。用 M9 横向、M10 纵向与默认 V9 几何，从原 M10 接点接到框外 2×2 µm 的新 M10 落点。已存在的铜、PG、切孔和固定端口参与几何判冲突。两套框外落点格距分别得到 320 和 318 根通过独立矩形间距与连通核验的底层逃逸线。
- 仅把通过底层核验的端点重绑到新 M10 落点。原端口仍保留在固定几何中。顶层使用 CUGR 第二阶段的整板细粒度 Dijkstra，沿用 M11/M12 规则。短网优先，以引脚邻域密度选需预留的引脚，先占住一段合法接入和一个主轨步长。轮到该网时用预留线段作为接入，失败时释放预留。预留短线仅在整个逻辑网通过顶层核验后计入最终结果。

最佳配置布通率 **37.5%**。相较原第二阶段的 501 根，净增 187 根。同一底层逃逸版本中，最佳预留策略较不预留多 23 根。最佳配置的已布通网包括母控报文 358 根、C0→U0 94 根及 U0↔DMA 236 根。终局保留 468 个预留引脚的实际接入。其余 1,146 根中，驱动端接入失败 131 根、接收端接入失败 354 根、细搜没有找到可用路径 661 根。[原 501 网对照](../stage2/README.md)

320 根底层逃逸使必须通过外框的顶层网从 909 根降到 589 根。原两层方向和线距下，外框容量上限为 342 根。因此在当前的新落点安排下，至少还有 **247 根**需要改变过框方式，才可能做到全通。[原外框容量核验](../README.md#交换器周边容量)
