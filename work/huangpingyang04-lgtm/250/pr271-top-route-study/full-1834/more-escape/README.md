# 保留 320 根底层逃逸后的增量布线

2026-11-15（中国标准时间） · [PR #276](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/276) · Refs #250、#228

固定 PR #271 方案 A 的 112878 摆位，保留作业 116240 的 320 根底层路径和对应 M10 落点。作业 116313 重新从同一交换器 OpenDB 导出 M7–M10、V7–V9、端口、PG 和声明的障碍。新增路径保留原网 ID、驱动与接收关系。底层几何核验检查新路径与原生几何及旧 320 根路径的间距、连续性、接点归属和新落点。顶层沿用 CUGR 第二阶段的整板细粒度 Dijkstra 和拥挤引脚接入预留。

最佳作业 116336 按短网优先，接入预留邻域阈值为 9。预留 1,967 个引脚，其中 843 个进入最终通过核验的线路。734 根比上轮净增 46 根，按网 ID 对照为 206 根此前未布通的网这次布通、160 根上轮已布通的网此次未通。上轮的 320 根底层逃逸路径在各组中都保留。

- 最佳作业有 320 根经框外新 M10 落点端到端布通，其中 157 根使用旧逃逸路径，163 根使用本轮新增路径。
- 新增逃逸最多的版本有 339 根经框外落点端到端布通，其中 205 根使用本轮新增路径。新增底层逃逸数量与顶层布通数在本轮各配置里并非单调对应。
- 最佳作业分类布通为母控报文 395/1,031、C0→U0 93/153、U0↔DMA 246/650。

## 剩余卡点

最佳作业的 1,100 根未通网中，驱动端接入失败 107 根、接收端接入失败 268 根、已进入整板细搜但在当时占用下找不到合法路径 725 根。同一版落点下，其他三组顶层配置曾分别布通其中一部分，按网 ID 取并集共 263 根。

交换器仍须顶层过框 249 根，低于外框上限 342，也低于原端点紧包围框的 272 根上限。249 根中实际布通 48 根、剩余 201 根，仍要面对局部出入口和路径竞争。新增逃逸最多的版本仅余 30 根必须顶层过框，实际布通 5 根、剩余 25 根。其余未通还分布在母控报文、C0→U0 与 U0↔DMA，详见各作业分项和截面复算。

作业均为 `COMPLETED 0:0`。上层沿用 PR #259 固定版本 `4ebd2a2f` 的独立几何核验，并对照原交接核对 1,834 根全覆盖、新落点对应的 V10 和上下层网 ID。结果是归档几何上的上下层连通性试验。工艺 DRC、OpenDB 回写验收和时序尚未执行。
