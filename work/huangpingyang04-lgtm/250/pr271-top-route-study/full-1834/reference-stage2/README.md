# 只运行 CUGR 原版细粒度迷宫阶段

2026-11-15（中国标准时间） · [PR #276](https://github.com/rayggxia-workspace/LLMHardwareDesign/pull/276) · Refs #250、#228

固定 PR #271 方案 A 的作业 112878 摆位与完整 1,834 根逻辑网。分别使用作业 114252 的原始 M10 落点、已核验的 660 根逃逸版本和已核验的 879 根逃逸版本。底层逃逸版本是既有固定输入。

## 源码对照与本轮范围

上一轮作业 116336 使用项目自写的双向 Dijkstra、短网优先和预先落下的接入短线。本轮直接提取并编译 CUGR 作者在 `9b1aa8a7` 的细粒度迷宫搜索循环 `MazeRoute::route()`。编译内容逐字节等于上游函数。适配层把整板 M11/M12 主轨、固定 V10 落点和引脚附近的细网格作为同一个图送入作者循环。边成本沿用本项目按论文式 (4)、(5) 映射到物理轨道的整数成本。CUGR 在原论文中接收由前一级产生的引导框，本次输入的搜索区域取整板合法范围。完整按交接文件网序运行一次，关闭粗网格规划、模式布线、预留、拆线重布和搜索状态预算。诊断程序独立运行，其输出未传给路由器。[论文 §III-B、§III-D](https://cwpui.com/doc/c10.pdf#page=4) · [上游源码](https://github.com/cuhk-eda/cu-gr/blob/9b1aa8a7db4e32877614d7a4f6aa983254e626ce/src/single_net/MazeRoute.cpp#L37-L117) · [实际编译函数](cugr-maze-route.inc) · [适配器](reference-maze.cpp) · [CUGR 许可](CUGR-LICENSE.txt)

## 为什么不能全通

| 首次失败阶段 | 原始落点 | 660 逃逸版本 | 879 逃逸版本 |
| --- | ---: | ---: | ---: |
| 驱动端的局部细网格无法接到主轨 | 362 | 308 | 313 |
| 接收端的局部细网格无法接到主轨 | 560 | 384 | 326 |
| 引脚可到主轨，当前占用下整网无路径 | 268 | 306 | 385 |
| 已找到图路径，同网 V11 间距冲突，几何核验前剔除 | 238 | 255 | 236 |

每个落点版本在只有固定端口的图上，1,834 根网各自可达同一个主轨连通分量。这项独立诊断检查可达性，逐网提交之后的信号占用和各网并存容量由另一个实验检验。细粒度迷宫找的是单网最小代价路径。一个网找到路径也可能占住后续网的接入，并且该搜索状态本身未编码同一网不同 V11 之间的联合间距。

对每个截面，连续上限先按两层方向、线宽和线距计算。轨道图上限再枚举所有主轨和全部引脚窗口在该截面上允许的细网格跨越位置，允许每根网借用任意窗口，并以相邻中心至少 4 µm 做最大数量装填。这个上限仍未扣除实际占用。按同一张已核验输入图复算得出下面的必要条件。

| 截面 | 原始落点必过 | 660 逃逸版必过 | 879 逃逸版必过 | 轨道图上限 |
| --- | ---: | ---: | ---: | --- |
| 交换器外框 | 909 | 249 | 30 | 324 |
| U0 外框 | 1,076 | 1,076 | 1,076 | 1,046 |

原始落点的交换器外框即使放宽到连续位置也最多 342 根。两种逃逸版本的交换器需求降到上限以内，但 U0 在当前轨道和窗口规则下仍至少缺 30 个过框位置。放宽截面至连续位置会给出 U0 的 1,104 根上限。1,046 根是现有布线图的限制，区分这两者是判定全通条件的关键。工艺 DRC、寄生提取、OpenDB 回写和全量时序均未执行。

## 复跑

在含源码和脚本的服务器工作目录提交。

```bash
sbatch --output=original-%j.log run-reference.sh original original
sbatch --output=escape660-%j.log run-reference.sh escape660 "$lower660"
sbatch --output=escape879-%j.log run-reference.sh escape879 "$lower879"
sbatch --output=diag-escape660-%j.log run-diagnostic.sh escape660 "$graph660"
```

两组逃逸作业的旧提交脚本尝试载入不在计算节点上的分配器，加载器忽略后使用系统默认。当前复跑脚本直接使用相同的默认分配器。搜索源码、输入图、作业和输出的 SHA-256 见 [证据](evidence.json)。截面复算在各作业核验后执行，见 [脚本](check-cut.py)。
